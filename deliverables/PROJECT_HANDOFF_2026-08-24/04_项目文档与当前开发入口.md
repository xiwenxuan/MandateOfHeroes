# 项目文档与当前开发入口

## 1. 项目一句话

《群雄志：仕途》是一款开源单机家族人生模拟、角色扮演与战略沙盒游戏。玩家可自建任意人物
或选择历史人物，以军人、官吏、商人、农户、工匠等身份生活数代，并在同一永久人口、经济、
设施、组织、地图和战争世界中留下可继承后果。

## 2. 权威层级

```text
用户当轮明确指令
→ AGENTS.md
→ mandate-unity-development Skill
→ task-routing.md
→ GAME_SYSTEMS_MASTER_AND_STATUS.md
→ 当前领域 L1 设计与任务书
→ 现有代码、测试和存档兼容事实
```

任务书已经建立、代码已经存在、自动测试通过和玩家已经认可，是四种不同事实，不能混写。

## 5. 关键不可破坏规则

- 核心世界事实不能只存在于 UI、场景对象或表现层。
- 每个人从出生起具有永久身份；冷热降级不能删除、合并、替代或重新随机人物。
- 人口、兵员、物资和财政变化必须可追溯，损耗也必须有来源和账目。
- 存档是兼容合同，持久结构变化必须顺序迁移和往返测试。
- 玩家关注改变信息与表现精度，不改变同一世界事实。
- 作物、产品、配方、设施、技能、科技、装备、兵种和任务等开放集合使用稳定命名空间 ID 与数据定义。
- 外部代码、数据和素材必须确认兼容许可证并登记来源；禁止复制商业游戏内容。
- Global Cell 是最终权威空间分区；正式 Cell 仍为 2,000 米，不因表现细化创建模拟 SubCell。

## 6. 代码架构

| 程序集 | 职责 |
|---|---|
| `Mandate.Domain` | 纯 C# 世界状态、不变量、稳定身份、确定性规则 |
| `Mandate.Simulation` | 跨实体行为、时间推进、命令、事务和世界系统编排 |
| `Mandate.Persistence` | 序列化、迁移、检查点与兼容 |
| `Mandate.Presentation` | Unity 场景、界面、输入和视觉表现 |

`Mandate.Domain` 不得反向依赖 Unity 表现层。

## 7. 新任务开工流程

1. 先读 `AGENTS.md` 与项目 Skill。
2. 检查 `git status`，保护当前 342 条工作区状态。
3. 从 `task-routing.md` 选择最小必要设计。
4. 检查现有实现与测试后再设计新抽象。
5. 涉及存档、架构、玩法方向或公开行为的假设必须明说。
6. 代码任务按项目规定的完整验证顺序验收。
7. 未经用户明确授权，不提交、不推送、不创建 PR、不删数据、不关闭 Unity。
