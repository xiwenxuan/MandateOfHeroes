# M25-P19 任务书：村内跨家庭救济排序与授权快照

## 一、任务定位

承接 M25-P16 的具体家庭领取、M25-P18 的逐人配额和现有县级治理事实。本阶段解决村公共
粮仓不足以同时满足全部家庭时的两个核心问题：哪些家庭先领，以及该次排序由什么政策、什么
组织和什么人物授权。排序和授权必须成为持久、可审计的世界事实，不能继续隐含在家庭 ID 顺序
或界面表现中。

## 二、实现范围

### 2.1 V41 村庄政策合同

- 村庄保存救济优先政策 ID、授权政策 ID 和授权组织 ID；普通内容使用稳定命名空间 ID，
  不用固定枚举封死未来政策。
- 原型村庄采用“缺口严重度→脆弱受损人数→受损总人数→家庭稳定 ID”的需要优先政策，
  并由所属县政府当前领袖依法授权。
- 没有正式县治理的兼容村庄使用明确的紧急系统授权政策，不伪造官府、里正或个人签字。

### 2.2 家庭领取授权快照

- 每张新领取单保存优先政策、授权政策、授权组织、授权人物、授权日、短缺严重度、
  脆弱受损人数和授权时受损总人数。
- 短缺严重度按 `缺失营养 / 原始所需营养` 计算为 1—10,000 基点。
- 当前营养模型中儿童和老人均使用 20,000 月需求，授权快照据此统计脆弱受损人数；
  该统计只用于排序，不改变 P18 的逐人配额或实际健康后果。
- 授权快照在建单时冻结；后续官员更替不得静默改写旧请求的授权人和排序依据。

### 2.3 跨家庭分配顺序

- 先按月结日、村庄稳定 ID 保持旧请求优先；同日同村且均使用新政策时，再按严重度、
  脆弱人数和受损人数降序，最终按家庭稳定 ID 破同分。
- 只有真实可用村仓批次、合格领取人和家庭仓容量同时存在时才交付；政策不产生粮食，
  也不绕过 P16/P18 的库存、人物和份额规则。
- V40 既有请求保持旧“月结日→村庄→家庭 ID”兼容顺序，不从当前家庭状态倒推历史优先级。

### 2.4 V40→V41 迁移

- 为现有村庄设置当前默认政策；能找到所属县治理时引用其政府组织，否则设置紧急系统授权。
- 所有既有领取单标记为明确旧排序和旧系统授权，新增评分、人数和授权日使用 `-1` 兼容哨兵，
  授权组织/人物留空。
- 不重排已经发生的交付，不修改库存事务，不伪造历史官员决定。

## 三、验收标准

1. 村仓只有少量粮食时，更严重的同日家庭先于家庭 ID 更小但缺口较轻的家庭领取。
2. 新领取单的政策、授权组织、授权人物、授权日和排序指标与建单时世界事实闭合。
3. 相同种子、相同政策与相同库存产生相同排序、事务和快照。
4. 紧急系统授权不伪造组织或人物；县政府授权必须引用真实政府组织和永久人物。
5. V40 有请求存档迁移后保持旧顺序且不伪造历史授权；V41 当前存档可往返保存。
6. 篡改严重度、人数、授权引用、政策 ID 或兼容哨兵会被领域校验拒绝。
7. 全工程编译、完整核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别通过。

## 四、非目标

- 本阶段不实现玩家政策编辑器、逐单人工批准、贪腐截留、关系徇私或排队动画。
- 不实现照护者送餐、病号餐、长期营养史、疾病恶化或备餐腐败。
- 不改变家庭实际缺口、逐人配额、永久人物冷热层级或关注精度。
- 不把县级自动授权扩写为完整州郡法定授权树。
