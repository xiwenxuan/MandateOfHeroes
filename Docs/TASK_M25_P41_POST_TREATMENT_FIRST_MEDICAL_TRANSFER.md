# M25-P41 部分疗程后首次同组织转院任务书

## 一、阶段目标

承接 M25-P32 的治疗前首次转院与 M25-P35/P36 的住院、转运死亡结案，把同一永久伤员、
同一伤情和同一冻结疗程扩展到“已经完成一个或多个、但尚未完成全部疗程阶段”后的首次转院：

```text
来源设施完成部分冻结疗程
→ 军队级权限批准首次同组织直接转院
→ 冻结转院时已完成阶段数，只预留剩余阶段药材
→ 来源床位释放，患者与原救护队沿真实道路旅行
→ 目标医者接收后承担后续责任
→ 已完成治疗永久保留在来源设施/来源医者账中
→ 未完成阶段只消耗目标院预留药材并继续原冻结顺序
```

转院不得重做已完成阶段、重新生成伤情、重算冻结计划、复制药材、回退永久伤残结果或改变
人物身份。关注层级、读档与以后内容定义变化不得改变转院时冻结的阶段边界。

## 二、本阶段范围

1. 存档升级至 V63，新增部分疗程后转院合同启用日；V62→V63 只建立次日启用边界。
2. 允许住院伤员在完成至少一个、少于全部冻结疗程阶段后，执行首次、直接、同组织转院。
3. 转院记录必须冻结 `CompletedTreatmentStagesAtDispatch`；来源阶段、治疗ID、来源设施、医者、
   药材和库存事务保持原记录，不改写为目标院责任。
4. 目标院只按转院时尚未完成的冻结协议计算药材需求，并在一个具体药材批次中正式预留。
5. 患者与原救护队继续使用普通人物旅程；目标床位从出发时预留，正式接收后才迁移当前设施、
   当前照护地点和主治责任。
6. 接收后的治疗只能从冻结阶段边界继续，使用目标院预留批次并同步减少实物和预留量。
7. M25-P35 的住院死亡与 M25-P36 的转运死亡继续适用：已完成治疗不回滚，只释放本次转院
   尚未使用的目标药材预留。
8. 治疗前首次转院保持原有 V54 语义；旧转院的阶段快照继续为零。

## 三、验收条件

- 完成部分疗程后合法转院，只预留剩余药材；往返保存后可以在目标院完成剩余阶段并正常结案。
- 来源治疗仍引用来源设施、来源医者及非预留库存事务；目标治疗引用目标设施、接收医者和本次
  转院预留批次，全部阶段索引连续且不重复。
- 部分疗程后合同尚未启用、疗程已经完成、已经转过一次、目标药材不足、路线/人员/权限
  不合法时原子拒绝；治疗前首次转院继续使用既有 V54 合同。
- 篡改转院时阶段数、预留数量、来源治疗地点/医者、目标治疗批次或责任交接时世界校验拒绝。
- V62→V63 不创造部分疗程后转院历史，不修改既有治疗、转院、死亡或资源结案事实。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 与范围审阅分别完成。

## 四、明确不包含

- 第二次及更多连续转院；
- 跨组织费用、药材、床位、抚恤或医疗责任结算；
- 转院取消、改道、拒收、自动选院、床位队列和多批次药材预留；
- 新增转运途中急救、队员伤亡、车辆、天气或袭击；
- 修改已完成手术造成的永久伤残，或实现术后护理班次和玩家医疗界面。
