# M21-P3 任务书：农业生产人物仓储迁移

## 一、阶段目标

承接 M21-P2 的村庄生活与人口台账迁移，把农业工单创建、家庭劳作者选择和收获结算中
对具体人物的访问切换到统一 `IPersonRepository`：

```text
农业工单经理与劳作者稳定ID
→ 人物仓储只读访问
→ 校验身份、位置、劳力与农业技能
→ 家庭粮账、设施库存和农业工单按原规则结算
```

本阶段不改变农业配方、产量、劳动、粮食守恒、随机坐标或存档结构。农业系统当前只读取
人物事实，不修改人物状态，因此不得把经理或劳作者误标为待写回人物。

## 二、权威边界

- 永久身份、冷热存储和关注规则遵守 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 农业内容与守恒遵守 `PRODUCTION_AGRICULTURE_INDUSTRY_AND_PROGRESSION_DESIGN.md` 和
  `TASK_M17_P0_DATA_DRIVEN_PRODUCTION_CONTENT_CONTRACT.md`。
- 作物、品种、产品、配方和生产方法继续使用稳定数据定义 ID，不新增固定内容枚举。
- 本阶段不提升世界存档版本，不新增持久字段，不改变 `WorldState.People` 兼容视图。

## 三、工作包

### WP1：农业人物访问接入

- `AgricultureProductionSystem` 接受可选共享 `IPersonRepository`。
- 工单经理、指定劳作者、委任家庭劳作者和结算技能读取都通过仓储完成。
- 未注入时按世界缓存兼容适配器，保持所有既有构造调用有效并避免循环中重复建索引。

### WP2：村庄共享注入

- `VillageLifeSystem` 把自身收到的共享人物仓储传给农业系统。
- `WorldSimulator` 现有注入链无需新增公开参数；同一模拟器内继续共享调用者提供的仓储。

### WP3：回归验证

- 验证注入与未注入模式从建单到收获生成完全相同的世界快照。
- 验证成功生产只读人物，不产生新增或修改人物集合。
- 验证缺失经理在改变任何世界事实前被拒绝，并保持人物仓储干净。
- 保留一年村庄闭环、数据驱动生产、粮食与库存守恒回归。

### WP4：状态同步与交付

- 更新系统总纲和 M12 当前迁移状态。
- 完成编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅。
- 只提交本任务文件，并推送当前分支。

## 四、不纳入本阶段

- 教育、医疗、军事、建设、科研、加工和贸易人物访问迁移。
- 人物农业经验、技能成长、劳动疲劳或工单期间 `LocalDuty` 改写。
- 新作物、配方、产品批次、市场成交、多仓库物流和农业界面。
- 未驻留人物完全移出 `WorldState.People`、异步数据库或千万级完整游戏负载。

## 五、验收标准

1. 农业系统不再直接遍历 `WorldState.People` 查找人物。
2. 注入与兼容模式在相同世界、种子、日期和指令下生成相同快照。
3. 农业建单、选工、收获和审计不会产生伪人物变更。
4. 缺失人物引用在粮食、设施和工单发生变化前明确失败。
5. 既有农业内容 ID、粮食与库存守恒、年度村庄闭环保持有效。
6. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和差异审阅通过。
