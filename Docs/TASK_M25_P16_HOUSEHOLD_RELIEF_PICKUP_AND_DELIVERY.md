# M25-P16 任务书：家庭缺粮申请、月内领取与实际交付闭环

## 一、任务定位

承接 M25-P10 的正式家庭月度用粮结算、M25-P14 的跨县救济到村恢复和
M25-P15 的正式仓储损耗。本阶段把村级“有人缺粮”继续下钻为可持久、可审计的
具体家庭领取申请：月结准确保存每户尚未满足的营养缺口；村仓后来获得粮食时，
由真实家庭成员领取到家庭粮仓，并由正式库存事务解释实物移动。

本阶段不回写已经发生的饥饿健康损失，也不把领取粮再次计入已经结束的当月消费。
领取到家的粮食成为家庭真实库存，参与后续消费、仓储损耗和其他正式系统。

## 二、实现范围

### 2.1 V38 持久合同

- 新增家庭救济领取申请，保存稳定 ID、来源月结短缺事件、村庄、家庭、月结日、
  缺口营养、已交付营养与实物数量、最近领取人、最近领取日、状态及库存事务引用。
- 请求状态为封闭协议状态；作物与食物内容仍由稳定命名空间 ID 和数据定义决定。
- V37 到 V38 只初始化空领取账，不从历史村级事件猜测具体家庭缺口。

### 2.2 月结建单

- M25-P10 月结在完成原有“家庭库存→村仓即时补助→当月消费”后，按具体家庭保存
  剩余营养缺口。
- 同一月、同一村、同一家庭只能有一张请求；重复命令或存档恢复不得重复建单。
- 请求来源与原村级短缺事件一致；原事件仍保持一村一月一条。

### 2.3 月内领取

- 领取只扫描已有开放请求和涉及家庭的成员，不扫描全世界永久人物。
- 以结算日、村庄 ID、家庭 ID 的稳定顺序排队；先到期请求先领取。
- 领取人优先为仍在本村、存活且未服征兵役的家主，否则按稳定人物 ID 选择合格成员。
- 食物从该村公共粮仓转入对应家庭粮仓；容量、批次、营养和正式库存事务沿用统一
  `FoodInventorySystem`。
- 村仓无粮、家庭仓无容量或没有合格领取人时保留开放请求，不伪造交付、不删除人物。
- 请求可部分完成；实际转移营养可能因最小实物单位略高于剩余缺口，此时请求完成，
  超出的实物仍真实留在家庭仓。

### 2.4 统一世界运行

- 每个新日，在正式家庭月结之后、仓储损耗之前执行一次领取调度，使月结后仍可用的
  村仓库存立即参与分配。
- 每个运输到达段，在跨县救济恢复到村之后执行一次领取调度，使新到村粮食无需等到
  下月结算。
- 命令、事务和事件使用稳定 ID；无可交付工作时不创建空命令。

## 三、验收标准

1. 月结为每个真实短缺家庭保存精确缺口，且不重复计算 M25-P10 已经发放的村仓粮。
2. 到村粮食按稳定队列转入具体家庭仓，库存总量守恒并留下正式库存事务。
3. 部分领取、无领取人、家庭仓容量不足和村仓无粮均不伪造完成状态。
4. 重复调度、存档往返和相同种子世界结果确定且幂等。
5. V37 到 V38 初始化空账；篡改请求数量、状态、引用或库存事务会被领域校验拒绝。
6. 模拟器可在同一到达段完成“跨县到村→家庭领取”，并在月结日按规定顺序运行。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 与范围审阅分别通过。

## 四、非目标

- 本阶段不实现玩家界面、排队动画、腐败截留、灾民跨村移动或救济资格政策编辑器。
- 本阶段不追溯重算 V37 及更早存档中已经发生的家庭短缺。
- 本阶段不治疗或撤销月结时已经发生的健康损失；后续健康恢复另立任务。
- 本阶段不改变永久人口、人物冷热、关注度和历史人物规则。
