# M24-P3任务书：百万家庭土地、种子/产品批次与年度农业工单

## 一、阶段目标

在M24-P2家庭库存、县级市场、官仓和跨县赈运闭环上，接入M17/M19已经建立的数据驱动生产合同：

```text
正式生产内容包中的稳定作物/品种/种子/产品/配方/方法ID
→ 固定县级可耕地分配为家庭自有地、租用地和未分配公地
→ 具体家庭以具体农业劳力、土地和真实种子批次建立年度工单
→ 工单按劳力、种子、天气和方法结算具体产品批次
→ 收获分成留种、地租、税粮、家庭粮食和明确损耗
→ 家庭产品进入M24-P2市场、消费、官仓与赈运
→ 土地、种子、产品、现金、人口和工单历史共同接受长期守恒审计
```

本阶段继续使用独立百万世界压力工具，不升级V28正式存档，不把压力工具的紧凑记录冒充正式`WorldState`产品批次实现。

## 二、实施合同

1. 工具直接读取`Assets/Resources/Content/Core/Production/core-production.json`，不得在模拟代码中写死`CropKind`或把显示名作为身份。
2. 农业绑定由作物、地方品种、种子产品、收获产品、种植配方和生产方法稳定ID组成；缺失或重复引用必须拒绝。
3. 每户保存自有地、租用地、当前作物绑定、种子批次数量、活力、纯度、当前收获批次数量和来源年度。
4. 批次稳定ID由家庭ID、内容ID和来源工单坐标确定性重建，不依赖列表位置、系统时间或Unity对象。
5. 每个实际耕作家庭每年形成一张紧凑、流式写盘的农业工单；工单保存家庭、县、年份、土地、劳力、种子投入、收获、留种、地租和税粮。
6. 新婚家庭的土地和种子只能从双方原家庭转移；绝户的土地、种子与粮食进入所在县公地、县种子储备或官仓。
7. 家庭可耕面积同时受已分配土地、具体农业劳力和真实种子数量限制；缺种不能凭空播种。
8. 留种是收获产品向种子批次的内部用途转换；地租和税粮是家庭向县级公共库存的内部所有权转移。

## 三、守恒式

土地：

```text
各户自有地 + 各户租用地 + 县级未分配公地 = 开局固定县级可耕地
```

粮食与种子折算总量：

```text
期末家庭粮食 + 期末家庭种子 + 期末官仓粮食 + 期末县种子储备
= 开局粮食/种子总量 + 工单毛收获
 - 工单播种投入 - 仓储腐败 - 冲突征夺 - 家庭消费
 - 运输自然损耗 - 承运途中口粮
```

每张工单：

```text
毛收获 = 家庭可用收获 + 留种 + 地租 + 税粮
```

现金继续沿用M24-P2全局守恒式。

## 四、性能与记录策略

- 当前家庭批次状态常驻紧凑数组；历史工单按年度和稳定家庭顺序流式写入，不把50年全部工单对象常驻内存。
- 同一家庭同一内容ID且所有权、用途和来源摘要相同的当前库存允许紧凑聚合；工单历史仍保留来源年度。
- 关注状态不进入产量公式；本压力工具不创建逐地块Unity对象或百万份完整NPC AI。

## 五、验收标准

1. 内容投影拒绝缺失作物、品种、种子、收获产品、配方或方法引用。
2. 增加新的合法种植定义不要求新增作物枚举或改变紧凑批次结构。
3. 1万人10年双跑的工单文件、家庭生产文件、内容摘要和世界结果完全一致。
4. 每县及全局土地严格守恒；种子不足会缩小耕作面积且不会产生负库存。
5. 工单投入、毛收获、留种、地租、税粮和家庭可用收获逐笔守恒。
6. M24-P0/P1/P2兼容自测继续通过。
7. 100万开局连续运行50年，不超过285秒候选超时并形成内存、磁盘和SHA-256证据。
8. 全工程编译、核心测试、受控Unity EditMode测试、`git diff --check`与范围审阅分别通过。

## 六、不包含

- 多块田的逐日生长阶段、土壤网格、水文寻路、病虫害传播与现场动画；
- 同一家庭同时经营多种作物、混批拆批、跨仓转运和逐维品质衰减；
- 私人地主之间的租约、债务、诉讼、继承份额与豪族兼并；
- 农具、畜力、肥料、水利设施和农业技能成长的百万规模同时负载；
- 正式存档迁移、Unity生产界面、提交或推送仓库。
