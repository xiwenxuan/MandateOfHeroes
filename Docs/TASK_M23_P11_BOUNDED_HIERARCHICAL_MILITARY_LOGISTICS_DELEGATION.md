# M23-P11 有边界的父子军需目标拆解与权限预算继承任务书

## 1. 阶段目标

在M23-P9/P10已经形成的军需目标、报价、自动调度和履约报告之上，建立第一条可审计的
逐级委任闭环：

```text
军队主将签发根目标
→ 根目标受任人把完整数量拆给若干下级
→ 子目标继承目标军队、产品、目的地、红线与总预算边界
→ 子目标可在深度上限内继续拆解
→ 叶子目标分别接受真实报价并生成真实货运
→ 子目标状态按稳定顺序回写父目标
→ 全部子目标真实完成后父目标完成
```

拆解只分配责任和预算，不得制造军粮、资金、军权或运输结果。根签发人的军级权限与下级
受任人的执行责任分开保存；真实发运继续使用根签发人的有效军权，并要求受任人仍保持被
委任时的军职权限。

## 2. 必须完成

1. 为持久军需目标保存父目标、深度、受任人、委任人、受任时权限和直接子目标ID。
2. 根目标深度为0、受任人为签发人；V24旧目标迁移为没有父子的根目标，不倒推历史委任。
3. 首批层级上限为2：军队主将可委任分队主将或在役成员，分队主将可再委任普通在役成员，
   `Self`级受任人不得继续向下拆解。
4. 委任人必须是父目标当前受任人，且当前军权不得低于受任时权限；新受任人必须在目标军队
   服役、存活、可用，并且当前权限严格低于委任人。
5. 一次拆解创建1—8个直接子目标；输入先按受任人稳定ID排序，再生成稳定子目标ID。
6. 同一批子目标受任人不得重复，子目标数量之和必须等于父目标数量，预算之和不得超过父
   目标预算，最高单价和期限不得放宽父目标约束。
7. 子目标必须继承签发人、目标军队、目的地、产品、货物使用红线、风险政策与威胁组织；
   可以在父目标范围内选择更严格的单价、预算、期限、报告周期和承运偏好。
8. 父目标已有报价、货运或子目标时不得再次拆解；拆解必须原子化，任一子请求无效时世界
   快照零变化。
9. 拆解后的父目标不得接受报价或直接发运；叶子目标继续复用既有报价、自动调度和真实货运。
10. 叶子目标发运前同时复核根签发人军级权限和当前受任人的存活/军职权限；失效形成持久异常。
11. 日界先处理叶子目标，再按深度从深到浅汇总父目标；全部直接子目标完成后父目标完成，
    子目标异常或未完成时形成有子目标引用的周期/异常报告。
12. 存档升级到V25，并增加父子引用、预算/数量继承和无环层级校验。
13. 自动测试覆盖单层拆解、两层拆解、越权/同级/超深拒绝、数量预算约束、原子失败、受任人
    失权、父子完成回写、稳定顺序、V25往返和V24迁移。

## 3. 本阶段边界

- 本阶段实现同一军队内部的“军主—分队主将—具体在役人员”责任链；
- 尚不伪造当前代码中不存在的君主—都督—太守跨组织法定权限树，该能力需先建立政权、州郡、
  军团和财政授权合同；
- 不自动让NPC决定如何拆分目标，拆解由明确领域命令提交；后续AI只能调用同一命令；
- 不支持拆解后改配、撤销子目标、追加预算、跨军队转派或部分数量回收；
- 不实现信用、违约赔偿、自动寻路或自动多段方案生成；
- 不增加Unity界面；不提交、不推送仓库。

## 4. 验收标准

1. 父子结构无环、深度不超过2，父子双向引用和继承字段完全一致；
2. 任一无效拆解不会创建目标、报告或修改父状态；
3. 子预算合计不超过父预算，子数量完整覆盖父数量，实际支出仍来自真实组织金库；
4. 越权、同级转派、失去军职或受任人死亡都不能发运；
5. 叶子目标到货前父目标不得提前完成，全部直接子目标完成后可在同一日界逐级完成；
6. 父目标报告能够通过稳定子目标ID追溯创建、进度和异常；
7. 玩家关注与界面加载不影响拆解、调度、发运或完成结果；
8. V25快照往返一致，V24迁移只建立根目标默认值且不伪造委任历史；
9. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。
