# M21-P0 任务书：模拟人物仓储访问层与增量变更检查点

## 一、阶段目标

承接 M15-P6 分区人口包与 M20-P0 关注驻留底座，建立模拟系统从直接扫描
`WorldState.People` 逐步迁移到人物仓储访问层的第一条正式通路：

```text
模拟系统按稳定人物 ID 读取或申请修改
→ 仓储访问层返回当前权威人物实例
→ 修改访问形成稳定脏人物集合
→ 只重写受影响的人口分区
→ 原子提交新代际并清除已提交变更
```

本阶段以旅行、关系和任务三个活跃人物系统作为首批消费者。未迁移系统继续使用内联人物，
不得一次性移除 `WorldState.People`，也不得把局部接入描述为超大人口完整运行时。

## 二、权威边界

- 永久身份、分级模拟和批量存储规则以
  `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md` 为准。
- 分区人口包、冷热扩展和脏降温合同以
  `TASK_M15_P6_FORMAL_PARTITIONED_POPULATION_ADAPTER_AND_RESIDENCY_CONTRACT.md` 为准。
- 关注驻留计划以
  `TASK_M20_P0_ATTENTION_LOCAL_RELATIONSHIP_AND_RESIDENCY.md` 为准。
- 增量检查点只能更新既有永久人物；出生、死亡档案迁移和跨分区新增人物留给后续阶段。

## 三、实施范围

### WP1：统一人物访问合同

- 新增纯 C# `IPersonRepository`，区分只读取得与修改取得。
- 提供当前内联世界适配器，按稳定 ID 建索引，并在人物出生后允许增量发现。
- 修改访问进入稳定、去重、可查询的变更集合；成功提交后只清除对应变更。
- 仓储访问层不复制、合并、删除或重新随机人物。

### WP2：首批模拟系统迁移

- `TravelSystem` 的旅行消耗与抵达地点修改通过访问层取得人物。
- `RelationshipSystem` 的访问者需求修改通过访问层登记。
- `TaskSystem` 的任务奖励通过访问层登记。
- 现有调用不注入仓储时继续兼容内联世界；`WorldSimulator` 可注入同一访问层供首批系统共享。

### WP3：按分区增量检查点

- 新增只包含存储修订号和变更人物的检查点合同。
- 提交前完整验证变更 ID、现有核心、详细扩展和存储修订单调性。
- 只读取和重写包含变更人物的分区；未变化分区在新清单中继续引用已有校验文件。
- 每个变化人物同时更新永久核心和完整扩展，二者必须匹配。
- 新清单和当前指针继续原子提交，失败不得改变当前代际。

### WP4：世界与变更集协调

- 协调器从人物仓储取得稳定排序的变更人物并提交增量检查点。
- 成功后同步 `WorldState.PopulationStorage` 修订与清单摘要，再确认变更。
- 提交失败时世界存储元数据和仓储脏集合保持原样。
- 检查点成功后，M20 驻留会话能够安全降温已经持久化的人物。

### WP5：验证与文档同步

- 验证首批三个系统在注入访问层前后产生相同世界结果。
- 验证修改人物被登记，纯读取不产生脏记录。
- 验证单人物修改只生成一个新分区文件对，其他分区路径和摘要不变。
- 验证未知人物、重复人物和非递增修订在提交前被拒绝，当前指针不变。
- 验证增量提交后人物核心、扩展、人口计数和永久 ID 往返一致。
- 更新系统总纲、M12/M15/M20兼容记录、确定性存档说明和 Skill 路由。

## 四、不纳入本阶段

- 一次迁移全部模拟系统或从主世界快照移除冷人物。
- 在增量检查点中新增人物、删除人物或改变分区数量。
- 自动轮换、压缩、合并或清理旧代际。
- 异步 IO、后台线程、跨进程数据库和 Unity 场景对象驻留。
- 千万级完整游戏负载验收。

## 五、验收标准

1. 人物访问合同按稳定 ID 工作，读访问不脏、修改访问可审计且顺序稳定。
2. 旅行、关系和任务系统不再各自直接扫描人物列表，并保持原有确定性结果。
3. 单人物增量检查点只改写其所属分区，未变化分区文件路径和摘要保持不变。
4. 检查点后核心和详细扩展匹配，人物总数、在世数、永久 ID 和跨引用不变。
5. 失败提交不推进当前指针、不修改世界存储元数据、不清除脏人物。
6. 已提交热人物可以安全降温，未提交修改仍被拒绝。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。

## 六、执行记录

### 6.1 实现结果

- 新增 `IPersonRepository` 与 `WorldStatePersonRepository`，按稳定人物 ID 提供读取、修改取得、稳定脏集合和提交确认。
- `TravelSystem`、`RelationshipSystem`、`TaskSystem` 已移除各自的人物列表扫描；`WorldSimulator` 与 `NpcActionResolver` 支持注入共享人物仓储。
- 新增 `PopulationIncrementalCheckpoint`，并扩展正式人口存储接口以读取完整分区和提交人物变更集。
- `PartitionedPopulationStore` 会在写盘前加载并验证全部受影响分区，只替换既有人物核心与扩展；未变化分区继续引用已有路径和摘要。
- 新代际目录只包含受影响分区的核心/扩展文件对及新清单，当前指针继续原子替换。
- `PopulationPersonCheckpointCoordinator` 在成功后同步世界存储元数据、刷新 M20 热驻留基线并清除已提交脏集合；失败时三者均不提前改变。
- 系统总纲、M12、M15-P6、M20-P0、确定性存档说明和 Skill 路由已经同步。

### 6.3 保留限制

- 当前只有旅行、关系和任务三个活跃人物系统接入统一仓储；其他系统仍需逐步迁移。
- 增量检查点只更新已经存在且同时具有永久核心和详细扩展的人物；出生与新增人物仍使用完整检查点。
- `WorldState.People` 继续保留，尚未验收未驻留人物完全外置后的世界运行。
- 新清单可能继续引用旧代际分区文件；自动清理必须进行引用追踪，本阶段不删除旧代际。
- 尚未实现增量变更日志压缩、后台异步写入和千万级完整游戏负载。
