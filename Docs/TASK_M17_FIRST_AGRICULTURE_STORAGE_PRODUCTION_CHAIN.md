# M17：首条真实农业—仓储生产链任务书

## 1. 任务性质

- 类型：领域模型、世界模拟、存档迁移、回归测试与文档同步；
- 状态：已完成（包含M17-P0数据驱动合同纠偏）；
- 全局位置：承接M14真实村庄与M15-P6人口存储合同，落实系统总纲当前第一优先级；
- 编号只记录本阶段，不改变总纲规定的全局建设顺序。

## 2. 目标

把M14中“三月直接扣种粮、九月直接增加粮食”的临时结算改为第一条正式生产链：

```text
具体家庭与人物
→ 在真实农田上建立农业工单
→ 投入土地、种粮、负责人、劳动者和时间
→ 统一公式结算小麦收成
→ 受仓储容量约束进入家庭粮账
→ 溢出成为可追溯损耗
→ 继续进入消费、救济和税收闭环
```

亲自劳动、实时派工、工单、目标指令和方针托管只决定工单如何产生；五种方式必须使用
同一个世界状态、同一种工单和同一套结算公式。

### 2.1 后续确认的兼容修订

本任务建立期间使用的固定`CropKind`只属于小麦链原型，不是最终内容合同。根据后续确认的
[`PRODUCTION_AGRICULTURE_INDUSTRY_AND_PROGRESSION_DESIGN.md`](PRODUCTION_AGRICULTURE_INDUSTRY_AND_PROGRESSION_DESIGN.md)，
M17正式完成前必须先执行
[`TASK_M17_P0_DATA_DRIVEN_PRODUCTION_CONTENT_CONTRACT.md`](TASK_M17_P0_DATA_DRIVEN_PRODUCTION_CONTENT_CONTRACT.md)：

- 作物、地方品种、产品、配方和生产方法改用稳定命名空间ID与数据定义；
- `ProductionControlMode`和`ProductionOrderStatus`等封闭协议状态可以继续使用枚举；
- 小麦默认参数迁入核心内容包，模拟代码不再硬编码`CropKind.Wheat`；
- 新增普通作物或MOD作物不得要求修改代码枚举或升级存档结构；
- 既有种粮、劳动、仓容、损耗、确定性和V7人口迁移不变量继续有效。

在该纠偏完成前，不得填写本任务完成记录或把固定作物原型描述为正式农业内容底座。

## 3. 纳入范围

1. 定义首批作物、控制方式、工单状态、农业工单和生产账本的持久领域合同；
2. 以现有村庄农田、灌溉、家庭土地、人物能力、工具、治安和仓储为真实投入；
3. 为每户生成有所有者、管理人、容量和库存的家庭粮仓；
4. 将M14自动播种和收获改为“方针托管生成工单、到期统一结算”；
5. 保留既有家庭粮账为首阶段权威粮食余额，家庭粮仓库存是与之同步的设施库存视图；
6. 记录种粮投入、劳动承诺、入仓和溢出损耗，并提供守恒审计；
7. 存档版本由V7顺序迁移至V8；V7人口存储合同原样保留，新增生产集合初始化为空；
8. 更新系统状态、存档说明和Skill任务路由。

## 4. 不纳入范围

- 水稻、粟、黍、豆类的独立地区参数与平衡数据；
- 市场出售、运输、磨坊加工和军粮调拨；
- 农业操作UI、地图设施绘制和NPC选址；
- 科技卡、灾害、虫害、地块级土壤与逐日劳动动画；
- 把家庭粮食权威余额迁移为通用多仓库库存系统；
- 提交、推送或创建拉取请求。

这些是后续实现范围，不因本阶段暂未实现而从完整设计中删除。

## 5. 不变量

1. 世界人物、家庭、设施、库存、工单和账本具有稳定且唯一的ID；
2. 种粮在工单创建时扣除，不能被多个工单重复使用；
3. 同一家庭同一季不能拥有重叠的活动农业工单；
4. 同一劳动者不能同时被两个重叠农业工单重复承诺；
5. 已完成工单满足 `产量 = 入仓量 + 损耗量`；
6. 入仓不能超过设施容量；家庭粮账与家庭粮仓库存同步；
7. 关注程度和控制方式不进入产量公式；
8. 相同初始世界、工单和时间坐标必须产生相同结果；
9. V7迁移不得重建、合并、删除或重新随机人物，也不得改变人口存储模式。

## 6. 交付物

- `ProductionState`领域合同；
- `AgricultureProductionSystem`统一生产与审计；
- M14村庄循环和原型工厂接入；
- V7至V8迁移和快照往返；
- 核心回归测试；
- 总纲、存档说明和任务路由同步。

## 7. 验收标准

1. 五种控制方式在同一事实输入下得到相同产量；
2. 种粮不足不会创建工单或改变世界账；
3. 仓容不足时只存入可用容量，余量进入损耗账；
4. 200—500人村庄全年循环形成一户一张完成工单，不重复直接收获；
5. 农业审计无无效引用，且产出守恒；
6. 相同种子与相同时间推进的生产快照完全一致；
7. V7存档迁移为V8后人口身份和人口存储合同不变；
8. V8生产工单与账本快照往返不丢失；
9. 全工程编译、核心测试、受控Unity EditMode测试、`git diff --check`和范围审阅通过。

## 8. 完成记录

M17已经完成首条正式小麦—家庭粮仓链：具体家庭和人物建立持久农业工单，种子和劳动在
创建时承诺，收获由人员、设施、水利、工具、治安、技能、天气和内容方法统一结算，仓容
溢出进入明确损耗，家庭粮账、粮仓和生产账同步。

后续确认的M17-P0已将原型固定`CropKind`迁移为稳定内容ID，并建立作物、地方品种、产品、
配方、生产方法、核心JSON、内容清单和缺失MOD校验。V7至V8迁移保留人口存储合同；
200—500人村庄一年形成每户一张完成工单，不再使用三月/九月直接扣加粮食。
