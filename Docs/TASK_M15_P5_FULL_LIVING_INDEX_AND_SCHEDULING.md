# M15-P5补充任务书：5000万全在世索引与日月年推进

## 一、任务定位

本任务承接M15-P5全热集上界矩阵。该矩阵证明5000万基础永久核心和在世调度字段能够
生成、查询并紧凑常驻，但尚未证明全体在世时家户、职业、地区和到期队列能否建立，也
没有实际推进世界时间。

本任务直接消费已通过的5000万全在世工作区，建立具体索引并分别推进1日、30日和365日。
仍属于独立压力原型，不修改V6存档或Unity运行时。

## 二、输入与固定事实

输入为M15-P5全热集产物：

```text
tmp/m15-p5-all-hot/all-hot-14000015/all-alive-core.bin
tmp/m15-p5-all-hot/all-hot-14000015/all-alive-hot.bin
tmp/m15-p5-all-hot/all-hot-14000015/manifest.json
```

启动时必须验证：

- 人物数、清单、文件头和文件长度均为5000万；
- 人物ID连续且摘要与全热报告一致；
- `CurrentLivingPopulation = CumulativePersonCount = 50,000,000`；
- `DeceasedColdArchiveCount = 0`。

## 三、索引合同

### 3.1 家户索引

每个家户保存稳定家户ID、首成员ID、成员数和地区。当前确定性压力数据每户最多5人，
预计形成1000万家户。能够按家户ID直接读取全部具体成员。

### 3.2 职业索引

压力原型使用16个明确标记的测试职业分类。每个人保存一个职业码；每个职业拥有具体
人物ID倒排文件和计数。职业只用于技术查询，不冒充东汉真实职业比例。

### 3.3 地区索引

沿用1182个稳定地区编号，保存每区在世人数，并验证总和严格等于5000万。地区索引不得
把人物合并为统计人口；它只是能够重建的计数和查询入口。

### 3.4 到期队列

每个人拥有一个1至365日内的下一生命周期日。到期索引按日分桶，桶内保存稳定人物ID，
全部桶计数之和必须严格等于5000万。推进时间只能扫描进入窗口的桶，不能全量扫描5000万
后再过滤。

## 四、推进矩阵

使用同一初始索引分别运行三个独立窗口：

1. 1日：处理第1日到期人物；
2. 30日：处理第1至30日到期人物；
3. 365日：处理第一年全部到期人物。

每个模拟进程必须：

- 将5000万条紧凑在世核心载入内存并保持到推进完成；
- 只读取窗口内的到期桶；
- 对每个到期人物校验ID、家户、职业和地区；
- 写出人物ID、处理日、下一到期日、事件类型、职业和地区的固定长度变更记录；
- 保持人口守恒，不制造出生或死亡；
- 输出扫描节点、变化人物、写回记录、磁盘、耗时、峰值工作集和确定性摘要。

三个窗口相互独立，避免1日结果被30日或365日重复消费后误写成连续推进。它们用于比较
窗口成本；正式连续世界推进仍属于运行时适配器任务。

## 五、防卡死与证据

- 索引构建、1日、30日和365日各使用独立进程；
- 每个候选预算最多285秒，外部调用不超过300秒；
- 索引只写任务专用临时目录，先写暂存目录，完整校验后提交完成清单；
- 模拟每完成一个日桶刷新进度；
- 超时或内存不足必须保留最后阶段、PID、工作集、日志和机器可读外层结果；
- 不得通过减少5000万人、跳过常驻加载或只写汇总数字宣称通过。

## 六、实现边界

- 不运行5000万份完整NPC AI、关系网、生产、战争或Unity对象；
- 不修改`WorldState.CurrentSchemaVersion`、`WorldSnapshotSerializer`或正式程序集；
- 不把16种测试职业和确定性到期日写成历史事实；
- 不删除、合并、替代或重新随机任何永久人物；
- 不把实验索引格式直接宣布为正式存档格式。

## 八、验收条件

1. 5000万人全部属于一个具体家户、职业和地区；
2. 家户、职业、地区和到期计数分别守恒；
3. 1日和30日扫描数小于5000万，365日扫描数严格等于5000万；
4. 扫描数、变化人数和写回数严格相等；
5. 每条写回都能追溯到具体人物及原到期日；
6. 同一窗口重复运行产生相同摘要；
7. 全量紧凑在世核心在推进完成前保持常驻；
8. 每个外部进程在硬超时内结束，或形成明确负面证据；
9. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别有结果。

## 九、完成定义

只有索引、自测试、三个推进窗口、汇总报告和项目级验证全部形成后，本补充任务才可完成。
任何窗口失败都必须按真实状态记录，不能用其他窗口通过替代。
