# M25-P10任务书：正式家庭食品月结命令、库存消费与缺口事件

## 一、任务定位

在M25-P3正式食品运行闭环和M25-P7统一持久执行内核之上，把村庄月结中的“家庭营养需求—村仓救济—正式批次消费—食品缺口后果”迁移为按村庄执行的V33持久命令、显式事务与提交后缺口事件。

本阶段只拆分正式食品月结，不把工具、医疗、劳役、农业、税粮、迁徙、婚姻或完整村庄生活一次性事务化。`VillageLifeSystem.ResolveMonthly`继续保留原有直接兼容语义；正式`WorldSimulator`先提交并执行食品命令，再运行跳过第二次食品消费的其余村庄月结。

## 二、实现合同

### 2.1 按村庄的有界工作单元

- 只有`FormalProductBatches`世界、30日月界且村庄尚未完成当日结算时才发现工作；
- 每个有家庭的活动村庄建立一张稳定命令，一个村庄事务只读取该村家庭及其成员ID，不扫描永久人物全表；
- 空村、非月界、已完成当日结算或兼容标量世界不产生空命令；
- 命令ID、事务ID和事件ID由绝对日、稳定类型和村庄稳定ID派生，重复调度不建立副本。

### 2.2 家庭需求与正式库存消费

- 每个实际在村、存活且非征发中的家庭成员按既有年龄口径形成当月营养需求；
- 家庭粮仓不足时先按M25-P3规则从村公共粮仓进行守恒拆批救济，再从家庭粮仓按消费优先级、生产日和批次ID稳定扣除未预留食品；
- 家庭`LastConsumptionGrain`和`FoodSecurityBasisPoints`只记录实际物理消费和营养满足摘要，不成为库存权威；
- 既有食品消费、村仓救济库存事务和村庄流水继续保留产品、品质、来源、容量、预留与逐产品守恒；
- 营养不足继续复用既有具体居民健康和生计压力后果，并通过共享人物仓储访问，不产生抽象人口伤害。

### 2.3 命令、事务与失败边界

- 命令保存`expected_day`和`village_id`，处理器只解析稳定参数并规划一张事务；
- 事务预检正式库存权威、内容清单、月界、村庄引用、未结算状态和同村同日共享预约；
- 日期漂移、权威变化、村庄已结算或引用无效时在任何库存、家庭、人物和流水写入前拒绝；
- 应用阶段调用独立的正式食品村月结入口，事务成功结果由M25-P7持久保存；
- 不增加存档字段，不升级V33，也不序列化处理器、人物仓储或事务对象。

### 2.4 缺口事件

- 至少一个家庭营养未满足时，事务发布一条村级稳定`formal_food.household_shortfall_detected`事件；
- 同村同月最多一条缺口事件，具体家庭、需求、实际摄入和食品安全继续从家庭摘要及村庄消费流水查询；
- 无缺口时事务仍成功，但不制造缺口事件；
- 正式无业务写入投影处理器只确认事件，后续赈济、市场、AI和知识系统可另行订阅，但不得二次消费库存。

### 2.5 调度顺序与兼容

- 食品命令在`DailySimulation`中位于其余村庄月结之前，延续“月界食品先结算、其他家庭后果随后运行”的既有顺序；
- 正式模拟器的其余村庄月结必须跳过食品步骤，防止同月重复救济和消费；
- 兼容标量世界和外部直接调用`ResolveMonthly`继续使用原完整路径；
- 县级税粮汇缴、县仓赈济和市场价格阶段顺序不在本阶段改变。

## 三、工作包

### WP1：正式食品月结拆分

- 提取按村正式食品结算入口和结果摘要；
- 保持需求、救济、消费、家庭摘要、健康后果和流水语义；
- 增加“已由命令完成食品后”的其余村庄月结兼容入口。

### WP2：持久命令适配器

- 增加按村工作发现、稳定命令调度器、命令处理器和事务；
- 增加月界、村庄、正式权威与共享预约预检；
- 仅在真实营养缺口时发布稳定缺口事件并注册正式投影处理器。

### WP3：世界调度接线

- `WorldSimulator`注册食品月结命令和事件处理器；
- 在村庄月结之前确保命令并处理到期命令；
- 正式模式运行其余月结时不再重复食品消费，兼容模式保持原状。

### WP4：测试、文档与交付

- 覆盖持久命令读档后只消费一次并发布缺口事件、日期漂移零业务修改、无工作不建命令、正式模拟器真实接线和同种子确定性；
- 保留M25-P3正式消费—税粮—汇缴—赈济及一年确定性回归；
- 同步总纲、世界模拟、确定性存档、M25-P3兼容说明和Skill任务路由。

## 四、验收标准

1. 正式模拟器每村每月最多一张食品命令和一张食品事务，不重复救济或消费。
2. 家庭营养需求只来自该村具体存活居民；不扫描永久人物全表，不按关注层级改变需求。
3. 正式产品批次、预留、容量、逐产品守恒和消费稳定顺序继续满足M25-P3合同。
4. 营养不足仍落实到具体居民健康与生计压力，并发布同村同月唯一缺口事件。
5. 日期漂移或权威变化在应用前拒绝，库存、家庭、人物、流水和事件均零业务修改。
6. 兼容标量月结与直接`ResolveMonthly`入口保持原语义；正式世界其余村庄月结只跳过已经提交的食品步骤。
7. 相同种子、村庄、家庭、库存和世界时间产生相同命令、事务、事件和快照。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 工具、医疗、劳役、农业、税粮、迁徙、婚姻或完整村庄月结事务化；
- 自动根据缺口创建市场买单、跨县货运、县仓赈济命令或AI经营决策；
- 仓储腐败、鼠害、霉变、营养疾病、个体菜单或烹饪配方；
- 新持久字段、V34迁移、外部副作用Exactly-once或通用事务回滚；
- 全天下未载入村庄逐人月结和百万正式Unity长跑。
