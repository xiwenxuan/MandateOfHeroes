# 任务书：洛阳权威50m布局数据包与县域空间闭环 V1

## 1. 任务定位

本任务承接“洛阳50m县域真实规模原型与Facility迁移验证 V1”的技术门 Decision A，
把原先由代码即时缩放得到的候选布局，固化为可版本管理、可审查、可重复生成的正式运行时输入。

这里的“权威”只表示：该数据包是运行时读取候选坐标、尺寸与网络几何的唯一输入；不表示
2,083项玩法重建位置已经得到历史考证。数据状态保持
`gameplay-reconstruction-review-candidate`，历史精确标志为false。

## 2. 冻结合同

- 全国战略层继续使用2km Global Cell；洛阳县域细节为320×640个50m PlanningCell。
- 2,084项Facility的稳定ID、Definition、Model、旧CellId64、资料精度和历史置信度不变。
- 旧源锚点与50m候选位置同时保存；候选位置不得写回正式Facility源坐标。
- 道路、水渠只连接源包中四邻相接的同类Facility，不自动补齐未知干线。
- 城防边、入口方向、分区凸包和四个县界Portal均保存明确Provisional来源。
- 运行时加载县域布局数据不得改变Person、Household、Inventory、Production、Owner、
  Controller、WorldTime或结算结果。
- World Schema保持V79；本任务不执行存档迁移，不开放正式建设写入。
- 生成器必须对两个源Facility文件保存SHA-256，并保证相同输入得到稳定布局指纹。

## 3. 交付范围

1. 新增版本化JSON布局包与确定性生成脚本。
2. 固化2,084项Facility的源锚点、候选格、Footprint、朝向、Entrance来源和六类分区。
3. 固化359个道路节点/334条源四邻道路边、19个水渠节点/17条源四邻水渠边。
4. 固化144条城防边、4个县界Portal、6个分区UrbanArea候选凸包和全城候选凸包。
5. 让洛阳50m运行时反向读取该数据包，删除坐标和Footprint的运行时重算权威。
6. 新增核心合同测试、Unity装载测试和“布局闭环/网络几何”审阅视图。
7. 输出数据审计、自动验证结果、限制和下一阶段建议。

## 4. 验收标准

- JSON计数严格为Facility 2,084、Road 359/334、Canal 19/17、Fortification 144、
  Portal 4、District Area 6。
- 两个源文件指纹在加载时逐个校验，任一源文件漂移必须显式失败。
- 每个Facility与正式目录的ID、Definition、CellId64、源Row/Column、资料等级完全一致。
- 所有候选格、网络端点、城防边、Portal和凸包均在320×640边界内。
- 道路和水渠边集合必须等于源Facility四邻关系集合；不得缺边、重边或造边。
- P1运行时所有候选坐标、尺寸、朝向和分区均读取数据包，重复加载Hash一致。
- 全工程编译、定向Core、受控Unity、任务范围`git diff --check`分别报告。

## 5. 决策门

- **数据合同门**：通过后，布局包可作为建设规划与地图表现的正式运行时输入。
- **历史位置门**：仍需独立史料审查；未通过前不允许写成历史精确洛阳。
- **存档门**：仍关闭；只有建设事务与旧存档兼容方案另行通过后才允许升级V79。

下一阶段候选为“洛阳县域规划建设工具 V1”：读取本包提供可建设格、占地、道路可达、
施工蓝图和撤销预览，但正式世界写入与存档升级必须另设决策门。
