# M25-P17 任务书：家庭月内实际进食、饥饿恢复与救济资格闭环

## 一、任务定位

承接 M25-P10 的具体家庭缺粮后果与 M25-P16 的月内实物领取。本阶段明确区分
“获批/领取”“进入家庭粮仓”“被真实人物吃掉”和“健康恢复”四类事实：领取到家的
粮食不会自动视为已经进食，也不会自动撤销饥饿后果；只有本次缺粮中实际受损的人物，
在仍存活、仍在本地且未服征兵役时，才能通过吃掉本张领取单所交付的真实食品批次，
按实际营养比例恢复本次损失。

## 二、实现范围

### 2.1 V39 持久合同

- 新增家庭救济进食账，保存稳定 ID、领取单、来源短缺事件、村庄、家庭、月结日、
  应补营养、已吃营养/实物、剩余营养、最后进食人/日期、状态和库存事务引用。
- 每张账保存本次月结的具体受损人物，以及实际健康损失、生活压力增加和累计恢复；
  不允许用家庭当前成员、食品安全缓存或关注度反推资格。
- 正式库存事务增加救济进食来源引用，消费负向行必须指向该领取单实际交付形成的批次。
- V38 到 V39 只建立空进食/恢复账，不从旧领取单伪造受灾人物或历史治疗。

### 2.2 资格建账

- M25-P10 在扣除当月真实家庭食品并施加缺粮后果时，记录每名实际受损居民及其
  实际扣减值；被征发、死亡或不在本村的人不进入本次资格清单。
- 同月、同村、同家庭的进食账与领取单一一对应，来源于同一短缺事件和精确营养缺口。
- 迁入者、新加入家庭者、未受本次短缺影响者不得替代原受损人物取得恢复。

### 2.3 月内实际进食与恢复

- 只消费 `HouseholdReliefPickupState.InventoryTransactionIds` 所形成、仍在对应家庭
  粮仓且未预留的食品批次；普通自有粮、其他救济或其他家庭批次不能冒充。
- 实际扣减批次数量、家庭粮仓占用和库存事务；最小实物单位造成的超额营养计入真实
  消费，但恢复比例最多按本张账的应补营养计算。
- 健康与生活压力恢复按累计实际进食营养比例计算，分别以本次实际损失为上限；领域账
  保存累计恢复，重复执行、读档续跑或其他系统先行治疗都不能导致过度恢复。
- 原受损人物死亡、离村或服征兵役时不得远程治疗，也不得把其恢复份额转给新人。

### 2.4 统一世界运行

- 日界在 M25-P16 领取和 M25-P15 仓损之后、村庄生活结算之前调度进食。
- 每个运输到达段在 M25-P16 把到村粮交付家庭后立即调度进食。
- 命令、事务和事件使用稳定 ID；无合格人物或无可追溯食品时不创建空命令。

## 三、验收标准

1. M25-P10 精确保存实际受损人物及实际健康/生活压力后果。
2. P16 领取完成后、P17 执行前，家庭库存增加但人物状态不恢复。
3. P17 只扣除本领取单交付的真实批次，库存、营养、恢复和事务引用闭合。
4. 恢复只作用于原受损且当前合格的人物；征发/离开/死亡人物与新成员不被替代。
5. 部分进食、重复调度、存档往返、同种子世界和同一到达段流水均确定且幂等。
6. V38 到 V39 不伪造历史资格；篡改恢复上限、库存来源或事务引用会被校验拒绝。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅分别通过。

## 四、非目标

- 本阶段不实现救济资格政策编辑器、排队动画、照护者分餐、医嘱、特殊病号餐或玩家 UI。
- 不追溯重算 V38 及更早存档已经发生的家庭短缺、领取或饥饿恢复。
- 不改变永久人物身份、冷热存储、关注度、历史人物或一般疾病治疗规则。
- 不允许领取本身、计划数量、抽象食品安全或 UI 展示直接恢复人物。
