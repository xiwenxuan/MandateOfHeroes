# M25-P24 正式诊疗服务：医者工时、诊金、处方与病例结案任务书

## 一、阶段目标

承接 M25-P22 的正式营养病案和 M25-P23 的真实草药供应，把“有医者、有药就直接恢复健康”推进为可审计的民间诊疗服务：

```text
具体营养性疾病发作
→ 合法授权与正式病案
→ 医者签发稳定内容 ID 的处方实例
→ 本地诊所接诊或上门诊疗
→ 占用具体医者的当日工作时间
→ 患者家庭向医者家庭支付诊疗与药材费用
→ 真实药材批次消耗、医术实践成长与治疗记录
→ 恢复、原发营养问题结束或患者死亡后的明确结案
```

本阶段只建立第一种简明草药支持疗法，但处方实例、给药方式、服务场所、收费政策和结案原因均使用稳定命名空间 ID；以后增加普通方剂和服务政策不得要求扩展固定枚举或升级存档结构。

## 二、本阶段完成

1. 新增永久处方实例及处方行，记录病案、开方医者、签发日、治疗方案、药品产品 ID、每次用量和给药方式。
2. 新增追加式诊疗服务记录，记录病案、处方、患者、医者、授权人、诊所或上门场所、实际工时、诊金、药材费、付款与收款家庭、治疗和医术变化。
3. 每名医者每日具有明确的诊疗工时上限；已完成服务按实际分钟占用额度，同日超额接诊在任何状态写入前被拒绝。
4. 异户诊疗由患者家庭支付、医者家庭收款；同户照护不制造资金流。资金不足时保留病案和处方，但不扣药、不恢复健康、不增加医术，也不生成完成服务。
5. 治疗继续消费医者家庭的真实药材批次；服务、治疗、处方、库存事务、健康、资金和医术变化相互闭合。
6. 成功诊疗给予医者有界医学实践成长，并通过人物仓储修改接口记录真实脏人物；关注层级不参与技能计算。
7. 病例支持活动与结案两态，按稳定结案原因记录伤害已恢复、营养发作已结束或患者死亡；结案后不得继续治疗。
8. 村庄月结继续只遍历已加载村庄、家户成员和稀疏营养病案，并把真实诊所设施传入服务记录。
9. 存档升级到 V46。V45→V46 只建立空处方与服务集合、初始化病例活动状态和正式服务启用日，不倒推旧处方、旧工时、旧诊金、旧技能成长或旧结案事实。

## 三、领域约束

- 处方是病案的永久事实；药材不足或资金不足不能删除已经签发的处方。
- 同一病案最多存在一个活动处方；当前原型处方每次只使用一个单位草药材，但结构必须允许后续多行扩展。
- 诊疗收费必须在付款家庭和收款家庭之间守恒，费用不能只写在摘要文本中。
- 正式服务启用日前的 V44/V45 治疗按旧合同保留；启用日及之后的治疗必须恰好引用一条服务记录。
- 医者同日累计工时不得超过上限；失败尝试不占用工时，也不能产生半笔资金、药物或健康写入。
- 医术成长只能来自成功完成的真实诊疗服务，并保存开闭技能值。
- 结案只结束该病案的继续治疗资格，不删除人物、营养档案、疾病发作、处方、治疗或服务历史。
- 自动结算不得扫描全局永久人口表，只能沿活动村庄与其家户成员边界访问人物仓储。

## 四、明确不做

- 不实现传染病传播、复杂辨证、药物相互作用、针灸、手术、住院或死亡概率模型。
- 不实现医疗欠款、慈善减免、官府报销、保险、医馆雇员分成和动态价格谈判。
- 不迁移军医旧库存，不把民间诊疗规则直接套到军队伤兵。
- 不实现未来预约队列、跨县求医、远程会诊、玩家医疗 UI 或完整医者人生任务线。
- 不提交、不推送；版本操作仍需用户另行授权。

## 五、验收用例

1. 新诊断生成唯一病案和唯一处方，处方行引用正式草药产品与稳定给药方式 ID。
2. 成功异户治疗同时闭合服务工时、家庭资金、药材批次、库存事务、健康恢复和医术成长。
3. 同户治疗费用为零且不制造资金；资金不足、药材不足或医者工时已满均不产生部分写入。
4. 同一医者同日累计工时不超上限；次日可以重新接诊，且相同世界和日序列得到相同结果。
5. 伤害恢复、营养发作结束和患者死亡分别结案；结案病案拒绝后续治疗且保留全部历史。
6. 篡改处方引用、服务—治疗关系、费用守恒、工时、技能闭合或结案原因时 `WorldState.Validate()` 拒绝。
7. V45→V46 不生成处方、服务、费用或结案历史；V46 往返保留新增合同。
8. 全工程编译、聚焦核心测试、全量核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。
