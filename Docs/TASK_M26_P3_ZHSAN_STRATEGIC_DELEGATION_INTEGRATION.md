# M26-P3 《中华三国志》战略委任参考接入任务书

## 一、目标

在许可证与资源边界清楚的前提下，把《中华三国志》地区/军团 AI 中“允许做什么、优先做
什么”的成熟问题转成 MandateOfHeroes 可复用的战略委任合同，为后续太守、县令、军团都督、
家主和玩家托管提供同一套数据入口。

本阶段不声称接入《中华三国志》完整代码或资源，也不改变现有世界存档合同。

## 二、来源与许可闸门

执行前必须读取
[`ZHSAN_OPEN_SOURCE_LICENSE_AND_INTEGRATION_AUDIT.md`](ZHSAN_OPEN_SOURCE_LICENSE_AND_INTEGRATION_AUDIT.md)。

- 审计源码固定到 `k2lizheng/ZHSan@851e0a222af214ba65b9881fb90411248a56f3d1`；
- 源码许可证为 Ms-PL；
- 本阶段只作结构和玩法问题参考，不复制源文件；
- 不导入地图、美术、头像、音乐、音效、字体、剧本、MOD、Content 或整合包；
- 不使用《中华三国志》的名称、标志或宣传表达作为本项目品牌。

## 三、实施范围

### P3-A 来源审计

- 核实免费游玩、源码仓库、具体提交和 LICENSE；
- 区分代码许可证与资源授权；
- 记录技术栈、耦合情况和不适合整包迁入的原因。

### P3-B 数据驱动政策合同

- 使用稳定 ID 定义政策、允许命令和优先级；
- 首批提供均衡经营、商贸振兴、边郡固守；
- 权重采用基点并校验范围；
- 普通新政策或新优先级不要求增加枚举或升级存档结构。

### P3-C 确定性候选选择

- 先按政策权限过滤候选命令；
- 以基础效用和优先级影响计算显式分数；
- 同分按稳定候选 ID 排序；
- 非法 ID、重复 ID、重复优先级和越界权重必须明确失败；
- 选择器不直接修改粮食、财政、人口、军队或设施。

### P3-D 测试与文档

- 商贸政策优先商业且拒绝自动发动战役；
- 同分结果不受候选输入顺序影响；
- 重复候选 ID 被拒绝；
- 核心政策均通过稳定 ID 与唯一性校验；
- 更新法律规则、系统总纲、游戏愿景、任务路由及 M26-P2 兼容说明。

## 四、架构边界

- `Mandate.Domain`：政策定义、稳定 ID、权限和权重合同；
- `Mandate.Simulation`：候选校验、权限过滤、计分和确定性选择；
- `Mandate.Persistence`：本阶段不修改；
- `Mandate.Presentation`：本阶段不修改。

后续把政策挂到真实组织或职位时，必须同时保存发布者、受任者、管辖范围、期限、预算、
权限快照、报告规则和例外上报。政策只能产生候选命令，真实系统仍负责人员、物资、财政、
时间与权限结算。

## 五、验收标准

1. 来源、提交、许可证和禁止使用的资源边界可追溯；
2. 没有第三方资源或未隔离的 Ms-PL 原代码进入项目；
3. 三种核心政策和稳定 ID 合同可由纯 C# 使用；
4. 选择结果可解释、可重复，不依赖随机字典顺序；
5. 政策不能选择不具权限的命令；
6. 编译、核心测试、受控 Unity 测试、`git diff --check` 和范围审阅分别报告；
7. 不把本阶段写成真实职位绑定、完整组织 AI 或完整《中华三国志》接入。
