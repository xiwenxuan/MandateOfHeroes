# M23-P9 分级军需目标、承运报价与异常上报委任任务书

## 1. 阶段目标

在M23-P5至P8已经建立的真实军粮批次、承运人物、运输分段、途中风险和局部交战之上，
建立第一条“下达目标而非手填运输细节”的军需委任闭环：

```text
有军级权限人物下达军需目标
→ 明确目标军队、目的地、数量、期限、预算和承运偏好
→ 真实承运人物提交绑定库存、容器和路线的报价
→ 委任系统按稳定规则重新验证并择优
→ 调用既有军需运输命令生成真实货运单
→ 成功或异常形成可审计报告
```

委任只减少玩家操作，不减少世界事实。系统不得用“自动补给加成”直接增加军粮，也不得
绕过人物、组织、库存、资金、路线、运输损耗和风险结算。

## 2. 必须完成

1. 建立持久军需委任目标，保存签发人、目标军队、产品、目的地、数量、预算、最高单价、
   期限、报告周期、承运偏好、货物使用红线和风险政策。
2. 目标创建和执行时都重新检查军级权限；失去权限不得发运，并形成异常报告。
3. 建立持久承运报价，绑定真实承运人物、组织、货物批次、自用口粮批次、运输容器、路线、
   取得方式、损失承担方、数量和单价。
4. 报价提交时检查人物存活、组织成员身份、容器保管、同地库存、军需产品标签、路线、
   自用口粮和取得方式；报价不预留库存，执行时必须再次验证。
5. 使用稳定命名空间ID定义可扩展的承运偏好：最低成本、最安全路线、本组织优先。
6. 候选比较不得依赖集合遍历顺序；相同评分最终按报价稳定ID排序。
7. 预算同时受目标预算、最高单价和目标军队所属组织当前金库约束；不得透支或虚构付款。
8. 选中报价后必须复用`MilitaryLogisticsSystem.Dispatch`，由既有系统完成库存扣减、付款、
   旅行、损耗、风险和到货；委任系统不得复制第二套物流结算。
9. 无报价、报价失效、预算不足、权限失效、期限已过或发运被领域规则拒绝时，目标进入
   待处理状态并形成持久异常报告；补充新报价后允许重新评估。
10. 成功发运后保存所选报价、真实货运单和承诺支出，并形成普通决策报告。
11. 存档升级到V23；V22迁移只建立空目标、报价和报告集合，不倒推旧货运的委任历史。
12. 自动测试覆盖授权闭环、三种偏好中的确定性选择、预算异常、失效报价、权限复核、
   往返存档和V22迁移。

## 3. 本阶段边界

- 只实现军队层级的单次目标分解，不实现君主—都督—太守—军需官的递归再委任；
- 报价由明确命令提交，不自动让全天下商人扫描所有军队需求；
- 不实现竞价保密、保证金、信用、违约赔偿、合同转卖和承运联盟；
- 不自动寻路，也不生成多段方案；首批报价使用一条既有直达路线；
- 不实现日历队列自动唤醒，调用评估入口代表受任者在当日处理该目标；
- 不增加Unity界面和表现层对象；报告先作为领域数据和测试可读结果存在；
- 不提交、不推送仓库。

## 4. 验收标准

1. 未授权人物创建目标时世界快照零变化；
2. 成功委任产生一个目标、至少一个报价、一个真实军需货运单和可追溯报告；
3. 真实货物、资金和承运人物均由既有物流系统结算且审计守恒；
4. 最低成本、最安全路线和本组织优先使用稳定比较键，重复世界得到相同选择；
5. 超预算、库存变化、承运人离位、权限失效和过期不会发运，并留下明确异常原因；
6. 异常目标可在补充合法报价后重新评估，既有报告不被删除；
7. V23快照往返一致；V22迁移集合为空且不伪造历史；
8. 全工程编译、核心测试、适用的受控Unity测试、`git diff --check`和差异审阅按项目规则报告。
