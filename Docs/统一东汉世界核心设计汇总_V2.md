# 统一东汉世界核心设计汇总 V2

> 项目：三国志思路 / 《群雄志：仕途》
> 文档性质：当前阶段核心设计母线
> 用途：Demo 竖切、数据合同、后续系统扩展的统一参考
> 说明：本文区分“已基本确定”“V1 候选数值”“Demo 前暂缓深化”。后续如有新决策，应以明确更新后的规则覆盖旧口径。

---

# 1. 游戏世界核心定位

游戏不采用彼此割裂的“战略地图 / 城市经营地图 / RPG 人物地图 / 战斗地图”多套空间体系。

核心原则：

> 所有人物、产业、军队、城镇、土地、事件，都发生在同一个统一东汉世界中。

从天下到州、郡、县、城镇、村庄、庄园，本质上是同一地理空间的不同观察尺度。

---

# 2. Cell：世界基本空间单位

Cell 是抽象的大型世界地块，不强制对应现实多少米。

Cell 负责：

- 位置；
- 相邻关系；
- 地形；
- 水文；
- 自然资源；
- 行政归属；
- 产权；
- Facility；
- Force 位置。

一个 Cell 可以同时属于：

- 某县；
- 某郡国；
- 某州；
- 某国家 / 势力。

行政归属与产权必须严格区分。

## 2.1 Cell 自然属性

例如：

```text
Terrain
Elevation
Water
Fertility
Forest
MineralResources[]
...
```

自然资源属于世界事实。

例如矿产：

> 同一个 Cell 可以同时存在铁、铜、铅、石灰石等多种矿产。

矿产不是矿场生成的。

---

# 3. 产权：一 Cell 一 Owner

已确定：

> 一个 Cell 同一时间只能有一个 Owner。

不做：

```text
张三 50%
李四 50%
```

也不长期存在：

```text
土地属于张三
建筑属于李四
```

正常规则：

> 只有 Cell Owner 可以在该 Cell 建设。

别人要建设，必须先通过：

- 购买；
- 赠与；
- 分配；
- 征收；
- 没收；
- 战争夺取；
- 继承；
- 其他合法产权转移；

改变 Owner。

---

# 4. 行政辖区、官府、产权严格分开

例如“广宗县”作为行政 / 地理区域可以长期存在，但“广宗县府”是一个真实政府机构 / 设施体系。

县域存在不代表县府一定正常运作。

县府缺失或瘫痪时：

- 县域仍存在；
- 人口仍存在；
- 土地产权仍存在；
- 但县级行政能力受影响。

1182 个县级目录可以继续作为县级地理行政母版。

---

# 5. Facility：统一设施模型

矿场、铁坊、农田、仓库、住宅、县府等，尽可能使用同一套 Facility 体系。

不为每一种设施分别写一套完全独立系统，而采用：

```text
FacilityDefinition
+
FacilityState
```

通过配置形成差异。

## 5.1 Facility 核心概念

```text
CellId
OwnerId

人员容量
仓储容量
生产 / 服务能力
设备
模块
允许配方
并行能力

当前工作人员
当前生产状态
当前库存

MaxDurability
CurrentDurability
```

---

# 6. 一设施占一 Cell

已确定：

> 一个基础建设 / 生产 / 服务 Facility 占 1 个 Cell。

例如：

```text
铁坊A = 1 Cell
铁坊B = 1 Cell
仓库 = 1 Cell
住宅 = 1 Cell
```

大型庄园、县府建筑群、矿区、城市都不是一个超级 Facility，而是多个 Cell + Facility 组成的空间集合。

例如：

```text
张氏庄园
=
住宅Cell
农田Cell
铁坊Cell
仓库Cell
道路Cell
...
```

---

# 7. Facility 内部不继续切小格

参考《了不起的修仙模拟器》的设施内部成长思路，但不采用 Facility 内部微型 Cell 地图。

采用：

```text
World Cell
↓
Facility
↓
设备 / 容量 / 模块
```

不采用：

```text
World Cell
↓
Facility
↓
16×16 小格
↓
炉子 / 桌子 / 床等
```

---

# 8. Facility 升级不是简单 Lv1 → Lv2

设施成长主要通过：

- 人员容量；
- 设备数量；
- 设备质量；
- 模块；
- 仓储；
- 结构改良；
- 耐久；
- 防火、防潮、排水、支护等；

体现。

例如铁匠铺：

```text
原来：
炉1
工位2
工人6

改造后：
炉2
工位4
工人10
```

仍然占一个 Cell。

如果还要扩大总规模：

> 再获得一个 Cell，再建一个 Facility。

因此：

> 升级提高单 Cell 能力，扩张增加 Facility 数量。

---

# 9. 属性、状态、动作、配方严格分开

## 9.1 属性

回答：这个设施最多能干什么。

例如：

- 人员容量；
- 仓储容量；
- 并行能力；
- 设备容量。

## 9.2 状态

回答：现在是什么情况。

例如：

- 当前作物；
- 当前耐久；
- 当前工作人员；
- 当前库存。

## 9.3 动作

例如：

- 播种；
- 维修；
- 开始生产；
- 停止生产；
- 收割。

## 9.4 配方

回答：

```text
输入
+ 时间
+ 条件
→ 输出
```

---

# 10. 生产 Facility 可以同时生产多种产品

例如铁坊：

```text
并行生产能力 = 4
```

可以同时生产：

- 农具；
- 长矛头；
- 刀；
- 建筑铁件。

也可以多条生产能力集中生产同一种商品。

真正约束来自：

- 人员；
- 设备；
- 原料；
- 时间。

---

# 11. 农业特殊约束

农田仍然使用统一 Facility 体系。

但：

> 一块农业 Cell 同一时间只能种一种主作物。

例如：

```text
CurrentCrop = Wheat
```

不能同时再种粟、菽等主作物。

同时：

> 作物达到 80% 成熟以后允许抢收。

是否抢收是动作；80% 是作物成熟规则。

---

# 12. 矿场处理

矿场完全统一进 Facility 体系。

Cell 可能同时有：

- 铁；
- 铜；
- 铅；
- 石灰石；
- 其他资源。

矿场只是利用这些自然资源的生产 Facility。

矿场内部通过：

```text
工作面
采矿设备
排水
支护
运输
人员容量
```

决定：

- 同时能开多少条采矿线；
- 能开多难的矿；
- 实际产量。

例如 3 个工作面可以：

```text
铁
铁
铜
```

也可以：

```text
铁
铜
石灰石
```

---

# 13. Facility 耐久

所有人工设施都有：

```text
MaxDurability
CurrentDurability
```

耐久变化来源：

- 自然老化；
- 使用损耗；
- 灾害；
- 战争破坏。

维护可以修复或减缓损耗。

耐久归零后，设施停止正常功能，可进入：

- 废墟；
- 修复；
- 拆除；
- 重建。

后台不需要每天扫描所有设施，采用事件 / 计划检查。

---

# 14. 人物是永久真实 Person

核心原则：

> 所有人口最终都是具体 Person。

“总人口、劳动力、军人数量”等只是对 Person 的统计汇总，不是最终真实对象。

---

# 15. 一个人同一时间只能做一件事

已确定：

```text
CurrentActivity = 铁坊生产
```

则不能同时：

- 种田；
- 经商；
- 修路；
- 学习；
- 旅行；
- 从军；
- 战斗。

如果被征兵：

```text
铁坊生产
↓
MilitaryService
```

原 Facility 立即失去这名劳动力。

---

# 16. 日常通勤不计算

已确定：

> 位置决定人物能不能在这里工作，但本地正常住处 → 工作地通勤不消耗工作时间，也不产生效率惩罚。

不模拟每天上下班逐 Cell 移动。

但以下必须真实移动：

- 跨县旅行；
- 迁居；
- 赴任；
- 行军；
- 商队；
- 返乡；
- 其他跨区域行为。

---

# 17. 人口生命周期

为减少计算，不做连续年龄衰减曲线。

当前规则：

| 年龄 | 状态 |
|---|---|
| 0–13 | 儿童，不进入正式劳动力 |
| 14–19 | 少年，可参与生产劳动 |
| 20–59 | 正常生产、行政、军事人口 |
| 60–69 | 不再做农业 / 采矿 / 制造等生产工作，但可教学、管理、经商、医疗、官府等 |
| 70+ | 默认退休 |

人物出生 / 初始化时就确定：

```text
NaturalDeathTime
```

但可因以下原因提前死亡：

- 战死；
- 病死；
- 饿死；
- 灾害；
- 其他事件。

---

# 18. 人口台账

管理者需要知道：

- 谁空闲；
- 谁在工作；
- 谁在从军；
- 谁在学习；
- 谁在旅行；
- 谁在治疗；
- 谁退休。

真实来源始终是：

```text
Person.CurrentActivity
```

台账只是索引与管理视图，不复制人物状态。

---

# 19. 《九州》式人物派遣 + 产业派工

两种操作统一到底层。

人物侧：

```text
张三
→ 去铁坊
```

Facility 侧：

```text
铁坊缺3人
→ 从人口台账筛3人
```

最终都改变同一个真实人物状态。

---

# 20. 管理采用辖区制，不做固定管理人数上限

不做：

```text
县令最多管理10万人
```

而采用：

```text
职位
→ Scope
```

- 县令：本县；
- 太守：本郡；
- 州牧：本州完整管理；
- 中央官：天下范围内自己的专业领域。

---

# 21. 官职意义：真实权力，不是 Buff

一个职位至少应满足以下一项才值得独立存在：

- 有实际权力；
- 能承担上级委任；
- 有政治分权价值；
- 能作为拉拢家族 / 亲信的职位；
- 有仕途价值；
- 有监察 / 制衡价值。

不做：

```text
功曹：行政效率 +5%
```

而要真正负责一类事务。

# 23. 职位统一结构

可以理解为：

```text
CivilOffice
=
Scope
+ Domain
+ ViewRights
+ ActionRights
+ SubordinatePosts
+ Delegation
```

例如中央大司农：

```text
Scope = 天下
Domain = 财政 / 税粮 / 仓储
```

可以：

- 查看全国相关数据；
- 调度公共钱粮；
- 下相关目标；
- 任命本官署属官；
- 一键委任；
- 只看异常。

---

# 24. 一键委任是硬要求

无论：

- 家主；
- 县令；
- 太守；
- 州牧；
- 中央官；
- 将军；

都应该支持：

```text
全部亲管
部分委任
全部委任
只报告异常
```

职位越高，默认操作尺度越高，而不是点击次数越多。

---

# 25. 职位本身也是政治资源

例如：

```text
县丞给张氏
功曹给李氏
县尉给亲信
```

实际是在分配：

- 综合行政权；
- 人事权；
- 治安 / 军事行政权。

因此任命可以用于：

- 拉拢豪族；
- 培养亲信；
- 平衡家族；
- 扩大本家影响；
- 削弱敌对家族。

---

# 26. 职位任命与生命周期

职位属于组织，人物只是 Holder。

支持：

- 任命；
- 免职；
- 升迁；
- 调任；
- 代理；
- 兼任；
- 真实赴任。

异地任命后人物必须真实赴任。

职位空缺不产生简单效率 Debuff，而是对应事务无人处理、转交上级或代理人。

---

# 27. 军职：只使用真实军职

游戏正式军事职位只使用真实军职，不额外设计抽象“军团长 Lv5 / 高级军官”等体系。

军职核心只保留：

```text
MaxCommandStrength
```

也就是：

> 最大正常统兵数量。

不设最低人数，不使用 AuthorizedStrength。

# 29. 军职不直接等于实际兵权

军职只回答：

> 正常最多能带多少。

真正兵权来自：

> 当前到底有多少真实 Force / 士兵归这个人物指挥。

例如：

```text
破虏将军
Max = 10000
当前实际指挥 = 7600
```

实际兵权就是 7600。

---

# 30. 超编

允许：

```text
校尉
Max = 3000
实际 = 3700
```

进入超编状态。

当前 V1 候选：

> 默认整改期限 30 日，战时可延期。

超编期间：

- 可以正常战斗；
- 可以移动；
- 不直接扣战斗力；
- 但会产生后勤、补员、财政、军政管理压力。

超编可通过：

- 升军职；
- 分兵；
- 转隶；
- 转地方军；
- 复员；

消化。

---

# 31. 君主

君主不是军职。

规则：

> 君主最大直属统兵上限 = 当前势力最高军职的最大统兵上限。

例如当前最高军职为大将军 100000，则君主直属最多也 100000。

更多大军仍需：

```text
授军职
↓
分兵权
↓
建立指挥链
```

---

# 32. 地方军 / 正规军 / 私军

## 32.1 地方公共武装

```text
县兵
郡兵
州兵
```

默认：

- 县兵 → 本县；
- 郡兵 → 本郡；
- 州兵 → 本州。

真正亲自带兵的人也进入真实军职体系。

## 32.2 正规军

可跨县、跨郡、跨州行动。

## 32.3 私军

属于个人 / 家族。

可以：

1. 保持私军直接参战；
2. 与官军协同；
3. 部分 / 全部收编进正规军。

---

# 33. 私军不需要第三套正式军职

私人部队只需：

```text
Commander
SubordinateCommanders
```

作为实际指挥关系。

不建立“私人军司马 / 私人校尉”等平行官制。

私军转官军以后，才进入正式军职体系。

---

# 34. Force：真实地图军事单位

Force 由：

- 指挥者；
- 真实 Person；
- 武将；
- 装备；
- 库存；
- 马匹；
- 车辆；
- 归属；
- 当前任务；

组成。

---

# 35. 一支 Force 一 Cell

已确定：

> 一支独立 Force 固定占 1 个 Cell。

80 人一格，10000 人仍然一格。

分成三支 Force，就占三个 Cell。

一个 Cell 同一时间只能有一支独立 Force。

---

# 36. Force 规模自由

不规定只有校尉以上才可以成为地图部队。

任何合法带队人物都可以形成独立 Force，例如：

```text
屯长 + 80人
军候 + 400人
校尉 + 2500人
将军 + 9000人
```

军职只负责检查是否超出正常统兵上限。

---

# 37. 军队移动与整编

不设计“运输部队”这一特殊类型。

任何 Force 都可以：

- 移动；
- 分兵；
- 合军；
- 增援；
- 转隶；
- 驻扎；
- 移交人员。

---

双方可直接移动：

- 装备；
- 马匹；
- 车辆；
- 军粮；
- 库存；
- 归属关系。

支持：

- 全部留下；
- 部分留下；
- 部分带走；

---

# 39. 武将和兵可以分别去留

允许：

- 将留兵留；
- 将走兵留；
- 将留部分兵；
- 将带部分兵继续走；
- 兵完全拆编；
- 保留原建制。

但一名武将同一时间不能同时在两支异地 Force 中实际指挥。

---

# 40. 战后军队去向

正规军战后可：

- 继续服役；
- 驻扎某地；
- 驻扎某城；
- 转为地方军；
- 卸甲归田。

注意：

> 驻扎某城 ≠ 并入该城地方军。

复员后：

```text
MilitaryService
↓
Civilian
```

根据原籍、家庭、原职业回归社会。

---

# 41. 人物装备

每个真实 Person 都可以有：

```text
主武器
副武器 / 盾
远程武器
甲具
头盔
坐骑
个人物品
```

重要人物允许细调；普通士兵主要批量自动配装。

---

# 42. 扎营 / 睡觉不反复卸装备

现实表现上可以脱甲、把武器放在身旁，但数据层：

```text
AssignedEquipment
```

保持不变。

休息只改变：

```text
CurrentActivity = Rest
```

不每天执行万人级装备入库 / 出库。

---

# 43. 兵种

Person 不拥有永久“骑兵 / 弓兵 / 枪兵”标签。

兵种来自：

> 人物技能 + 当前装备 + 马匹 + 当前军事岗位。

例如：

```text
有马 + 骑兵装备
→ 当前为骑兵
```

没马，即使骑术高，也不是实际骑兵。

---

# 44. 军队可以设置兵种目标

例如：

```text
长兵 1500
弓兵 600
弩兵 300
骑兵 300
```

然后：

```text
[自动整编]
```

系统按技能、装备、马匹匹配真实 Person。

# 49. 阵型不做硬相克

不做：

```text
锋矢克方圆
方圆克鹤翼
```

真正看：

- 兵种；
- 人数；
- 装备；
- 训练；
- 武将；
- 地形；
- 阵型朝向；
- 敌军进攻方向。

---

# 50. 大地图方向直接映射阵型薄弱处

Force 有 FormationFacing。

例如朝北：

```text
北 = 正面
南 = 后方
东 = 右翼
西 = 左翼
```

敌军从西边攻击，就是打左翼；从南面绕后，就是打后方。

---

# 51. 敌军可以主动寻找薄弱处

通过：

- 侦察；
- 将领判断；
- 已知阵型；

可以发现：

- 左翼兵少；
- 正面精锐；
- 右翼骑兵多；
- 预备不足；

并选择薄弱方向进攻。

夹击优势来自真实阵型受力，而不是固定伤害倍率。

---

# 52. 战斗不是瞬间结算

两支 Force 相邻后发生持续战斗，可持续数小时甚至数日。

允许：

- 援军赶到；
- 改阵；
- 撤退；
- 疲劳；
- 补给变化；
- 多方向进攻。

但不建立第二套小格战斗地图。

---

# 53. 战斗首先结算受击方向

例如敌军攻击左翼：

```text
敌军攻击投入
VS
本军左翼实际部署
```

不是整支 5000 vs 5000 一次整体互扣。

---

# 54. 阵线状态

当前倾向使用离散状态：

```text
稳固
承压
动摇
破裂
崩溃
```

左翼动摇时，玩家可：

- 投预备队；
- 调武将；
- 调整阵型；
- 后撤。

左翼破裂后，敌军可向中军 / 后方突破。

---

# 55. 战争结果最终落回真实 Person

战斗内部为了性能可批量计算：

```text
战死60
负伤120
```

但最后必须落实到具体 Person：

```text
Dead
Wounded
Captured
Routed
Retreated
```

战斗通常通过撤退、溃败、投降结束，而不是杀光才结束。

---

# 56. Person / Household / FamilyOrganization 严格区分

## Person

真实人物与个人产权主体。

## Household

生活家庭：

- 夫妻；
- 子女；
- 居住；
- 日常消费。

## FamilyOrganization

长期家族组织：

- 族产；
- 家族产业；
- 家族资金；
- 私军；
- 家族管理职位。

不是所有小家庭都自动建立 FamilyOrganization。

---

# 57. 家族成员 ≠ 家族资产

人物加入张氏：

```text
Membership = 张氏
```

不代表他的 Cell、钱、铁坊自动变成张氏。

私人资产始终私人。

只有明确贡献、赠与、划拨等行为才改变 Owner。

---

# 58. 家族可以成为产权主体

FamilyOrganization 可以拥有：

- Cell；
- Facility；
- 资金；
- 库存；
- 牲畜；
- 车辆；
- 私军资产。

家主只是管理这些族产，不是族产个人 Owner。

---

# 59. 私人继承

已确定：

> 默认一个主继承人拿大部分核心资产。

主继承人优先获得：

- 主宅；
- 核心 Cell 组合；
- 核心产业；
- 核心 Facility；
- 重要家传物品。

其他继承人主要获得：

- 现金；
- 库存；
- 次要 Cell；
- 非核心产业。

不要求绝对平均。

---

# 60. 继承支持默认 + 手动修改

普通 AI 人物自动按默认规则处理。

玩家 / 重要人物可：

- 指定主继承人；
- 指定资产给谁；
- 指定某资产归族；
- 修改现金分配。

---

# 61. 族产不进入个人遗产

家主死亡时：

```text
家主职位 → 换人
```

族产 Owner 始终是 FamilyOrganization，不进入家主私人遗产。

---

# 62. 爵位体系

不做伯、子、男。

当前采用：

```text
王       特殊
公       特殊

县侯
↓
乡侯
↓
亭侯
↓
关内侯
↓
无爵
```

普通爵位采用降级继承。

---

# 63. 爵位不带默认行政权和兵权

爵位主要提供：

- 身份；
- 政治地位；
- 食邑收益；
- 继承价值；
- 拉拢价值。

官职给行政权，军职给军事资格与统兵上限，爵位给长期身份与经济利益。

---

# 64. 食邑

食邑不绑定具体家庭，不改变 Cell 产权。

例如：

```text
广宗乡侯
食邑1500户
```

采用：

```text
广宗县正常征税
↓
广宗财政
↓
按食邑计算应付爵禄
↓
转移支付给侯爵
```

地方财政没钱则形成拖欠，不凭空生成钱。

---

# 65. 分家 / 分宗

分家不是成年、结婚、创业的常规生命周期事件。

人物可以建立自己的 Household、拥有私人资产、外地做官、经营产业，仍然属于原 Family。

只有某一支系真正要建立新的 FamilyOrganization 时，才叫分家 / 分宗。

---

# 66. AI 可以分家，但必须低频

AI 只有在以下情况长期形成时才可能分家：

- 支系已经很大；
- 长期在不同地区发展；
- 自己资产和关系独立；
- 与本家利益冲突；
- 有明显组织独立需求。

分家是家族政治事件，不是普通人口事件。

---

# 67. 分家不等于分族产

已最终明确：

> 分家是组织独立，不是强制财产分割。

分家人物自己的私人资产继续属于本人。

原 Family 族产默认全部留原家族。

是否给予新家：

- 钱；
- Cell；
- Facility；
- 启动族产；
- 私军资产；

完全由原家族自己决定，可以多给、少给或完全不给。

---

# 68. 税收 / 财政基础方向

已确定的基础方向：

- 县府可对辖区产权主体征税；
- 县府自己拥有的公田、公共 Facility 不向自己缴县税；
- 公共产业产出扣除人工、材料、维护等真实成本后进入公共收益；
- 政府财政同时拥有钱、粮食、物资、库存；
- 不把所有实物自动折成货币。

尚未完全冻结：

```text
县 → 郡 → 州 → 中央
```

各级税种、留成、上缴、转移支付比例。

# 71. 项目“宪法”级原则

## 71.1 世界里的重要东西尽量是真实对象

- 人是真 Person；
- 土地是真 Cell；
- 设施是真 Facility；
- 商品是真库存；
- 军队由真实 Person 组成。

## 71.2 产权、管理权、行政权、军权严格分开

- 县令管理县 ≠ 县令拥有县；
- 家主管理族产 ≠ 族产属于家主个人；
- 将军带官军 ≠ 官军是将军私人财产。

## 71.3 同一人物同一时间只干一件事

经济、学习、旅行、战争共享同一人物时间体系。

## 71.4 底层可以真实复杂，操作必须简单

必须支持：

- 一键派工；
- 一键委任；
- 一键任官；
- 一键整编；
- 一键配装；
- 一键征兵；
- 异常上报；
- 分层下钻。

这些不是后期 UI 优化，而是核心设计。

## 71.5 职位越高，默认操作尺度越高

- 普通人：管自己；
- 产业主：管产业；
- 县令：管县；
- 太守：管县群；
- 州牧：管郡国；
- 中央官：管天下某领域；
- 将军：管 Force 与下属军官。
