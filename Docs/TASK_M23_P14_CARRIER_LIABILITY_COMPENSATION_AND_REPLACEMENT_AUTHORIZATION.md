# M23-P14 承运履约责任、违约赔偿与截获货物替代采购授权任务书

## 1. 阶段目标

在M23-P13按实到货与顺序补运之上，补齐“谁承担运输损失、赔偿是否真实支付、截获货物仍在
敌方保管时能否先行补购”的第一条可审计合同：

```text
报价明确买方自担风险或承运组织担责
→ 真实货运发生自然损失或净敌对损失
→ 货运结束时形成一次责任结算
→ 责任方以真实财政向买方赔偿，资金不足形成欠款
→ 实际收到的赔偿恢复目标可用预算，欠款不能当作现金使用
→ 若截获货物仍由威胁组织保管，补购默认暂停
→ 有军权签发人明确授权后才可按当前缺口补购
```

赔偿不是创造资金，也不抹去货损、截获保管或原付款。替代采购授权也不删除买方对被截货物
的权利；未来若跨地区追回产生超额到货，必须进入后续剩余物资处置合同。

## 2. 必须完成

1. 使用稳定命名空间ID保存买方自担风险、损失承担方赔偿和旧存档不追溯结算三种责任策略。
2. 新军需委任报价的损失承担方只能是目标军队所属买方组织或承运组织；本阶段不允许把未经
   同意的任意第三方写成付款人。
3. 新委任货运根据报价责任生成责任策略；V27既有货运全部进入旧版不追溯策略，升级不能
   倒扣历史组织财政。
4. 每张完成货运最多生成一条持久责任结算，保存目标、货运、责任方、受偿方、自然损失、
   净敌对损失、计价、应付、已付、欠款、创建日、最近付款日和状态。
5. 赔偿基数为“净自然损失＋净敌对保管损失”，单价使用该货运发运时的真实单价；应付赔偿
   不超过该单原付款。买方自担、内部零价调拨或旧版策略的应付为0。
6. 责任组织财政不足时只支付现有非负余额，剩余金额进入欠款；不得把组织财政扣成负数。
7. 提供显式欠款追偿命令，由原目标签发人重新校验军级权限后执行；每次只转移责任方当前
   可支付金额，重复调用不得超过应付总额。
8. 目标分别保存历次原付款和实际收到赔偿；补运预算使用“原付款－已收赔偿＋下一单费用”，
   欠款不得提前恢复预算。
9. 对已完成货运关联的途中事件汇总“截获－夺回”得到仍在敌方保管量。存在该保管量时，
   新目标默认禁止补购。
10. 提供显式替代采购授权命令：只允许目标签发人、仍有军级权限、叶目标待处理、无在途单、
    有剩余需求且确有敌方保管量时调用；保存累计授权量、已消费量、最近授权日/人物/原因。
11. 发运涉及未解决敌方保管量的补运时必须消费足够授权；自然损耗且无敌方保管量的普通补运
    不需要授权。新一轮截获需要新授权，不能重复消费旧授权。
12. 日界仍只处理持久目标、货运、事件和责任结算，不扫描全部永久人物，不依赖关注层级。
13. 存档升级到V28；V27目标采用明确旧版替代采购兼容策略，保持原有可补运行为，不伪造
    授权记录或责任结算。
14. 自动测试覆盖足额赔偿、部分赔偿与欠款追偿、赔偿恢复净预算、未授权替代采购拒绝、
    授权后真实发运、授权不重复消费、V28往返和V27无追溯迁移。

## 3. 本阶段边界

- 不实现保险商、保证金、信用评分、利息、诉讼、强制执行或第三方担保；
- 不把应急获准食用托运货物自动认定为承运违约；
- 不改变截获货物的威胁组织保管事实，不支持货运结束后的跨地区追回；
- 不处理未来追回后造成的超额到货、退货、转卖或军队剩余物资处置；
- 不自动生成报价、不自动授权替代采购、不自动抽取欠款；
- 不实现自动寻路、跨组织递归授权、Unity界面；
- 不提交、不推送仓库。

## 4. 验收标准

1. 赔偿资金严格满足责任方支出＝买方收入，组织财政始终非负；
2. 每张完成货运只有一条责任结算，应付＝已付＋欠款，重复日界不重复赔偿；
3. 目标实际赔偿等于其所有责任结算已付之和，净预算不会使用尚未收回的欠款；
4. 未解决敌方保管量存在时，未授权补购原子拒绝且不改变报价、库存、资金和货运；
5. 授权只消费一次且数量可追溯，授权后的替代采购仍使用P13真实报价、付款、运输和损耗；
6. V28往返一致，V27迁移不追溯扣款、不伪造赔偿或授权；
7. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。
