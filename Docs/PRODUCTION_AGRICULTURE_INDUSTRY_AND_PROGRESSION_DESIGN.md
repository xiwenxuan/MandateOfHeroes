# 数据驱动生产、农业、产业与成长详细设计

## 1. 文档定位与状态

本文是生产、农业、产品、配方、地方经济、职业成长和分层委任之间的专项详细设计。
跨系统状态和全局建设顺序仍以
[`GAME_SYSTEMS_MASTER_AND_STATUS.md`](GAME_SYSTEMS_MASTER_AND_STATUS.md)为准；世界事实、
人口、设施、市场和战争回写仍以
[`WORLD_SIMULATION_FOUNDATION.md`](WORLD_SIMULATION_FOUNDATION.md)为准；人物能力、词条、
教育和师承仍以
[`CHARACTER_ATTRIBUTES_TRAITS_AND_GROWTH.md`](CHARACTER_ATTRIBUTES_TRAITS_AND_GROWTH.md)
为准。

当前状态：**已有底座（M17与M17-P0）**。第一条小麦—粮仓链以及数据驱动作物、地方品种、
产品、配方、生产方法、核心JSON、内容清单和MOD校验已经实现；通用产品批次、完整配方
网络、职业突破、环境生产、区域市场和宏观委任仍属于已定方案，不能误报为已完成。

## 2. 设计目标

本系统要同时满足：

1. 每次生产都由具体土地或设施、具体人物、材料、工具和世界时间完成；
2. 玩家可以亲自劳动，也可以在设施、家族、县郡、军团和政权层级委任；
3. 所有控制层级使用同一世界事实和同一结算链；
4. 作物、产品、配方、设施、技艺、词条、政策和兵种等开放集合使用数据定义；
5. 增加普通内容或MOD内容不要求修改代码枚举或升级存档结构；
6. 作物、原料、半成品和成品可以组成任意深度但无非法循环的生产图；
7. 人物、品种、设施、工艺和组织都能成长，但成长不能凭空创造物资或能力；
8. 地方经济、家族经营、战争补给和人物人生共享同一本世界账；
9. 历史核心包只使用135—260年能够证明或合理推定的内容，并记录来源等级；
10. 完整目标不靠删除细节控制复杂度，而靠自动派工、工单、目标指令、组织委任、
    聚合报告和连续接管控制操作量。

## 4. 统一玩法链

五类参考必须组合为一条因果链：

```text
人物禀赋、技能、知识、身份与时间
→ 取得土地、设施、工具、种子和原料
→ 亲自劳动或接受工作分配
→ 工单按环境、方法、人员和风险推进
→ 产出具体产品批次并写入库存账
→ 家庭消费、加工、市场、税赋或军需消耗
→ 形成利润、声望、经验、职位、灾害与战争后果
→ 反过来改变人物、家族、设施、市场和地区
```

城市农业、商业和军备数值只能是上述事实的汇总，不是独立产出源。

## 5. 开放内容与封闭协议

### 5.1 必须数据驱动的开放集合

下列集合预期持续增加、由资料包扩展或允许MOD定义，因此不得以固定枚举作为公开内容合同：

- 作物物种和地方品种；
- 商品、材料、半成品和成品；
- 配方、生产方法和工艺路线；
- 设施种类、设施模块和工具；
- 技艺、知识、词条、职业道路和突破条件；
- 科技、政策、委任模板和市场需求类型；
- 装备、兵种、阵法、任务、事件和历史内容条目。

这些对象使用稳定、带命名空间的ID，例如：

```text
crop.wheat
crop_variety.wheat.guanzhong_winter
product.wheat_grain
product.wheat_flour
recipe.mill.wheat_to_flour
method.farming.dryland_standard
facility.water_mill
knowledge.agriculture.dryland_rotation
policy.commandery.grain_reserve
```

### 5.2 可以保留枚举的封闭集合

只有生命周期或协议状态可以保留枚举，例如：

- 工单：草拟、活动、暂停、完成、失败、取消；
- 账本方向：借、贷或增、减；
- 控制方式：亲自劳动、实时派工、工单、目标指令、方针托管；
- 存档载入结果、校验状态和错误等级。

判断标准不是“现在条目少”，而是该集合是否属于规则协议且未来扩展必须修改代码逻辑。

## 6. 静态定义、运行状态与存档状态

三层必须分离：

```text
静态内容定义
  说明某种小麦、面粉、磨坊和配方是什么

运行时世界状态
  说明某块田、某批种子、某袋面粉、某张工单现在怎样

存档兼容状态
  保存稳定ID、发生的变化、来源和必要快照
```

静态内容定义由核心内容包和MOD加载；世界状态不能持有Unity对象引用；存档不得依赖
列表位置、显示名称或运行时内存地址。

## 7. 内容清单与兼容合同

每个世界保存创建时使用的内容清单：

```text
ContentManifest
  content_schema_version
  packages[]
    package_id
    package_version
    load_order
    content_hash
    required
  resolved_definition_hash
  aliases[]
```

规则：

1. 定义ID进入公开存档后不得改作其他含义；
2. 改显示名不改变ID；
3. 合法重命名使用显式别名或迁移表；
4. 新增作物、配方或产品不升级世界存档版本；
5. 只有持久结构改变才升级世界存档版本；
6. 缺失内容不能静默映射成另一物品；
7. 缺失的非关键定义保留未知占位、原ID和已有数量，等待玩家修复内容包；
8. 缺失会影响守恒或关键世界事实的定义时，默认阻止原存档直接载入，并允许复制后修复；
9. 内容冲突按固定加载顺序解析，最终结果和来源写入日志。

### 8.1 作物定义

`usage_tags`可以同时包含主粮、饲料、油料、纤维、药用、染料、救荒、经济、军需或
地方特产；这些标签用于搜索、AI和市场规则，不构成互斥类型。

### 8.2 地方品种定义与世界品种状态

```text

  crop_definition_id

  base_trait_ids[]

```

核心内容包可以定义有资料依据的地方品种；运行世界也允许通过选种、异地种植、灾害筛选
和试验产生新世界品种。新品种必须记录父系、发现者、地点、时间、方法和确定性坐标。

### 8.3 种子批次

种子是有数量、所有权和质量的产品批次，不是作物定义上的无限资源：

```text
SeedBatchState
  id
  owner_id
  storage_id
  crop_variety_state_id
  quantity
  unit_id
  harvest_day
  origin_site_id
  germination_basis_points
  purity_basis_points
  moisture_basis_points
  health_trait_ids[]
  reserved_for_order_id
```

不同批次可以混合，但混合会形成新批次并按照明确规则重算数量、品质和品种纯度。

### 8.4 环境与农时

作物结算至少读取：

- 地形、土壤、坡度和地块面积；
- 温度、降水、日照和极端天气；
- 水源、灌溉、排水和洪涝；
- 肥力、轮作、休耕和投入；
- 人力、畜力、工具和负责人能力；
- 播种时间、生长阶段和收获窗口；
- 病虫害、治安、战争和设施损坏。

这些事实可以按地块、设施网络或地区缓存聚合，但玩家关注不能改变真实结果。

当来源、所有权、品质、损耗、保质期或历史会改变玩法结果时，保存批次：


```text
RecipeDefinition
  id
  facility_tag_requirements[]
  knowledge_requirements[]
  input_slots[]
    accepted_product_ids[]
    accepted_tags[]
    quantity
    consumption_mode
  tool_requirements[]
  labor_requirements[]
  duration
  output_slots[]
    product_id
    quantity_rule
    trait_transfer_rule
  byproduct_slots[]
  waste_slots[]
  compatible_method_ids[]
  risk_rules[]
```

产品可以再次作为任何配方输入：

```text
小麦 → 麦粒 → 面粉 → 饼或面食 → 干粮 → 军粮包
桑叶 → 蚕茧 → 生丝 → 丝线 → 丝织物 → 染整织物 → 礼服或贡品
麻茎 → 麻纤维 → 麻线 → 麻布、绳索、渔网、船具或军需
药草 → 晾晒或炮制药材 → 方剂原料 → 成药 → 医疗消耗
水果 → 鲜果 → 果干、酒或醋 → 市场、宴饮、礼物和军需补充
```

加载时构建配方有向图并校验：

- 不允许没有时间、损耗或外部投入却能够无限增殖的闭环；
- 不允许配方引用不存在的产品、设施、方法或知识；
- 输出计量单位必须能够换算；
- 副产品和废料也必须进入库存、排放或损耗账；
- 不允许只记录主产品而让输入差额消失。

## 11. 生产方法与工艺选择

同一配方可以选择不同生产方法：

```text
ProductionMethodDefinition
  id
  applicable_recipe_ids[]
  knowledge_requirements[]
  facility_module_requirements[]
  input_modifiers[]
  labor_profile
  duration_modifier
  yield_modifier
  quality_modifier
  fuel_modifier
  risk_modifier
  trait_transfer_modifier
  unlock_conditions[]
```

方法升级不能只做线性“+10%产量”。它可以形成取舍：

- 省种但更费劳力；
- 高产但依赖水利；
- 快速加工但品质下降；
- 节省燃料但需要熟练工；
- 适合军需大批量，但不适合高价值精品；
- 适合地方原料，但异地采用风险较高。

## 12. 统一工单与结算

所有生产方式最终生成统一工单：

```text
ProductionWorkOrderState
  id
  recipe_definition_id
  method_definition_id
  site_id
  owner_id
  manager_person_id
  control_mode
  status
  created_day
  scheduled_start_day
  expected_finish_day
  priority
  input_reservations[]
  worker_assignments[]
  tool_assignments[]
  target_quantity
  quality_target
  shortage_policy
  interruption_policy
  output_destination_ids[]
  progress
  deterministic_action_key
```

结算顺序：

```text
验证权限和知识
→ 预留输入、工具、地块与工位
→ 分配人员世界时间
→ 按稳定顺序推进阶段
→ 处理天气、事故、疾病、战争和缺料
→ 消耗输入
→ 生成产品、副产品和废料批次
→ 入库、转运或形成损耗
→ 写入库存、生产、人物经验和组织账本
→ 释放预留并生成报告
```

失败不能把已消耗的劳动、燃料和原料回滚成未发生。取消工单只释放尚未使用的预留。

## 13. 生产公式和可解释性

通用结算框架：

```text
理论产出
= 配方基准
× 有效投入率
× 有效劳动率
× 方法效率
× 设施状态
× 环境适宜度
× 工具与畜力
× 管理与协作
× 当前风险结果
```

品质由独立维度构成，不压缩成万能星级：

- 粮食：纯净度、含水量、饱满度、储藏稳定性；
- 纤维：长度、韧性、均匀度；
- 药材：品种正确性、炮制状态、效力和污染；
- 金属：纯度、硬度、韧性和缺陷；
- 食品：营养、风味、保质和卫生。

界面必须能解释主要增减来源，避免只显示不可审计的最终百分比。

## 14. 人物能力、技艺与职业突破

生产表现来自五层：

```text
基础禀赋
→ 专业资质
→ 技能熟练度
→ 已掌握知识与技艺
→ 当前状态、职位、工具和资源
```

职业成长采用《鬼谷八荒》式“资质差异、组合构筑和阶段突破”的表达，但条件历史化：

| 阶段 | 核心条件示例 |
|---|---|
| 学徒或初学 | 有教师、家学、书籍或岗位；完成基础学习 |
| 熟手 | 完成多个真实生产周期，并达到稳定质量 |
| 管事或师傅 | 管理他人、控制损耗、处理缺料和事故 |
| 匠师或农师 | 完成高难项目、跨地区实践或成功应灾 |
| 名家 | 改良方法或品种、著书、建立流派并培养继承人 |

突破由`ProfessionProgressionDefinition`描述，必须引用真实事件、作品、人物、地点和时间。
经验达到阈值只说明具备申请或尝试资格，不会自动授予名家身份。

人物可以组合不同技艺形成路线，例如：

```text
善察地力 + 旱作经验 + 水利知识
→ 北方田庄与救灾路线

识货 + 记账 + 熟悉商路 + 仓储管理
→ 粮商与跨郡调运路线

辨药 + 炮制 + 军中外伤经验
→ 军医和战地药坊路线
```

## 15. 品种、设施、工艺与组织升级

升级不只属于人物。

### 15.1 品种升级

- 连续选种；
- 异地适应；
- 杂交或混种结果；
- 灾害筛选；
- 稳定性提高；
- 退化、污染或失传。

### 15.2 设施升级

- 扩大容量；
- 增加工位；
- 改善水利、通风、防火和卫生；
- 安装工具或模块；
- 调整布局和运输；
- 维修、改造或转换用途。

设施等级只用于摘要，实际能力来自已建模块、规模、状态和人员。

### 15.3 工艺升级

- 改善投入比例；
- 缩短时间；
- 稳定品质；
- 降低事故；
- 允许新材料；
- 产生新的副产品用途。

### 15.4 组织升级

- 形成标准工单和检验制度；
- 建立师徒和培训体系；
- 建立采购、仓储与运输网络；
- 建立地区分号、庄园和官营机构；
- 扩大授权范围和报告能力。

组织优势不能让远方工人瞬间获得知识；需要人员、文书、实物样品、交通和时间传播。

## 16. 控制层级与自动化

所有层级最终生成同一种工单：

| 层级 | 玩家主要决定 | 自动系统负责 |
|---|---|---|
| 个人 | 今日做什么、学习什么、使用什么工具 | 时间推进、体力消耗、技能经验和结果 |
| 工位或设施 | 人员、队列、优先级、配方、质量和缺料策略 | 人物领取任务、运输、阶段推进和报告 |
| 家庭或商号 | 产业组合、库存底线、利润、雇工和契约 | 管事拆分设施工单、采购和销售 |
| 村庄或县 | 种植结构、公共工程、赈灾和税役 | 里正、县吏和负责人拆分到家户及设施 |
| 郡州或军团 | 粮食安全、军需、运输走廊、预算和政策红线 | 太守、都督及下属逐级分解和上报 |
| 政权 | 战略目标、法令、财政和跨区调拨 | 军团与州郡执行，异常进入评定 |

玩家接管一个节点时继承现有人员、库存、预留、进度、成本和期限；交还委任时继续执行，
不得重开工单或重掷结果。

## 17. 九州式区域经济

每个市场以具体库存和需求形成价格：

```text
可出售库存
+ 预计到货
- 家庭保留
- 种子保留
- 组织预留
- 军需征购
```

需求至少来自：

- 常住人口消费；
- 设施原料；
- 建设项目；
- 军队与驻军；
- 官仓储备；
- 宴饮、祭祀、医疗和身份消费；
- 商人投机、跨区契约和灾害预期。

地方特产由适宜环境、品种、工艺、声誉和运输共同形成，不能只给某城市永久价格加成。
商队携带真实货物，占用车马船只和人物时间，并面对税卡、匪患、天气、战争和过期损耗。

## 18. 三国志式治理、委任与评定

宏观命令不直接修改产量，而生成带约束的目标：

```text
RegionalProductionMandate
  issuer_office_id
  jurisdiction_id
  objective_tags[]
  target_metrics[]
  budget
  deadline
  authority_scope
  policy_constraints[]
  protected_reserves[]
  report_interval
  escalation_rules[]
  delegate_office_id
```

示例：

```text
目标：两年内把郡级官仓储备提高到六个月
预算：三百万钱
限制：不得额外征用民田，不得侵占留种
优先级：修复水利 > 增建仓储 > 扩种
授权：太守可以调整县级种植结构和采购价格
上报：缺粮、民变、预算超支或军队征发立即上报
```

负责人能力影响调查、拆解、协调、监督和纠错；一个官员同时承担其他任务时，有效投入
下降。能力不能直接替代种子、劳力、设施或运输。

## 19. 战争与生产

生产和战争共享以下对象：

- 永久人物既是劳动力，也可能被征兵、受伤、逃亡或死亡；
- 粮食、布帛、皮革、木材、铁器、牲畜和药物都是实际军需；
- 道路、港口、仓库、磨坊、铁坊和水利既有经济价值，也有军事价值；
- 军队征购、征发、购买、借贷、抢掠和破坏必须写入库存及财政账；
- 烧田、毁渠、劫仓会影响后续多年，而不是只扣一次城市农业值；
- 地方价格、税收、饥荒、难民、治安和家族关系会反馈战争。

军团界面看到的是其合法取得且具有时间戳的库存与产能报告，不得读取未知敌境实时产量。

## 20. 有限认知、知识与信息资产

- 角色不知道的作物品种、矿脉、配方、库存和布防不能出现在其决策输入；
- 人物亲眼观察、师承、农书、商号账簿、官府统计和军情属于不同知识资产；
- 抄录品种目录、配方、账簿和地图需要人物、载体、工具和时间；
- 离任官员保留记忆和合法取得的副本，但不继续收到自动更新；
- 外派庄园或商号按照报告周期回传产量、库存和风险；信息会迟到、缺失或失真；
- 关注只决定展示和报告精度，不改变生产事实。

## 21. 确定性、性能与聚合

随机结果使用：

```text
世界种子
+ 工单稳定ID
+ 生产阶段
+ 世界日期
+ 明确动作键
```

禁止用当前帧、系统时间、列表位置或Unity实例ID决定持久结果。

性能分层：

- 关注设施可以逐阶段显示人员和运输；
- 活跃地区按日或旬推进到期工单；
- 远方稳定设施可以批量推进，但必须得到与逐步推进一致的账本终值；
- 普通产品按同质批次聚合；重要来源、品质、预留和所有权差异必须保留；
- 人物冷热状态只改变数据驻留和调度频率，不改变其劳动、死亡、财产与经验事实。

## 22. 首批内容分类

首批内容用于验证体系，不构成最终上限。所有物种和传播年代必须另行史料审核。

### 22.1 主粮和豆类

- 稻；
- 小麦；
- 大麦；
- 粟；
- 黍；
- 稷的历史名物映射；
- 大豆及其他经审核豆类。

### 22.2 蔬菜、果树与救荒

- 葵、韭、葱、蒜、芋等经时代审核的蔬菜；
- 桃、李、杏、梨、枣、栗、梅、柑橘等地方果树；
- 可采集野生植物及其救荒处理方法。

### 22.3 饲料、油料、纤维与染料

- 豆秸、麦秸、草料和粮食加工副产物；
- 胡麻、荏等经审核油料；
- 麻、苎麻、葛和桑蚕原料；
- 蓝草、茜草等经审核染料植物。

### 22.4 药用、香辛与地方特产

- 常见药草和地方药材；
- 姜、椒等经时代审核的调味作物；
- 漆、桑蚕及其他地区产业原料；
- 不把后世传入作物因现代常见而提前加入核心历史包。

## 23. 端到端示例：关中冬麦

```text
1. 核心内容定义小麦物种和关中冬麦地方品种。
2. 某家户拥有上一季收获的具体种子批次。
3. 太守下达提高官仓储备目标，县令制定收购与水利计划。
4. 家主选择方针托管，管事按土地、留种和劳力生成播种工单。
5. 家庭成员或雇工领取整地、播种、灌溉和收获任务。
6. 天气、水利、工具、技能和品种性状决定产量及品质。
7. 麦粒分为留种、家庭口粮、税粮、市场出售和损耗。
8. 磨坊把部分麦粒加工为面粉，再制成干粮。
9. 商人把剩余麦粒运往歉收地区，价格随库存和战争变化。
10. 军团征购干粮；运输损耗和征兵减少下一季农业劳力。
11. 农户、管事、商人和官员分别获得与实际行为对应的经验、声望和责任记录。
```

这个例子同时落实微观生产、居民自动化、职业成长、区域商旅、宏观委任和军粮战争，
但只存在一套麦粒、库存和人物事实。

## 24. 界面与玩家操作

同一设施至少提供四层信息：

1. 摘要：产量、库存、利润、风险和异常；
2. 经营：配方队列、人员、投入、目标、采购和销售；
3. 现场：工位、运输、具体人物、生产阶段和环境；
4. 审计：工单、库存事务、损耗原因、权限来源和计算解释。

专题视图包括生产、资源、物流、市场、建设、军需和知识视图，全部受主体认知约束。
玩家可设异常阈值，只有缺料、事故、灾害、破产、战争、违法或目标偏离超过阈值时打断。

## 25. 当前原型与正式方案差异

M17-P0实施前的原型曾存在：

- 固定`CropKind`枚举；
- 作物只保存为工单字段，尚无作物和地方品种定义；
- 家庭粮食以单一`long`余额为权威，商品市场另有`CommodityState`；
- 农业账本使用`SeedCommitted`、`GrainStored`等专用事件；
- 只有小麦、粮食和家庭粮仓链；
- 尚无通用产品批次、配方图、生产方法、品质维度和内容清单。

M17-P0已经完成固定作物枚举纠偏、小麦核心内容包和V8内容清单；家庭单一粮食余额、
农业专用兼容账和通用产品批次尚未完全迁移，继续作为下一阶段技术债。后续不能重新引入
固定作物枚举，也不能把当前首条小麦链描述为完整产业网络。

M18-P0进一步建立V9人物技能、知识、科研项目、技术掌握、设施级技术应用和科研账底座，
并把选种法、垄作播种、协同农作三张原创农业科技卡接入M17田地、配方、方法和工单技术
快照。当前只验证了农业第一条局部应用闭环；组织知识、传播失传、研究材料、风险与完整
职业突破仍未实现。

M19-P0进一步建立V10产品/种子批次、通用库存事务、加工工单和旧粮账转换适配器，打通
“10麦粒→8面粉＋2麸皮→8干粮”的首条守恒加工链，并提供按产品标签统计未预留市场可售量
的查询。当前农业收获仍写入旧粮食兼容余额，只有明确转换后的数量进入批次；运输、腐败、
拆分合并、市场成交、家庭消费与军需尚未全部迁移到批次合同，不能描述为完整产业网络。

M23-P0进一步把六种核心军械登记为产品定义，增加组织所有的移动库存容器，并完成第一条
“商号成品批次—采购发运—人物承运—军械库入库”链。发运会扣减产品批次，入库会增加
M11军械库存，两端由同一采购ID和双边资金账关联。当前成品军械是原型开局库存，尚无
冶铁、锻造、木作、制弓或制甲配方，因此不得把采购闭环描述为军械制造闭环。

## 26. 自动验证要求

后续实现至少覆盖：

1. 内容注册表拒绝重复ID、缺失引用、非法单位和非法配方循环；
2. 增加一个MOD作物、产品和配方不修改代码枚举与存档版本；
3. 相同定义、世界种子、工单和时间坐标产生相同结果；
4. 输入消耗等于产品、副产品、废料和明确损耗之和；
5. 批次拆分、合并、运输、加工和存档往返保持数量与来源；
6. 五种控制方式在相同事实输入下得到相同结算；
7. 玩家关注变化不改变产量、品质和库存；
8. NPC只能使用其已知作物、配方、资源和市场信息；
9. 职业突破满足技能、知识、实绩和身份条件并保留来源；
10. V8生产原型迁移到V9后不丢失工单、人物、家庭、种粮、产量和账本；
11. 缺失内容ID不静默替换或删除产品；
12. 军需、市场、消费和生产不能重复扣减或凭空增加同一批物资。

## 27. 领域实现顺序

本领域内部建议顺序如下，不覆盖总纲的全局排期：

1. 建立稳定内容ID、产品、作物、品种、配方和方法定义合同；
2. 建立内容注册、引用校验、清单和缺失内容策略；
3. 把M17固定`CropKind`迁移为定义ID，并将小麦链改为首个数据内容包；
4. 接入稳定ID技能、知识、科研项目和设施局部技术应用；
5. 建立产品批次、通用库存事务和农业种子批次；
6. 建立通用生产工单与任意深度配方结算；
7. 扩展人物实践经验和职业突破；
8. 接入设施模块、生产方法、品质与环境；
9. 接入市场需求、商队、契约和地方特产；M23-P0已完成军械采购运输的首条受限切片；
10. 接入县郡政策、太守与军团委任；
11. 接入军需、征发、破坏、灾害和跨年代产业演化。

每一步只代表实现依赖，不删减后续完整目标。
