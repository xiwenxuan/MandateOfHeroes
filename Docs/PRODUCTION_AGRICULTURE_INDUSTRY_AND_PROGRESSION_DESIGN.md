## 2. 设计目标

本系统要同时满足：

1. 每次生产都由具体土地或设施、具体人物、材料、工具和世界时间完成；
2. 玩家可以亲自劳动，也可以在设施、家族、县郡、军团和政权层级委任；
3. 所有控制层级使用同一世界事实和同一结算链；
4. 作物、产品、配方、设施、技艺、词条、政策和兵种等开放集合使用数据定义；
5. 增加普通内容或MOD内容不要求修改代码枚举或升级存档结构；
6. 作物、原料、半成品和成品可以组成任意深度但无非法循环的生产图；
7. 人物、品种、设施、工艺和组织都能成长，但成长不能凭空创造物资或能力；
8. 地方经济、家族经营、战争补给和人物人生共享同一本世界账；
9. 历史核心包只使用135—260年能够证明或合理推定的内容，并记录来源等级；
10. 完整目标不靠删除细节控制复杂度，而靠自动派工、工单、目标指令、组织委任、
    聚合报告和连续接管控制操作量。

## 4. 统一玩法链

五类参考必须组合为一条因果链：

```text
人物禀赋、技能、知识、身份与时间
→ 取得土地、设施、工具、种子和原料
→ 亲自劳动或接受工作分配
→ 工单按环境、方法、人员和风险推进
→ 产出具体产品批次并写入库存账
→ 家庭消费、加工、市场、税赋或军需消耗
→ 形成利润、声望、经验、职位、灾害与战争后果
→ 反过来改变人物、家族、设施、市场和地区
```

城市农业、商业和军备数值只能是上述事实的汇总，不是独立产出源。

## 5. 开放内容与封闭协议

### 5.1 必须数据驱动的开放集合

下列集合预期持续增加、由资料包扩展或允许MOD定义，因此不得以固定枚举作为公开内容合同：

- 作物物种和地方品种；
- 商品、材料、半成品和成品；
- 配方、生产方法和工艺路线；
- 设施种类、设施模块和工具；
- 技艺、知识、词条、职业道路和突破条件；
- 科技、政策、委任模板和市场需求类型；
- 装备、兵种、阵法、任务、事件和历史内容条目。

这些对象使用稳定、带命名空间的ID，例如：

```text
crop.wheat
crop_variety.wheat.guanzhong_winter
product.wheat_grain
product.wheat_flour
recipe.mill.wheat_to_flour
method.farming.dryland_standard
facility.water_mill
knowledge.agriculture.dryland_rotation
policy.commandery.grain_reserve
```

### 5.2 可以保留枚举的封闭集合

只有生命周期或协议状态可以保留枚举，例如：

- 工单：草拟、活动、暂停、完成、失败、取消；
- 账本方向：借、贷或增、减；
- 控制方式：亲自劳动、实时派工、工单、目标指令、方针托管；
- 存档载入结果、校验状态和错误等级。

判断标准不是“现在条目少”，而是该集合是否属于规则协议且未来扩展必须修改代码逻辑。

## 6. 静态定义、运行状态与存档状态

三层必须分离：

```text
静态内容定义
  说明某种小麦、面粉、磨坊和配方是什么

运行时世界状态
  说明某块田、某批种子、某袋面粉、某张工单现在怎样

存档兼容状态
  保存稳定ID、发生的变化、来源和必要快照
```

静态内容定义由核心内容包和MOD加载；世界状态不能持有Unity对象引用；存档不得依赖
列表位置、显示名称或运行时内存地址。

## 7. 内容清单与兼容合同

每个世界保存创建时使用的内容清单：

```text
ContentManifest
  content_schema_version
  packages[]
    package_id
    package_version
    load_order
    content_hash
    required
  resolved_definition_hash
  aliases[]
```

规则：

1. 定义ID进入公开存档后不得改作其他含义；
2. 改显示名不改变ID；
3. 合法重命名使用显式别名或迁移表；
4. 新增作物、配方或产品不升级世界存档版本；
5. 只有持久结构改变才升级世界存档版本；
6. 缺失内容不能静默映射成另一物品；
7. 缺失的非关键定义保留未知占位、原ID和已有数量，等待玩家修复内容包；
8. 缺失会影响守恒或关键世界事实的定义时，默认阻止原存档直接载入，并允许复制后修复；
9. 内容冲突按固定加载顺序解析，最终结果和来源写入日志。

### 8.3 种子批次

种子是有数量、所有权和质量的产品批次，不是作物定义上的无限资源：

```text

  germination_basis_points
  purity_basis_points
  moisture_basis_points

  reserved_for_order_id
```

不同批次可以混合，但混合会形成新批次并按照明确规则重算数量、品质和品种纯度。

### 8.4 环境与农时

作物结算至少读取：

- 地形、土壤、坡度和地块面积；
- 温度、降水、日照和极端天气；
- 水源、灌溉、排水和洪涝；
- 肥力、轮作、休耕和投入；
- 人力、畜力、工具和负责人能力；
- 播种时间、生长阶段和收获窗口；
- 病虫害、治安、战争和设施损坏。

这些事实可以按地块、设施网络或地区缓存聚合，但玩家关注不能改变真实结果。

M24-P1使用`product.food.grain_equivalent`和整数标准口粮，把100万具体人物的年龄需求、
县级固定土地、具体农业劳力和粮食损耗连续结算50年，作为大规模承载压力证据。该标准口粮
只是对多种真实食物产品的性能折算接口，不替代M17/M19的作物、地方品种、种子与产品批次；
后续必须从具体批次折算营养供给，不能反向恢复固定作物枚举或凭县级产量直接造粮。

```text
小麦 → 麦粒 → 面粉 → 饼或面食 → 干粮 → 军粮包
桑叶 → 蚕茧 → 生丝 → 丝线 → 丝织物 → 染整织物 → 礼服或贡品
麻茎 → 麻纤维 → 麻线 → 麻布、绳索、渔网、船具或军需
药草 → 晾晒或炮制药材 → 方剂原料 → 成药 → 医疗消耗
水果 → 鲜果 → 果干、酒或醋 → 市场、宴饮、礼物和军需补充
```

加载时构建配方有向图并校验：

- 不允许没有时间、损耗或外部投入却能够无限增殖的闭环；
- 不允许配方引用不存在的产品、设施、方法或知识；
- 输出计量单位必须能够换算；
- 副产品和废料也必须进入库存、排放或损耗账；
- 不允许只记录主产品而让输入差额消失。

## 11. 生产方法与工艺选择

同一配方可以选择不同生产方法：

```text
ProductionMethodDefinition
  id
  applicable_recipe_ids[]
  knowledge_requirements[]
  facility_module_requirements[]
  input_modifiers[]
  labor_profile
  duration_modifier
  yield_modifier
  quality_modifier
  fuel_modifier
  risk_modifier
  trait_transfer_modifier
  unlock_conditions[]
```

方法升级不能只做线性“+10%产量”。它可以形成取舍：

- 省种但更费劳力；
- 高产但依赖水利；
- 快速加工但品质下降；
- 节省燃料但需要熟练工；
- 适合军需大批量，但不适合高价值精品；
- 适合地方原料，但异地采用风险较高。

## 12. 统一工单与结算

所有生产方式最终生成统一工单：

```text
ProductionWorkOrderState
  id
  recipe_definition_id
  method_definition_id
  site_id
  owner_id
  manager_person_id
  control_mode
  status
  created_day
  scheduled_start_day
  expected_finish_day
  priority
  input_reservations[]
  worker_assignments[]
  tool_assignments[]
  target_quantity
  quality_target
  shortage_policy
  interruption_policy
  output_destination_ids[]
  progress
  deterministic_action_key
```

结算顺序：

```text
验证权限和知识
→ 预留输入、工具、地块与工位
→ 分配人员世界时间
→ 按稳定顺序推进阶段
→ 处理天气、事故、疾病、战争和缺料
→ 消耗输入
→ 生成产品、副产品和废料批次
→ 入库、转运或形成损耗
→ 写入库存、生产、人物经验和组织账本
→ 释放预留并生成报告
```

失败不能把已消耗的劳动、燃料和原料回滚成未发生。取消工单只释放尚未使用的预留。

## 13. 生产公式和可解释性

通用结算框架：

```text
理论产出
= 配方基准
× 有效投入率
× 有效劳动率
× 方法效率
× 设施状态
× 环境适宜度
× 工具与畜力
× 管理与协作
× 当前风险结果
```

品质由独立维度构成，不压缩成万能星级：

- 粮食：纯净度、含水量、饱满度、储藏稳定性；
- 纤维：长度、韧性、均匀度；
- 药材：品种正确性、炮制状态、效力和污染；
- 金属：纯度、硬度、韧性和缺陷；
- 食品：营养、风味、保质和卫生。

界面必须能解释主要增减来源，避免只显示不可审计的最终百分比。

M23-P4已实现这一规则的第一条V18底座：品质维度作为开放内容定义，产品声明自身维度，
生产方法声明实践技能、难度和逐维修正，产品批次保存按定义排序的逐维数值。旧
`QualityBasisPoints`暂保留为逐维数值算术平均的兼容汇总缓存，校验会拒绝缓存与维度事实
不一致；它不是新的万能星级，也不能代替具体维度参与后续玩法。

## 14. 人物能力、技艺与职业突破

生产表现来自五层：

```text
基础禀赋
→ 专业资质
→ 技能熟练度
→ 已掌握知识与技艺
→ 当前状态、职位、工具和资源
```

职业成长采用《鬼谷八荒》式“资质差异、组合构筑和阶段突破”的表达，但条件历史化：

| 阶段 | 核心条件示例 |
|---|---|
| 学徒或初学 | 有教师、家学、书籍或岗位；完成基础学习 |
| 熟手 | 完成多个真实生产周期，并达到稳定质量 |
| 管事或师傅 | 管理他人、控制损耗、处理缺料和事故 |
| 匠师或农师 | 完成高难项目、跨地区实践或成功应灾 |
| 名家 | 改良方法或品种、著书、建立流派并培养继承人 |

突破由`ProfessionProgressionDefinition`描述，必须引用真实事件、作品、人物、地点和时间。
经验达到阈值只说明具备申请或尝试资格，不会自动授予名家身份。

人物可以组合不同技艺形成路线，例如：

```text
善察地力 + 旱作经验 + 水利知识
→ 北方田庄与救灾路线

识货 + 记账 + 熟悉商路 + 仓储管理
→ 粮商与跨郡调运路线

辨药 + 炮制 + 军中外伤经验
→ 军医和战地药坊路线
```

## 15. 品种、设施、工艺与组织升级

升级不只属于人物。

### 15.1 品种升级

- 连续选种；
- 异地适应；
- 杂交或混种结果；
- 灾害筛选；
- 稳定性提高；
- 退化、污染或失传。

### 15.2 设施升级

- 扩大容量；
- 增加工位；
- 改善水利、通风、防火和卫生；
- 安装工具或模块；
- 调整布局和运输；
- 维修、改造或转换用途。

设施等级只用于摘要，实际能力来自已建模块、规模、状态和人员。

设施成长统一归入参数升级、设备/内部模块、配方/工艺/服务内容扩展、改造转型和空间扩张
五类。达到单Cell合理上限后必须取得新Cell并建设新Facility；具体目录与Module/独立Facility
判定规则见统一世界与权力设计。该归类不表示通用成长运行时已经完成。

### 15.3 工艺升级

- 改善投入比例；
- 缩短时间；
- 稳定品质；
- 降低事故；
- 允许新材料；
- 产生新的副产品用途。

### 15.4 组织升级

- 形成标准工单和检验制度；
- 建立师徒和培训体系；
- 建立采购、仓储与运输网络；
- 建立地区分号、庄园和官营机构；
- 扩大授权范围和报告能力。

组织优势不能让远方工人瞬间获得知识；需要人员、文书、实物样品、交通和时间传播。

## 16. 控制层级与自动化

所有层级最终生成同一种工单：

| 层级 | 玩家主要决定 | 自动系统负责 |
|---|---|---|
| 个人 | 今日做什么、学习什么、使用什么工具 | 时间推进、体力消耗、技能经验和结果 |
| 工位或设施 | 人员、队列、优先级、配方、质量和缺料策略 | 人物领取任务、运输、阶段推进和报告 |
| 家庭或商号 | 产业组合、库存底线、利润、雇工和契约 | 管事拆分设施工单、采购和销售 |
| 村庄或县 | 种植结构、公共工程、赈灾和税役 | 里正、县吏和负责人拆分到家户及设施 |
| 郡州或军团 | 粮食安全、军需、运输走廊、预算和政策红线 | 太守、都督及下属逐级分解和上报 |
| 政权 | 战略目标、法令、财政和跨区调拨 | 军团与州郡执行，异常进入评定 |

玩家接管一个节点时继承现有人员、库存、预留、进度、成本和期限；交还委任时继续执行，
不得重开工单或重掷结果。

## 17. 九州式区域经济

每个市场以具体库存和需求形成价格：

```text
可出售库存
+ 预计到货
- 家庭保留
- 种子保留
- 组织预留
- 军需征购
```

需求至少来自：

- 常住人口消费；
- 设施原料；
- 建设项目；
- 军队与驻军；
- 官仓储备；
- 宴饮、祭祀、医疗和身份消费；
- 商人投机、跨区契约和灾害预期。

地方特产由适宜环境、品种、工艺、声誉和运输共同形成，不能只给某城市永久价格加成。
商队携带真实货物，占用车马船只和人物时间，并面对税卡、匪患、天气、战争和过期损耗。

## 18. 三国志式治理、委任与评定

宏观命令不直接修改产量，而生成带约束的目标：

```text
RegionalProductionMandate
  issuer_office_id
  jurisdiction_id
  objective_tags[]
  target_metrics[]
  budget
  deadline
  authority_scope
  policy_constraints[]
  protected_reserves[]
  report_interval
  escalation_rules[]
  delegate_office_id
```

示例：

```text
目标：两年内把郡级官仓储备提高到六个月
预算：三百万钱
限制：不得额外征用民田，不得侵占留种
优先级：修复水利 > 增建仓储 > 扩种
授权：太守可以调整县级种植结构和采购价格
上报：缺粮、民变、预算超支或军队征发立即上报
```

负责人能力影响调查、拆解、协调、监督和纠错；一个官员同时承担其他任务时，有效投入
下降。能力不能直接替代种子、劳力、设施或运输。

## 19. 战争与生产

生产和战争共享以下对象：

- 永久人物既是劳动力，也可能被征兵、受伤、逃亡或死亡；
- 粮食、布帛、皮革、木材、铁器、牲畜和药物都是实际军需；
- 道路、港口、仓库、磨坊、铁坊和水利既有经济价值，也有军事价值；
- 军队征购、征发、购买、借贷、抢掠和破坏必须写入库存及财政账；
- 烧田、毁渠、劫仓会影响后续多年，而不是只扣一次城市农业值；
- 地方价格、税收、饥荒、难民、治安和家族关系会反馈战争。

军团界面看到的是其合法取得且具有时间戳的库存与产能报告，不得读取未知敌境实时产量。

## 20. 有限认知、知识与信息资产

- 角色不知道的作物品种、矿脉、配方、库存和布防不能出现在其决策输入；
- 人物亲眼观察、师承、农书、商号账簿、官府统计和军情属于不同知识资产；
- 抄录品种目录、配方、账簿和地图需要人物、载体、工具和时间；
- 离任官员保留记忆和合法取得的副本，但不继续收到自动更新；
- 外派庄园或商号按照报告周期回传产量、库存和风险；信息会迟到、缺失或失真；
- 关注只决定展示和报告精度，不改变生产事实。

## 21. 确定性、性能与聚合

随机结果使用：

```text
世界种子
+ 工单稳定ID
+ 生产阶段
+ 世界日期
+ 明确动作键
```

禁止用当前帧、系统时间、列表位置或Unity实例ID决定持久结果。

性能分层：

- 关注设施可以逐阶段显示人员和运输；
- 活跃地区按日或旬推进到期工单；
- 远方稳定设施可以批量推进，但必须得到与逐步推进一致的账本终值；
- 普通产品按同质批次聚合；重要来源、品质、预留和所有权差异必须保留；
- 人物冷热状态只改变数据驻留和调度频率，不改变其劳动、死亡、财产与经验事实。

## 22. 首批内容分类

## 23. 端到端示例：关中冬麦

```text
1. 核心内容定义小麦物种和关中冬麦地方品种。
2. 某家户拥有上一季收获的具体种子批次。
3. 太守下达提高官仓储备目标，县令制定收购与水利计划。
4. 家主选择方针托管，管事按土地、留种和劳力生成播种工单。
5. 家庭成员或雇工领取整地、播种、灌溉和收获任务。
6. 天气、水利、工具、技能和品种性状决定产量及品质。
7. 麦粒分为留种、家庭口粮、税粮、市场出售和损耗。
8. 磨坊把部分麦粒加工为面粉，再制成干粮。
9. 商人把剩余麦粒运往歉收地区，价格随库存和战争变化。
10. 军团征购干粮；运输损耗和征兵减少下一季农业劳力。
11. 农户、管事、商人和官员分别获得与实际行为对应的经验、声望和责任记录。
```

这个例子同时落实微观生产、居民自动化、职业成长、区域商旅、宏观委任和军粮战争，
但只存在一套麦粒、库存和人物事实。

## 24. 界面与玩家操作

同一设施至少提供四层信息：

1. 摘要：产量、库存、利润、风险和异常；
2. 经营：配方队列、人员、投入、目标、采购和销售；
3. 现场：工位、运输、具体人物、生产阶段和环境；
4. 审计：工单、库存事务、损耗原因、权限来源和计算解释。

专题视图包括生产、资源、物流、市场、建设、军需和知识视图，全部受主体认知约束。
玩家可设异常阈值，只有缺料、事故、灾害、破产、战争、违法或目标偏离超过阈值时打断。

## 25. 当前原型与正式方案差异

M17-P0实施前的原型曾存在：

- 固定`CropKind`枚举；
- 作物只保存为工单字段，尚无作物和地方品种定义；
- 家庭粮食以单一`long`余额为权威，商品市场另有`CommodityState`；
- 农业账本使用`SeedCommitted`、`GrainStored`等专用事件；
- 只有小麦、粮食和家庭粮仓链；
- 尚无通用产品批次、配方图、生产方法、品质维度和内容清单。

M17-P0已经完成固定作物枚举纠偏、小麦核心内容包和V8内容清单；家庭单一粮食余额、
农业专用兼容账和通用产品批次尚未完全迁移，继续作为下一阶段技术债。后续不能重新引入
固定作物枚举，也不能把当前首条小麦链描述为完整产业网络。

M18-P0进一步建立V9人物技能、知识、科研项目、技术掌握、设施级技术应用和科研账底座，
并把选种法、垄作播种、协同农作三张原创农业科技卡接入M17田地、配方、方法和工单技术
快照。当前只验证了农业第一条局部应用闭环；组织知识、传播失传、研究材料、风险与完整
职业突破仍未实现。

M19-P0进一步建立V10产品/种子批次、通用库存事务、加工工单和旧粮账转换适配器，打通
“10麦粒→8面粉＋2麸皮→8干粮”的首条守恒加工链，并提供按产品标签统计未预留市场可售量
的查询。当前农业收获仍写入旧粮食兼容余额，只有明确转换后的数量进入批次；运输、腐败、
拆分合并、市场成交、家庭消费与军需尚未全部迁移到批次合同，不能描述为完整产业网络。

M23-P0进一步把六种核心军械登记为产品定义，增加组织所有的移动库存容器，并完成第一条
“商号成品批次—采购发运—人物承运—军械库入库”链。发运会扣减产品批次，入库会增加
M11军械库存，两端由同一采购ID和双边资金账关联。当前成品军械是原型开局库存，尚无
冶铁、锻造、木作、制弓或制甲配方，因此不得把采购闭环描述为军械制造闭环。

M23-P1把加工工单扩展为家庭或组织二选一的通用合同，增加组织工坊、静态工坊仓、铁料、
木料、皮革和角料，以及六种质量守恒的军械制造配方。工坊由永久人物管理，订单真实预留
原料并按世界日结算，成品批次可由商队从静态仓装运。损坏军械使用独立维修订单，但耗材、
预留和结算继续写入同一产品批次账。M23-P1完成时四类原料仍只是可追溯的原型期初库存，
尚未连接矿山、冶炼、伐木、制革、燃料、废料、品质差异和工匠成长。

M23-P2增加V16资源体、采集工单和资源账，并在中山原型以真实组织人物打通铁矿石与木料
采集、木料—木炭/草木灰、矿石＋木炭—铁料/炉渣，再复用M23-P1工坊制造军械。资源体保存
来源、生成规则版本、地点、储量、预留、品位、难度和设施要求；采集批次可以继续被下游
消耗而不丢失初始产出证据。当前只存在人工编写的两个原型资源体，尚未实现确定性资源创世、
勘探、多矿脉、工作面、事故、林木再生、畜牧屠宰与制革，不能描述为完整林矿产业或军工网。

M23-P3增加V17畜牧材料切片。普通羊群不使用封闭牲畜枚举或逐只人物结构，而作为带稳定
产品ID、组织、地点、来源、数量和质量的活体批次保存；开局种羊、采得牧草和鞣料树皮均
通过库存事务入账。牧场繁育以1只种羊和10单位牧草形成2只羊，屠宰将每只羊守恒拆分为
肉、生皮、生角、骨和下水，随后生皮＋鞣料形成皮革与废料，生角形成角料与边角料。全链
复用通用组织工单的预留、耗时、质量传递和结算，产出的皮革与角料可继续制造木盾和角弓。
本切片没有实现逐只年龄、性别、血统、疾病、季节繁殖、草场退化、羊毛乳品或牲畜运输。

M23-P4增加V18多维品质与工匠实践切片。核心产品明确声明纯净、完整、均一、耐久、工艺、
健康、卫生、营养或活力等开放品质维度；加工方法通过稳定ID引用食物加工、金属、木作、
制弓、制甲、畜牧屠宰和鞣革等专门技能，并保存难度与逐维修正。工单创建时冻结管理者
开工技能，结算时由输入批次、设施状态、技能快照和方法修正产生输出维度；随后才按工期、
批量、难度、人物资质和递减收益增加专门技能并写实践流水。尚无专门技能的人物以既有
综合工艺作为首次基线，之后成长保存到开放式`SkillMasteries`。本切片尚未实现师承、秘诀、
多人分工、储运品质衰减、市场溢价、军械品质入库加权或战斗效果。

M23-P5增加V19军需货运责任与损耗切片。军粮必须来自带稳定产品ID、品质和来源的真实批次；
商业采购、内部调拨、补偿征购、无偿征发和劫掠共用一套库存与物流流水。买方、货源、承运
组织和损失承担方相互独立，商人可以独立承运，现役军人可以随目标军队行军自运。托运军粮
与承运队自用补给分别装载和消费，途中按照发运时快照的易腐参数产生确定性自然损耗，只按
剩余数量增加军队口粮。M23-P6继续增加V20持久运输分段：路线必须连续，下段口粮先进入
真实批次预留账，中转时承运人物和容器必须同地，完成保管交接和实际装载后才能开始下一段；
最终可以自动全收或按实分批收货。M23-P7增加V21真实押运人物和途中风险：押运者随分段
旅行，风险按稳定时间坐标结算；被截货物进入带威胁组织归属的永久事件并纳入货运守恒账。
M23-P8继续增加V22真实人物局部交战、伤病回写和有军权目标军队同路线单次追击夺回；夺回量

## 28. 设施岗位与建设蓝图补充合同

生产设施的正常运行必须读取由永久Person ID填充的真实岗位。岗位定义使用稳定数据ID保存职业、主要技能、
最低能力、地点、容量与权限；资格和适配度分开计算。没有达到最低工人数时设施仍存在并可维护、招募或停产，
但不能从汇总缓存获得正常产出。

跨Cell产业、市场、仓储、宫署和防御工程使用统一多Cell蓝图。蓝图放置只建立选址与施工阶段，不绕过土地
Owner、材料、工时、道路、技术、财政和权限。历史初始化、玩家自建与AI自建共享同一蓝图定义及验证规则。

## 30. V78 统一农业早收合同

正式 `AgricultureProductionSystem` 使用版本化
`mandate.agriculture.harvest-maturity.v1`，默认收割门槛为8,000 basis points。低于门槛不能正常收割；
8,000时可早收并取得满产的7,000 basis points，8,000至10,000成熟度之间线性恢复到满产，10,000
取得100%产量。成熟度、规则ID、门槛和实际产量快照随工单持久化，使 Save/Load 与重放不依赖后来
修改的全局常量。该规则属于统一农业，不是洛阳专用 `Harvest80Percent`，也不改变种子、劳动或其他
作物参数。
