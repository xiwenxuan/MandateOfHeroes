# M13-P0任务书：140年人口数据合同与验证器

## 一、任务定位

本任务执行
[`TASK_M13_HAN_140_POPULATION_AND_STABLE_GEOGRAPHY.md`](TASK_M13_HAN_140_POPULATION_AND_STABLE_GEOGRAPHY.md)
的P0阶段，为后续约105个郡国和约1180个县级单位的分批校录建立唯一的数据合同、
来源登记和离线验证入口。

P0只证明数据结构、来源边界和验证机制可用，不代表140年郡国人口已经校录完成，
也不改变当前V5存档或Unity运行时地点。

## 二、交付范围

本任务交付：

1. `Docs/HAN_140_POPULATION_DATA_DICTIONARY.md`；
2. `Data/HistoricalPopulation/`中的来源、行政、人口、稳定地理、映射和交叉表模板；
3. 固定全国史籍锚点9,698,630户、49,150,220口；
4. `Tools/Validate-Han140PopulationData.ps1`离线验证器；
5. `Tools/Test-Han140PopulationValidator.ps1`自动化验收脚本；
6. 确定性的`han_140_audit_report.json`。

## 三、明确不做

- 不录入全部郡国或县级人口；
- 不为缺失史料填入推定值；
- 不建立完整稳定地理树；
- 不完成6个运行时地点或77城交叉映射；
- 不生成永久人物；
- 不选择大人口存储技术；
- 不修改存档版本、场景、ScriptableObject或程序集。

## 四、数据合同

P0采用六个输入文件和一个派生审计文件：

```text
Data/HistoricalPopulation/
├─ han_140_sources.json
├─ han_140_administrative_units.csv
├─ han_140_population_records.csv
├─ stable_population_regions.csv
├─ han_140_region_mapping.csv
├─ game_location_crosswalk.csv
└─ han_140_audit_report.json
```

输入文件是事实来源；审计报告由验证器确定性生成，不得人工维护统计结果。

ID命名空间保持分离：

```text
source.*
admin.han140.*
geo.region.*
location.* / L### / C###
```

详细字段、空值、布尔值、列表分隔、年份和证据等级规则以
[`HAN_140_POPULATION_DATA_DICTIONARY.md`](HAN_140_POPULATION_DATA_DICTIONARY.md)
为准。

## 五、验证范围

验证器必须检查：

- 所有输入文件存在且为有效UTF-8；
- JSON结构和CSV表头与合同一致；
- 必需字段、ID格式和重复ID；
- 行政与稳定地理父级引用及父级循环；
- 治所、来源、行政、稳定地理和游戏地点交叉引用；
- 年份格式、范围和先后关系；
- 户数、口数和权重为非负整数；
- 原文缺失与数字0保持区别；
- 修正人口同时拥有修正码、说明和来源；
- 人口分配映射按来源严格合计10,000基点；
- 全国锚点保持9,698,630户、49,150,220口；
- 成功报告不含时间戳，确保相同输入得到相同输出。

验证失败时使用非零退出码，且不得为本次失败生成`validation_status=passed`报告。

## 六、自动化验收

测试脚本至少覆盖：

1. 正式P0模板验证成功；
2. 相同输入连续生成的审计报告字节一致；
3. 重复来源ID被拒绝；
4. 非法年份被拒绝；
5. 负人口被拒绝；
6. 缺失来源引用被拒绝；
7. 检入的审计报告与重新生成结果一致。

测试只在独立临时目录中制造错误样例，不修改正式输入。

## 七、完成条件

- 数据字典与六个输入文件字段完全一致；
- 来源登记区分公共领域古籍、项目原创整理和未知许可的现代材料；
- 空CSV模板能够通过结构验证，但审计报告明确显示当前记录数为0；
- 所有负向样例返回非零退出码；
- 重复运行得到相同审计文件；
- 验证器不访问网络、不启动Unity、不递归扫描任务目录之外的路径；
- 适用项目验证和`git diff --check`通过；
- 完成范围经过差异审阅后才能提交。
