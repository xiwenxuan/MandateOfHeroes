# M24-P5任务书：正式产品批次与库存事务桥接

## 一、阶段目标

在M24-P4已校准的100万人、50年具体家庭生产世界之上，把最终检查点中的紧凑家庭/县级
粮食与种子余额，无损投影为M19 V10合同兼容的产品批次和库存事务证据：

```text
紧凑家庭粮食/种子与县级官仓余额
→ 稳定所有者、产品、品种、容器、批次和事务身份
→ 源余额等量负向冲销
→ 产品批次数量等量增加
→ 逐批事务行审计与物理重载
```

本阶段同时在正式`ProductInventorySystem`增加“已完成农业工单→粮食/种子批次”的原子
转换入口。百万工具仍是独立压力原型，不把数十万批次塞入内联`WorldState`，也不升级V28
存档结构。

## 二、实施合同

1. 正式小世界只允许转换已完成、已结算且有实际入库量的农业工单。
2. 同一农业工单只能转换一次；失败在修改家庭余额、批次或事务前完成校验。
3. 粮食与留种按既有农业结算公式拆分，旧`Family.Grain/SeedGrain`等量减少，仓库物理占用
   不变，批次和事务保存农业工单来源。
4. 百万世界桥接以检查点替换语义工作：源紧凑余额的总负向变动必须等于新增批次数量，
   不允许紧凑余额与正式批次作为两份可消费库存并存。
5. 家庭旧余额对应`LegacyBalanceConverted`；县级公共库存对应`OpeningBalance`，同时由桥接
   扩展记录其被替换的紧凑源余额负向变动。
6. 产品、品种等开放内容使用生产内容包的稳定命名空间ID，经确定性64位投影写入紧凑文件；
   所有者、容器、批次和事务身份只由稳定世界坐标派生。
7. 当前抽象粮食账无法表达多个作物混合库存的逐批来源，因此本桥接档明确要求核心内容只有
   一条农业绑定；多作物接入前必须先保留交易、税粮、赈济后的产品来源，不能静默归为小麦。
8. 桥接报告只读取最终世界事实，不参与出生、死亡、生产、消费或校准随机公式；M24-P4的
   家庭生产、农业工单和年度反馈哈希必须保持不变。

## 三、工作包

### WP1：正式V10农业批次入口

- 增加完工农业单原子批次化接口；
- 保存工单来源、粮食/种子批次和单笔转换事务；
- 覆盖一次性、物理库存不变、余额冲销及世界校验测试。

### WP2：百万检查点桥接格式

- 新增数据驱动桥接配置；
- 输出`formal-inventory-batches.bin`和`formal-inventory-transactions.bin`；
- 文件头保存版本和记录数，每条记录为固定长度，支持顺序写入和批量重载；
- 校验稳定ID碰撞、文件长度、批次总量、事务行总量和源余额冲销。

### WP3：安全入口与回归证据

- 安全脚本新增`-FormalInventoryBridge`，自动继承P4已验收候选三参数；
- P5自测执行两次1万人10年并比较文件哈希；
- 运行100万人50年候选，保留峰值内存、耗时、文件大小和SHA-256；
- 验证M24-P4生产与反馈哈希未变化。

## 四、验收标准

1. 正式农业完工单转换后旧粮种余额减少量等于批次量，仓库物理量不变。
2. 同一正式农业工单重复转换被拒绝且不产生第二笔事务。
3. 百万检查点批次数量等于家庭与县级最终粮食、种子余额总和。
4. 桥接源余额总变动为批次数量的相反数；批次、事务和事务行一一审计。
5. 批次与事务稳定ID无碰撞；双跑文件SHA-256一致。
6. 100万人50年仍得到M24-P4已验收的人口、生产工单和年度反馈事实。
7. P0—P5兼容自测、全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅
   分别报告。

## 五、不包含

- 把百万批次直接写入当前内联V28 JSON快照；
- 多作物混合商品、逐次市场成交、税粮、赈济和损耗的来源批次拆分；
- 日常消费自动扣减正式产品批次；
- 腐败、保鲜环境、批次拆分合并UI；
- 1,000万或累计5,000万完整游戏负载。
