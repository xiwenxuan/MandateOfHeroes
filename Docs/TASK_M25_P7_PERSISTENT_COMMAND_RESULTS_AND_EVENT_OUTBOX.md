# M25-P7任务书：持久命令、执行结果与事件出站箱

## 一、任务定位

在M25-P0统一执行内核之上，把必须跨保存点继续存在的命令、事务批次结果和提交后事件升级为V33领域事实。保存发生在命令到期前，命令不能消失；保存发生在事务已经提交但事件尚未分发时，事件不能丢失或被当作未提交重新执行。

本阶段持久化命令信封、执行审计和事件出站箱，不序列化运行时处理器、委托或`IWorldTransaction`对象。事务对象仍由稳定命令类型和参数重新规划；只有已经确认的执行结果及其事务ID、类型和事件ID进入存档。

## 二、实现合同

### 2.1 持久命令

- 命令保存稳定命令ID、类型ID、签发者、创建时间、到期时间、优先级、有序参数和生命周期。
- 普通内容命令类型继续使用稳定命名空间ID，不使用固定枚举；只有待执行、完成、取消等封闭生命周期使用枚举。
- 到期顺序继续按日期、时段、优先级和稳定ID决定，保存/读取不得改变顺序。
- 成功命令保留为完成历史而不是从世界删除；失败批次保留待执行命令并累计尝试次数。
- 不扫描人物全表；调度只扫描持久待执行命令集合。

### 2.2 执行结果

- 每次非空到期批次形成唯一持久结果，记录命令ID、有序事务摘要、成功/拒绝结果、事件ID、时间与稳定失败代码。
- 批次验证、预约或处理器解析失败时，不应用业务事务、不产生事件、不完成命令，但保存失败尝试用于审计。
- 成功结果必须与命令完成状态、事务摘要和出站事件相互引用；重复推进不得再次执行已完成命令。
- 不把异常堆栈、系统时间、线程ID或本地化错误文字作为确定性世界事实。

### 2.3 持久事件出站箱

- 事务全部提交后，事件以稳定ID写入世界出站箱，再由运行时处理器按稳定处理器ID分发。
- 出站事件保存事件类型、来源事务、发生时间、分发状态和已确认处理器ID；保存/读取后继续未完成分发。
- 同一运行时重复分发已经完成的事件没有副作用；处理器成功返回后才写确认。
- 处理器抛错时事件保持待分发且不写确认。处理器必须以事件ID实现幂等，因为外部副作用无法由本地存档提供跨进程“恰好一次”保证。
- 事件用于报告、AI需求和后续命令，不得绕过事务直接制造人口、物资、财政或兵员。

## 三、工作包

### WP1：V33领域与迁移

- 新增持久命令、参数、批次结果、事务摘要和事件出站箱状态；
- 建立唯一性、引用、时间、生命周期、尝试次数和成功结果闭环校验；
- 完成V32到V33顺序迁移，只建立空集合，不伪造此前内存命令、结果或事件。

### WP2：运行时适配

- 将命令入队和到期处理改为读写`WorldState`持久集合；
- 成功提交后原子记录结果、完成命令并写入事件出站箱；
- 失败时记录稳定拒绝结果、保留命令且不发布事件；
- 将事件分发改为读取持久出站箱并保存处理器确认。

### WP3：保存恢复与回归

- 覆盖未来命令保存恢复、成功批次往返、提交后未分发事件恢复、重复分发幂等、失败尝试审计和相同输入确定性；
- 覆盖V32迁移为空集合以及非法引用/篡改拒绝；
- 同步总纲、确定性存档、世界模拟、NPC AI和Skill任务路由。

## 四、验收标准

1. 保存并载入后，未到期命令仍按原稳定顺序执行一次。
2. 成功命令保留完成历史，事务摘要、执行结果和事件出站箱引用闭合。
3. 验证或预约失败不改变业务事实、不完成命令、不发布事件，但留下确定性失败尝试。
4. 事务提交后保存、载入并更换运行时，未分发事件仍可继续分发。
5. 已确认事件重复分发不再次调用同一处理器；处理器失败不提前确认。
6. 相同世界、命令和处理器产生字节一致的快照。
7. V32安全迁移至V33且不伪造旧运行时事实，V33往返及非法账簿校验通过。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 序列化C#处理器、委托、事务对象或任意代码；
- 为全部既有生产、人口、战争系统自动生成命令和事件；
- 跨机器分布式事务、消息中间件或外部服务的恰好一次投递；
- 完整叙事日志、玩家知识传播、UI命令控制台和事件回放界面；
- 取消/改签权限、命令超时补偿和长事务断点续作。
