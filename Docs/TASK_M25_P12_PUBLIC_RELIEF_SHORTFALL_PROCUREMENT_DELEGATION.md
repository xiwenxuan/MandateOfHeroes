# M25-P12任务书：县仓赈济缺口、官府采购委任与真实市场履约

## 一、任务定位

在M25-P10家庭食品缺口事件、M25-P11公共粮食结算和M25-P4正式县级市场之上，把“县仓无法满足赈济需求”转成一张可保存、可审计、有权限、有预算和真实卖方库存来源的官府采购委任。

正式市场当前只支持家庭买方，本阶段不得把县政府伪装成管理员家庭。因此新增独立的公共赈济采购成交账，世界存档由V33顺序升级为V34；V33→V34只建立空成交集合，不伪造历史采购。家庭卖单、卖方预留和市场价格继续复用M25-P4合同，买方资金来自县政府组织金库，货物直接进入该县县仓。

## 二、实现合同

### 2.1 缺口事实与事件触发

- M25-P11县仓赈济必须同时记录请求量、实际发放量和未满足量；未满足量写入县财政审计账，不因库存为零而消失。
- 只有实际未满足量大于零时才发布同县同月唯一`county_relief_shortfall_detected`事件。
- 事件处理器不直接买粮，只为次日建立一张稳定公共采购命令；重复分发不得制造第二份委任。
- 委任只遍历来源事件、县治理、活动家庭卖单和对应预留批次，不扫描永久人物或家庭全表。

### 2.2 权限与预算

- 采购命令绑定来源缺口事件、县治理、最大采购量、最大预算和最高单价。
- 执行时必须存在真实县政府组织、存活组织领袖和正确县仓；组织领袖作为采购执行人写入库存流水。
- 实际支出不得超过命令预算、组织实时金库、最高单价或卖单剩余量；失败和不足不得形成负财政。
- 采购采用首批稳定默认政策上限，后续可以数据驱动替换，但不得在读档时重新解释已保存命令参数。

### 2.3 真实市场与库存履约

- 货源只来自本县仍有效的正式家庭卖单及其真实预留食品批次，不读取旧市场挂牌库存。
- 候选按单价、创建日、产品ID和稳定订单ID排序；只购买价格不超过委任上限的食品。
- 商品从卖方家庭粮仓守恒拆批进入县仓，保留产品、品种、品质、鲜度、产地、产日和工单来源。
- 县政府金库支付卖方家庭；卖单剩余量、预留量、成交量和成交额同步减少/增加，不能重复出售。
- 公共采购进入正式市场价格累计账，但使用独立`PublicReliefProcurementTradeState`记录政府买方、来源事件、命令、卖单、库存事务、数量和金额。
- 未采购部分写稳定县财政异常账，世界继续推进；本阶段不凭空补齐，也不自动跨县寻找未知货源。

### 2.4 持久命令、结果和调度

- 复用M25-P7持久命令、批结果和事件出站箱；命令由缺口事件触发，次日`DailyCommand`执行。
- 事务预检V34正式库存权威、来源事件、日期、县政府权限、命令上限、县仓和同事件共享预约。
- 日期漂移、权限失效、来源事件错误或县仓引用失效时，在库存、现金、订单、价格和财政业务写入前拒绝。
- 成功评估发布`public_relief_procurement.resolved`事件；即使本地没有可买粮，仍保存未履约账而不反复执行同一委任。

## 三、工作包

### WP1：V34领域与迁移

- 新增公共赈济采购成交状态、正式采购库存事务类型和县财政缺口/采购/未履约类型。
- 扩展订单预留、成交累计、价格、财政、库存来源及政府县仓不变量。
- 完成V33→V34空集合迁移、当前版本往返与非法账篡改拒绝。

### WP2：M25-P11缺口证据

- 扩展县仓赈济结算摘要，保存请求、实发和未满足量。
- 只在真实县仓不足时发布稳定短缺事件。
- 保留既有公共粮食已结算事件和直接兼容路径。

### WP3：事件驱动采购命令

- 新增缺口事件消费者、次日持久采购命令、处理器和显式事务。
- 实现权限、预算、最高单价、真实卖单、县仓容量和共享预约预检。
- 实现稳定本县采购、卖单/预留结算、政府付款、县仓入库、价格回写和未履约审计。

### WP4：世界接线、测试与文档

- 在`WorldSimulator`注册短缺事件消费者、采购命令处理器和采购结果投影处理器。
- 覆盖读档后只采购一次、日期/权限失败零业务修改、无卖方时保留未履约、正式模拟器事件链、确定性和V33迁移。
- 同步总纲、世界模拟、确定性存档、M12、M25-P4/P7/P10/P11兼容说明和Skill任务路由。

## 四、验收标准

1. 县仓实发少于请求时保存准确缺口并发布唯一短缺事件；足额赈济不产生采购委任。
2. 同一短缺事件最多产生一张采购命令，保存/读取后只执行一次。
3. 采购执行人具有当前县政府权限，支出不超过保存预算、最高单价和组织真实金库。
4. 货源来自本县活动卖单及预留批次，县仓入库、卖方收入、订单结算、采购账和市场价格闭合。
5. 没有卖方、预算不足或县仓容量不足时不伪造粮食，未履约量有审计且世界继续推进。
6. 日期、权限、来源事件或引用漂移在应用前拒绝，库存、现金、订单、价格和财政业务账零修改。
7. V33迁移到V34只建立空采购成交集合；V34往返、非法状态拒绝和相同事实确定性通过。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 跨县赈济采购、未知货源发现、商人承运、多段运输、途中损耗和目的县收货。
- 完整赈济审批树、太守界面、玩家手工改签、豪族捐粮、信用贷款、强征、劫掠或价格管制。
- 自动创建卖单、扫描全体家庭库存、全天下未载入人物月结或关注层级改变业务事实。
- 仓储腐败、鼠害、霉变、倒卖、舞弊、问责和通用事务回滚。
- 提交、推送、创建PR或清理工作区既有修改。
