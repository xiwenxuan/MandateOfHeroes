# M25-P9任务书：民用货运规划持久命令、事务与提交后事件

## 一、任务定位

在M25-P5/P6的跨县民用货运事实与M25-P7统一执行内核之上，把“需求生成、承运报价选择、发运触发”迁移到V33持久命令—显式事务—提交后事件管线。

本阶段不重写既有货运业务规则，不增加存档字段，也不升级V33。`CivilianFreightSystem.ProcessDailyPlanning`继续作为兼容领域入口，但正式`WorldSimulator`日界不得直接调用它。

## 二、实现合同

### 2.1 有界每日工作发现

- 只检查活动正式市场订单、活动货运需求、承运登记和报价账，不扫描永久人物全表；
- 存在活动货运需求时，需要重新检查失效、报价或发运，因此视为当日工作；
- 不存在活动需求时，只有发现尚未被活动需求占用的跨县、同商品、价格和质量可相交买卖单，才视为当日工作；
- 单独存在承运登记不产生空命令；无工作日不得写入命令、结果或事件；
- 每个世界日最多建立一个稳定命令，重复调度不得制造副本。

### 2.2 持久命令与事务

- 命令保存期望日、最大新需求数64、最大新报价数256、最大发运数32；
- 命令处理器只解析稳定参数并规划一项`IWorldTransaction`，规划期不得写世界；
- 事务预检要求正式商品批次权威、期望日等于当前世界日，并以共享预约键限制同日只提交一次规划；
- 应用阶段复用M25-P6的失效需求关闭、需求生成、报价生成和稳定最低报价发运；
- 日期漂移或权限失效时，业务账零修改，由M25-P7记录拒绝结果，命令保留待审计。

### 2.3 提交后事件

- 成功事务发布唯一稳定`civilian_freight.planning_resolved`事件；
- 事件写入V33出站箱，并由正式无业务写入的投影处理器确认；
- 事件只说明规划事务已经提交，不得二次修改订单、库存、现金、需求、报价或货运。

### 2.4 世界调度接线

- 保持原有`DailyTransit`阶段、顺序5的调度位置；
- 调度器先确保当日命令，再由统一运行时处理到期命令；
- 发运仍发生在日常在途损耗和移动补给之前；
- 在途损耗、分段移动、到货卸载和运费释放继续使用现有路径。

## 三、工作包

### WP1：货运规划事务适配器

- 增加有界工作检测、正式权威与期望日预检；
- 增加稳定每日命令调度器、处理器和显式事务；
- 增加稳定提交后事件与无业务写入投影处理器。

### WP2：正式世界接线

- `WorldSimulator`注册货运规划命令与事件处理器；
- 替换日界直接规划写入为“确保命令—处理到期命令”；
- 保持现有阶段顺序、兼容入口与其他系统不变。

### WP3：验证与文档同步

- 覆盖持久命令读档后只执行一次、日期漂移零业务修改、无工作不建命令、正式模拟器接线与同种子确定性；
- 保留M25-P6既有直接入口回归；
- 同步总纲、世界模拟、确定性存档、NPC AI边界和Skill任务路由。

## 四、验收标准

1. 正式日界不再直接调用民用货运规划写入。
2. 有工作日最多一张规划命令和一项规划事务，重复推进不重复发运。
3. 需求、报价、订单、库存、现金、路线和货运继续满足M25-P5/P6不变量。
4. 日期漂移在应用前拒绝，货运业务账零修改且保留稳定拒绝证据。
5. 成功事件可跨存档恢复后确认，事件处理器不制造第二次业务写入。
6. 无活动需求且无跨县可成交订单时不产生空命令。
7. 工作发现不扫描永久人物全表；相同世界产生相同命令、事务、事件与快照。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 在途自然损耗、路径逐段移动、到货结算或运费释放事务化；
- 自动生成所有家庭的买卖单，或扫描永久人物全表寻找承运人；
- 承运登记、信用、保险、税费、劫掠或军用物流改造；
- UI、通知、玩家知识传播和完整NPC经营策略；
- 新存档字段、V34迁移或全系统通用回滚。
