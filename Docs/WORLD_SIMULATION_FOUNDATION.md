## 2. 核心愿景

游戏世界不依靠“城市等级自动产生粮食”“占领城市自动获得全部税收”或“战争结束后人口自动恢复”等抽象结果运行。

世界中的资源变化应当能够追溯：

```text
谁拥有土地
谁建立设施
谁提供资金
谁在那里工作
使用了什么原料
生产了什么商品
商品存放在哪里
由谁运输和购买
谁征收了税款
哪支军队消耗或抢走了物资
哪些人在战争、疾病或灾害中死亡
```

核心原则是：

> 每个人从出生起都拥有永久、唯一、可追溯的身份；只有需要独立关系、财产、
> 记忆、任务或关键决策的人，才持续运行较完整的AI。模拟精度可以升降，
> 人物存在本身不能降级、合并或因玩家未关注而消失。

## 3. 不可违反的系统原则

### 3.1 人口守恒

```text
期末人口
= 期初人口
+ 出生
+ 迁入
- 死亡
- 迁出
- 永久失踪
```

民间人口、在役军人、伤员、俘虏、流民和已实例化人物必须属于同一本人口总账，不能重复计算。

### 3.2 物资守恒

```text
期末库存
= 期初库存
+ 生产
+ 输入
- 消费
- 输出
- 损耗
- 抢夺
- 焚毁
```

军队抢到的粮食必须从农庄、市场或官仓的真实库存转移，不能凭空增加。

### 3.3 兵员守恒

```text
军队期末人数
= 期初人数
+ 征召和补充
+ 伤愈归队
- 阵亡
- 被俘
- 逃亡
- 退伍
- 永久失踪
```

征兵时人口已经从民间转入军队，阵亡时只能从军队扣除，不能再次从原籍民间人口重复扣除。

### 3.4 财政守恒

个人财产、家族财产、设施账本、地方政府财政和势力国库必须分开。

任何财政收入都应来自税收、产业、贸易、贡赋、罚没、借贷、战利品或其他明确来源；任何支出都进入另一主体账户或形成真实消耗。

### 3.5 视角一致

战略地图上的农庄、县镇、港口和坞堡，与玩家进入详细场景后看到的对象必须是同一个世界实体。

战术地图烧毁的仓库，返回战略地图后仍然损毁；战术地图死亡的人物，返回世界模拟后不能复活为原有统计人口。

### 3.6 观察不能创造世界

玩家点击一个家庭或设施，只能展开已有永久人物的详细资料，不能额外创造人口、财产、库存或关系。

重复进入同一地点不能重新随机获得不同家庭或商品。

### 3.7 创世与运行分界

世界只在创世阶段初始化一次：

```text
基础地理与历史行政锚点
→ 城镇、道路、河流和交通节点
→ 人口、家户、土地和自然资源
→ 产业、设施、库存、财政和组织
→ 人物关系、职位和知识
→ 各人物与组织的初始认知
→ 世界时间开始运行
```

创世完成后，出生、死亡、迁徙、建设、生产、交易、灾害和战争只能在既有世界账上
产生变化。缩放、观察、加载场景和切换玩家人物不能成为第二条创世入口。历史事件也
必须读取当前世界条件，不能为了恢复既定剧情重置已经改变的地点、人物或设施。

## 4. 多层地图结构

### 4.1 天下战略地图

主要显示：

- 州郡、势力与法理归属；
- 城市圈和主要据点；
- 大型道路、河流、关隘和港口；
- 军团、补给线和大规模人口迁徙；
- 战争、商业、财政和灾害态势。

### 4.2 州郡与郡县地图

主要显示：

- 郡治、县城、乡镇和地方据点；
- 农业区、林区、矿区、牧区和水域；
- 主要庄园、市场、仓库和工坊区；
- 渡口、驿站、道路、河港和运输容量；
- 地方官府、豪族、军队和宗教组织控制。

这是建设、经营、行军、剿匪和地方治理的主要地图。

### 4.3 城市、县镇和乡村地图

显示具体功能区和设施：

- 官署、民居、市场、客栈；
- 仓库、工坊、医馆、学塾；
- 农庄、牧场、林场和矿场；
- 港口、船坞、车马行和驿站；
- 军营、城门、坞堡和寺观。

### 4.4 具体场所地图

玩家进入家庭、店铺、工坊、客栈、军营或坞堡后，加载已有实体的详细资料和表现对象：

- 家庭成员；
- 所有者和管理者；
- 雇工与学徒；
- 当前客人；
- 当前在场的具体士兵和平民；
- 具体库存、订单、矛盾和任务。

### 4.5 战场地图

野战、攻城、乡镇攻防、坞堡防御和设施争夺使用详细战场，但战果统一回写世界账本。

### 4.6 连续比例尺与语义缩放

地图层级只改变显示精度、图标密度和可用操作，不改变对象是否存在：

- 天下视图显示重大城镇、关港、军团和区域网络；
- 州郡视图显示县乡、路线、主要设施和区域项目；
- 地方视图显示土地、功能区和具体设施；
- 场所视图显示建筑布局、工位、库存与在场人物。

低比例尺可以隐藏对象或把多个子设施聚合为区域网络；放大后必须展开原有稳定ID，
不能重新抽取另一套位置和状态。技术上允许分区加载、不同场景和不同细节层级，逻辑上
仍是一张共享稳定坐标、地理锚点、土地单元和路线网络的世界地图。

### 4.7 主体认知与专题视图

世界事实、人物所知、人物所信和组织档案相互分离。玩家当前能够使用的信息来自：

```text
当前人物的观察与记忆
+ 合法持有的实物文档
+ 家族共享档案
+ 当前职位授权的组织档案
+ 同行者、信使、斥候、商旅和密探报告
```

综合地理、个人、建设、资源、生产、商业、交通、民生、治理、战争、情报和势力视图
只是对主体认知账本的不同筛选器。任何视图都不能绕过来源、授权、观察时间、可信度和
过时程度读取世界真相。大型公开城镇可以是常识，具体库存、矿脉、秘密营寨、驻军和
布防仍需查阅、勘察或侦察。

一条观察记录至少包含：

```text
观察主体或持有组织
目标实体与事实类型
观察值、估计范围或传闻
来源与取得时间
可信度、精度和保密级别
访问权限与过时规则
```

### 4.8 信息资产、复制与传播

个人记忆、实物文档、家族档案和组织档案是不同对象。任职只授予组织资料的访问权；
离任后不再自动获得更新。人物可以在权限允许或承担秘密行动风险的前提下抄录资料，
但复制必须形成真实工作：

```text
选择文字、账表或地图范围
→ 准备简牍、纸、缣帛、笔墨等载体和工具
→ 指派具体抄写与校对人物
→ 消耗世界时间
→ 形成有完整度、误差和来源的新副本
→ 运输、保存、阅读或纳入家族档案
```

副本不会与原档案自动同步。个人阅读和理解还受识字、专业、记忆、语言与内容难度影响；
文档可以被窃取、伪造、损坏、查扣、出售、继承或销毁。后台可以批量结算抄录工单，
但必须保留实际行动者、材料、时间、地点和结果。

抄录工作量至少由文字数量、账表单元、地图面积与符号复杂度组成：

```text
抄录时间
= 内容工作量 ÷ 抄写速度
× 载体与字迹难度
× 校对和保密要求
× 疲劳、照明和工作环境
```

具体字数、简牍或纸张容量、书吏速度和校对误差必须在后续内容数据任务中按史料与玩法
分别校准，不能用“复制完成”按钮绕过工作量。

## 5. 城市圈

一个城市不是孤立节点，而是一个城市圈的行政、市场和军事中心。

```text
城市圈
├─ 中心城市或郡治
├─ 所属县城
├─ 乡镇
├─ 村落和庄园
├─ 农业与牧业分区
├─ 林场、矿山和药材产区
├─ 河流、湖泊、渡口和港口
├─ 道路、驿站和商路
└─ 军营、关隘和坞堡
```

中心城市主要承担行政、市场、仓储、高级加工、教育、城防和商品集散。

乡镇与农村主要承担土地生产、资源采集、初级加工和地方人口生活。

史料中的郡国人口不能直接视为中心城市人口。必须按照行政边界、可耕土地、水源、历史县治、道路、市场和聚落容量分配到所属县镇与乡村。

## 6. 全地图可建设土地

所有土地原则上可以被开发，但不同土地具有不同用途、成本和风险。

每个土地单元记录：

```text
地形与坡度
海拔
气候与降水
水源
土壤肥力
林木储量
草场容量
关联资源体ID
适航条件
洪水、干旱和火灾风险
道路和市场距离
行政归属
土地所有权
当前利用方式
```

设施适宜度由地理、资源、历史传统、人口技能、交通、市场和政策共同决定。

```text
设施适宜度
= 地理条件
+ 资源条件
+ 历史传统
+ 技能人口
+ 交通条件
+ 市场需求
+ 政策支持
```

适宜度影响：

- 建设成本；
- 最大规模；
- 单位产量；
- 维护费用；
- 灾害概率；
- 所需技术和公共工程。

历史和地理决定潜力，不锁死未来。玩家可以通过治水、修路、移民、技术和投资改变地区发展，但不能无成本违背自然条件。

### 6.1 可配置资源创世

资源创世把“采用何种证据”和“世界资源有多丰富”分成独立参数：

- 档案考据：只采用明确史料、考古和可靠历史地理锚点；
- 历史重建：在史料锚点外加入地质、生态和区域产业支持的合理推定；
- 贫瘠或丰富变体：保留历史锚点，调整资源点密度、储量、品位、开发难度、
  土地潜力和可再生速度；
- 自定义：分别设置矿产、林业、草场、水产、药材、土地和稀有资源参数。

资源来源至少标记为史料明确、历史推定、地质生态生成或沙盒补充。增加资源仍受地质、
地形、气候和水文约束，不能为了平均分配让每个县拥有相同资源。创世界面可以告知规则，
不能因此把具体资源位置写入角色认知。

相同内容版本、创世规则、随机算法版本和世界种子必须生成相同的初始资源事实。

### 6.2 资源层级与多矿脉

自然资源不得只压成一个永久不变的地区加成。例如山地矿产使用以下层级：

```text
山系
→ 山地单元
→ 矿区
→ 矿床
→ 多条矿脉或矿体
→ 矿井、采掘点和工作面
```

同一座山可以拥有不同矿种、品位、储量、深度、岩层、地下水、伴生矿和开采风险的
多条矿脉。勘察只提高对既有矿体的位置、规模和可信度认识，不能临时生成资源；开采、
枯竭、坍塌、淹水和新工作面必须改变对应实体及其账本。

实际采矿至少受有效劳动、人员技能、工具、可用工作面、岩层难度、运输、排水、支护、
安全和管理影响。矿石还需经过搬运、选矿、冶炼和加工，发现矿脉不等于直接获得金属。

```text
实际矿石产量
= 有效劳动时间
× 人员技能与工具效率
× 可用工作面和矿石品位
× 排水、支护、通风与管理效率
× 运输能力
```

结果受已经暴露的可采储量和工作面容量硬限制，并同时产生废石、工具损耗、事故风险和
矿脉消耗记录。

## 7. 建筑位与空间容量

### 7.1 战略建筑位

数量较少，在地图上明确存在：

- 官署；
- 城门和城墙；
- 大型市场与仓库；
- 港口和船坞；
- 军营和军械库；
- 官营作坊；
- 大型寺观；
- 豪族庄园与坞堡。

### 7.2 产业地块

代表成片生产区域：

- 农田；
- 牧场；
- 林场；
- 矿区；
- 药田；
- 渔场；
- 工坊区。

一个产业地块可以代表几十至数百户人口，不要求一户一格。

### 7.3 居住容量

普通民居使用容量而不是逐栋建筑：

```text
民居区
├─ 可容纳500户
├─ 当前430户
├─ 当前人口2,160
├─ 拥挤度
├─ 卫生
└─ 火灾风险
```

历史人口上限用于校准整个城市圈的承载规模，而不是要求生成对应数量的可见房屋。

### 7.4 设施空间尺度与区域网络

设施按其独立所有权、建设、运营和损坏事实分为单体设施、聚落设施、战略设施与区域网络。
所谓州级或郡级设施通常表示出资、管辖和影响尺度，不表示一栋没有具体位置的建筑。
驿站网、烽火线、水利体系、粮仓体系和边防线采用母项目与真实子设施：

```text
区域建设项目
├─ 具体道路、桥梁或水渠
├─ 具体仓库、驿站或烽燧
├─ 具体关卡、营寨或港口
└─ 负责人、预算、施工与维护账
```

关卡、渡口堡垒等战略设施必须锚定山口、河渡、道路交汇、城门或其他真实地理要点，
其控制效果作用于实际路线、视野、通行和补给，而不是给予整个州郡无条件加成。

## 8. 城市圈资源与产业档案

每个城市圈建立资料驱动的生产档案：

```text
历史行政范围
史料年份
中心城市与所属县镇
总人口和人口结构
地形单元
可耕土地

历史产业标签

```

资料分级：

- A级：明确史料或考古证据；
- B级：依据地理、区域产业和周边资料合理推断；

《九州》系列主要参考地方商品差异、跑商、商队、仓库、投资和供需玩法；不复制其城市商品表、价格、数值、UI、任务文本和素材。

历史资料和地理资料决定产业基础，市场和人物行为决定最终产量。

```text
迁徙倾向

```

家户、设施、村庄和组织可以批量作出日常决策，但结果必须落实到具体成员。

### 9.2 历史留名人物

- 家主和庄主；

### 9.3 三国重要人物

该层目标规模为数千名，拥有完整性格、能力、志向、认知、主动行动和重要关系，包括：

- 玩家和家族成员；
- 历史人物；

### 9.4 玩家关注人物

表现精度，不决定人物是否存在。

## 10. 人物资料展开与分区加载

未被玩家详细观察的人物仍以永久基础档案存在。家庭和设施可以使用汇总缓存加速结算，
但缓存不得代替或删除其具体成员。

玩家进入时，从永久档案加载详细资料：

```text
进入前：500名永久人物的基础档案
展开：一家五口的详细资料和关系视图
进入后：人口仍为同一批500名永久人物
```

人物生成使用稳定组合：

```text
世界种子
+ 地点ID
+ 家户ID
+ 出生序号
```

离开后可以释放详细视图和表现对象、降低结算频率，但不得删除、合并或重随机人物。
出生、死亡、财产、健康、职业和家庭变化必须写回永久档案及其汇总缓存。

M24-P0已用M13的105项140年郡国人口来源和1182县目录建立独立人口世界层，并让
1,000,000名具体永久人物连续自然演化50年。长跑结束时在世1,463,934人、累计永久人物
2,756,134人，死亡人物仍保留在永久核心。该结果验证家庭形成、婚育、死亡、事件调度与
永久档案增长，不代表生产、消费、战争、疾病、迁徙或完整NPC AI已经达到百万人规模。

M24-P1继续在该百万世界中加入家户成员年龄口粮、县级固定可耕地、具体农业劳力、收获、
田间与仓储损耗、地方冲突征夺和家户消费；粮食满足度会降低后续生育，并把饥荒、疾病和
地方冲突死亡落实到具体永久人物。50年长跑的土地与粮食账守恒，但县内仍采用批量配给，
尚未建立家户自有产品批次、市场价格、官仓救济和跨县运输。

## 11. 设施与生产

设施不是图标，而是有所有权、人员、库存和账本的生产组织。
作物、地方品种、产品、配方、生产方法、职业成长和分层生产委任的详细数据合同见
[`PRODUCTION_AGRICULTURE_INDUSTRY_AND_PROGRESSION_DESIGN.md`](PRODUCTION_AGRICULTURE_INDUSTRY_AND_PROGRESSION_DESIGN.md)。

```text
设施
├─ 所有者
├─ 所在土地
├─ 管理者
├─ 建筑等级和完好度
├─ 最大岗位
├─ 实际雇员
├─ 生产配方
├─ 原料库存
├─ 产品库存
├─ 资金账户
├─ 技术水平
├─ 当前订单
└─ 维护成本
```

实际产出：

```text
实际产出
= 基础产能
× 人员满足率
× 技能效率
× 原料满足率
× 地理适宜度
× 设施完好度
× 治安效率
× 健康效率
× 季节和天气
```

城市粮食、布帛、兵器和船只产量等于所属设施真实产出的汇总，不由城市等级直接产生。

设施可以在地方和场所视图展开建筑布局、工位、运输区、仓储区与安全设施；远方结算时
可以使用工单和设施缓存，但不得改变设施身份、人员来源、库存、进度和损坏事实。亲自劳动、
实时派工、工单、目标指令和组织委任统一进入同一结算链，详见
`GAME_SYSTEMS_MASTER_AND_STATUS.md` 第4.1节。

```text

→ 商人收购
→ 商队或船队运输
→ 短缺地出售
→ 居民、设施、军队和政府消费
```

价格取决于：

- 当前库存；
- 当地人口消费；
- 生产成本；
- 军队与建设需求；
- 战争和灾害；
- 道路安全；
- 运输容量；
- 税收和关卡；

## 14. 世界主体的自发建设

世界建设不只依靠玩家点击。

### 农户

根据粮价、种子、工具、地租、税收、灾害和其他职业收入决定开垦、改种、购买耕牛或弃田。

### 工匠

根据订单、售价、原料、工资、贷款和技术决定扩建、招徒、转产或关闭。

### 商人

根据价差、商路、仓储、税收、匪患和资金成本决定投资和运输。

### 豪族

根据家族资产、粮食自给、政治影响、部曲供养和地方安全决定兼并土地、建设庄园、工坊、学塾或坞堡。

### 官府

根据财政、治安、粮食安全、战争、灾害和政绩建设水利、道路、官仓、城防、港口与官营作坊。

建设必须具备土地权利、资金、劳动力、原料、实际需求、运输和政策许可。设施也会停产、破产、废弃、转让、没收或被战争摧毁。

### 14.1 NPC选址与建设委任

NPC不得随机挑选一个无条件地点，也不能读取其角色或组织未知的资源。自主建设流程为：

```text
发现生计、利润、治理或军事需求
→ 在已有认知中生成候选区域
→ 查阅档案、雇佣向导或组织勘察
→ 评估土地权利、地理、资源、交通、市场、补给、风险和政策
→ 申请或行使权限
→ 筹集资金、材料、劳力和运输
→ 建设、验收、运营和维护
```

选址结果受负责人能力、性格、忠诚、利益、地方经验和情报质量影响。当地人物可能比远方
上级掌握更准确的地理信息；贪腐、偏私、误判和虚假报告可以形成真实后果。

上级可以只指定目标、走廊、预算、期限、权限和红线，由都督、太守、县令、管事、工头
逐级拆解为具体地块、子设施和人物工单。玩家可以在任意有权层级审查候选地、接管施工或
交还委任，已发生的成本、时间和进度不能重置。

## 15. 城市发展

城市不使用单一发展值直接产生资源。

分别记录：

- 农业；
- 工业；
- 商业；
- 行政；
- 军事；
- 交通；
- 民生和医疗；
- 文化和教育。

综合繁荣度只用于界面阅读，是人口、设施、产业、交通、治安和政策的汇总结果，不是产出的来源。

## 16. 身份、数量与税收

数量决定税基，身份决定税种、义务和减免，收入来源决定具体征收方式。

### 人口群体

普通农户、佃农、商贩、工匠、船工和军户按群体结算。

### 家户、设施和组织

玩家家族、豪族庄园、商铺、商队、农庄、牧场、工坊、船坞、寺观和商会单独记账。

### 重要人物

对俸禄、赏赐、产业分红、土地租金、贸易利润、利息和战利品单独结算。

身份财政示例：

| 身份 | 主要税基 | 主要义务 |
| --- | --- | --- |
| 自耕农 | 土地、收成、家户 | 田赋、户赋、徭役 |
| 佃农 | 收成、工资 | 地租、部分户赋、徭役 |
| 商人 | 交易、利润、货物 | 商税、关税、许可费 |
| 工匠 | 作坊销售和利润 | 作坊税、产品或官府订单 |
| 军户 | 军田和家庭 | 服役替代部分税役 |
| 豪族 | 土地、佃户和产业 | 法定税负、包税、军粮或部曲义务 |
| 宗教组织 | 寺产、捐赠和产业 | 减免或特别贡赋 |

多身份人物分别按照不同收入来源结算，不能选择一个最低税率覆盖全部资产。

## 17. 三级财政

```text
县城或城市财政
→ 州郡或地区财政
→ 中央政府或玩家势力财政
```

基层负责实际征收，按留成和上缴比例分配，不能对同一税基重复征收三次完整税率。

税收形式包括：

- 钱币；
- 粮食、布帛、马匹、木材和药材等实物；
- 徭役；
- 兵役；
- 战时军需征发。

实际税收：

```text
实际税收
= 理论税基
× 法定税率
× 户籍覆盖率
× 行政效率
× 实际控制力
× 纳税意愿
- 减免
- 隐瞒
- 贪污
- 截留
- 运输损耗
```

每个地点区分：

- 法理归属；
- 行政管理；
- 军事控制；
- 税收控制。

占领城市不等于立即获得全部财政，必须控制官府、豪族、户籍、仓库、税吏和运输。

## 18. 人物追随、投靠与起义

关系值只是私人信任的一部分。

人物是否追随需要比较追随、留任、投靠他人或自立的预期结果。

主要因素：

- 私人信任；
- 家世与政治合法性；
- 分类名声；
- 人品和道德；
- 志向与价值观；
- 相性；
- 能力与治理成绩；
- 财富和供养能力；
- 军力和未来胜算；
- 可提供的职位；
- 家族、宗族、朋友和同僚态度；
- 当前忠诚；
- 背叛成本；
- 失败后的个人与家族风险；
- 人物对信息的认知可信度。

相性拆为价值观向量，而不是单一循环数字：

- 名分与实力；
- 仁德与刑法；
- 家族与个人；
- 保守与求变；
- 地方与天下；
- 虔诚与世俗；
- 冒险与谨慎。

追随具有多级承诺：

```text
有好感
→ 同情
→ 暗中帮助
→ 公开合作
→ 成为门客或属官
→ 带家族、部曲和资产投靠
→ 成为核心集团
→ 共同起兵并承担灭族风险
```

## 19. 征兵与兵员聚合缓存

大规模军队不生成同等数量的完整AI。

征兵时从永久人物和家户中建立服役关系。下列数字只是在同一本人物账上的聚合结果：

```text
民间人口－征兵人数
在役人口＋征兵人数
```

军团结算可以建立兵员聚合缓存，但缓存必须能够解析回具体服役人物。每个缓存记录：

```text
成员ID索引或稳定分区引用
原籍郡县乡镇
来源身份和职业
人数
年龄结构
兵种
训练
装备
士气
家庭依赖程度
征召日期
所属部队
```

一个缓存可以聚合约100至1,000名永久服役人物。二十万军队可由数百个聚合缓存、
数十个部队和分级人物AI构成，但任何人的服役、家庭和生死事实仍由其永久人物档案保存。

## 20. 战争伤亡分配

总伤亡按以下层级分配：

```text
总伤亡
→ 军团
→ 部队
→ 阵列和兵种
→ 兵员聚合缓存
→ 缓存引用的永久服役人物
```

权重考虑：

- 参战人数；
- 接敌时间；
- 战场位置；
- 兵种暴露度；
- 装备和训练；
- 士气；
- 是否被包围；
- 撤退路线；
- 将领指挥。

分配必须使用整数守恒方法，保证所有缓存伤亡之和严格等于战斗总伤亡，并将结果
确定性落实到具体人物。

战损分为：

- 阵亡；
- 重伤；
- 轻伤；
- 被俘；
- 失踪；
- 逃亡；
- 溃散待归队。

重要人物可以使用更细的风险判定，但仍属于聚合伤亡预算，不能额外叠加。

## 21. 伤亡对原籍的影响

服役关系和兵员聚合缓存保留原籍、家庭和原职业，使伤亡能够回写：

- 遗属和孤儿；
- 主要劳动力家庭；
- 农业和工坊岗位缺口；
- 抚恤债权；
- 地方民怨；
- 未来征兵能力；
- 返乡伤兵和残疾人口。

生产下降不按“死亡比例”直接硬减，而是根据损失的具体职业、家庭补位、流民雇佣、工具牲畜和土地撂荒重新计算。

## 22. 军队的地方行动

军队进入乡镇后可以：

- 通过；
- 驻扎；
- 有偿征购；
- 强制征粮；
- 搜捕敌人；
- 占领官署；
- 攻击坞堡；
- 抢掠农庄；
- 焚毁仓库；
- 破坏水利；
- 强征民夫和工匠；
- 保护产业和居民。

统治者可以制定军纪政策，但实际执行还受将领忠诚、军队纪律、补给、军饷、敌意和督战能力影响。

## 23. 农庄、乡镇与坞堡防御

地方生产单位拥有真实防御：

```text
围墙和木栅
壕沟
箭楼
大门
警戒
常备私兵
临时乡勇
武器库存
粮食和水
避难容量
可坚持时间
```

私兵和乡勇来自真实地方人口，动员会减少生产劳动力；伤亡会永久减少原籍人口。

小型坞堡可以击退侦察队、劫掠队、溃军和缺少攻城能力的小部队。面对正规大军时，主要作用是拖延、保护人口、造成损失和等待援军，不应无条件阻挡主力军团。

攻击、征粮和破坏都需要时间。军队停留越久，补给消耗、疫病和遭遇援军的风险越高。

- 粮食、牲畜、工具和商品被抢；
- 土地弃耕；
- 火灾、尸体和疫病风险；
- 地方仇恨与势力声誉。

农庄被攻破不等于所有居民必然死亡。人口应分为死亡、逃亡、被俘和幸存，除非确实发生屠杀或无法逃生的灾难。

## 25. 后台结算与玩家进入战场

玩家远离时，按部队批次、设施和防御数据自动结算。

玩家在附近或担任指挥官时，可以进入乡镇、农庄、坞堡或攻城战场，直接决定进攻、防守、撤离、灭火、护送和投降。

两种模式共享同一战斗状态和结果结构：

- 进入战术地图不会重新生成一场战斗；
- 已经在后台结算的伤亡不能再次计算；
- 战术选择只改变尚未决定的过程；
- 结束后统一汇总到人口、设施和库存账本。

## 26. 战争的长期影响

地区记录：

```text
战争破坏度
流民
弃耕面积
设施损坏
道路安全
尸体与疫病风险
豪族武装化
居民仇恨
粮食短缺
重建需求
```

同一地区不能被军队无限征粮。第一次征粮减少库存，第二次抢掠导致逃亡和停产，第三次经过时可能已无粮可取。

战争行为形成分类声誉：

- 保护百姓；
- 有偿购粮；
- 约束军纪；
- 抢掠和屠杀；
- 焚毁农田；
- 释放俘虏；
- 强征工匠；
- 战后赈济。

农民、商人、豪族、士人、军人和宗教组织对同一行为会有不同评价，并影响投降、补给、招募、贸易和叛乱。

删除或合并永久人物档案。

世界模拟以到期事件、地点、设施、家户、组织、军队聚合缓存和重要人物数量为主要复杂度，
不得按总人口全量运行完整AI。

## 30. 总验收标准

目标世界架构完成后，应满足：

1. 城市不直接凭空产生商品；

3. 人口、物资、兵员和财政能够通过自动测试守恒；
4. 战争死亡真实减少人口和未来产出；
5. 征兵来源可以追溯到县镇、身份和职业；
6. 军队抢夺的物资来自真实库存；
7. 战术地图的破坏永久回写世界；
8. 玩家观察地点不会创造或重随机人口；
9. 普通人物以永久基础档案存在并由汇总缓存低频结算，重要人物能够独立行动；
10. 地理决定资源潜力，历史决定初始传统，人物和市场决定实际发展；
11. 农户、工匠、商人、豪族、官府和军队在同一经济世界中互相影响；
12. 玩家可以通过身份、家族、产业、政策、财政和战争改变世界，但不能绕过真实成本。
13. 同一世界实体在不同比例尺和专题视图中保持稳定身份；
14. 所有专题视图只显示当前人物及获授权组织已经掌握的信息；
15. 信息复制、建设和勘察由具体人物消耗材料与时间完成；
16. 资源创世配置、来源等级和世界种子可以存档、审计并确定性复现；
17. NPC自主建设只能依据自身认知、权限和真实资源选址；
18. 每个领域明确最小有意义实体，聚合缓存不得删除会独立改变世界结果的事实。

## 31. 最终总结

```text
土地和历史资料给出生产潜力
→ 家庭、组织和人物取得土地与设施
→ 真实人口提供劳动力与技能
→ 设施消耗原料并生产商品
→ 商人和运输网络完成流通
→ 居民、政府和军队形成需求
→ 税收和利润支持建设与战争
→ 战争、灾害和政策改变人口与设施
→ 家族和后代继承真实结果
```

项目的独特性不在于单独拥有城市建设、跑商、家族、人物扮演或战争，而在于这些玩法共享同一套人口、土地、设施、库存、财政和历史账本。

## 32. 历史城市在统一世界中的实现合同

历史城市不是从世界地图跳转到另一套坐标、人口或设施账。城市Anchor只负责定位，实际城市范围由同一
`GridSchemaVersion` 中占据真实Cell的Facility集合、道路、自然地物和防御网络形成并可随建设、破坏与权属
变化。2000m Cell是战略交互抽象，不代表单体建筑实测尺寸；缩放与专题视角只能改变显示，不改变CellId、
Owner、Person、Facility或库存事实。

184年洛阳原型采用操作性放大的城郭足迹，使十二城门、南北宫、礼制建筑、市场、仓储、兵营和里坊能够被
分别选择、控制和破坏。每个历史设施必须保存 `HistoricalAnchor / HistoricalReconstruction /
GameplayReconstruction` 来源等级，并另存 `Confirmed / Probable / Approximate` 空间精度；曹魏、北魏等
后世形态不得静默回填为东汉184年事实。

住房只按永久Person槽结算，岗位只由真实Person填充。地方建设AI读取无住房人数、可用住房槽、失业、岗位
空缺、技能短缺、粮食、治安和财政等真实压力，不使用固定住宅/岗位Cell比例。历史生成器、玩家和AI使用同一
多Cell建设蓝图及Owner、占用、道路、施工阶段校验。

`HanWorldV1` 的2000米Cell是已经发布的数据合同。任何早期“Cell不指定现实尺度”的讨论
不得覆盖现有网格或CellId。一个Cell最多一个基础Facility和一个独立Force，但二者使用不同
占用槽；建筑绘制和场所表现可以更细，不能因此产生SubCell世界账。Definition/Profile/Instance、
Complex、Facility五类成长及建设主体边界见统一世界与权力设计。

## 33. Living World运行宪法：信号、决策、行动与历史事件

世界运行统一遵循：

```text
永久世界事实 → 可重算WorldSignal → DecisionContext → Policy提出ActionIntent
→ WorldActionValidator → 既有Command/Transaction/Event执行 → 同一世界事实变化
```

- 信号来自真实Person、Household、Facility、Inventory、Route、Carrier、Army和Location；信号是可重算观察量，不是第二套权威库存或人口。
- 需求只能提高建设、采购、迁移或治理行动的效用，不能直接生成设施、商品、运输或人口。
- Rule、Utility、HistoricalConstraint、Randomized与Neural Adapter共用动作合同；神经网络只评分，不得直接修改世界。
- Order和Shipment复用正式市场、民用运输与军需账。史料县域关系不自动发货，也不保证未来供给。
- HOT/WARM/COLD分别采用高、中、低频调度，异常可唤醒；升降档不改变Permanent ID、所有权、库存或既有事件结果。
- 重大历史事件由时间窗口加至少一个非时间前提共同决定，允许Canonical、Variant、Delayed、Prevented和Transformed；结果通过幂等ChangePackage写入真实设施、人物、组织、地点、道路或军队事实。
- Scenario Snapshot只用于直接开局初始化。连续世界不得读取未来切片覆盖当前分支。

当前实现版本为World Schema V71，正式合同和验收证据见
[`WORLD_INTELLIGENT_POPULATION_DRIVEN_SIMULATION_AND_HISTORICAL_EVENT_CONTRACT_V1`](HISTORICAL_WORLD_REFERENCE/WORLD_INTELLIGENT_POPULATION_DRIVEN_SIMULATION_AND_HISTORICAL_EVENT_CONTRACT_V1/)。
