# M21-P1 任务书：人口与家庭访问迁移、出生人物增量写入

## 一、阶段目标

承接 M21-P0 的人物仓储访问层和按分区增量检查点，打通永久人物从出生到人口包持久化的第一条正式通路：

```text
月度生命与家庭结算
→ 通过人物仓储读取、修改和登记新生儿
→ 分别形成新增人物集与既有人物变更集
→ 原子重写受影响人口分区
→ 同步世界人口存储元数据
→ 清除已提交集合
```

本阶段迁移 `LifeSimulationSystem` 中的家庭开支、健康、出生、死亡和家主继承人物访问。村庄生产、教育、军事等系统继续按后续任务分批迁移，不以本阶段局部接入宣称完整外置运行时已经完成。

## 二、权威边界

- 永久身份、分级模拟与人口守恒遵循 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 正式分区人口包与冷热扩展遵循 `TASK_M15_P6_FORMAL_PARTITIONED_POPULATION_ADAPTER_AND_RESIDENCY_CONTRACT.md`。
- 人物仓储和既有人物增量写回遵循 `TASK_M21_P0_PERSON_REPOSITORY_AND_INCREMENTAL_CHECKPOINT.md`。
- 本阶段不升级主世界存档版本和人口包格式版本；新增/变更分类属于运行期检查点合同扩展，落盘的核心记录、详细扩展、清单和当前指针格式保持不变。
- 新生儿一经登记即为永久人物。提交失败、降温或玩家未关注均不得删除、合并、替代或重新随机。

## 三、实施范围

### WP1：人物仓储新增人物合同

- 增加稳定排序的已知人物、待新增人物和待修改人物查询。
- 新增人物只能通过仓储登记一次，同时写入当前内联世界账和仓储索引。
- 已登记的新人物后续修改继续属于新增集合，不能重复写入既有人物修改集合。
- 成功检查点分别确认新增和修改集合；失败时二者均保持原样。

### WP2：出生增量检查点

- `PopulationIncrementalCheckpoint` 明确区分 `AddedPeople` 与 `ChangedPeople`。
- 新增人物在目标分区中必须同时缺少核心和详细记录；既有人物修改必须同时存在两类记录。
- 同一人物不得同时出现在新增和修改集合，也不得在任一集合重复。
- 仅重写包含新增或修改人物的分区；未变化分区继续引用已有代际文件。
- 新清单重新汇总永久人数、在世人数和详细扩展数，当前指针继续原子替换。

### WP3：生命与家庭系统迁移

- `LifeSimulationSystem` 支持注入共享 `IPersonRepository`。
- 家庭成员读取、健康变化、父母读取、新生儿登记、死亡和继承候选读取通过仓储完成。
- `WorldSimulator` 将同一人物仓储注入生命系统，保证旅行、任务与生命结算共享变更账。
- 不改变既有确定性随机坐标、出生概率、死亡规则、家主选择规则和人口台账口径。

### WP4：协调与失败原子性

- 人口检查点协调器一次提交全部待新增和待修改人物，并返回分类结果。
- 成功后更新 `WorldState.PopulationStorage`，刷新已驻留人物，再确认两类集合。
- 非递增修订、重复 ID、把既有人物声明为新增、把未知人物声明为修改等失败均不得推进当前指针、世界元数据或仓储待提交集合。
- 分区模式下有未提交新人物时，主世界快照继续明确拒绝保存；检查点成功后允许保存。

## 四、不纳入本阶段

- 从 `WorldState.People` 移除冷人物，或让生命系统直接扫描数千万完整人口。
- 村庄生产、教育、军事、医疗、治理等其余系统的完整仓储迁移。
- 删除人物、清理旧代际、异步 IO、数据库后端或千万级完整游戏负载验收。
- 修改出生概率、家庭形成、孕期、婴儿抚养或人口缩尺玩法规则。

## 五、验收标准

1. 仓储登记的新生儿立即具有唯一永久 ID，并稳定出现在待新增集合而非待修改集合。
2. 生命系统注入仓储前后产生相同的确定性世界结果；注入模式能审计父母、健康和死亡等人物修改。
3. 新生儿增量提交只重写其所在分区，人口、在世和详细扩展计数各按事实增加。
4. 提交后核心记录与详细扩展匹配，新生儿可读取、升温、降温并随主世界快照往返。
5. 新增/修改冲突、未知修改、重复新增和非递增修订在写盘前拒绝，当前指针和待提交集合不变。
6. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。

## 六、执行记录

### 6.1 实现结果

- `IPersonRepository` 已增加稳定已知人物视图、新增人物登记、待新增集合与分别确认合同；
  仓储也能发现兼容代码直接加入世界账的新人物，并把其纳入待新增集合。
- `LifeSimulationSystem` 已通过共享仓储处理家庭开支影响、健康、父母、出生、死亡与继承
  候选人物；`WorldSimulator` 将同一仓储注入旅行、任务和生命结算。
- 新生儿通过仓储加入世界账，保持原有稳定ID、确定性随机、人口台账和家庭成员关系规则。
- `PopulationIncrementalCheckpoint` 已区分新增人物和既有人物修改；存储适配器在写盘前拒绝
  重复、冲突、未知修改和既有人物伪装新增，只重写受影响分区并重新汇总三类人口计数。
- `PopulationPersonCheckpointCoordinator` 能一次提交两类人物，成功后同步世界存储元数据、
  刷新热驻留基线并分别确认集合；失败时保持当前指针、世界修订与待提交人物。
- 系统总纲、M12、M15-P6、M21-P0、确定性存档说明和 Skill 路由已同步。

### 6.3 保留限制

- `WorldState.People` 仍保留全部物化人物；本阶段没有验收冷人物完全外置运行。
- 村庄生产、教育、医疗、军事等系统仍有直接人物列表访问，留给后续分批迁移。
- `PopulationLedgerSystem` 的统计人口实例化兼容入口尚未整体迁移，但仓储能够发现其新增人物。
- 尚未实现变更日志压缩、异步写入、引用感知的旧代际清理和千万级完整游戏负载。
- 分区世界在新人物尚未完成检查点前不能保存主快照；这是防止世界元数据与人口包分离的
  显式安全门槛，后续自动保存编排必须先提交人口检查点。
