# M25-P0任务书：统一世界调度、命令事务与事件阶段内核

## 一、任务定位

本阶段建立正式世界运行时的统一编排入口，让已有旅行、军队、军需、历史事件、任务、科研、
生产、村庄、家庭、治理、教育和市场系统不再依赖一段不可审计的手写调用列表。

M25-P0只建设运行合同并适配既有V28行为，不改变存档结构，不把M24百万压力工具直接并入
正式世界，也不宣称既有系统已经全部迁移为事务式写入。

## 二、运行合同

### 2.1 稳定阶段调度

系统使用稳定命名空间ID注册，并声明阶段、频率和阶段内顺序。同一顺序以稳定ID排序，注册
先后不能改变结果。首批阶段为：

```text
时段命令/事件 → 时段移动 → 时段到达
→ 日界命令 → 日界运输
→ 历史事件 → 日常模拟
→ 派生状态 → 运行时事件分发
```

阶段和频率属于封闭生命周期协议，可以使用枚举；具体系统、命令、事务和事件类型仍使用
稳定命名空间ID，不建立固定内容枚举。

### 2.2 到期命令

运行时命令至少保存稳定命令ID、类型ID、签发者、到期日、到期时段、优先级和参数。命令按
到期时间、优先级和稳定ID处理。未知命令处理器、重复命令ID或非法稳定ID必须明确失败。

当前命令队列是运行时合同，尚未进入V28存档；需要跨保存点存在的玩家、NPC或组织命令，
必须在后续任务升级为持久领域对象并顺序迁移，不能假装已经保存。

### 2.3 事务预检、预约与提交

命令处理器只能规划事务，不应在规划期修改世界。事务批次先按优先级和稳定ID排序，然后：

```text
全部事务验证
→ 在共享验证上下文预约资源
→ 验证全部通过
→ 顺序应用事务
→ 发布运行时事件
```

预约账可以阻止同一批次超额占用同一资源。验证或预约失败时，不应用批次内任何事务，命令
继续留在队列中。P0要求事务在验证成功后应用阶段不得再失败；对任意旧系统修改提供通用回滚
不在本阶段范围，后续迁移具体库存、财政、劳动和土地事务时必须提供相应原子领域操作。

### 2.4 提交后事件

事件只在事务全部验证并提交后发布，按稳定事件ID排序；事件处理器按稳定处理器ID分发。
事件用于触发报告、AI新需求和后续命令，不能绕过事务直接制造人口、物资、财政或兵员。

## 三、工作包

### WP1：执行内核

- 建立系统阶段、频率、执行上下文和稳定调度器；
- 拒绝重复系统ID；
- 提供本轮执行轨迹以便测试和诊断。

### WP2：命令、事务与事件合同

- 建立到期命令队列和稳定处理器注册；
- 建立两段式验证/预约/应用事务缓冲；
- 建立提交后事件发布与稳定分发；
- 对失败批次保留命令并证明未发生前置修改。

### WP3：现有世界适配

- 将`WorldSimulator`现有行为与命令/事件入口组成的25个时段及日界步骤注册到统一调度器；
- 保持旅行、行军、到货、军需、生产、家庭、市场等原顺序与公开调用入口；
- 允许调用者注入命令运行时，不启用命令时保持原行为。

### WP4：状态与验证

- 更新系统总纲、世界模拟状态和任务路由；
- 增加顺序、频率、重复ID、确定性、验证失败、预约冲突、事件提交后分发和正式适配测试；
- 完成编译、核心、受控Unity、差异与范围审阅。

## 四、验收标准

1. 注册顺序不同不会改变同阶段执行顺序。
2. 日界系统不会在普通时段错误运行。
3. 命令按到期时间、优先级和稳定ID处理。
4. 批次验证或资源预约失败时，世界不发生事务修改且命令不丢失。
5. 事件只在事务提交后出现，并以稳定顺序分发。
6. 现有`WorldSimulator`通过统一阶段运行，原有回归保持通过。
7. 不改变`WorldState.CurrentSchemaVersion`，不产生存档迁移。
8. 全工程编译、核心测试、受控Unity测试和`git diff --check`分别通过。

## 五、不包含

- 把全部旧系统写入改造成事务；
- 命令队列、执行轨迹和运行时事件的持久化；
- 跨进程回滚、分布式事务或并行系统执行；
- M24多作物百万世界正式并入V28；
- Unity世界运行控制台和地图专题视图；
- 1,000万或累计5,000万完整系统负载。
