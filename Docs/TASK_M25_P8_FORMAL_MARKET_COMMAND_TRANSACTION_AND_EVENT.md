# M25-P8任务书：正式县级市场持久命令、事务结算与提交后事件

## 一、任务定位

在M25-P4正式县级家庭市场与M25-P7持久执行内核之上，选择“正式市场每日到期与县内撮合”
作为第一条迁移到统一执行管线的经济路径。`WorldSimulator`不再在正式库存权威下直接调用每日
市场写入，而是仅在活动订单确有到期或可撮合工作时建立V33持久命令，由稳定命令处理器规划
显式世界事务，事务提交后发布持久出站事件。

本阶段不改变M25-P4的订单、批次预留、现金托管、成交价格和守恒口径，也不新增存档字段或
升级V33。现有`ResolveDaily`保留为兼容领域入口，但正式世界日界只能通过命令事务适配器调用。

## 二、实现合同

### 2.1 有界每日命令

- 正式库存权威下只扫描活动正式市场订单，不扫描永久人物、家庭全表或全世界商品批次；
- 只有存在到期订单或同县可相交买卖订单时，才为当日建立唯一稳定命令；
- 命令保存稳定类型、系统签发者、当日坐标和期望结算日参数，重复调度不得建立第二份；
- 兼容标量市场继续使用既有价格模拟，不生成正式市场命令；
- 已保存但尚未执行的市场命令随V33存档恢复，由新运行时注册同一处理器后继续执行。

### 2.2 显式事务边界

- 命令处理器只解析稳定参数并规划一张`IWorldTransaction`，规划期不修改世界；
- 事务预检要求世界仍为正式库存权威、期望结算日等于当前世界日且活动订单账有效；
- 同一批次通过共享预约键限制当日市场结算只能提交一次；
- 应用阶段调用M25-P4稳定撮合，商品变化继续形成`FoodMarketTransferred`库存事务，现金继续
  通过买单托管、卖方财富和正式成交记录闭合；
- 预检失败不关闭订单、不转移批次、不支付现金、不产生市场事件，只由M25-P7记录拒绝尝试。

### 2.3 提交后事件

- 成功事务发布唯一稳定`formal_market.daily_resolved`事件并写入V33事件出站箱；
- 正式世界注册稳定投影处理器确认该事件，后续报告、AI或知识系统可在同一事件类型上扩展；
- 处理器不得再次修改库存、资金或订单，事件只表示已经提交的事实；
- 保存发生在事务提交后、事件分发前时，载入后仍可完成确认且不重复撮合。

## 三、工作包

### WP1：市场事务适配器

- 增加活动订单有界工作检测、稳定每日命令调度器、命令处理器和市场事务；
- 增加当日预约、正式权威和日期预检；
- 在提交后产生稳定市场事件并提供无业务写入的正式投影确认处理器。

### WP2：世界调度接入

- `WorldSimulator`注册正式市场命令与事件处理器；
- 正式市场价格阶段改为“确保命令并处理到期命令”，不再直接写市场；
- 兼容标量价格路径与原系统顺序保持不变。

### WP3：恢复、失败与确定性验收

- 覆盖持久市场命令读档后成交一次、事务/事件引用、事件确认和重复推进幂等；
- 覆盖日期漂移或权威变化时拒绝且订单、批次和资金零修改；
- 覆盖无活动工作不生成命令、相同世界结果一致及正式`WorldSimulator`真实接入；
- 同步总纲、世界模拟、确定性存档、M25-P4兼容说明与Skill任务路由。

## 四、验收标准

1. 正式世界日界不再直接调用市场写入，所有自动到期和县内成交均有持久命令与成功结果。
2. 每个有工作日期最多一张市场命令和一张市场事务，重复推进不重复成交。
3. 商品批次、库存事务、买方托管、卖方财富、正式成交和价格账继续满足M25-P4守恒。
4. 预检失败不改变任何市场业务事实，但保留待执行命令和稳定拒绝结果。
5. 提交后事件可跨存档恢复，确认处理器不制造第二次业务写入。
6. 无到期或可撮合订单时不产生空命令，不扫描永久人物全表。
7. 相同种子、订单和世界时间产生相同命令、事务、事件和快照。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 把创建、取消市场订单改造成玩家/NPC持久命令；
- 自动为所有家庭生成买卖订单或扫描所有永久人物寻找交易者；
- 跨县货运、承运竞价、途中损耗、仓储腐败、信用、税费或保险事务化；
- 给全部旧系统提供通用回滚，或序列化处理器与事务对象；
- 市场UI、玩家通知、知识传播和完整NPC经营策略。

## 六、执行记录

一张市场事务。事务预检正式权威、日期和当日共享预约，应用阶段复用M25-P4库存转移、现金
托管、正式成交和价格账，提交后发布持久市场事件，由稳定投影处理器确认。
