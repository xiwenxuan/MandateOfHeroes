# M25-P14集成基线任务书：核心测试分组、完整验收与远程收拢

## 一、任务定位

当前远程分支停在M23-P4，本地工作区已经连续形成M23-P5—P14、M24-P0—P7、
M25-P0—P14以及Unity批处理恢复成果。全工程编译和333项Unity EditMode分组回归已有
通过证据，但纯C#核心回归在单进程295秒边界内没有生成最终`RESULT`，不能把本地V36
成果描述为已经完成完整集成验收。

本任务不增加世界规则、不升级存档版本，也不继续扩展玩法。它只建立可复现的核心测试
分组合同，重新验证当前源码，并把已经存在的V36实现、设计、压力工具和测试证据收拢为
一个远程集成基线。后续M25-P15仓储环境损耗从该基线继续。

## 二、实现范围

### 2.1 核心测试精确发现与执行

- `CoreTestRunner`必须从实际测试程序集列出其能够执行的全部核心测试。
- 保留既有子串过滤兼容入口；新增精确多测试过滤，未匹配任何测试必须失败。
- 测试发现和执行顺序使用稳定名称排序，不依赖反射返回顺序。
- 每组独立进程运行，单个外部进程硬超时不超过300秒，超时只清理本组进程树。

### 2.2 分组证据与聚合

- 准备阶段执行全工程编译、核心运行器编译和程序集测试发现。
- 清单保存源码指纹、测试总集、每组精确名称和核心二进制哈希。
- 每组保存预期集合、标准输出、标准错误、退出码和结构化结果。
- 聚合必须拒绝源码变化、二进制变化、漏组、漏测、重复测试、意外测试和失败结果。
- 只有聚合明确输出`total=N passed=N failed=0`，才能声称完整核心回归通过。

### 2.3 集成基线范围

本次基线包含当前工作区中相互依赖的下列既有成果：

- M23-P5—P14军需物流、委任、实际收货、责任和赔偿链；
- M24-P0—P7百万永久人口、家庭生产、市场赈济、多食品来源和生态压力工具；
- M25-P0—P14统一执行、正式食品、市场、民运、持久命令和公共赈济闭环；
- 与上述持久结构相匹配的V19—V36迁移、领域校验、确定性与回归测试；
- Unity批处理安全入口、分组EditMode工具、规则文档和恢复报告；
- 本任务新增的核心测试分组工具和执行证据说明。

不提交`tmp`、`Temp`、`Library`中的运行产物。若范围审阅发现与上述成果无关的用户修改，
必须原样保留在工作区，不得混入集成提交。

## 三、验收标准

1. 全工程编译在300秒内通过，并保存日志。
2. 核心测试从实际程序集发现；所有测试被精确执行一次，聚合结果零失败。
3. Unity EditMode使用既有12组安全入口；源指纹、预期集合和XML实际集合一致，零失败。
4. 存档迁移、当前V36往返和长期确定性测试包含在核心或Unity完整集合中。
5. `git diff --check`通过；任务范围审阅没有混入生成缓存、商业素材或无关修改。
6. 任务书完成记录分别报告编译、核心、Unity和差异检查，不以一项替代另一项。
7. 只在上述证据成立后提交并推送；报告提交号、远程分支和剩余工作区状态。

## 四、非目标

- 不实现M25-P15仓储环境损耗或M25-P16家庭月内领取。
- 不修改V36领域语义，不创建V37迁移。
- 不延长300秒硬超时，不以日志尾部的`PASS`代替最终聚合结果。
- 不删除历史任务书、压力失败候选或用户数据，不关闭用户程序。
