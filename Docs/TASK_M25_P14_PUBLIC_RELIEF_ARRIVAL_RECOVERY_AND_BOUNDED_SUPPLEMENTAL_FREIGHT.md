# M25-P14任务书：跨县赈济到仓恢复、途中异常账与有界补运

## 一、任务定位

承接M25-P13已经完成的政府跨县购粮与真实民用货运。本阶段不以计划发运量视为已经赈济，
而是在政府货运实际完成、粮食真实进入目标县仓后，立即建立一张持久恢复命令，按原县级短缺
中各村未满足量稳定分配真实县仓批次，并保存发运、自然损耗、实到、实发和剩余缺口。

若首票实际到货仍不能覆盖该次跨县短缺，系统只允许一次补运尝试。补运继续使用活动外县卖单、
真实承运登记和承运人已知路线，数量不得超过实际剩余缺口，商品与运费不得突破原跨县采购命令
尚未使用的预算。补运到仓后可以再次恢复分配，但不得递归建立第三票补运。

## 二、实现范围

### 2.1 V36持久恢复合同

- 新增县级赈济恢复账，绑定原县级短缺事件、外县寻源事件和目标县。
- 按村保存本次跨县责任范围、累计恢复量、剩余量和实际库存事务引用。
- 每票政府赈济货运保存发运量、自然损耗、实到量、恢复分配量、在途日数、到达后等待收货日数
  和异常代码。
- 恢复账汇总必须与分村账、逐票报告和真实货运字段闭合；同一货运只允许核销一次。
- V35到V36只建立空恢复集合，并为旧货运补齐空恢复引用和非补运默认值，不倒推旧世界历史。

### 2.2 到仓即恢复分配

- 每个片段的民用货运到达处理之后，扫描已完成且尚未核销的政府赈济货运，不扫描永久人物。
- 为每票货运建立同片段持久命令并通过统一事务内核执行；重复调度不得产生第二张命令或第二次分配。
- 分配只从目标县真实正式县仓转入原短缺村的正式公共粮仓，受县仓现存批次、目标容量和该村剩余
  缺口共同限制。
- 村庄顺序、批次顺序和命令/事务ID全部稳定；货物不足、容量不足或日期漂移时不得虚增粮食。

### 2.3 途中异常与一次补运

- 自然损耗、实到不足和到达后容量等待以逐票报告保存，不把发运量写成实到量。
- 首票恢复后仍有缺口时，读取原跨县采购命令的商品预算、运费预算和最高单价，扣除已经发生的
  外县成交和运费后，最多尝试一次补运。
- 补运沿用M25-P13有限知识选源和真实民运履约；无卖单、无已知路线、无承运能力、预算不足或
  县仓容量不足时保存耗尽状态，不造粮、不扣款。
- 补运票完成后再次按实到量分配；仍有缺口则结束本次自动补运，不形成无限循环。

## 三、验收标准

1. 政府赈济货运完成后，同片段形成唯一恢复命令并把真实县仓批次分发到正确短缺村。
2. 恢复账逐票区分发运、损耗、实到与实发，分村累计和总账严格相等。
3. 首票不足只建立至多一票补运，补运数量不超过真实剩余缺口，累计商品款和运费不突破原预算。
4. 补运仍受真实卖单、承运人、移动容器和已知路线限制；失败只保存缺口状态。
5. 同一货运重复扫描、存档恢复或重复处理不会重复发粮、重复补运或重复付款。
6. V35到V36迁移、V36往返、篡改恢复账拒绝和相同世界确定性测试通过。
7. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅按项目规则分别报告。

## 四、非目标

- 不实现第二次以上自动补运、州郡审批树、多承运人换手、保险、信贷或押运战斗。
- 不主动侦察未知市场，不自动创建家庭卖单，不扫描全部永久人物寻找临时承运人。
- 不在本阶段处理县仓日常腐败、村仓向具体家庭的二次月内配给或玩家界面。
- 不修改玩家关注、永久人物冷热存储和历史人口口径。
