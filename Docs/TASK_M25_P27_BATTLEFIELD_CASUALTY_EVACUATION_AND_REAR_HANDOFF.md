# M25-P27 战场伤员撤离、真实救护队与后方交接任务书

## 一、阶段目标

承接 M25-P25 的具体军役伤员和 M25-P26 的真实军药物流，把“后送”落实为永久人物、军役状态、道路和时间共同构成的世界事实：

```text
具体军役伤员
→ 有军权人物批准后送
→ 两名以上具体服役人物组成救护队并脱离战斗可用兵力
→ 伤员与救护队沿真实路线旅行并消耗个人口粮
→ 军队可以继续行军，但不得把已后送人员瞬移带走
→ 到达后方地点
→ 由预先指定且合格的具体医者验收
```

本阶段只闭合“撤离—旅行—到达—交接”，不把到达等同于治疗、康复或归队。

## 二、本阶段完成范围

1. 使用稳定命名空间 ID 表示撤离运输策略、救护队职责和后方接收策略；生命周期使用封闭枚举。
2. 每次撤离持久保存来源军队、伤员军役与人物、批准者及权限快照、起终点、路线、伤员旅行、具体救护队成员与旅行、指定接收医者、到达日和接收日。
3. 撤离必须由来源军队具有军队级权限的人物批准；伤员必须是该军具体 `Wounded` 军役，且尚未处于其他未闭合撤离中。
4. 首个运输策略要求 2—8 名同军、同地、存活且当前 `Active` 的具体服役人物；发出后转为医疗后送勤务，不再计入军队可战兵力。
5. 伤员与救护队复用真实个人旅行和既有路线，不瞬移、不绕过每日旅行口粮消耗。
6. 旅行到达时原子转为等待接收；指定医者必须是目的地存活、未在旅行且医术达到军医最低门槛的具体人物。
7. 接收只确认人物与责任交接，伤员仍为 `Wounded`，不得自动恢复健康、消耗军药或生成治疗记录。
8. 军团移动不得带走处于撤离中的伤员或救护队；随军治疗不得隔空治疗已后送伤员。
9. 存档升级到 V49；V48→V49 只建立空撤离集合，不倒推旧伤亡、旧旅行或旧医疗为后送历史。

## 三、领域约束

- 同一伤员同一时间至多有一条未完成医疗处置的后送事实；同一救护队员同一时间至多参加一支后送队。
- 伤员、救护队、指定接收医者、路线、军役、军队与地点都必须由稳定 ID 交叉验证。
- 后送中的人物可以与来源军队分离，但这种分离必须由有效撤离记录和对应旅行或到达状态解释；删除或篡改其中任一引用必须使存档校验失败。
- 救护队转入后送勤务后，军队 `Troops` 缓存必须同步扣减；伤员仍计入 `WoundedTroops`。
- 玩家关注、冷热分层、地图缩放或界面状态不得改变旅行距离、到达时间、人物口粮、权限和接收结果。

## 四、明确不做

- 不实现野战医院设施、床位、住院排队、手术、感染、残疾或复杂伤势。
- 不实现接收后的治疗、救护队返程、再次转院、伤员归队或退役；这些进入后续阶段。
- 不实现担架、车辆、舟船的装备耐久和不同速度；首个策略固定复用步行旅行速度。
- 不实现自动筛选后送目的地、AI 自动派队、玩家医疗界面或批量撤离。
- 不提交、不推送；版本操作仍需用户另行授权。

## 五、验收用例

1. 合法批准后，具体伤员和两名具体救护队员建立三条真实旅行；救护队脱离可战兵力，伤员仍在伤员缓存中。
2. 推进世界后，三人真实到达目的地并进入等待接收；指定合格医者验收后保存责任快照，但不恢复伤员健康或军役。
3. 来源军队在后送期间向另一地点行军时，不得带走或覆盖伤员与救护队的位置。
4. 已后送伤员不得被来源军队随军医疗隔空治疗。
5. 无权批准、人数不足、重复队员、错误军役、错误路线、接收医者不合格或已在旅行时原子拒绝。
6. 篡改人物、军役、旅行、路线、状态或到达事实时，世界不变量校验失败。
7. V48→V49 不制造后送事实；V49 往返保存完整后送、旅行和交接事实。
8. 全工程编译、聚焦回归、全量核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。
