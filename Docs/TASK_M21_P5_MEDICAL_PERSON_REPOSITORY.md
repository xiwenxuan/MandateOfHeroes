# M21-P5 任务书：医疗系统人物仓储迁移

## 一、阶段目标

承接 M21-P4，把军中治疗入口和真实伤员康复路径接入统一 `IPersonRepository`：

```text
医者与军队稳定ID
→ 仓储读取医者技能、位置和生存状态
→ 校验药材、行程、伤兵与治疗条件
→ 确定性选择真实伤病服役成员
→ 仅将健康实际恢复的士卒登记为待修改
→ 服役状态、军队缓存、药材和医案继续按原规则回写
```

当前原型没有诊金或医者经验收入。本阶段不凭空新增这类玩法，只迁移现有真实事实：医者
保持只读，药材属于库存事实，康复士卒的健康变化进入人物增量修改集合。

## 二、权威边界

- 永久身份、健康事实和冷热存储遵守 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 医者能力与健康规则遵守 `CHARACTER_ATTRIBUTES_TRAITS_AND_GROWTH.md`。
- 真实服役与伤员康复遵守 `UNIFIED_COMBAT_WARFARE_AND_AUTHORITY.md` 和
  `TASK_M10_REAL_MILITARY_SERVICE_AND_COMMAND.md`。
- 本阶段不增加持久字段，不提升 V11 世界存档版本，不改变治疗随机流、康复率或伤员选择。

## 三、工作包

### WP1：医疗入口人物访问

- `MedicalSystem` 接受可选共享 `IPersonRepository`。
- 医者按稳定 ID 从人物仓储读取；死亡、技能、地点和旅行校验保持只读。
- 未注入时按世界缓存兼容适配器，保持全部既有构造调用有效。

### WP2：真实伤员康复登记

- `MilitaryServiceSystem.RecoverWounded` 接受该次康复调用使用的人物仓储。
- 仅限医疗康复路径：恢复为在役的真实士卒若健康实际提升，则登记人物修改。
- 医者不因提供技能或消耗库存而被误标为人物修改。
- 抽象旧军队兼容路径没有具体人物，不制造人物修改。

### WP3：失败与守恒

- 无药材、无伤兵、技能不足、师兵异地、旅行或行军中的失败保持无副作用。
- 药材消耗、服役状态、军队兵力/伤兵缓存和医疗记录继续保持既有守恒。
- 不迁移战斗伤亡、逃亡、征募、行军人员同步等其他军事人物路径。

### WP4：验证与状态同步

- 验证注入与兼容模式产生相同治疗快照和康复人数。
- 验证修改集合恰好包含健康实际恢复的士卒，不包含只读医者。
- 验证失败治疗不改变世界快照且人物仓储保持干净。
- 更新系统总纲、M12、人物/战争设计、M10 后续兼容记录与 Skill 任务路由。

## 四、不纳入本阶段

- 诊金、医者收入、医术经验、声望、医案成长和治疗关系。
- 个体疾病诊断、处方、药物品质、医院、公共卫生和疫病传播扩展。
- 战斗伤亡、死亡、逃亡、征募、退役及完整军事系统人物仓储迁移。
- 药材数据驱动批次、通用医疗工单和正式医疗界面。
- 未驻留人物完全外置运行和千万级完整医疗负载。

## 五、验收标准

1. `MedicalSystem` 不再直接遍历 `WorldState.People` 查找医者。
2. 医疗康复路径通过人物仓储修改具体伤员健康，并保持服役账和军队缓存一致。
3. 注入与兼容模式在相同世界、命令与随机坐标下产生相同快照。
4. 修改集合只包含健康实际恢复的士卒，不包含只读医者。
5. 失败治疗不改变库存、军队、医案或人物变更集合。
6. 现有药材消耗、确定性康复、真实服役和存档往返回归保持通过。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。
