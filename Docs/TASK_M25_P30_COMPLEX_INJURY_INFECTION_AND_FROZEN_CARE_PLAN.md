# M25-P30 复杂伤情、感染处置与冻结诊疗计划任务书

## 一、阶段目标

承接 M25-P29 的一/两阶段住院合同，把所有后送伤员都相同的固定疗程推进为由具体伤情事实决定、
且接诊后不随界面或后续规则变化而重算的诊疗计划：

```text
具体后送伤员与健康快照
→ 接诊时生成永久伤情记录
→ 开放ID伤型、严重度、污染度与感染风险
→ 冻结本次住院的稳定治疗方案序列
→ 感染者先完成真实感染控制
→ 再完成既有稳定伤情/恢复阶段
→ 感染结案后才能取得返程资格
```

本阶段建立复杂伤病的第一条正式切片，不把随机死亡、手术和永久残疾一次性塞入同一状态转换。

## 二、伤情评估合同

1. 伤型使用开放稳定命名空间 ID，不使用固定伤型枚举。首批内置选择为软组织伤、骨折伤和
   穿透伤；新增普通伤型或 MOD 伤型不要求升级存档结构。
   世界持久保存当前启用的伤型定义、接诊健康范围和稳定选择优先级，接诊只按该数据集合选择。
2. 每次新住院建立唯一永久伤情记录，保存患者、军役、后送、住院、伤型、接诊健康、严重度、
   途中天数、污染度、感染风险、感染状态和结案引用。
3. 首版使用确定性规则从接诊健康与真实后送天数得出伤型和风险，不调用系统随机数，也不受
   人物关注、冷热层级或列表顺序影响。
4. 感染风险达到 6,000 时接诊即记为活动感染；低于阈值记为受监测但未感染。该结论是本次
   住院的冻结事实，不在读档时重新计算。

## 三、冻结诊疗计划

1. 住院记录保存稳定方案 ID 顺序，而不再只根据诊疗点种类和当前阶段临时推断。
2. 既有医馆的基础方案仍为一次草药恢复；野战医院的基础方案仍为稳定伤情、恢复返程两阶段。
3. 活动感染在最终恢复之前插入“感染控制”阶段：180分钟、2单位真实草药；完成后伤情感染状态
   转为已控制并保存具体治疗引用和日期。
4. 所有治疗继续共享每日480分钟医者工时，逐阶段保存具体批次、唯一库存事务、健康/医术开闭值。
5. 计划全部完成且感染已控制后才进入返程资格；缺药、工时不足、计划错序或来源篡改必须原子拒绝。

## 四、存档与迁移

- 世界存档升级为 V52。
- V51→V52 建立空复杂伤情集合。
- 既有住院按 V51 已确定的诊疗点和阶段数补齐等价方案序列；不得给旧住院倒推伤型、感染、污染
  或新增治疗阶段。
- 新住院必须同时生成伤情记录和冻结方案；二者与后送、患者、军役和治疗逐项交叉校验。

## 五、明确不做

- 不实现手术器械、麻醉、截肢、永久残疾、伤后死亡或家庭继承后果。
- 不实现住院后动态感染传播、院内传染、护理班次、转院、复发或长期康复。
- 不实现自动诊疗AI、自动补药、医疗收费、抚恤或玩家医疗界面。
- 不提交、不推送。

## 六、验收标准

1. 普通伤员仍保持 P28/P29 的一或两阶段行为。
2. 高严重度且长途后送的伤员生成活动感染和额外感染控制阶段，真实消耗2单位药材和180分钟工时。
3. 感染控制前不得完成住院或取得返程资格；控制后按冻结顺序继续治疗。
4. 药材不足、医者当日工时不足、治疗计划/伤情引用篡改时世界保持原子或校验拒绝。
5. V51→V52 不制造旧伤情或感染事实，旧住院计划语义不变；V52往返保持完整伤情与计划。
6. 全工程编译、聚焦核心、全量核心、受控 Unity EditMode、`git diff --check` 和范围审阅通过。
