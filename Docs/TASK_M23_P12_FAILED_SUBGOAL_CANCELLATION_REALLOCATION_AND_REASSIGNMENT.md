# M23-P12 失败子目标撤销、数量预算回收与受控重派任务书

## 1. 阶段目标

在M23-P11同军队两层父子军需目标之上，补齐尚未发运子目标无法履约时的恢复闭环：

```text
父级受任人确认未发运叶目标无法履约
→ 关闭该目标与仍有效报价，但不修改库存或资金
→ 完整回收该子目标占用的数量和预算
→ 保留旧目标、取消原因、报价关闭和父级回收报告
→ 父级受任人在原合同边界内把完整回收数量拆给新下级
→ 新目标以新稳定ID保存，并与被替代目标双向关联
→ 叶目标真实履约后继续自底向上完成父目标
```

取消任务不是回滚世界。已经发运的目标已产生真实付款、库存出库、人员旅行和在途货物，
本阶段一律不得取消或回收；它们只能由既有物流、夺回、收货或未来补运合同处理。

## 2. 必须完成

1. 父目标持久保存未分配数量和可用预算储备；活动直接子目标数量加未分配数量必须等于
   父目标数量，活动子预算加预算储备必须等于父目标预算。
2. 子目标保存取消日期、取消人、数据驱动取消原因、所替代目标和替代目标ID列表；历史目标
   不删除、不改ID、不重新随机。
3. 只允许父目标当前受任人取消自己的直接叶目标，并重新检查根签发人军级权限、取消人
   存活状态和受任时军职权限。
4. 只有`Pending`、`NeedsAttention`或`Expired`且没有货运单的叶目标可以取消；已发运、完成、
   已委任、有下级或已取消目标拒绝处理，世界快照保持不变。
5. 取消原因使用稳定命名空间ID；首批内置“受任人不可用、期限失效、无可行报价、上级改派”，
   普通新增原因不得要求升级存档结构。
6. 取消时所有仍有效报价转为“因目标取消关闭”，保存关闭日并逐条报告；报价阶段没有预留，
   因此库存数量、预留量、组织资金和真实货运集合必须零变化。
7. 取消后把子目标完整数量和预算加回父级池，父级进入`NeedsAttention`；取消目标不再参与
   活动数量、预算、完成比例或实际交付汇总。
8. 重派必须针对一个尚未被替代的已取消直接子目标，一次创建1—8个新目标；请求按受任人
   稳定ID排序并复用P11的下级权限、继承、单价、期限和承运偏好约束。
9. 新目标数量之和必须精确等于被替代目标数量，预算之和不得超过该目标预算和父级可用
   预算储备；父级活动子目标数不得超过8。
10. 重派先完整验证再一次性修改世界；任一无效请求不得改变目标、报价、报告、数量池或
    预算池。
11. 重派成功后，新旧目标保存双向替代关系；父级未分配数量归零时恢复`Delegated`，否则
    保持`NeedsAttention`。
12. 日界对`Delegated`和存在子目标的`NeedsAttention`父目标统一做聚合；存在未分配数量时
    只报告缺口，不得误走叶目标报价或提前完成。
13. 存档升级到V26。V25父目标依据现有直接子目标计算预算储备，未分配数量为0；已有取消
    状态使用明确的“迁移来源不详”原因，不倒推不存在的重派链。
14. 自动测试覆盖取消回收守恒、报价关闭、已发运拒绝、权限拒绝、稳定重派、预算/数量约束、
    原子失败、旧目标保留、完成传播、V26往返和V25迁移。

## 3. 本阶段边界

- 只处理尚未发运的直接叶目标，不撤销真实物流、不返还已经支付的资金；
- 不支持已发运短缺量自动补运、跨父目标预算调剂、追加总预算、跨军队转派或批量级联取消；
- 不允许取消带下级的中间目标，避免隐式删除整棵责任树；
- 不让NPC自动选择取消原因、替代人或预算，AI后续只能调用相同显式领域命令；
- 不实现商人信用、违约赔偿、保证金、自动寻路或跨组织法定授权；
- 不增加Unity界面；不提交、不推送仓库。

## 4. 验收标准

1. 任意有效快照中，父目标活动数量加未分配数量守恒，活动预算加可用储备严格守恒；
2. 取消和重派不改变产品批次、库存预留、组织资金或真实货运，除非新叶目标以后正常发运；
3. 被取消目标、报价、报告和替代关系永久保留，可由稳定ID完整追溯；
4. 已发运、已完成、中间层、越权或重复取消/重派均原子拒绝；
5. 重派目标不放宽父级合同，数量精确覆盖旧目标且不突破预算池和活动子目标上限；
6. 存在未分配数量时父目标不得完成；替代叶目标全部真实完成后仍可同日自底向上完成；
7. V26快照往返一致，V25迁移不伪造重派历史；
8. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。
