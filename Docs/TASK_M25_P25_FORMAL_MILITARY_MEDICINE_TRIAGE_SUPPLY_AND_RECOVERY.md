# M25-P25 正式军队医疗：分诊、军药库存、军医劳动与伤员归队任务书

## 一、阶段目标

承接 M10 的永久人物军役、M21-P5 的人物仓储接口，以及 M25-P23/P24 的正式药材与医术成长合同，把旧军医原型从“医者背包里的抽象药材换取伤兵汇总恢复”推进为可审计的具体人物闭环：

```text
具体军役伤员
→ 稳定分诊等级与军队授权快照
→ 军队所属正式药材容器和具体产品批次
→ 具体医者的当日劳动时间
→ 逐人治疗、健康恢复和军役归队
→ 医术成长、库存事务与追加式军队医疗档案
```

本阶段不照搬民间诊金规则。军队医疗由军队组织承担，内部军医或由在位主将授权的同地医者均可执行；治疗不会在患者家庭和医者家庭之间制造资金流。

## 二、本阶段完成范围

1. 每支正式军役军队保存唯一军药库存容器引用；容器由军队所属组织拥有，位置随军队当前驻地校验。
2. 新原型世界为各军队建立正式军药容器和可追溯的开局草药材产品批次；旧存档迁移只建立空集合和空引用，不倒推旧药库或旧救治历史。
3. 以稳定命名空间 ID 保存分诊等级、治疗方案、救治场所、授权政策和结案原因；普通医疗内容扩展不得依赖固定枚举或升级存档结构。
4. 每名被治疗伤员建立永久病例，记录军队、军役、患者、医者、授权主将、分诊等级、方案、开诊日和结案事实。
5. 每次成功救治建立追加式服务记录，闭合具体药材批次、库存事务、医者工时、医术开闭值、患者健康开闭值和军役状态变化。
6. 正式路径只消耗军药容器内未预留的 `product.medicine.herbal_material` 批次；不再把人物背包的 `commodity.herbs` 作为正式军役伤员的权威药源。
7. 同一医者同日军队医疗工时与民间医疗工时合并计算，不得突破统一日上限；失败尝试不占工时、不扣药、不增技能、不改变伤员。
8. 伤员选择使用稳定 ID 排序；关注等级、热冷存储和界面状态不得影响分诊、用药、恢复或医术成长结果。
9. 存档升级到 V47；V46→V47 不伪造历史病例、服务、药库或物资，只把正式军医合同启用日设为迁移后下一日。

## 三、领域约束

- 患者必须是目标军队中状态为 `Wounded` 的具体永久军役人物；治疗不得直接篡改军队汇总缓存替代人物事实。
- 医者必须存活、具备最低医术、与军队同地且双方不在行军/旅行中。
- 同军队有效 `Medic` 军役使用内部军医授权；其他合格医者必须由目标军队当前在位主将授权。授权快照写入病例和服务，不能只保留在摘要文本。
- 一单位正式药材只服务一名伤员；每次服务占用明确分钟数。首版成功服务把伤员健康至少恢复到可归队阈值并把其军役状态从 `Wounded` 改为 `Active`。
- 药材批次扣减、库存事务、病例、服务、人物健康、军役状态、军队缓存和医术成长必须共同闭合；任一预检失败时不得出现部分写入。
- 军队医疗不收家庭诊金；服务记录中的支付政策明确为军队内部供给，费用为零。
- 旧 `MedicalTreatmentRecordState` 只保留为兼容展示汇总，不再是正式军队医疗的事实权威。

## 四、明确不做

- 不实现手术、截肢、永久残疾、传染病、复杂方剂、药物相互作用、住院床位和死亡概率。
- 不实现战场担架运输、后送路线、野战医院建设、跨军调药和军费采购自动化。
- 不改造完整战斗伤势严重度模型；当前分诊只根据已存在的健康值确定稳定等级。
- 不制作玩家军医界面，不提交、不推送；版本操作仍需用户另行授权。

## 五、验收用例

1. 正式新世界每支军队具有唯一组织军药容器和可追溯开局草药批次。
2. 战斗产生具体伤员后，合格内部军医或主将授权医者可按稳定顺序逐人救治，病例、服务和兼容汇总同步生成。
3. 每名成功伤员只消耗一单位正式药材，军役恢复为 `Active`、健康达到归队阈值、军队缓存与具体服务人数一致。
4. 同日工时上限、药材不足、医术不足、异地、行军中、无伤员或无有效授权时保持完全原子失败。
5. 军医服务不改变患者或医者家庭财富；成功服务才产生有界医术成长，并通过人物仓储修改接口追踪。
6. 篡改病例—军役—军队关系、授权人、分诊 ID、批次所有权、事务来源、工时、技能或健康闭合时 `WorldState.Validate()` 拒绝。
7. V46→V47 不生成军药库存和历史医疗记录；V47 往返保存新增合同，旧兼容医疗记录仍可读取。
8. 全工程编译、聚焦测试、全量核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。
