# M25-P40 救护队员返军途中死亡、遗体归军与返程结案任务书

## 一、阶段目标

承接 M25-P28 的全员返军合同和 M25-P38/P39 的患者返军死亡合同，处理原救护队员已经建立真实返军旅程后，在尚未抵达来源军队前死亡的世界事实：

```text
具体救护队员仍在返军旅程中
→ 冻结死亡政策、路线、死亡时剩余里程和健康开闭值
→ 永久人物、人口、军籍、家庭继承和来源军队组织抚恤原子闭合
→ 原个人旅程继续表示同队护送遗体归军，死者不再消耗行粮
→ 患者和其他队员继续各自既有返程
→ 来源军队保持冻结，直至全部生者和遗体归抵
→ 死者军籍保持死亡，生还队员恢复现役，住院与后送记录统一结案
```

## 二、本阶段范围

1. 存档升级至 V62，新增数据驱动的救护队返军死亡政策、救护队员死亡记录、遗体随原旅程归军策略、队员死亡引用和次日启用边界。
2. 只处理后送记录已进入返军阶段、目标队员仍为医疗后送勤务、本人存活且具有非零剩余里程返军旅程的情形。
3. 允许患者仍存活、患者返军途中已死亡或患者已抵军等待队员期间已死亡三种既有返军状态；不改变患者既有死亡责任与遗体策略。
4. 队员死亡冻结后送、来源军队、所属组织、返程路线、起终点、开始日、个人返程旅程、死亡时剩余里程及健康开闭值。
5. 死亡必须永久保留人物身份，并一次闭合人口、军籍、个人财富继承、家主稳定继任、来源军队组织抚恤和人生事件；任一引用、权限、家庭或财政不合法时不得部分写入。
6. 死者原返程旅程继续作为遗体归军旅程，死者不再消耗个人行粮；其他患者和队员不重建、不改道各自旅程。
7. 返程任务只在全部活动旅程结束后结案；死亡队员军籍保持 `Dead`，生还队员恢复 `Active`，患者按其既有返程/死亡/退役策略结算。
8. V61→V62 只建立核心未来政策、空死亡集合、空队员引用、空继承/抚恤反向引用和次日启用边界，不从旧人物生死、返程进度或既有死亡倒推历史。

## 三、验收条件

- 合法返军队员死亡后，人物永久死亡、财富与抚恤守恒，原旅程和非零死亡里程保持可审计。
- 死者不再消耗行粮；遗体归军前军队不得行军，全部旅程结束后死者保持死亡、生还成员归队且医疗记录结案。
- 与患者存活、患者返军途中死亡、患者已抵军等待队员死亡三种状态组合时，既有患者闭环不被重写。
- 等待期不足、队员已经抵达、旅程缺失、军籍错误、权限不足、家庭或财政不足时，世界序列化结果保持不变。
- 篡改死亡策略、队员引用、路线、剩余里程、健康、继承、抚恤、旅程或遗体到达日时，`WorldState.Validate()` 拒绝。
- V62 往返保存完整；V61 迁移不制造救护队员死亡历史。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 和范围审阅分别完成。

## 四、明确不包含

- 救护队员在原始后送或跨院转运阶段死亡；
- 救护队员返军途中受伤、逃亡、失踪、被俘或主动脱队；
- 队员已经抵达来源军队后才死亡；
- 遗体改道、棺木、家属接回、安葬、讣告传播、医疗事故归责或额外赔偿；
- 自动每日死亡调度、动态追逐移动军队、多段返程和玩家医疗界面。
