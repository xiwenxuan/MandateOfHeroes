# M25-P33 伤后死亡、家庭继承与军队抚恤任务书

## 一、阶段目标

承接 M25-P31 的永久伤残/医疗退役和 M25-P32 的跨设施责任交接，建立第一条可审计的
战后死亡回写闭环：完成后方疗程并医疗退役的重伤员，仍可能在稳定等待期后因伤死亡；
人物永久档案不会删除，个人财产进入原家庭，死亡家主由仍在世家庭成员稳定继任，原军队
所属组织依冻结政策支付抚恤。

```text
已完成后方疗程与救护队返程的重伤退役者
→ 军队级权限确认伤后死亡
→ 永久人物转为死亡、军籍转为死亡、人口账减一
→ 个人财产完整转入原家庭
→ 必要时稳定选择新家主
→ 组织财政向同一家庭支付抚恤
→ 死亡、继承、抚恤和人生事件互相引用并可随存档往返
```

## 二、本阶段范围

1. 存档升级至 V55，新增数据驱动的伤后死亡政策、伤后死亡记录、家庭继承记录和军队
   抚恤记录。
2. 第一版只处理已经完成后方疗程、救护队已经返回、因永久伤残医疗退役且仍留在照护
   地点的伤员；转运途中、住院途中、返程途中死亡以及遗体运输留给后续任务。
3. 核心政策使用稳定命名空间 ID，冻结最低伤情、最高治疗后健康、完成照护后的最短等待
   天数、基础抚恤和军衔加成；新增普通政策不要求升级存档结构。
4. 结算前必须验证人物、伤情、住院、后送、军籍、家庭、继承人、军权和组织财政；财政
   不足或任何引用不合法时不得写入部分死亡、继承或付款事实。
5. 死亡只改变人物生死状态，不删除、合并或重新随机人物；原人物 ID、家庭成员关系、
   伤情、治疗、迁移和履历继续永久保存。
6. 个人财富先以继承账完整转入家庭，再以独立抚恤账接收组织付款；两条账分别保存开闭值，
   组织支出与家庭收入严格相等。
7. 死者是家主时，从仍在世家庭成员中按出生日期、稳定 ID 选择继任者；不是家主时只完成
   财产继承，不改写家主。
8. V54 迁移只创建核心政策和空历史集合，启用日设为迁移日下一天，不倒推旧死亡、继承
   或抚恤。

## 三、验收条件

- 符合政策的重伤退役者在等待期后可以一次性完成死亡、人口、军籍、继承、家主和抚恤回写。
- 家庭财富增加量等于死者个人财富与实付抚恤之和，死者个人财富归零，组织财政减少量等于
  抚恤金额。
- 财政不足、等待期不足、非重伤退役者、重复结算或错误权限均原子拒绝。
- 篡改政策快照、财富开闭值、继承人、组织财政开闭值或交叉引用会被 `WorldState.Validate()`
  拒绝。
- 当前 V55 存档往返保持全部死亡/继承/抚恤事实；V54 迁移不虚构历史。
- 完成全工程编译、核心测试、受控 Unity EditMode 测试、`git diff --check` 和差异审阅。

## 四、明确不包含

- 转运、住院或返程途中死亡；
- 尸体、棺木、安葬、祭祀和讣告传播；
- 抚恤欠款、分期支付、冒领、腐败或跨组织追偿；
- 多继承人份额、遗嘱、宗法争议、孤儿监护和土地/设施逐项析产；
- 自动全军每日死亡扫描、随机死亡概率或玩家界面。
