# M25-P37 原始战场后送中死亡、来源责任与遗体护送任务书

## 一、阶段目标

承接 M25-P27 的具体伤员道路后送、M25-P33—P36 的永久人物死亡闭环，把伤员死亡时点扩展到
“已经离开来源军队、尚未由后方指定医者接收”的首次战场后送阶段：

```text
活动原始后送或到达待接收
→ 数据政策冻结未正式诊断前的健康恶化与健康反推伤势
→ 永久人物、人口、军籍、继承和抚恤原子闭合
→ 后方接收尚未发生，不伪造诊疗点、住院、伤情或接收医者责任
→ 来源军队及原后送授权链继续承担交接前责任
→ 在途时原救护队沿原路线继续护送遗体
→ 全员抵达后遗体留置原定后方地点，救护队沿真实道路独立返军
```

## 二、本阶段范围

1. 存档升级至 V59，新增数据驱动原始后送恶化政策、原始后送死亡结案、后送死亡状态、交叉引用和次日启用边界。
2. 只处理 M25-P27 首次后送的 `InTransit` 与 `AwaitingReception` 两种尚未完成后方交接的状态；不创建住院、正式伤情、治疗、床位或药材事实。
3. 原始后送尚无正式伤情评估，因此结案以健康开值反推未诊断伤势严重度，并冻结政策、派出日、死亡日、健康开闭值、路线、死亡时剩余里程、起终点与指定接收医者；以后政策变化不得重算。
4. 死亡复用 V55 永久人物、人口、军籍、家庭继承、家主继任和组织抚恤闭环；任一权限、家庭、财政、旅程或交叉引用失败时不得先写部分事实。
5. 责任记录使用稳定策略 ID，冻结来源军队、所属组织、原后送批准人及死亡确认权限；指定接收医者尚未接收，不得成为责任医者，也不得生成接收日期、医术或责任交接。
6. 在途死亡保留患者原旅程，该旅程转为同一救护队护送遗体；死亡人物不再消耗个人行粮。全员抵达后后送进入救护队待返状态，遗体留置原定目的地。
7. 到达待接收时死亡直接进入救护队待返状态；患者不再接收、不住院、不参加返军。
8. 既有返军入口扩展为允许“没有住院记录但具有原始后送死亡结案”的救护队，从原定后方地点沿明确路线返回当前来源军队；来源军队仍不得在返程期间移动。
9. V58→V59 只补核心未来政策、空结案集合、空引用和次日启用边界，不根据旧活动后送、人物健康、路线进度或既有死亡倒推历史。

## 三、验收条件

- 在途死亡冻结非零剩余里程、健康和反推伤势，患者死亡但原旅程与救护队旅程继续存在。
- 全员抵达后遗体位于原定后方地点，指定接收医者没有接收或医疗责任事实；救护队可独立返军并恢复现役。
- 到达待接收死亡不产生接收、住院、正式伤情或责任移交事实，直接取得救护队返程资格。
- 等待期不足、健康阈值不符、已完成接收、错误权限、家庭/财政/旅程事实不完整时原子拒绝。
- 篡改来源军队、路线、剩余里程、健康开闭值、反推伤势、授权人、指定接收人、状态或交叉引用时世界校验失败。
- V59 往返保留全部事实；V58 迁移不制造原始后送死亡。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 和范围审阅分别完成。

## 四、明确不包含

- 患者或救护队返军旅程中的死亡；
- 途中急救、车辆/担架耐久、天气、袭击、改道、拒收和第二接收目的地；
- 遗体改道、棺木、安葬、家属接回、讣告传播和关系反馈；
- 医疗事故过失比例、司法追责、额外赔偿、抚恤欠款和复杂析产；
- 自动每日死亡调度和玩家医疗界面。
