# M15-P5 补充报告：5000万全在世索引与日月年推进

## 一、结论

2026-08-02，M15-P5在既有5000万全部在世数据上完成了家户、职业、地区和按日到期
索引，并分别完成1日、30日和365日三个独立推进窗口。所有窗口均把5000万人的紧凑
在世核心与职业码保持在内存中，只读取窗口内的到期分区；没有删除、合并、替代或重新
随机任何永久人物。

本结果证明当前机器能承担“5000万基础在世记录常驻 + 分区到期调度 + 固定长度变更
写回”的独立压力原型。它不证明5000万份完整NPC AI、关系网、生产、战争、寻路、
Unity对象或正式游戏存档已经可运行。

- 扫描数、变化人数和写回数严格相等；
- 1日和30日扫描量小于5000万，365日严格覆盖5000万人；
- 每个到期ID均校验连续人物ID、家户、职业和地区；
- 每条20字节写回保存人物ID、处理日、下一到期日、事件类型、职业和地区；

摘要与写回数一致，确定性验证通过。

## 六、结论边界与后续

本补测修正了“只验证5000万基础记录可常驻，却没有实际推进”的证据缺口。正式人口
适配器现在可以依据以下结构继续设计：追加式永久核心、全在世紧凑索引、可重建家户/
职业/地区索引、按日分区到期队列、固定长度变更日志和死亡冷档案。

仍未验证的高成本部分包括：

- 5000万人同时运行完整人物属性、关系网络和逐人AI；
- 生产、消费、迁徙、疾病、战争等多个系统在同一年度同时改变大量人物；
- 5000万大量在世者与超过5000万累计死亡冷档案同时存在；
- 正式V6/V7存档迁移、创建世界UI和Unity运行时接入。

因此下一阶段仍应先建立正式分区人口存储适配器与V6/V7共存迁移任务书，不应直接把
实验二进制格式宣布为正式存档格式。
