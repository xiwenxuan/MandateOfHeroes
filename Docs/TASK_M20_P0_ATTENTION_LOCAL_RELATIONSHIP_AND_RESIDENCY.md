# M20-P0 任务书：关注系统、局部关系网络与人物冷热驻留触发

## 一、阶段目标

在 M12 永久人物规则与 M15-P6 分区人口驻留合同之上，建立第一版可持久、可审计、可确定性重放的关注闭环：

```text
玩家或系统提出关注原因
→ 同一目标按原因叠加关注等级
→ 按人物、家庭、村庄或组织局部展开关系邻域
→ 生成有上限的热人物计划
→ 分区人口会话升温或安全降温
```

关注只改变加载、信息与表现精度，不改变人物属性、关系、生产、战斗或其他世界事实。冷人物仍然具有永久身份和完整持久扩展；不得删除、合并、替代或重新随机。

## 二、权威边界

- 永久人口、关注层级与关系局部展开以 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md` 为准。
- 热冷扩展、升温和安全降温以 `TASK_M15_P6_FORMAL_PARTITIONED_POPULATION_ADAPTER_AND_RESIDENCY_CONTRACT.md` 为准。
- 稳定 ID、确定性顺序和顺序迁移以 `DETERMINISTIC_SIMULATION_AND_SAVE.md` 为准。
- 本阶段新增的是运行底座，不代表人物认知、地图情报、全部事件触发器或正式 UI 已完成。

## 三、实施范围

### WP1：V11 关注原因账

- 新增人物、家庭、村庄、设施和组织五类关注目标。
- 每条关注原因独立保存观察者、目标、等级、原因 ID 和变更时间。
- 同一目标的有效等级取全部原因中的最高等级；移除一个原因不得误删其他原因。
- 每次新增、升级、降级或移除都写入不可变的关注账记录。
- V10→V11 顺序迁移只初始化关注集合，不改变人物、家庭、关系和人口存储合同。

### WP2：局部关系网络

- 从一个人物按需展开家庭成员、显式双向关系邻居、共同组织成员和所属村庄。
- 展开顺序使用稳定 ID，人物数量受调用方上限约束。
- 返回的是派生快照，不向 `WorldState.Relationships` 制造共同成员的两两关系。

### WP3：关注到热人物计划

- 玩家当前控制人物始终进入热人物计划。
- 普通人物关注只升温目标；深度人物关注同时展开局部关系邻域。
- 家庭、村庄、设施和组织关注按等级选择负责人或有限成员。
- 多个关注原因和目标合并去重，超过上限时按稳定优先级截断。

### WP4：分区驻留协调

- `PopulationResidencySession` 接受热人物计划并升温缺失人物。
- 不再需要的人物只调用既有 `DemoteUnchanged` 安全降温。
- 已修改但未提交检查点的人物不得被丢弃，应留在热集并在结果中明确报告。
- 协调结果记录升温、降温、脏数据保留和最终热集，便于测试与后续 UI 审计。

### WP5：验证与文档同步

- 当前 V11 快照往返保留关注原因与账目。
- V10 迁移到 V11 后人口、人物、家庭、关系和存储元数据不变。
- 验证关注变化不改人物和关系事实，局部关系网不制造新边。
- 验证深度关注升温邻域、取消关注安全降温、脏热人物拒绝丢弃。
- 更新系统总纲、M12 状态、确定性存档说明和 Skill 任务路由。

## 四、不纳入本阶段

- 全部任务、旅程、战斗、工程和历史事件的自动关注触发器。
- 人物知识、组织知识、情报时效和地图迷雾。
- 关系词条、关系传播、社交 AI 与完整关系网络界面。
- 将全部 `WorldState.People` 从主快照移出；V11 继续兼容 M15-P6 的内联世界与外部分区包并存边界。
- 自动提交脏人物检查点；本阶段只拒绝静默丢弃。

## 五、验收标准

1. 多个关注原因可以独立增删，同一目标有效等级正确合并且全部变化有账可查。
2. 局部关系网络结果稳定、有上限，并且构建前后显式关系集合完全相同。
3. 玩家控制人物始终为热；普通关注升温目标；深度关注按上限升温局部邻域。
4. 取消关注后未修改人物可降温，已修改人物保留在热集并明确报告。
5. 关注操作不改变人物属性、家庭成员、关系值、人口数量或永久存储记录。
6. V10→V11 为顺序迁移；当前版本快照往返保留关注状态与账目。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和差异审阅通过。

## 六、执行记录

### 6.1 实现结果

- 世界模式升级到 V11，新增 `AttentionFocusState` 与 `AttentionLedgerEntryState`，同一目标可按稳定原因 ID 独立增删和取最高有效等级。
- `AttentionSystem` 已支持人物、家庭、村庄、设施和组织目标，并提供确定性、有上限的局部关系网络与热人物计划。
- 玩家控制人物始终进入热计划；普通关注加载直接责任人，深度关注进一步展开家庭、显式关系、村庄或组织成员。
- 局部关系网络只返回派生快照，不向世界关系表写入共同家庭、村庄或组织成员的虚构边。
- `PopulationResidencySession.ReconcileAttention` 已接入升温、安全降温和脏人物保留结果；未提交检查点的热人物不会被静默丢弃。
- V10→V11 迁移只初始化关注集合，既有人物、家庭、关系和人口存储模式保持不变。
- 系统总纲、M12实施状态、确定性存档说明和 Skill 任务路由已经同步。

### 6.3 保留限制

- 当前只接入手动或调用方显式写入的原因；任务、旅程、战斗、工程和历史事件尚未自动登记关注。
- 人物热计划已经可以驱动分区驻留会话，但既有模拟系统仍直接读取内联 `WorldState.People`。
- 局部网络尚未展开到县郡、政权和人物知识层，也没有正式游戏界面。
- 脏人物会保留在热集；自动写入增量检查点属于下一阶段人物仓储访问层任务。
