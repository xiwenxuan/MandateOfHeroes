## 2. 一句话认识项目

《群雄志：仕途》（Mandate of Heroes）是一款以东汉末年至三国时代为主要历史舞台的
开源单机家族人生模拟、角色扮演与战略沙盒游戏：玩家可自建任意人物或选择世界中的
历史人物，以不同身份生活数代，并通过家庭、职业、组织、经济、建设和战争持续改变同一世界。

玩家主要选择 135—260 年之间的年份开局；260 年不是强制终局，世界可以继续演化。

## 3. 核心体验

- 玩家不是只能扮演君主；可以成为军人、武将、士人、官吏、商人、侠士、医者、家主、
  农户、工匠、宗教人士、密探等具体人物。
- 人物可以拥有主身份、有限社会身份、隐藏身份和多个真实组织职位。身份决定玩法入口，
  职位与授权决定能够合法支配的资源。
- 玩家可以细致经营，也可以下达目标、政策或委任，让太守、军团、商号、家庭等组织代理执行；
  两种操作方式必须使用同一本世界账。
- 一代人会成长、受伤、衰老和死亡；家庭、产业、知识、关系、债务与历史后果由后代继承。
- 战争不是背景动画。大地图行军、军团指挥、兵种、装备、补给、局部战斗、个人比武、
  辩论、剿匪和战后回写都属于长期正式玩法。
- 世界不围着玩家停止。NPC 家庭、组织、市场、生产、治理、迁徙、战争和历史事件持续运行。

## 4. 不可破坏的统一世界原则

### 4.1 一个世界、一本事实账

人物、家庭、土地、资源、设施、库存、市场、组织、军队、财政和事件只能有一份权威事实。
战略地图、城镇地图、建筑界面、战场和报表是对这些事实的不同比例尺读取与操作，不能各建
一套互不相干的 Demo 数据。

世界只在创世时初始化一次。缩放、切换视角、进入场景或关注人物不得凭空生成第二套人口、
资源、建筑或库存。

### 4.2 永久人物

每个人从出生起具有稳定且永久的身份。不活跃人物可以降为冷档案，减少计算和表现数据，
但不得删除、合并、替代或重新随机。死亡者仍保留身份、亲属、经历和世界后果。

史料人口只作分布和比例参考，玩家按硬件选择人口缩尺。正式长期目标是单局累计约 5000 万
永久人物，不等于承诺开局或同时在世 5000 万人都以最高精度运行。

### 4.3 守恒、确定性与存档

人口、兵员、物资和财政变化必须有来源、去向和审计记录。运输粮食会因人畜自用、腐败、
道路、天气、包装、劫掠或事故产生真实损耗；守恒要求损耗有原因和账目，不表示货物永不减少。

随机行为使用稳定 ID、明确时间或动作坐标和项目确定性随机机制。存档是兼容合同：持久结构
变化必须顺序迁移、往返验证并保持关键不变量。

### 4.4 数据驱动的开放内容

作物、产品、配方、设施、技艺、词条、科技、装备、兵种、任务等可持续扩展集合优先使用
稳定命名空间 ID 和数据定义。增加普通内容不应要求升级存档；缺失内容 ID 不能静默改指、
删除或重新随机。只有生命周期、协议状态等真正封闭集合才适合枚举。

### 4.5 有限知识

玩家只能看到当前人物亲历、获准查阅或合法持有的信息。个人记忆、家族档案、商号账簿、
官府户籍、军情和密报分别属于不同知识主体；人物离任后不会继续自动获得原组织的新情报。

信息可由具体人物抄录到个人或家族档案，但需要载体、识字能力、工作时间和保管成本。地图、
建设、资源、贸易、战争等专题视角都必须基于观察者已经掌握且可能过期的信息。

### 4.6 设施、产权与权力分账

HanWorldV1沿用2000米Cell；一个Cell同一时刻只有一个Owner、一个基础Facility槽和一个独立
Force槽。Facility与Force可以使用不同占用槽共存。Facility采用数据驱动的
Definition/Profile/Instance，宫廷、家族、官府和民间不各建一套建筑系统。

行政管辖、产权、设施运营、官职、军职、爵位和实际兵权分别保存。皇帝、皇室组织和国家资产
也必须分账；王国与郡同级，但封国不改变区域内全部Cell产权。详细规则见
[`UNIFIED_WORLD_FACILITY_AUTHORITY_AND_POLITICAL_AI.md`](UNIFIED_WORLD_FACILITY_AUTHORITY_AND_POLITICAL_AI.md)。

## 5. 地图与空间方向

所有比例尺展示同一个连续世界：

```text
天下战略图
→ 州／郡区域图
→ 县域与乡野图
→ 城镇空间图
→ 村庄／庄园图
→ 具体建筑与室内功能
→ 局部战术战场
```

- 天下图采用原创“东汉军府舆图＋绢本设色＋山水战略图”方向，追求山河之间坐落城池、
  关隘与军队的宏观自由感，但不得临摹《三国志11》等商业游戏的地图、笔触、UI 或素材。
- 城镇图不是建筑卡片墙。街巷、城门、水系、坊区和建筑形成可读空间；点击建筑本体后，
  才进入市场、仓库、商行、官署、医馆等真实功能。
- 历史地形和稳定地标可以进入底图；军队、库存、价格、火灾、布防、建设进度等动态事实
  由数据图层表现，不能画死在原画中。
- 玩家所见受个人或组织知识限制；过期侦察显示时间戳、可信度和来源。

当前 M26-P5B 中山空间实现是通过自动验证的候选原型，不代表正式美术和最终城镇玩法已经
获得产品验收。最新产品决策是：继续扩展空间地图代码前，先以原创样图确认各级地图的视觉
语言，再按确认结果修订中山纵向切片。

## 6. 系统如何共同运行

```text
具体人物与家庭
→ 提供劳力、技能、消费、关系和继承
→ 加入或建立官府、军队、商号、家族、师门等组织
→ 在具体土地、资源与设施中建设和生产
→ 形成库存、市场、运输、税收、财政与军需
→ 通过治理、任务、外交、情报和战争改变地方与天下
→ 后果回写人物、家庭、组织、设施、地理与历史进程
```

科研、技能和属性不是互不相干的加点菜单：属性影响学习与执行效率，技能通过实践和教育成长，
知识或配方决定人物知道什么，科研把知识转成可验证方案，设施应用才把方案转成实际的生产、
医疗、治理或战争效果。

## 7. 代码架构边界

| 程序集 | 职责 |
|---|---|
| `Mandate.Domain` | 纯 C# 世界状态、不变量、稳定身份和确定性领域规则 |
| `Mandate.Simulation` | 跨实体行为、时间推进、系统调度、命令和事务编排 |
| `Mandate.Persistence` | 序列化、存档版本、迁移、检查点与兼容 |
| `Mandate.Presentation` | Unity 场景、界面、输入、动画和视觉表现 |

核心世界事实不得只存在于 `MonoBehaviour`、场景对象或 UI；`Mandate.Domain` 不得反向依赖 Unity。

## 8. 状态术语

| 状态 | 含义 |
|---|---|
| 已有原型 | 已经能在 Unity 原型中操作并观察结果 |
| 已有底座 | 关键数据或最小闭环已有代码，但内容、规模或表现不完整 |
| 已定方案 | 设计已经确认，尚未形成正式可玩实现 |
| 待研究 | 方向存在，但数据、性能或实现方法仍需验证 |

任务书已建立、代码可编译、自动测试通过和玩家已认可，是四种不同事实，必须分别报告。

## 9. 当前实现快照

### 已能运行或已有可操作原型

- Unity 2022.3.62f3c1 工程与 `Assets/Scenes/PlayableDemo.unity`；
- 自建人物或选择世界人物、初始身份和地点；
- 时间、地图旅行、行动、事件、任务、建设、生产、贸易和局部战斗的首个共享账闭环；
- 商旅行情、筹资、采购、运输事件、交付和家庭长期选择的候选路线；
- 中山可进入城镇、七座持久设施和商号总部／仓库的候选切片；
- 军队编制、权限、行军、补给、简化战斗、军械生产和采购运输等缩尺原型。

### 已有较深底座但远非完整成品

- 永久人口、家户、冷热关注、分区存储和百万级长期人口压力实验；
- 数据驱动作物、产品、配方、批次、库存事务、生产加工和多维品质；
- 家庭粮食、县级市场、仓储损耗、民用与军用运输、赈济和财政链；
- 人物属性、教育实践、技能知识、科研项目与设施应用；
- 民间和军队医疗、伤员后送、家庭继承与责任审计等后端合同。

### 不得误报为已经完成

- 全国连续比例尺地图、正式原创地图美术、完整城镇建筑空间和室内行走；
- 全国商号、NPC 商号竞争、完整招募工资、载具、水与疲劳、产业和经营委任；
- 所有身份成熟玩法、完整组织 AI、完整统一战争和正式 223 年剧本；
- 5000 万永久人物的完整游戏负载保证；
- 独立玩家 20—30 分钟盲玩验收。

精确、最新状态必须读取 [`GAME_SYSTEMS_MASTER_AND_STATUS.md`](GAME_SYSTEMS_MASTER_AND_STATUS.md)。

## 12. 开工检查表

- 确认用户要讨论、诊断、写文档还是修改代码；
- 检查 `git status`，保护用户已有和无关修改；
- 从任务路由选择最小必要文档，不以编号推断优先级；
- 检查现有实现和测试后再提出新抽象；
- 涉及存档、架构、玩法方向或公开行为的假设必须明说；
- 外部代码、数据和素材先确认兼容许可证并登记来源；
- 代码按编译、核心测试、受控 Unity 测试、差异检查和审阅验收；
- 外部工具遵守 300 秒硬超时，不关闭用户正在运行的程序；
- 未经明确授权不提交、不推送、不创建 PR。
