# 《中华三国志》开源许可与接入审计

## 一、结论

《中华三国志》可以免费游玩，其可定位的官方关联源码采用 Microsoft Public License
（Ms-PL）发布。Ms-PL 是 OSI 批准的开源许可证，允许复制、修改、制作衍生作品和分发，
同时提供相应专利授权。

这不等于整款游戏的全部文件都能并入本项目：

- 源代码可以在遵守 Ms-PL 的前提下使用；
- 源码形式分发任何原代码或衍生代码时，相关部分必须继续使用 Ms-PL，并附完整许可证；
- 必须保留原有版权、专利、商标和署名声明；
- Ms-PL 不授予《中华三国志》名称、标志或其他商标的使用权；
- 地图、美术、头像、音乐、音效、字体、剧本资源和整合包不自动适用源码许可证；
- 官方公开说明要求使用资源前联系团队，部分历史版本还混有单独授权或第三方资源，
  因此本项目不得导入这些资源。

## 三、技术兼容性审计

审计源码不是 Unity 包，而是面向 .NET Framework 4.5 和 XNA/MonoGame 体系的完整游戏工程。
主要世界类高度集中：审计版本中的 `Architecture.cs`、`Troop.cs`、`Person.cs` 和
`Faction.cs` 分别达到数千至一万余行，并广泛依赖全局 `Session`、XNA 类型和表现层。

因此禁止下列“接入”方式：

1. 把完整工程复制到 Unity `Assets` 下并尝试直接编译；
2. 把 XNA、全局 Session、UI 和世界状态连同搬入本项目；
3. 用其地图、数值表、人物数据或表现资源覆盖本项目原创内容；
4. 仅因仓库公开就把第三方源码改标为本项目 MIT 代码；
5. 把“可阅读参考”写成“已经完成系统接入”。

## 四、首批转换选择

首批参考源码中的 `SectionAIDetail`，它表达了地区或军团委任时的两类信息：

- 权限：粮食调拨、资金调拨、军队调拨、整军、训练、调查和发动战役等；
- 倾向：农业、商业、征募、训练、科技、防守和进攻等优先级。

本项目没有复制该文件的代码、字段布局或序列化结构，而是依据上述玩法问题重新设计：

- 所有命令、政策和优先级采用稳定命名空间 ID；
- 开放内容集合不使用固定枚举；
- 权限与优先级分离；
- 候选行动按明确权重计分；
- 同分时按稳定候选 ID 决定，保证重放确定性；
- 领域定义位于 `Mandate.Domain`，决策编排位于 `Mandate.Simulation`；
- 当前不修改世界存档版本，不伪造太守、军团或组织已经绑定该政策。

由于本批是独立重写而非复制或修改 Ms-PL 源文件，新文件继续随本项目 MIT 许可证发布。
未来若直接复制、翻译或修改任何 Ms-PL 源码，必须把该部分隔离登记、保留原声明并附完整
Ms-PL 文本，不能把它改称 MIT。

## 五、当前接入状态

已接入的是“战略委任政策合同和确定性选择器”，不是《中华三国志》整套游戏：

- 三种核心政策：均衡经营、商贸振兴、边郡固守；
- 十一种首批战略命令；
- 八种可扩展优先级；
- 权限过滤、权重评分、稳定 ID 同分裁决；
- 重复候选 ID、非法 ID 和越界权重拒绝；
- EditMode/核心测试入口。

后续应先把政策绑定到真实职位、组织和授权范围，再让县令、太守、军团都督或玩家托管
产生真实世界命令；不得直接让政策改数字、凭空调拨粮食或越权发动战争。
