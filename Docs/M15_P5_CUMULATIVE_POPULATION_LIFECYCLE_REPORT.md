# M15-P5 累计永久人物、冷热档案与长期增长压力报告

## 一、结论

M15-P5已建立独立的累计永久人物容量模型、追加式永久核心、双槽在世热索引、死亡冷档案
和可续跑检查点。8项冷热自测试通过；从10万开局在世人物出发，同一工作区依次续跑到
累计100万、500万和1000万永久人物，三个阶梯均通过。用户指出在世峰值缺口后，又完成
100万至5000万的十一级全热集矩阵，全部基础核心与紧凑常驻索引通过。

本报告关闭P5及全热补测，不代表正式V6/V7存档已经接入，也不代表5000万完整游戏运行时
已经通过。

## 二、容量模型

原型明确区分：

- 史料参考人口与玩家缩尺比例；
- 开局、当前与峰值在世人口；
- 累计永久人物与死亡冷档案；
- 带明确年限的长期累计预测；
- 玩家提供的内存、磁盘预算与压力等级；
- 接近或超过累计5000万时的性能警告与出生许可。

本轮复现配置使用5000万史料参考、20基点缩尺，实际开局10万人；容量示例按125年、
年出生率和死亡率各300基点估算，得到预计出生37.5万、死亡37.5万、累计47.5万人。
该配置只验证计算合同，不是东汉历史人口预测，也不是推荐档最终参数。

## 三、物理原型

```text
permanent-core.bin
  追加式永久人物核心，41字节/人

living-hot-0.bin / living-hot-1.bin
  当前在世人物和下一生命周期日，45字节/在世人物

deceased-cold.bin
  死亡人物ID、死亡日与原因，13字节/死者

manifest.json
  守恒计数、确定性参数、活动热槽和三个文件摘要
```

每个批次先追加永久核心和冷档案，再写入非活动热槽，最后原子替换清单并切换活动槽。
若进程在清单提交前中断，恢复时读取旧活动槽，并把追加文件截断到旧清单计数；不会重复
出生、跳过ID或重随机既有人物。

## 四、自测试

1. 史料参考按基点缩尺并明确舍入；

3. 相同输入产生相同容量估计；

## 六、证据边界

- 压力负载保持10万人在世并按顺序死亡/出生替换，用于放大累计档案；不是历史生育、
  疾病、战争或迁徙模型；
- 永久核心只包含P5合同所需的ID、父母、家户、出生时间、地区和性别，当前体积不能
  外推完整人物属性、履历、生产、战争和认知数据；
- 峰值工作集证明热集与累计档案可以分离，不证明完整游戏运行时只需要相同内存；
- 硬件压力使用传入预算，不包含正式自动硬件检测和最低配置承诺；
- 5000万全部在世的基础核心与紧凑调度索引已经通过，详见
  [`M15_P5_ALL_HOT_UPPER_BOUND_REPORT.md`](M15_P5_ALL_HOT_UPPER_BOUND_REPORT.md)；家户、
  职业、地区、分区到期队列和日/月/年基础推进也已通过，详见
  [`M15_P5_FULL_LIVING_INDEX_AND_SCHEDULING_REPORT.md`](M15_P5_FULL_LIVING_INDEX_AND_SCHEDULING_REPORT.md)；
  完整人物属性和其他游戏系统仍未进入该负载；
- 10万在世的冷热生命周期只累计到1000万，尚未验证超过5000万后大量在世者与大量
  死亡冷档案同时存在的混合上界。

## 七、决策

P5证明正式人口存储设计必须至少分离：追加式永久核心、可切换的在世热索引、死亡冷档案
和原子清单。全热补测进一步证明正式适配器不能假设在世人数始终很小；5000万人都活着时
仍须保留全量基础核心，而分区到期队列已证明日/月窗口不必扫描全员，只有到期或受关注者
进入更昂贵视图。下一任务可以进入正式分区
人口存储适配器与V6/V7共存迁移设计，但仍须先建立新任务书并取得用户确认。
