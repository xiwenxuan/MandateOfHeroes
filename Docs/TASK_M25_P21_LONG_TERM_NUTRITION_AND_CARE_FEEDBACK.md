# M25-P21 任务书：长期营养、营养性疾病风险与照护反馈

## 一、任务定位

承接 M25-P10 的正式家庭月度进食、M25-P17 的真实救济进食恢复、M25-P18 的逐人份额和
M25-P20 的家庭照护送餐审计。本阶段把单月缺粮从即时健康损失扩展为人物长期营养事实：
连续缺粮形成营养债和营养性疾病风险，实际被具体人物吃掉的救济营养才冲减营养债，后续
充足进食按月逐步恢复。

本阶段只建立营养不足导致的疾病风险原型，不宣称完成传染病、病原传播、药方、诊断、死亡
判定或完整医疗职业玩法。

## 二、实现范围

### 2.1 V43 稀疏永久合同

- 新增按人物稳定 ID 保存的长期营养档案；只有发生过营养短缺的人物才建立档案。
- 新增追加式营养变更账，逐笔保存月度短缺、充足月份恢复和实际救济进食抵扣。
- 新增营养性疾病发作记录，保存稳定数据 ID、起止日期、累计健康伤害和恢复量。
- 营养政策和疾病内容使用稳定命名空间 ID；账目事件类型属于封闭协议状态，可以使用枚举。
- V42→V43 只初始化空集合，不根据旧健康值、旧救济单或玩家关注状态伪造长期营养历史。

### 2.2 月度营养结算

- 复用正式家庭食品结算已经访问的本村家庭成员，不新增全世界人物扫描。
- 月度短缺按 M25-P18 已冻结的逐人缺口记入人物营养债。
- 连续短缺提高疾病风险；首次短缺保留缓冲，达到连续月份和风险阈值后才建立营养性疾病发作。
- 疾病生效后产生独立、可追溯的长期健康伤害，不替代 M25-P10 的即时饥饿伤害。
- 已有营养档案的人物在完整供给月份逐步降低营养债和风险；连续恢复达到条件后结束发作，
  但历史记录永久保留。

### 2.3 家庭照护反馈

- M25-P20 的准备营养或可追溯食品只有在具体受助人实际获得营养后才写入抵扣账。
- 照护者只负责交付；营养债归实际受助人，不得记到照护者名下。
- 无合格照护者、未送达、只取粮未进食或仍保留在准备营养余额中的物资不能降低风险。
- 旧 V42 消费单可继续运行；没有 V43 营养档案时不得倒推或补造历史抵扣。

### 2.4 校验与确定性

- 领域校验逐人物重放营养账的开闭债务、风险和连续月份，最终必须与当前档案闭合。
- 救济抵扣必须引用真实消费单和受助人；库存事务存在时必须引用同一消费单和受助人。
- 疾病发作的健康伤害与恢复必须和引用该发作的营养账闭合。
- 相同世界事实产生相同人物顺序、账目 ID、风险和健康结果，不使用集合插入顺序或玩家关注度。

## 三、验收标准

1. 两次连续严重缺粮会建立同一人物的长期营养档案、追加账和营养性疾病发作，并产生额外健康伤害。
2. 实际救济进食按具体受助人精确冲减营养债；照护者不会获得受助人的营养抵扣。
3. 完整供给月份逐步降低营养债和风险，并可在满足恢复条件后关闭发作而不删除历史。
4. 篡改账目开闭值、风险、救济来源、人物引用或疾病伤害闭合会被领域校验拒绝。
5. V42 存档迁移到 V43 时三个新集合为空，不根据旧状态推定历史；V43 可往返保存。
6. 全工程编译、完整核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。

## 四、非目标

- 不实现传染病传播、流行病地图、药材处方、医生诊断、护理工时或死亡概率。
- 不扫描未加载人口，不让关注层级改变营养事实，不创建临时人物或替代永久人物。
- 不重写 M25-P10 即时饥饿伤害、P18 份额、P19 授权优先级或 P20 照护者选择。
- 不提交或推送仓库；版本操作需要用户另行授权。
