# M23-P6 多段军需运输、中转交接与分批收货任务书

## 1. 阶段目标

在M23-P5真实军粮批次、承运责任、自用补给、自然损耗和货运审计之上，建立第一条
持久化多段运输闭环：

```text
起运承运人装货
→ 第一段真实旅行
→ 中转地点双方人物和容器会合
→ 下段预留口粮真实出库
→ 货物保管责任转移并启动下一段旅行
→ 最终与目标军队会合
→ 一次或多次按实收货
```

运输分段是领域事实，不由地图缩放、玩家关注或表现层临时推算。

## 2. 必须完成

1. 每张新军需货运单持久保存最终目的地、当前分段、计划分段数和自动/手动最终收货策略。
2. 每段保存顺序、起终点、路线、承运人物、承运组织、运输容器、口粮批次、计划/装载/消费数量、
   货物接收/转交数量、旅程、起止日期和生命周期状态。
3. 发运前校验全部路线连续，最终地点可由目标军队接收；增加普通路线或承运内容不要求新增枚举。
4. 下游承运人和容器必须在中转点等待；交接时双方人物及容器必须同地，否则拒绝且世界不变。
5. 下段口粮在计划时进入真实批次预留账，在交接时同时减少批次数量和预留量，并进入通用库存流水。
6. 交接后当前承运人、组织、容器、路线、旅程和分段顺序同步更新；货物数量只转移保管责任，不复制。
7. 每段继续结算承运队口粮和确定性自然损耗，并保留分段统计与全单守恒审计。
8. 最终支持自动全量收货或手动分批收货；每批只按实际数量增加军队口粮和军需记录。
9. 存档升级到V20；V19旧单保留为无分段历史的兼容单，迁移不得伪造旧中转记录。
10. 自动测试覆盖两段交接、承运人缺席拒绝、分批收货、V20往返和V19顺序迁移。

## 3. 不在本阶段

- 自动寻路、任意段数路径搜索、临时改道、撤单及释放未使用预留；
- 一单拆成多支车队并行运输、不同目的地分拨和途中合单；
- 民夫、逐辆车马船只、驿站换马和装卸工时；
- 天气、路况、包装、污染、税卡、保险、信用和运费竞价；
- 押运遭遇、盗匪战斗、截粮、夺回货物和人员伤亡；
- 太守、都督、主将的递归军需委任及正式玩家界面；
- 通用民用多段货运和移除`ArmyState.Provisions`兼容桥。

## 4. 验收结果（2026-08-03）

- 新军需单建立持久分段合同和V20顺序迁移；
- 两段商队可在安平完成真实交接并继续运往广宗；
- 下段口粮预留、装载和库存流水可以重算批次数量与预留量；
- 承运人缺席时交接被拒绝，快照无变化；
- 最终收货支持手动分批并保持货物、军队口粮和货运流水平衡；
- 全工程编译通过；核心测试`221/221`通过；`git diff --check`通过；
- Unity EditMode本轮未运行：上一阶段同一环境两次受控启动均未创建启动日志，已确认批处理环境阻塞。

当前成果是预先规划路线的多段军需原型，不得描述为自动州郡物流网。
