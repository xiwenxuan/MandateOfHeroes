# M25-P23 正式草药供应：采集、初加工与县内补货任务书

## 一、阶段目标

把 M25-P22 已经能够消耗的草药材，从“开局直接赠送库存”推进为可以在同一世界账中真实产生和流通的供应链：

```text
有来源等级的野生药草资源体
→ 永久人物参加家族采集订单
→ 家族设施中的原药草批次
→ 晾晒、拣选加工订单与技艺成长
→ 可交易草药材批次
→ 县内正式市场买卖与医者家族补货
→ 既有诊疗系统按批次消耗
```

本阶段验证“生产—市场—医疗”的第一条跨系统闭环，不以 UI 数量、抽象商店库存或无来源补货替代世界事实。

## 二、范围

### 2.1 本阶段完成

1. 增加稳定命名空间 ID 的原药草产品、晾晒拣选配方、加工方法、技艺和设施能力标签。
2. `VillageFacilityState` 增加开放能力标签；普通内容扩展不新增设施种类枚举。
3. 资源采集订单支持组织和家族两种互斥所有权模式；家族模式必须引用真实家庭、设施、管理者和劳动者。
4. 家族加工订单按设施能力标签校验，不再只能依靠固定 `VillageFacilityKind`。
5. 县内正式市场支持所有带 `product.market` 标签的产品；粮食原有行为保持不变。
6. 村庄原型生成可追溯野生药草资源体，并让一个确定选择的采集家庭具备采集、晾晒能力。
7. 每日供应规划只遍历已加载村庄和村庄家户：库存不足时依次建立采集、加工、出售和医者家族购买订单。
8. 新增存档 V45 迁移，补齐设施能力集合与家族采集字段默认值，不伪造历史订单、批次、交易或资源变化。

### 2.2 明确不做

- 不做跨县自动未知货源、远程货运与瞬间补货。
- 不做医生工时、诊金、处方组合和病例关闭；这些进入 M25-P24。
- 不做军事医疗、复杂疾病谱、采药 UI 和地图表现。
- 不删除、合并或重新随机任何永久人物。

## 三、领域与确定性约束

1. 原药草与草药材是两个不同产品定义；加工前后均为真实批次并守恒重量。
2. 资源体记录 `historical_fact`、`historical_inference` 或 `gameplay_completion` 来源等级；原型采用合理推断，不冒充精确史实。
3. 家族采集必须由同村、存活、有劳动能力的本家永久人物执行；关注度不改变订单结果。
4. 家族设施能力使用稳定字符串 ID，配方与资源体只引用能力 ID，不把开放内容塞入枚举。
5. 县内交易转移保留批次产品、品质、产地、生产日和来源链；现金、预留量、设施容量同时记账。
6. 同一种子、同一初始状态和同一日序列得到相同的采集家庭、订单、批次与交易。
7. 自动供应不得扫描全局永久人口表；只允许沿 `WorldState.Villages → HouseholdIds → MemberIds` 的已加载边界查找候选人。

## 四、存档合同

世界存档从 V44 升级到 V45：

- `VillageFacilityState.CapabilityTags`：旧设施补入其固定种类对应的规范标签。
- `ResourceExtractionOrderState.OwnerFamilyId` 与 `StorageFacilityId`：旧组织订单保持空值。
- 内容清单刷新到本阶段核心生产内容版本。
- 迁移不得创建资源体、采集订单、加工订单、批次、市场订单、交易或账本记录。
- V45 必须通过往返存档与篡改拒绝测试。

## 五、验收用例

1. 内置 C# 内容包与 JSON 内容包哈希、版本和定义数量一致。
2. 家族采集：资源预留、完成、资源余量、设施库存、批次与两条采集账本完全闭合。
3. 非本家人物、异地人物、无能力标签设施和超容量落库均被拒绝且不产生部分写入。
4. 原药草经晾晒拣选生成草药材，输入输出重量守恒，品质按现有多维品质规则产生，管理者技艺可成长。
5. 草药材在同县不同家庭之间完成正式市场交割，批次、预留、现金、容量和交易审计闭合。
6. 医者家族获得的草药材可被 M25-P22 正式诊疗消耗；不存在无来源补货。
7. 自动供应链在相同种子和天数下快照一致，并且不会为库存充足或已有活动订单重复下单。
8. V44→V45 迁移和 V45 往返通过；篡改所有权模式、能力引用或账本闭合时 `WorldState.Validate()` 拒绝。
