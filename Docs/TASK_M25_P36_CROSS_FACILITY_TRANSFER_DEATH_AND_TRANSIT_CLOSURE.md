# M25-P36 跨设施转运中死亡、床药取消与在途责任结案任务书

## 一、阶段目标

承接 M25-P32 的治疗前跨设施转运和 M25-P35 的住院中死亡，把伤员死亡时点扩展到
“已经离开来源床位、尚未由目标医者接收”的转运阶段：

```text
活动跨设施转运或到达待接收
→ 数据政策冻结健康开闭值与死亡时路线进度
→ 永久人物、人口、军籍、继承和抚恤原子闭合
→ 目标床位立即取消预留
→ 目标药材全部未用预留以正式库存事务释放
→ 接收责任尚未发生，死亡责任冻结在来源设施与原主治医者
→ 在途时原救护队继续护送遗体到目标地点
→ 全员抵达后遗体留置目标地，救护队沿真实道路独立返军
```

## 二、本阶段范围

1. 存档升级至 V58，新增跨设施转运死亡情境、转运死亡结案、转运死亡状态和次日启用边界。
2. 只处理 M25-P32 的首次、治疗前、同组织直接转运；允许 `InTransit` 与
   `AwaitingReception` 两种尚未交接状态死亡。
3. 复用数据驱动住院恶化政策，冻结死亡时健康开值、损失量、闭值、路线、是否在途和剩余里程；
   关注、读档和以后政策变化不得重算。
4. 死亡继续复用 V55/V56 的永久人物、人口、军籍、家庭继承、家主继任、组织抚恤及医疗责任
   原子闭环；任一前置事实失败不得先写死亡、释放资源或改变旅程。
5. 目标床位在死亡当日立即停止预留；目标具体药材批次的全部未用预留通过正式库存事务释放，
   不增加实物数量、不制造治疗记录。
6. 接收医者尚未接收，因此责任仍冻结为来源设施、来源照护组织和来源主治医者；同时保留目标设施、
   指定接收医者、批准人、路线和死亡时进度，以便后续审计。
7. 在途死亡不删除患者旅程；该旅程此后表示由同一救护队继续护送遗体。全员抵达后转运以死亡结案，
   当前留置地点迁移到目标地点，患者不参加返军，救护队可走既有返程闭环。
8. 已到达待接收时死亡直接完成转运死亡结案并进入救护队待返状态。
9. V57→V58 只建立空转运死亡结案集合、空引用和次日启用边界，不倒推旧死亡、资源释放或责任。

## 三、验收条件

- 在途死亡冻结非零剩余里程，释放目标床位和全部未用药材预留，人物死亡但遗体旅程继续存在。
- 全员抵达后转运关闭、遗体位于目标地点、救护队可以独立返军并恢复现役。
- 到达待接收死亡不产生接收或责任移交事实，直接关闭转运并允许救护队返军。
- 等待期不足、已完成接收、错误权限、资源/旅程/家庭/财政事实不完整时原子拒绝。
- 篡改死亡路线进度、来源或目标责任、药材预留开闭值、库存事务、状态或交叉引用时世界校验失败。
- V58 往返保留全部事实；V57 迁移不制造转运死亡。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 和范围审阅分别完成。

## 四、明确不包含

- 原始战场后送或返军旅程中的死亡；
- 转运途中急救、车辆、天气、袭击、改道、拒收、多次或跨组织转院；
- 遗体改道、棺木、安葬、家属接回和讣告传播；
- 医疗事故定责、过失比例、司法追责或额外赔偿；
- 自动每日死亡调度和玩家医疗界面。
