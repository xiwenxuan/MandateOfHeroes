# M23-P0 军械采购、运输与军械库入库任务书

## 1. 阶段目标

在现有 M19 产品批次库存、M11 军械库、人物旅行、军队行军和组织财政底座上，建立第一条可审计的军械供应链：

```text
商号成品军械批次
→ 有权限的军队人物下达采购
→ 买方军费转入卖方账簿
→ 真实承运人沿既有路线运输
→ 与目标军队在交付地点会合
→ 军械进入目标军械库
```

本阶段验证“物、钱、人、路、时间、军械账”是否同时闭合，不把军械制造配方、动态市场价格、跨路线寻路或完整国家后勤网伪装成已完成。

## 2. 必须完成

1. 将六种 M11 核心军械映射为数据驱动产品定义，稳定 ID 不依赖枚举扩展。
2. 增加组织/商队库存容器，使产品批次可归组织所有并随承运人移动。
3. 增加永久采购单和采购账：记录买卖组织、签发人、承运人、路线、目标军队、数量、单价、付款和状态。
4. 采购发运时一次性扣减卖方产品批次，并以等额双边财政变动完成付款。
5. 承运人必须是永久人物，运输必须使用现有 `JourneyState`；关注层级不得改变到货事实。
6. 目标军队未到交付地时货物进入等待状态；会合后只允许入库一次。
7. 军械入库必须产生 `ProcurementReceipt` 军械交易，并纳入 M11 军械守恒审计。
8. 存档升级为 V14；V13 迁移只建立空采购合同并补齐军械产品映射，不伪造历史采购。
9. 原型世界提供商号军械库存和可执行采购闭环。
10. 更新总纲、世界模拟、生产设计、战争设计、存档说明和 Skill 路由。

## 3. 不在本阶段

- 冶炼、锻造、木作、制弓、制甲的完整生产配方；
- 多段自动寻路、押运战斗、劫掠和保险；
- 动态竞价、信用、分期、税关和跨郡结算；
- 将旧粮草系统一次性重写为产品批次系统；
- UI 美术成品和完整玩家操作流程。

## 4. 验收用例

- 核心内容 JSON 与内建内容哈希一致，产品总数由 5 增至 11。
- 原型商号拥有可追溯的六类成品军械批次，容器容量不超限。
- 合法采购扣除卖方库存、买方军费，增加卖方资金，创建旅行和在途订单。
- 库存不足、资金不足、错误路线或无军队权限时拒绝，且无部分写入。
- 承运人与目标军队同时抵达后，订单完成且军械库数量精确增加。
- 军队未抵达时订单保持等待，不提前入库、不重复入库。
- 快照 V14 往返一致；V13 迁移不制造采购历史。
- 相同种子和相同指令得到相同订单、账簿与快照。
