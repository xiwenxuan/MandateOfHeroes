# M26 Merchant Gameplay Capability Audit

- 审计日期：2026-08-30
- 审计基线：`940c4381da4cbb893c0882fd28e68914397af897`
- 审计对象：`PlayableDemo` 普通玩家路径、中山商旅—家庭目标、洛阳供给卡与正式玩家运粮入口
- 状态口径：`READY` / `PARTIAL` / `MISSING` / `DEVELOPER_ONLY` / `NOT_REQUIRED_FOR_V1`

## 结论摘要

项目已经拥有两条由正式世界事实支撑、用途不同的商旅入口：

1. `SimulationDashboard` 的“商旅—家族体验（推荐）”是 20—30 分钟盲玩的主路径，使用沈衡、家庭债务、中山商行、布帛 `ProductBatch`、商队容器、`TradeRecord`、`Journey`、途中事件与长期选择。
2. 洛阳 Golden Slice 的“登记商车 / 小批运粮”是正式城市供给干预入口，使用洛阳人物、家户资金、正式载具、外部供应者、正式 `CellRoute` 评估以及 Gate / Road / Bridge 可用性。

两条路径共用项目的正式人物、库存、市场、时间、存档与物流原则，但并非同一条地图路线。审计当时中山—涿县仍只由区域 `RouteState/JourneyState` 驱动，洛阳外围供给路线才接入正式 `CellTraversalPlanner`；这是编码前缺口记录，不得倒写为当时已经完成。

2026-09-01整改说明：中山—涿县现复用既有 `RouteState/JourneyState/CivilianFreight/CellRoute` 权威链，并由全国 `R003` 生成连续四向 CellRoute；没有接入或伪装成洛阳局部路网，也没有建立第三套商旅权威。详见 `route-flow.md`。

当前最大的产品缺口不是后端商旅系统，而是普通玩家界面缺少结构化预检、实时成交预览、行程准备总览、到站结算与世界影响反馈；商号成员可见性和玩家文案也需要收口。

## 28 项能力审计

### 1. 当前正式玩家商人入口在哪里？ — READY

主菜单“商旅—家族体验（推荐）”直接创建中山商人沈衡，并进入普通玩家行动页。洛阳 Golden Slice 另有城市供给干预入口。两者都不依赖开发者观察台。

证据：`Assets/Scripts/Mandate.Presentation/SimulationDashboard.cs`、`Assets/Scripts/Mandate.Presentation/LuoyangGoldenSliceController.cs`。

### 2. 当前是否仍有推荐商旅体验入口？ — READY

`PlayableDemo` 保留推荐入口；场景序列化为 `_playerDemoMode: 1`、`_showDeveloperTools: 0`。

证据：`Assets/Scenes/PlayableDemo.unity`、`Assets/Tests/EditMode/DashboardSceneTests.cs`。

### 3. 当前玩家能够看到哪些行情？ — PARTIAL

玩家能看到中山—涿县布帛口信估价，以及所选地点的当前市场价格、库存和常态库存。缺少将“历史口信”与“现场现价”汇总到同一份交易准备视图的产品化呈现。

### 4. 行情是否带来源、时间、可信度？ — PARTIAL

布帛商机已有来源、获得日和可靠度；但缺少明确的新鲜度/距今多久提示，本地公开市场行情也没有统一的信息来源说明。

### 5. 玩家如何购买货物？ — READY

在目标阶段执行“按计划采购6匹中山布帛”，调用 `TradingSystem.Buy`，扣人物现金、减市场库存并推动即时价格。

### 6. 购买是否形成正式 ProductBatch？ — READY

布帛映射为 `product.textile.plain_cloth`，购买后创建正式批次与 `MerchantMarketPurchased` 库存事务。

### 7. 货物位于哪里？ — READY

正式批次位于人物承运的 `inventory_container.merchant_caravan` 中，容器具有家庭所有者、承运人物、位置与容量。

### 8. 玩家如何选择携带数量？ — NOT_REQUIRED_FOR_V1

首轮教学目标固定为 6 匹，且会按缺口补齐。自由数量交易可在后续沙盒商旅阶段建设；本轮用清晰固定数量和真实预检保证可玩性。

### 9. 当前人物 / 车辆容量在哪里显示？ — PARTIAL

商队行旅账和车马院显示人物总载重；采购行动只在超载时给出失败，尚未在执行前显示“当前/新增/执行后/容量”。洛阳运粮使用正式载具容量，但按钮前缺少完整预览。

### 10. 当前是否需要配置同行人员？ — PARTIAL

苏双是真实人物并会在同地、空闲时同行，信任与在途状态可见；首轮不要求玩家配置同行者，也没有同行者选择器。固定伙伴足以满足 V1，需在行程预检中明确说明。

### 11. 当前路线如何选择？ — PARTIAL

中山教学路线由目标固定为中山—涿县，普通地图也可点击相邻地点旅行；洛阳运粮从人物已知路线中自动选择供应地。V1 不需要自由多路线规划，但需要在启程前显示实际采用路线。

### 12. 路程、时间、口粮、风险在哪里显示？ — PARTIAL

目标卡显示估计天数和口粮，行动卡显示途中事件风险，地图显示剩余公里；这些信息分散，缺少统一行程准备单和执行后余粮。

### 13. Gate / Road / Bridge 状态如何向玩家解释？ — PARTIAL

洛阳正式供给路线会读取 Gate / Road / Bridge，并将受阻转换为“道路或城门暂不可通行”；内部评估保留阻塞对象与原因。中山教学路线不是 Cell 路线，不能显示具体洛阳门桥状态。本轮只对洛阳入口提供玩家可读失败，不伪造中山 Cell 权威。

### 14. 途中事件是否仍接正式世界？ — READY

折轴车事件使用稳定随机坐标，改变口粮、货损、健康、人物关系与人生事件，并继续推进世界时间。

### 15. 到达后如何卖出 / 交付？ — READY

玩家在涿县执行交付；系统按当地当前价卖出实际在途数量、回填市场、生成销售库存事务与交易记录，再由商行真实金库支付按时或逾期佣金。

### 16. 盈亏在哪里显示？ — PARTIAL

`TradingSystem.Sell` 已计算本批盈亏，行动结果显示现金变化；但教学交付把底层成交消息包装掉了，普通玩家看不到采购成本、销售收入、佣金、货损和净结果的完整结算。

### 17. 玩家如何知道这次交易改变了世界？ — PARTIAL

市场库存、价格、人物钱财、商行金库、家庭债务、正式批次和人生事件均真实改变；当前只用一句叙述反馈，缺少成交前后价/库存和家庭/组织变化摘要。

### 18. 当前家庭债务 / 财富动机是否仍存在？ — READY

开局会增加真实家庭债务，目标卡显示家产与债务，结尾可偿债或投资货车。

### 19. 当前商号 / 商业组织能力已经做到哪一步？ — PARTIAL

中山商行有稳定组织、资金、声望、成员关系、总部据点和仓库；玩家是正式商人职位。缺少产品化的成员名单、当前商号目标和连续经营面板。

### 20. 当前仓库是否正式可操作？ — MISSING

仓库、容器、容量、批次与访问规则均为正式事实，但普通玩家当前只能查看，不能存入/取出。本轮不新增高风险转存权威；标记为 `MISSING / NEXT PHASE`。

### 21. 当前商号成员是否正式存在？ — READY

成员使用 `MembershipState`，关联真实 `PersonState`、组织和职位。当前 UI 只显示人数，需要补成员姓名与玩家职位的只读投影。

### 22. 当前岗位 / 委任能力是否存在？ — MISSING

职位 ID 和成员关系存在，但没有正式任免、委派和岗位结算循环。本轮明确不建设。

### 23. 当前是否存在最低商号长期循环？ — PARTIAL

首轮完成后生成“偿债后的第二次经营”或“购车后的更大商旅”跟踪目标，商号资金和货车容量也会变化；后续目标尚不是可连续执行的完整商号经营循环。

### 24. 哪些 UI 仍是开发者界面？ — DEVELOPER_ONLY

`DrawDeveloperDashboard`、人口审计、全世界市场、张世平演示等属于开发者观察台；`PlayableDemo` 已隐藏入口。洛阳验证控制器仍混合普通表现与验证用途，不纳入本轮独立盲玩主路径。

### 25. 哪些文字暴露内部类型名？ — PARTIAL

普通中山城镇页面仍出现“正式库存”“真实需求”“任务系统”“正式市场、库存和行程系统”“写回同一世界账”等开发语汇；洛阳建设面板还显示 `BuildBlueprint`、产品 ID、设施 ID、`VisualProfile`。本轮清理商旅主路径的文案，不扩展到全部洛阳开发验证页面。

### 26. 哪些失败只返回技术错误？ — PARTIAL

商旅行动的大部分失败已是中文业务原因；城镇进入、通用旅行和部分异常仍直接显示 `Exception.Message`。本轮为商旅主路径补可读预检与无副作用失败测试，不吞并全项目异常本地化。

### 27. 当前 20—30 分钟内最可能卡在哪里？ — PARTIAL

最可能卡点依次是：不知道执行后还剩多少钱和载重、行情是否过时、启程需要多少口粮、到站后是否已经抵达/该按哪个按钮、成交到底赚了多少、结尾后下一目标是否可继续。保存/读取入口可见，但缺少盲玩专用提示和核对表。

### 28. 哪些系统已经完成，不应重复建设？ — READY

不得重复建设：永久人物与家户、组织与成员关系、人物钱财、市场货单、交易记录、正式产品批次与容器、库存事务、区域 Journey、确定性途中事件、世界时间、V79 存档、正式 Cell 路线与供给物流、城镇设施/分号/仓库事实、玩家行动服务。

## 本轮冻结范围

### 必须补齐

1. 中山商旅产品就绪只读投影：人物/家庭动机、现金、位置、行情新鲜度、实时采购预览、容量、同行者、路线、口粮、风险、抵达后的销售预览。
2. 真实成交结算摘要：采购成本、销售收入、佣金、可追溯净结果、市场与家庭/组织变化。
3. 商号最小只读页：组织身份、资金、声望、成员姓名/职位、仓库状态、当前长期方向。
4. 商旅主路径玩家文案清理和失败可读性。
5. 保存/读取、确定性、无副作用失败、正式批次/市场/组织守恒的自动回归。
6. 20—30 分钟独立人工盲玩包、观察表和缺陷记录模板。

### 明确不做

1. 仓库存入/取出。
2. 岗位任免、复杂委任和自动经营。
3. 多分号扩张、跨州供应链和商号战争。
4. 中山—涿县到洛阳 Cell 路网的跨地图重构。
5. 自由交易数量、自由路线组合和完整商队装备编辑器。
6. 第三套商旅/市场/库存权威。

## 产品验收边界

自动化和开发者自测只能证明开发就绪。最终 Gate Q 仍要求一名未参与开发、未阅读答案脚本的独立玩家完成 20—30 分钟盲玩；在获得合格人工记录前，最终结论只能是 `NOT ACCEPTED / BLOCKED`，阻塞项为 `QUALIFIED INDEPENDENT HUMAN BLIND TESTER REQUIRED`。
