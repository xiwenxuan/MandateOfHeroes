# M25-P5任务书：正式跨县民用货运与县间市场履约

## 一、任务定位

在M25-P4同县家庭市场之上，建立第一条把不同县买卖订单、真实承运人物、真实路线、移动容器、
途中损耗和目的地收货连成一体的民用货运闭环。县间商品不能在撮合后瞬移；地图缩放、玩家关注
和界面是否打开都不能改变运输事实。

本阶段采用“起运地交割”合同：装车时商品由卖方预留批次转为买方所有，商品价款从买单托管
支付卖方；运输途中商品风险由买方承担。运费从买方家庭另行托管，到达并完成收货后支付承运
人物所属家庭。承运人物使用既有个人口粮和健康旅行规则，不得食用托运商品。

新增持久民用货运状态，世界存档由V30顺序升级为V31。V30迁移只建立空货运集合并把既有同县
成交补为同县目的县与零货运引用，不得根据旧路线、人物旅行或市场记录伪造历史货运。

## 二、实现合同

### 2.1 跨县订单与起运

- 买卖订单必须处于活动状态、产品相同、县属不同、限价相交且具有足够未履约数量。
- 卖单继续消耗其明确批次预留；同一预留量不能同时进入两张货运单。
- 承运人物必须存活、位于起点且没有其他旅程；移动容器必须由其家庭所有、由其承运、位于起点
  并有足够重量容量。
- 路线必须直接连接卖方家庭所在地与买方家庭所在地；首个切片不自动寻路或多段中转。
- 装车用守恒库存事务把卖方预留批次拆分为买方所有的在途批次，保留产品、品种、产地、产日、
  品质、鲜度和原工单来源。
- 商品价款按卖方限价从现有买单托管支付；买卖订单在起运数量上形成正式成交。运费独立从买方
  财富托管，不混入商品价或卖方收入。

### 2.2 旅行、损耗与收货

- 民用货运保存路线、旅程、承运人物/家庭、移动容器、起终县与地点、产品、数量、商品成交、
  运费、易腐快照和生命周期日期。
- 承运人物和移动容器复用既有`JourneyState`移动；人物每日消耗自己的兼容口粮，托运批次不作为
  自用口粮。
- 每个实际运输日按产品易腐参数、食品腐败敏感度、货运稳定ID和绝对日确定性计算自然损耗；损耗
  必须写负向库存事务和货运流水，不能为保持“到货等于发货”而消失。
- 抵达后移动容器先进入待收货；按买方家庭粮仓剩余重量容量分批卸货，容量不足时货物继续留在
  到达地容器中。
- 完成收货或全部自然损失后关闭货运并向承运家庭支付托管运费；不能重复交付或重复付款。

### 2.3 守恒与调度

```text
起运数量 = 在途/待收货数量 + 已收货数量 + 自然损耗数量
商品成交额 = 卖方实际所得
运费 = 在途托管 + 承运家庭已收
```

- 日界只扫描活动民用货运，不扫描全部永久人物或全部产品批次。
- 相同世界、订单、路线、货运ID和日期产生相同损耗、抵达与快照。
- 关注层级只改变信息和演出，不改变损耗、旅程或交付结果。

## 四、验收标准

1. 跨县成交必须来自两张真实活动订单、卖方真实预留批次和买方真实托管。
2. 装车后商品成为买方在途财产；卖方收到商品价，承运家庭只收到独立运费。
3. 承运人物、路线、容器和货物地点一致，不出现人物已抵达而货物仍留在起点。
4. 托运商品不充当承运人口粮；自然损耗有确定性原因账，商品数量完整守恒。
5. 目的粮仓容量不足时允许分批收货，不删除或复制剩余货物。
6. 重复日结、重复收货和重复付款没有副作用。
7. V30安全迁移到V31且不伪造货运；V31保存往返和不变量校验通过。
8. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 自动寻路、多段中转、并行车队、改道、返程和跨路线合单；
- 押运、盗匪、战斗、截获、赎回、保险、信用和承运赔偿；
- 逐辆车马船只、包装材料、装卸工时、关税、路费与住宿细账；
- NPC自动生成跨县买卖单、自动选择承运人或自动议价的完整经营AI；
- 仓储霉变、鼠害、品质逐维衰减和损失品转饲料。
