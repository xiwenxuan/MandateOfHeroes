# M15-P6任务书：正式分区人口存储适配器与人物冷热扩展合同

## 一、任务定位

本任务承接M15-P4的100万人分区二进制共同合同和M15-P5的累计冷热档案、5000万全部
在世基础索引证据，把实验结论第一次接入正式`Mandate.Persistence`程序集。

本阶段交付“正式接口、V7元数据、可校验侧车人口包和冷热扩展驻留规则”。为避免一次性
破坏现有玩法原型，V7采用共存迁移：现有`WorldState.People`继续作为当前小世界运行时
数据，同时可以附着经过校验的分区人口包。只有后续系统逐步改用人物访问服务并完成正式
规模验收后，才允许把未驻留人口从内联列表移出。

## 二、固定决策

1. 正式主候选采用分区二进制，不引入新的数据库运行时依赖。
2. `WorldState`存档版本从V6顺序迁移到V7；V6人物全部保留并进入内联模式。
3. 人口包使用稳定人物ID分区，禁止使用运行时哈希、数组位置或观察顺序。
4. 永久核心和详细扩展分离；冷热只决定扩展是否驻留内存，不改变永久核心。
5. 从V6导入的人物全部写入详细扩展，不能以迁移为由删减既有属性、财富、技能或状态。
6. 热人物发生变化后，必须先形成新检查点才能降格；适配器必须拒绝静默丢弃脏扩展。
7. 当前任务不直接删除`WorldState.People`，也不宣称完整游戏已能以5000万人运行。

## 三、V7存档合同

`WorldState.PopulationStorage`至少保存：

```text
contract_version
mode                         // inline_snapshot | partitioned_package
package_id
partition_count
permanent_person_count
living_person_count

```

### 3.1 V6迁移

- V6至V7迁移不得重建、合并或重新随机人物；
- 迁移后的模式为`InlineSnapshot`；
- 人物总数、在世数和详细扩展数由原`People`确定；
- 旧世界在没有外部人口包时继续正常保存、载入和运行。

### 3.2 分区共存

- V7世界可以切换为`PartitionedPackage`元数据；
- 当前切片仍保留全部内联人物，以兼容现有直接访问`People`的模拟系统；
- 世界元数据、清单、核心和详细扩展必须互相校验；
- 未物化人物的正式运行时访问留给后续人物仓储访问层，不在本阶段伪装完成。

## 四、人口包物理合同

```text
population-package/
  current.json
  current.previous.json
  generations/
    generation-00000000000000000001/
      manifest.json
      core-00000.bin
      detail-00000.bin
      ...
```

- 每次检查点写入新的代际目录；
- 完整写入并刷新文件后，才原子替换`current.json`；
- 旧代际保留，用于回滚和审计；
- 清单记录每个分区的计数、长度和SHA-256；
- 读取时拒绝路径越界、头版本错误、长度不符、摘要错误和计数不守恒；
- 分区内按稳定人物ID排序，使相同事实不受输入顺序影响。

## 五、永久核心与详细扩展

永久核心保存身份、姓名、出生、地点、家户、父母、婚姻、生死、健康与劳动摘要、职业、
下一到期事件和基层职责。详细扩展保存完整`PersonState`，包括财富、物资、能力、性格、
需求及后续可扩展人物数据。

人物可以只有永久核心，但只有存在已持久化详细扩展时才能直接晋升为完整热人物。未来由
确定性规则首次展开普通人物时，必须立即固化扩展；反复查看不得重新生成。

## 六、冷热驻留合同

```text
Promote(person_id)
  → 读取永久核心
  → 读取详细扩展
  → 校验二者身份与基础事实一致
  → 加入热驻留集

DemoteUnchanged(person_id)
  → 与已提交详细扩展比较
  → 未变化才释放内存
  → 已变化则拒绝，要求先提交新检查点
```

玩家控制、关注、重要事件和组织调度可以触发晋升，但关注只改变加载和表现，不改变人物
事实。降格不能删除扩展、回退属性或重随机技能。

## 七、实现内容

- `PopulationStorageState`及V7顺序迁移；
- `IPermanentPopulationStore`正式接口；
- 永久核心、详细扩展、检查点和清单DTO；
- `PartitionedPopulationStore`参考实现；
- V7世界与人口包附着、校验和退回内联模式的适配器；
- `PopulationResidencySession`冷热驻留合同；
- 当前版本、V6迁移、往返、确定性、损坏拒绝和脏降格测试。

## 八、验收条件

1. 全工程编译通过；
2. V6世界顺序迁移到V7，人物和引用不丢失；
3. 当前V7内联快照往返保持兼容；
4. 200人村庄能够写入多分区人口包并逐人读取核心与完整扩展；
5. 相同人物事实以不同输入顺序写入时，分区和清单摘要一致；
6. 人口包被篡改后必须拒绝打开；
7. 未变化热人物能够降格并重新晋升，变化未提交时降格被拒绝；
8. 新存储修订能够保存热人物变化，旧代际仍保留；
9. 核心测试和受控Unity EditMode测试形成明确结果；
10. `git diff --check`与范围审阅通过。

## 九、不包含

- 从`WorldState.People`移除全部冷人物；
- 把现有所有模拟系统一次性改写为异步分区查询；
- 增量人物变更日志压缩、自动检查点轮换和旧代际清理策略；
- 5000万份完整技能、关系、生产、战争或Unity对象；
- 创建世界硬件检测和人口档位界面；
- 公开承诺最低配置或正式5000万完整游戏负载。
