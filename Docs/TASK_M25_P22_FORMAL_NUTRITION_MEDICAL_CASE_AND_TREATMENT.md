# M25-P22 任务书：正式营养病案、诊疗权限与药物治疗闭环

## 一、任务定位

承接 M25-P21 的长期营养档案和营养性疾病发作，把村庄中原有的“诊所库存数值直接换健康”升级为可追溯的民间诊疗事实：具体患者因具体营养性疾病发作形成病案，患者本人或同户成年照护者授权，由同地合格医者诊断并消耗真实药材批次实施治疗。

本阶段明确区分病因和治疗：药物只能恢复该次营养性疾病已经造成、尚未恢复的健康损伤，不能减少营养债务、降低由营养债务计算的疾病风险，也不能代替进食和救济。

## 二、实现范围

### 2.1 V44 永久医疗合同

- 新增稀疏的民间医疗病案，使用稳定 ID 记录患者、营养发作、诊断内容、治疗方案、诊断医者、授权人和授权政策。
- 新增追加式民间治疗记录，记录医者、授权人、真实药材批次、库存事务、治疗前后健康值和营养债务快照。
- 诊断内容、治疗方案、授权政策和药品使用稳定命名空间 ID；只有处理结果等封闭协议状态使用枚举。
- V43→V44 只初始化空病案和空治疗记录，不根据旧健康值或旧诊所库存伪造既往病史。

### 2.2 诊疗权限

- 患者、医者、授权人必须是永久人物；医者和患者必须存活、同地且医者不得处于旅行或徭役/征发状态。
- 医者必须具有 `Physician` 村庄职业和最低医术能力，不能仅因玩家关注而获得权限。
- 能独立授权的成年患者可本人授权；未成年人由同户、同地、存活的成年人授权。
- 诊断成功后即保存病案；缺药只能阻止治疗，不能抹去已经成立的诊断事实。

### 2.3 真实药物与治疗

- 核心生产内容新增可扩展产品 `product.medicine.herbal_material`，使用正式产品批次而非新的固定作物/药物枚举。
- 药材必须来自医者家庭的真实库存批次，治疗按确定顺序消费未预留数量，并写入 `MedicalTreatmentConsumed` 库存事务。
- 治疗效果由医术和药材品质确定，受患者缺失健康及该营养发作尚未恢复的伤害上限约束。
- 治疗记录的营养债务开值和闭值必须相等；只有后续真实进食、救济或充足月份能够偿还营养债务。

### 2.4 村庄月结接入

- 村庄月结只处理本次已经加载的村庄家庭成员和稀疏营养发作，不新增全世界人物扫描。
- 诊所可用时按稳定顺序选择本地合格医者、病患和授权人；诊所容量限制本月诊疗人数。
- 旧 `clinic.InventoryUnits` 不再作为民间治疗的药品权威账；没有正式药材批次时只形成诊断，不恢复健康。
- 本阶段不迁移军中旧式 `commodity.herbs` 救治，军队医疗正式库存化留给后续独立任务。

## 三、验收标准

1. 活跃营养性疾病可由合格同地医者在合法授权下形成唯一病案；未成年人必须由同户成年人授权。
2. 缺药时病案保留，但不产生治疗记录、库存事务或健康恢复。
3. 有药时真实批次数量、储存设施库存和库存事务闭合，治疗恢复量与病案累计量闭合。
4. 治疗前后营养债务和风险不变；篡改药品引用、授权关系、健康闭合或营养债务闭合会被领域校验拒绝。
5. V43 存档迁移到 V44 时新医疗集合为空、生产内容清单更新且不伪造历史；V44 往返存档保留病案、治疗和库存引用。
6. 全工程编译、完整核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。

## 四、非目标

- 不实现传染病传播、流行病、复杂辨证、方剂组合、手术、死亡概率或完整医者职业任务线。
- 不让药物替代粮食，不扫描未加载人口，不因关注层级改变世界事实。
- 不在本阶段重构军队伤兵救治、旧个人商品库存或所有历史诊所库存。
- 不提交或推送仓库；版本操作需要用户另行授权。
