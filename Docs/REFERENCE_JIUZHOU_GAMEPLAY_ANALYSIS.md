# 《九州：商旅》截图玩法参考分析

## 一、文档性质

本文是基于 2026-08-06 提供的一组本地游戏截图完成的黑盒玩法观察，用于回答“怎样让商旅、商号和地方经营形成可理解的玩家循环”。它不是需求规格、实现证明或素材授权文件，也不改变
`GAME_SYSTEMS_MASTER_AND_STATUS.md` 所定义的项目状态与开发顺序。

### 证据标签

- **观察**：截图中存在明确的文字、数值、控件或状态变化。
- **推断**：由多张截图之间的关系推导出的可能规则，必须通过试玩或独立证据确认。
- **启发**：可转化为本项目原创设计的问题或体验目标，不代表应复制参考作品。
- **不确定**：静态截图不足以证明算法、AI、存档或实时结算行为。

## 二、玩法总览

### 2.1 可观察的四层结构

1. **个人层**：创建人物，选择属性、才能与身份；进行休息、交谈、交易、制作和事件选择。
2. **队伍层**：给成员分配领队、会计、医生、厨师、向导、护卫等岗位，并配置牲畜和货物。
3. **商号层**：管理资金、成员、仓库、设施、分会、委托、研究、生产和账本。
4. **世界层**：在州郡城市、道路、河流、地形、势力与地方产出构成的地图上规划跨城活动。

**推断**：其主要体验不是孤立的“低买高卖”，而是让角色能力、队伍配置、组织建设和地理市场共同约束商旅活动。

### 2.2 可观察的主循环

```text
建立人物与商号
→ 招募成员并分配岗位
→ 获取行情、委托、配方或资源
→ 采购、制作并装载货物
→ 选择目的地并推进旅行时间
→ 处理消耗、风险、事件和交付
→ 获得资金、声望、关系或产业机会
→ 建设设施、研究能力并扩大经营范围
```

## 三、分系统观察

### 3.1 人物、能力与岗位

**观察**：创建角色界面包含姓名、性别、年龄、生日、商队名以及统率、谋略、武学、异数、地理、医术、厨艺等属性，并允许选择或随机生成才能。成员界面显示独立属性、技能、装备和研究入口。商队存在领队、会计、医生、厨师、向导和护卫岗位。

**推断**：岗位会影响容量、消耗、行程、受伤、战斗或经营效率，但截图不能确认完整公式及岗位是否为硬性要求。

**启发**：本项目应让岗位由永久人物承担，并让岗位效果读取人物的真实技能、健康、关系、装备和所在位置；不能只在 UI 中生成一张临时加成卡。

### 3.2 商号、分会和设施

**观察**：商号具有资金、声望/影响力、成员和牲畜，并能查看总部与城市分会。管理页包含账本、建设、仓库、委托、货物、城郡、产业等入口。可见主堂、厨房、工坊、仓库、茶室、医所、书阁等设施及其升级成本、材料、工期和容量效果。

**推断**：商号会随着跨城经营形成多个节点，但截图不足以证明所有分会拥有独立库存、人员和会计结算。

**启发**：本项目的组织据点必须引用真实设施、库存容器、负责人、辖区和所有者；建设不能只增加抽象等级。

### 3.3 货物、仓库、制作和研究

**观察**：物品被分为武器、防具、药品、食物、原料、书籍与装备；制作页可选择配方、材料和数量，包含武器、药物和食物。仓库按粮食、石料、木材、食材、日用、材料、杂物等类别管理。研究页可见商品制作、人才招募及经营相关项目。

**推断**：研究用于解锁配方或组织能力，制作会消耗仓库材料并产出物品；截图不能证明生产是否逐批追踪来源、品质、工时与具体工人。

**启发**：本项目必须复用稳定产品 ID、配方、产品批次、库存交易、真实工作者和生产订单；普通内容扩展不能要求存档结构升级。

### 3.4 市场与交易

**观察**：交易页显示商品名、数量、价格、买卖数量、税率/费用、资金和载量。不同地点提供不同类别商品，马匹可购买并展示费用和效果。

**不确定**：静态截图不能证明价格是否由供需实时形成、NPC 是否参与同一市场、买卖是否永久改变地方库存，或系统是否存在价格套利保护。

**启发**：本项目的交易必须修改同一世界中的买卖双方资金、具体批次、库存容器和市场流水；不得另建只供玩家使用的报价表或无限库存商店。

### 3.5 委托与组织行动

**观察**：委托列表包含人员护送、货运、军需等类型，并展示地区、报酬、声望、期限和状态。策略页包含目标、执行成员、持续时间、成功率以及执行/停止操作。

**推断**：委托把既有货运和人物能力包装成有期限的玩家目标，策略则可能代表商号层的长期自动行动；截图不能证明失败、撤销、资源预留和存档规则。

**启发**：本项目的委托应引用真实发布者、受托者、路线、预算、货物或人物，并具有接受、执行、部分完成、失败、取消和结算生命周期。组织策略应经过权限、资源预留与正式世界命令执行，不可直接从 UI 改写结果。

### 3.6 城市、产业与大地图

**观察**：大地图显示州郡、城市、县城、道路、河流、山地、森林、势力范围、人口、规模、经济、发展度、气候和地方产出。城市列表汇总地点数据。产业页展示地块、地形、产物、成本、等级和投资入口；商号产业列表展示成员、管理者、资金、状态和自动出售选项。

**推断**：产业可为商号持续产生原料或商品，并能形成较高层的半自动经营，但截图不能证明土地权属、劳动力来源、实际产能和市场出售如何结算。

**启发**：本项目应把产业建立在具体土地/设施、永久人物劳动、输入批次、产出批次、维护成本和当地市场之上。自动经营只是委托决策权，不得绕过相同的资源守恒和世界规则。

### 3.7 时间、生活与事件反馈

**观察**：界面存在日期/时段、休息一天、恢复疲劳、对话选择、送礼、交涉、饮酒和借贷等行为；账本可按年份查看资金、库存、成员和产业变化。

**推断**：行动会消耗时间并受人物状态影响，账本承担长期结果反馈。截图不能证明事件随机机制、关系变化和债务利息的具体规则。

**启发**：本项目应让每次玩家行动明确展示动机、预期、时间、成本、结果和长期记忆，并使账本能够追溯人物、家庭、组织、库存及市场的真实变化。

## 四、适合转译为本项目问题的体验目标

以下内容属于体验问题，不属于可复制表达：

1. 玩家能否在一分钟内看懂“为什么要去下一座城”。
2. 装货、人员、牲畜、路线和口粮能否组成一个可见、可检查的出发准备过程。
3. 途中损耗和事件能否改变具体人物与具体货物，而不是只弹出结果文字。
4. 抵达后的交易能否回写同一地方市场、家庭财产和人物关系。
5. 商户做大以后，能否把重复工作委托给真实成员，同时保留例外报告和追责。
6. 建设、生产和研究能否扩展玩家选择，而不是只提供线性数值升级。
7. 账本能否回答“钱从哪里来、货到哪里去、谁承担了后果”。

## 五、禁止复制与合规边界

本分析不授予任何外部作品内容的使用权。实施时禁止：

- 导入、描摹或重制截图中的 UI 布局、图标、人物立绘、地图、字体、动画或配色组合。
- 复制参考作品的专有文本、商品表、配方表、任务文本、数值、地名组织方式或平衡公式。
- 反编译、抓取或调用参考作品的代码、配置、数据库和网络接口。
- 把本地截图加入仓库、构建产物、测试夹具、宣传材料或模型训练数据。
- 使用“截图看起来如此”替代项目自身的领域设计、许可证审计和验收证据。

允许借鉴的是抽象问题与通用机制，例如商队岗位、跨城贸易、组织委托和可追溯账本；本项目的代码、数据、文案、地图、美术、数值与交互必须原创或具有已记录的兼容许可证。

## 七、仍需通过试玩确认的问题

1. 交易是否真实改变城市供需，NPC 是否与玩家共享市场。
2. 岗位对旅途、战斗、医疗、消耗和谈判的确切影响。
3. 产业是否消耗具体劳动力和原料，产出是否进入具体仓库。
4. 分会是否拥有独立库存、人员、财务与地方权限。
5. 组织策略的资源预留、失败、取消和报告生命周期。
6. 保存读取后任务、价格、产业和成员状态是否完整往返。

这些未知项不得由开发人员自行补写为参考游戏事实；只能转化为本项目需要独立决策的问题。
