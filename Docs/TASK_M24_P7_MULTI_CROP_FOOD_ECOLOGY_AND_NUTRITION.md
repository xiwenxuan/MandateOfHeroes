# M24-P7任务书：多作物食物生态、营养与加工闭环

## 一、阶段目标

在M24-P6多产品来源账之上，以独立、可审核的数据包加入小麦、粟、黍、稻、菽五类农业
绑定和六类食品，并让以下差异实际进入百万世界结算：

```text
作物分布与产量差异
→ 县内豆科份额形成有界轮作支持
→ 家庭收获保留具体产品ID
→ 家庭保存加工改变产品形态
→ 营养折算影响食物满足
→ 体积影响运输能力
→ 产品组合影响市场价格
→ 易腐差异影响具体损耗对象
→ 产品、物理数量、营养与正式检查点分别审计
```

本阶段不改变V28正式存档结构。P7内容扩展包属于百万压力世界的历史候选内容；物种身份与
时代适用性和玩法参数必须分层标注，不能把校准份额写成史料结论。

## 二、实施合同

1. 作物、品种、种子、食品、配方和方法使用稳定命名空间ID，不增加固定枚举。
2. P7扩展包和核心生产包按固定顺序合并，重复ID、缺失引用或不完整份额拒绝运行。
3. 不启用P7时只加载原核心包，M24-P6及更早路径保持原结果合同。
4. 开局食品份额和农业户份额分别总计10000基点。
5. 每种食品声明营养、体积、易腐、市场价值和消费优先级；这些字段进入实际结算或来源审计。
6. 营养满足量与消耗的物理数量分账：前者影响饥饿，后者进入物资守恒。
7. 豆科轮作先采用县级有界支持：按实际分配给菽作家庭的土地份额计算，只修正本县响应作物；
   不伪装成已经实现逐地块多年轮作历史。
8. 第一条家庭保存加工按1:1把部分麦粒转为干粮，产品转换分别记输入与输出，不增减物理总量。
9. 多作物种子在家庭维持单一当前绑定；绝户转入官种时按原绑定保存，正式检查点不得把混合官种
   静默写成同一种种子。
10. 每种产品满足：

```text
开局 + 收获 + 加工输出
= 消费 + 腐败 + 冲突征夺 + 运输损耗 + 路粮 + 加工输入 + 期末库存
```

## 三、工作包

### WP1：内容与属性

- 增加粟、黍、稻、菽的作物、原型地方品种、种子、收获物、种植配方和方法；
- 增加P7食物来源与生态参数；
- 核心包与扩展包合并哈希稳定。

### WP2：世界结算

- 按数据份额确定家庭作物绑定；
- 接入作物产量、县级轮作支持、家庭加工、营养满足、市场价格和运输体积；
- 让易腐属性决定同一总损失中优先损失的真实产品。

### WP3：种子、来源与检查点

- 绝户官种按作物绑定保存；
- 加工输入/输出进入逐产品来源式；
- 正式批次检查点按食品和种子绑定拆分。

### WP4：校准与验证

- 1万人10年双跑确定性自测；
- 保留未达到人口包络的失败候选；
- 100万人50年候选记录人口、内存、工单、营养、加工和哈希；
- 完成工程编译、核心、Unity和差异验证。

## 四、验收标准

1. 至少5种农业绑定和6种食品加载成功。
2. 至少4种收获食品在长跑中产生真实收获与期末库存。
3. 轮作支持、加工、营养、体积和市场价值均产生非零可重复证据。
4. 营养量不替代物理数量，物理粮食和逐产品来源分别守恒。
5. 官种按原作物绑定导出，不能统一解释为小麦种子。
6. P7双跑哈希一致；P6兼容自测保持通过。
7. 百万50年候选进入既有75%—150%期末人口包络。
8. 全工程编译、核心测试、受控Unity和`git diff --check`分别通过。

## 五、不包含

- 逐地块多年轮作、土壤氮素和休耕史；
- 水田水利网络、气候适生区和地区限定种植；
- 麦粒—面粉—麸皮—干粮完整百万工单链；
- 每餐配膳、蛋白质/微量营养素和疾病模型；
- 把扩展包直接并入V28正式核心内容与分区存档；
- 1,000万或累计5,000万完整游戏负载。
