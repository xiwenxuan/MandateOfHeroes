# M26-P4 战略委任书、真实职位绑定与命令提案任务书

## 一、目标

把 M26-P3 的政策选择器接入已有组织、职位、成员、地点和存档合同，使太守、军团都督、
商号掌柜、家主等未来玩法可以签发一份可追溯委任书，并由真实受任者在明确辖区、期限、
预算和权限快照内生成命令提案。

本阶段只生成提案，不直接执行贸易、建设、征兵、调动或战争。领域命令仍必须由各自的
世界命令处理器验证人员、库存、财政、时间和专业权限。

## 三、实施内容

### P4-A 持久委任书

每份委任书保存：

- 政策、发布者、受任者、组织、受任职位和管辖地点；
- 发布日、截止日、预算上限、报告周期和下次报告日；
- 发布者是否为组织领袖、发布时双方职位与职级快照；
- 组织能力与政策权限交集形成的允许命令快照；
- 政策优先级权重快照和自动执行授权事实；
- 活动、撤销和完成生命周期。

发布时必须确认双方存活、受任者确实担任该组织职位、发布者是组织领袖或拥有更高职位，
辖区属于组织总部范围，预算不超过当时组织金库。创建委任书不预扣资金。

### P4-B 组织能力边界

政府、军队、商号、家族、宗教和情报组织分别使用稳定命令 ID 能力清单。最终权限是：

```text
政策允许命令 ∩ 组织类型能力 = 委任权限快照
```

例如商号可以经营商业、调拨粮款、调查和建设，但不能借“商贸振兴”政策自动获得发动
战役的权限。

### P4-C 真实命令候选与提案

候选必须绑定当前受任人物、组织、职位、辖区、实际命令类型、预计成本和有序命令参数。
评估时：

1. 校验委任仍活动且未过期；
2. 校验受任者仍存活并担任原职位；
3. 拒绝人物、组织、职位或辖区不匹配的候选；
4. 排除超过委任预算或当前组织金库的候选；
5. 复用 M26-P3 权限过滤和确定性评分；
6. 保存选中提案，但不生成或执行 `PersistentWorldCommandState`。

提案保存候选、战略命令、实际命令类型、执行人物、组织、辖区、成本、评分和参数，供后续
玩家批准、自动委任闸门或领域处理器使用。

### P4-D V66 存档合同

- `WorldState` 新增委任书与命令提案集合；
- V65→V66 显式初始化为空集合；
- 当前版本往返必须保留权限快照和提案；
- 缺失人物、组织、职位、地点、委任引用、越权命令和越界成本必须显式拒绝；
- 增加普通政策、命令或优先级仍不要求升级存档结构。

## 四、架构边界

- `Mandate.Domain`：持久委任、提案、生命周期、组织能力和不变量；
- `Mandate.Simulation`：签发校验、候选绑定、预算过滤、政策选择和提案记录；
- `Mandate.Persistence`：V65→V66 顺序迁移；
- `Mandate.Presentation`：本阶段不修改。

## 五、验收标准

1. 商号领袖能给真实商号成员签发商贸委任；
2. 委任权限不包含组织本身无权执行的战略命令；
3. 错误执行人物、职位、组织或辖区被原子拒绝；
4. 超预算候选不生成提案，不修改资金或世界命令；
5. 选中候选形成持久提案，但不会绕过领域处理器直接执行；
6. 当前版本往返保留委任和提案；
7. V65 迁移为空集合，不伪造历史委任；
8. 编译、定向核心、受控 Unity、`git diff --check` 和范围审阅分别报告。
