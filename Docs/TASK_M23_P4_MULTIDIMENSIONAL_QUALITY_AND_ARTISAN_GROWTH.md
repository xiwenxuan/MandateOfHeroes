# M23-P4 多维品质、工匠技艺成长与制造反馈闭环任务书

## 1. 阶段目标

在 M23-P3 已完成的采集、畜牧、初级加工、制造、采购与维修链上，把“品质”和
“工匠成长”从单一汇总数值与设计目标升级为可持久化、可审计的世界事实：

```text
数据驱动产品品质维度
→ 原料批次携带各维度事实
→ 加工工单冻结方法、难度和管理者开工技艺
→ 设施、方法、原料和技艺共同决定各维度产出
→ 完成真实劳动后产生专门技艺成长与实践流水
→ 新产批次继续进入后续制造链并保留来源
```

品质维度、专门技能及方法修正都使用带命名空间的稳定 ID；增加普通品质维度、技能或
方法内容不得新增封闭枚举。现有 `QualityBasisPoints` 暂保留为多维品质的确定性汇总缓存，
不得与维度事实相互矛盾。

## 2. 必须完成

1. 核心生产内容包升级到 8.0.0，内容清单协议升级到 V3；加入数据驱动品质维度定义，
   所有产品明确声明自身维度，所有加工方法明确实践技能、难度及维度修正。
2. 产品批次加入有序、唯一的多维品质状态；新建批次必须从产品定义生成维度，旧批次
   迁移时以原汇总品质建立等值维度，不伪造维度差异。
3. 加工工单在创建时冻结管理者的专门技能基线；结算时以输入品质、设施状态、开工技能
   和方法修正确定性地产生各维度品质，并重算汇总品质。
4. 专门工艺技能复用人物开放式 `SkillMasteries`；人物尚无该专门技能时，以既有综合工艺
   作为首次实践基线，之后按实际工期、批量、方法难度、资质和递减收益成长。
5. 每次完成的加工工单建立实践流水，记录人物、工单、技能、成长前后值、增量和产出品质；
   世界校验必须能拒绝伪造或不一致流水。
6. 加工系统接入正式人物仓储适配器；技能变化必须被增量存储跟踪，同时保留无适配器时
   对普通内存世界的兼容行为。
7. 存档顺序升级到 V18；V17→V18 初始化实践流水、补齐批次维度和旧工单快照，并刷新
   内容清单，不生成历史实践或倒推技能成长。
8. 更新系统总纲、生产设计、人物设计、确定性存档、README 与 Skill 路由，使当前状态、
   限制和后续顺序一致。

## 3. 不在本阶段

- 工匠师承、作坊声誉、秘诀、工艺突破、伤病、疲劳和多人协作分工；
- 品质随时间衰减、储存环境污染、运输损伤和维修后的品质变化；
- 军械入库后的军团品质加权、战斗数值换算与市场价格溢价；
- 自动排产、押运风险、多段物流、太守/军团军需委任；
- 以玩家关注度改变技能、品质或实践结果。

## 4. 验收用例

- 内建内容与核心 JSON 均解析为同一 8.0.0 内容包，品质维度、产品维度、方法技能和修正
  全部通过稳定 ID、引用完整性与哈希校验。
- 所有开局、采集及加工批次均拥有与产品定义一致的多维品质；汇总值等于维度算术平均。
- 同原料、设施和方法下，高技能人物的产出品质高于低技能人物；不同方法修正能让至少
  两个品质维度产生不同结果。
- 工单创建后再修改人物技能，不改变该工单的产出快照；相同初始世界和命令序列产生
  完全相同的品质、技能成长、流水和存档。
- 完成真实工单会提高对应专门技能并由人物仓储记录为已变更；未到期、失败或无效工单
  不产生技能成长和实践流水。
- V17 快照迁移到 V18 后，原批次数量、所有权、来源和汇总品质不变；不伪造历史流水；
  往返存档保持品质维度、技能快照和实践流水。
- 非法品质维度、重复维度、错误汇总、错误技能引用及伪造实践流水均被拒绝。
