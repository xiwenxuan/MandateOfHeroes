# M21-P6 任务书：军事人物核心路径仓储迁移

## 一、阶段目标

承接 M21-P5，把现有真实服役初始化、战斗伤亡、缺粮逃亡和整军行军接入统一
`IPersonRepository`：

```text
原型人口与军队
→ 仓储登记实例化新兵及异地到任主将
→ 军令驱动行军或战斗
→ 伤亡、死亡与随军迁居落实到具体永久人物
→ 仅登记真正新增或字段实际改变的人物
→ 服役、军队缓存、人口事务和战斗记录继续使用原有世界账
```

逃亡在当前原型中只改变 `MilitaryServiceState.Status`，不改变人物字段；因此它必须保持
人物仓储干净，而不是为了证明“接入”而制造虚假的人物修改。

## 二、权威边界

- 永久身份、实例化、死亡、迁徙和增量写回遵守
  `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 真实服役、伤亡、逃亡、军令和行军遵守
  `UNIFIED_COMBAT_WARFARE_AND_AUTHORITY.md` 与
  `TASK_M10_REAL_MILITARY_SERVICE_AND_COMMAND.md`。
- 本阶段不增加持久字段，不提升 V11 世界存档版本，不改变伤亡率、伤员比例、
  逃亡人数、行军速度、补给消耗或确定性随机坐标。

## 三、工作包

### WP1：原型服役初始化

- `MilitaryServiceSystem` 接受可选共享人物仓储，并按稳定 ID 读取主将。
- 原型新兵经共享 `PopulationLedgerSystem` 从人口批次实例化，登记为新增人物。
- 异地到任的既有主将经同一人口账迁居，只在地点实际变化时登记修改。
- `PrototypeWorldFactory` 提供仓储工厂接入点；默认创建入口与既有调用保持兼容。

### WP2：战斗伤亡与死亡

- `BattleResolver` 把共享人物仓储传入真实服役伤亡结算。
- 伤员健康实际降低时登记人物修改；死亡人物由共享人口账登记死亡和人口事务。
- 服役状态、军队兵力/伤兵缓存和人口死亡数继续保持守恒。

### WP3：整军行军与抵达迁移

- `ArmySystem` 从共享仓储读取集结、在役和伤病成员。
- 抵达后通过共享人口账迁移具体人员，人物地点变化进入修改集合。
- `WorldSimulator` 把其人物仓储传给 `ArmySystem`，避免日常推进另建不受控访问层。

### WP4：缺粮逃亡与只读边界

- 缺粮继续按稳定随机规则选择真实服役成员并改变服役状态。
- 因当前逃亡不改变 `PersonState`，人物新增和修改集合必须保持为空。
- 抽象旧军队兼容路径继续只改抽象兵力，不伪造永久人物。

### WP5：验证与状态同步

- 验证注入和兼容模式在征募、战斗、行军和逃亡路径产生相同世界快照。
- 验证原型新增人物、异地主将、全部具体伤亡和抵达成员的精确增量集合。
- 验证逃亡路径不制造人物修改。
- 更新系统总纲、M12、战争设计、M10 兼容记录与 Skill 任务路由。

## 四、不纳入本阶段

- `MilitarySupplySystem` 中供货人的经济访问与军需采购扩展。
- 新兵来源选择、正式征兵政策、退役安置、俘虏处置和逃兵返乡迁居。
- 装备、兵种、阵型、局部交战、个人战和战役目标。
- 未驻留人物完全外置运行和千万级完整战争负载。
- 新人物字段、新存档版本或军事数值重平衡。

## 五、验收标准

1. `MilitaryServiceSystem` 和 `ArmySystem` 不再直接遍历 `WorldState.People`。
2. 原型服役初始化把 237 名新兵登记为新增，并登记实际迁居的既有主将。
3. 注入和兼容模式生成的原型世界快照一致。
4. 战斗人物修改集合恰好覆盖双方具体伤亡，伤员健康和死者状态正确。
5. 随军抵达人物经共享人口账迁移，人物修改集合与实际迁居成员一致。
6. 缺粮逃亡保持世界结果一致且不产生虚假人物修改。
7. 军队缓存、人口审计、确定性战斗和存档往返既有回归保持通过。
8. 默认构造和既有 `PrototypeWorldFactory.Create184World(seed)` 调用保持兼容。
9. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。
