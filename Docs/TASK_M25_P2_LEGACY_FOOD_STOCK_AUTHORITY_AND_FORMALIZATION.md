# M25-P2任务书：旧粮库存权威与正式食品批次化

## 一、任务定位

在M25-P1正式汉代五作物六食品内容与家庭粮仓消费合同之上，建立旧粮标量到正式产品批次的
显式、守恒、可审计切换。旧V28存档不能在读取时臆造六类食品来源，因此顺序迁移只把世界升级
到V29并保留旧粮权威；只有明确调用正式化适配器时，才按当前内容清单的开局份额把家庭粮食、
村公共粮仓和县仓拆为产品批次，同时清零被替代的旧余额并切换世界级库存权威。

本任务解决“一份粮同时存在于标量与批次”造成的重复库存风险。它不在同一阶段改写农业、
税粮、赈济、市场和跨县运输的月度运行逻辑；正式化入口暂不由`WorldSimulator`自动调用，
运行时读写切换由M25-P3完成。

## 二、实现合同

### 2.1 V29库存权威

- `FoodInventoryAuthorityMode.LegacyScalar`：家庭`Grain`、村`PublicGranaryGrain`和县
  `CountyGranaryGrain`仍是权威；正式公共粮仓容器引用必须为空。
- `FoodInventoryAuthorityMode.FormalProductBatches`：上述三类旧食品余额必须全部为零；家庭食品
  由家庭粮仓批次表示，村仓和县仓分别引用组织库存容器。
- 种粮`SeedGrain`仍保留现有兼容合同，本阶段不伪装成已经完成多作物种子批次迁移。
- 权威只改变事实的保存形式，不改变人物、家户、组织、地点或总食品数量。

### 2.2 顺序迁移

- `WorldState.CurrentSchemaVersion`由28升级为29。
- V28→V29只初始化`LegacyScalar`并补齐空引用，不拆分来源、不修改旧余额、不制造库存事务。
- 既有库存事务的新来源字段规范为空字符串；旧事实和内容清单保持不变。
- V1—V27继续逐版迁移，禁止跳版本或用当前默认值覆盖旧事实。

### 2.3 显式正式化

- 使用正式内容注册表中非零`OpeningShareBasisPoints`且稳定ID排序的食品定义；全局份额必须恰好
  合计10000，普通新增内容不能依靠固定食品枚举。
- 旧粮单位只能适配为单位重量为1的食品；不兼容内容必须明确拒绝。
- 每个有旧粮的家庭建立一笔正式化事务和若干家庭粮仓批次，旧`Grain`等量归零，家庭粮仓
  物理占用不增不减。
- 每个村庄建立归县政府组织所有的村公共粮仓容器；每个县建立本县政府组织所有的县仓容器。
  原有村/县余额按相同份额建立组织批次并归零，村庄旧公共粮仓设施的镜像库存同时清零。
- 整数拆分余数稳定归入排序第一的开局食品，保证任意数量都精确守恒。
- 正式化只能执行一次；容器ID冲突、家庭粮仓不一致、村庄没有县政府归属或内容清单不兼容时，
  必须在写入前失败。

### 2.4 审计与校验

- 正式化事务分别声明家庭、村庄或县治理来源，且一次只能替代一类旧余额。
- 每笔事务的正向批次数量必须等于旧余额负向变化；家庭事务不能改变所有者，村/县事务只能
  写入其正式粮仓容器。
- 正式权威世界不得残留旧食品余额或缺失公共粮仓容器。
- 内容清单、产品ID、批次、事务、容量与保存往返继续使用既有正式校验。

### WP2：数据驱动正式化适配器

- 注册表提供食品稳定排序查询；

- 验证V29正式世界扩展内容清单往返与非法残留拒绝。

### WP4：状态同步与验收

- 更新系统总纲、世界模拟说明和任务路由；

## 四、验收标准

1. V28存档升级到V29后仍使用旧粮权威，家庭、村仓和县仓余额完全不变。
2. 显式正式化后三类旧食品余额为零，正式批次总量与原余额逐单位相等。
3. 所有村仓和县仓具有稳定容器ID、正确政府组织所有权与地点，批次不超过容量。
4. 正式化份额来自数据定义；不增加作物、食品或来源枚举。
5. 每笔正式化事务来源唯一、逐批次守恒，篡改余额、容器或流水会被校验拒绝。
6. V29正式世界带汉代食品扩展包完成保存往返，缺包仍明确报告原包ID。
7. 编译、核心测试、受控Unity测试和`git diff --check`分别通过。

## 五、不包含

- 把农业收获直接结算为正式多食品批次；
- 家庭消费、税粮、村县赈济在两种权威间的运行时自动分派；
- 县级市场挂单、成交和价格篮子的逐产品迁移；
- 跨县民用货运、仓储腐败、包装污染和多段物流；
- 多作物种子余额、逐地块轮作和水利适生；
- 在加载旧存档时推定不存在的历史食品来源。
