# M25-P26 军药采购、军需补运与随军药库收货任务书

## 一、阶段目标

承接 M23 的真实军需物流和 M25-P25 的正式随军药库，把军药从来源组织的具体产品批次，经真实付款、承运、路线、途中补给与损耗，送入目标军队的正式药材容器：

```text
来源组织正式药材批次
→ 有军权人物签发采购或内部调拨
→ 真实资金与库存出账
→ 永久人物承运并沿既有路线移动
→ 途中口粮、自然损耗、敌对损失与交接照常结算
→ 与目标军队会合
→ 按实际到货量生成目标军药批次与入库事务
```

本阶段复用同一军需货运事实，不建立会绕开损耗和在途风险的“医疗瞬移补给”。

## 二、本阶段完成范围

1. 使用稳定命名空间 ID 表示军需最终收货用途；旧有粮运为军队口粮桥，新用途为军队库存容器收货。
2. 每张货运单持久保存收货用途和目标库存容器；旧粮运不需要目标容器，新军药单必须指向目标军队唯一正式药库。
3. 军药补运只接受带 `product.medicine` 标签的产品，首版正式入口限定为 `product.medicine.herbal_material`。
4. 商业采购、内部调拨、补偿征购、无偿征发和劫掠继续复用 M23 取得方式、权限、财政和治安规则。
5. 军药运输继续复用永久承运人、人物旅行或随军运输、多段交接、途中口粮、自然损耗、敌对损失、夺回和分批收货。
6. 实际收货时按剩余库容确定可接收数量；每批收货生成新的可追溯产品批次和库存事务，不把来源批次瞬移或重复入库。
7. 军药入库不增加 `ArmyState.Provisions`，不生成粮草补给记录；粮运旧路径行为保持不变。
8. 增加正式军药补运入口，调用既有军需发运合同并强制绑定目标军队药库。
9. 存档升级到 V48；V47→V48 把所有旧军需单标记为军队口粮收货，不伪造军药订单、到货批次或采购历史。

## 三、领域约束

- 目标药库必须属于目标军队组织，位置必须随目标军队事实保持一致。
- 商业采购必须等额扣减买方组织金库并增加来源组织金库；内部调拨必须同一组织且价格为零。
- 发运数量必须来自未预留真实批次；到货、在途、自然损耗、敌对损失和被消耗数量之和必须闭合。
- 入库数量必须同时由货运交付流水、库存事务和新到货批次闭合；库容不足时只能按实分批接收，零库容不得产生部分写入。
- 玩家关注、地图缩放、人物冷热层级和界面状态不得改变货损或实际到货量。

## 四、明确不做

- 不实现伤员担架、救护队、后送路线、转院、野战医院床位或人物位置迁移；这些进入 M25-P27。
- 不实现自动军药需求预测、委任报价生成和跨军调药 AI；当前由明确领域命令签发。
- 不增加新的药物类型、复杂处方或医疗界面。
- 不提交、不推送；版本操作仍需用户另行授权。

## 五、验收用例

1. 商号真实草药批次经合法商业采购发运，买卖双方资金等额变化，运输完成后仅把实际剩余数量写入目标军队药库。
2. 军药在途继续发生确定性自然损耗；发运量等于到货、在途、自然损耗、敌对损失和授权消耗之和。
3. 军药收货生成新的正式批次和正向库存事务，来源批次发运事务、到货事务和物流流水可以交叉审计。
4. 库容不足支持分批实收；零库容、错误药库、错误产品、无权签发、资金不足或路线错误时保持原子失败。
5. 旧粮运仍增加军队口粮并生成既有军需记录，不生成药材批次。
6. V47→V48 不制造军药事实；V48 往返保存收货用途、目标容器和已到货批次。
7. 全工程编译、聚焦回归、全量核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。
