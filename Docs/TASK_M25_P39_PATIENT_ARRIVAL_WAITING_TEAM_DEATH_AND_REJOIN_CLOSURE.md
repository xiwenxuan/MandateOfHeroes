# M25-P39 患者已抵军、等待救护队期间死亡与归队结案任务书

## 一、阶段目标

承接 M25-P28 的全员返军闭环与 M25-P38 的患者返军途中死亡合同，处理患者本人已经完成返程、抵达来源军队，但至少一名原救护队员仍在真实返程旅程中时，患者伤情复发死亡的世界事实：

```text
患者先抵达来源军队，救护队尚未全员归队
→ 冻结返程、最后照护责任、患者已抵达事实与全队死亡时返程快照
→ 永久人物、人口、军籍、家庭继承和原军队组织抚恤原子闭合
→ 遗体留在来源军队，救护队继续原旅程
→ 来源军队继续冻结，直至最后一名救护队员归队
→ 救护队恢复现役，住院与后送记录统一结案
```

## 二、本阶段范围

1. 存档升级至 V61，新增患者已抵军等待队员死亡情境、数据政策、遗体留军策略、返军死亡结案扩展字段和次日启用边界。
2. 只处理住院已出院、后送仍处于返军阶段、患者返程旅程已经完成、患者位于来源军队、且至少一名救护队员仍有非零返程里程的情形。
3. 返军死亡结案冻结原返程路线、起终点、开始日、已完成的患者旅程 ID，以及全部救护队员在死亡时的返程旅程与剩余里程；至少一名队员的冻结剩余里程必须大于零。
4. 死亡继续复用永久人物、人口、军籍、家庭继承、家主继任、来源军队组织抚恤和最后照护责任闭环；最后照护组织与抚恤组织仍允许不同。
5. 患者死亡后遗体留在来源军队，不重建患者旅程、不消耗死者行粮；原救护队员沿各自既有返程旅程继续归队。
6. 来源军队在剩余救护队员全部归队前不得行军；全员归队后患者军籍保持死亡、队员恢复现役，住院和后送记录一次结案。
7. V60→V61 只补核心未来政策、结案字段默认值和次日启用边界，不从旧返程、人物位置、队员进度或既有死亡倒推历史。

## 三、验收条件

- 患者先抵军且队员仍在途时，死亡冻结完整队员返程快照、最后照护责任和健康开闭值；患者永久死亡并留在来源军队。
- 死亡后来源军队仍被返军任务冻结；剩余队员归队后军队解冻、队员恢复现役、住院与后送结案。
- 等待期不足、患者仍有返程旅程、没有在途队员、阶段错误、权限不足、家庭或财政不完整时，不得产生部分死亡事实。
- 篡改患者已抵达标记、遗体策略、死亡地点、返程路线、队员旅程快照、最后设施/医者或交叉引用时，世界校验失败。
- V61 往返保存完整；V60 迁移不制造患者已抵军等待队员死亡历史。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 和范围审阅分别完成。

## 四、明确不包含

- 救护队员返军途中死亡、受伤、逃亡、失踪或被俘；
- 遗体改道、棺木、家属接回、安葬、讣告传播和关系反馈；
- 医疗事故过失比例、司法追责、额外赔偿或抚恤欠款；
- 自动每日死亡调度、动态追逐移动军队、多段返程和玩家医疗界面。
