# M15-P5 全热集在世人口上界压力报告

## 一、补测原因

初次M15-P5只验证10万在世热集持续出生和死亡，累计到1000万永久人物。该负载证明了
死亡冷档案可以与在世数据分离，但没有覆盖一种合法的最坏情况：累计人物尚未死亡，
`CurrentLivingPopulation = CumulativePersonCount`。

本补测按用户要求，把全部人物保持为在世状态，并从100万逐级推进到5000万。

## 二、“全热集”的测试定义

每个在世人物同时具有：

- 41字节永久核心：人物ID、父母、家户、出生时间、地区和性别；
- 45字节在世索引：同一核心字段及下一生命周期调度日；
- 紧凑常驻数组：把上述45字节在世索引全部读入64位进程内存；
- 确定性摘要、首/中/末人物直接查询和连续ID校验。

“全热集”不表示为每个人创建完整属性对象、全部私人关系、完整AI、生产工单、战斗状态、
`GameObject`、动画或寻路。测试结论只能用于基础在世核心与调度索引上界。

## 三、实现与恢复

工具使用两个追加文件：

```text
all-alive-core.bin
all-alive-hot.bin
manifest.json
```

每100万记录提交一次清单。中断后按最后清单截断尚未提交的核心和热索引，后一级从前一级
稳定ID与摘要继续追加，不重新生成或覆盖旧人物。自测试覆盖常驻往返、分段/连续摘要一致
和未提交追加恢复，结果为`passed=3 failed=0`。

自测试证据：

## 五、结论

在本机、本原型字段和独立64位进程中，5000万人物同时在世的基础永久核心与在世调度
索引可以生成、恢复、直接查询并全部紧凑常驻。与原P5冷热矩阵结合后，当前证据覆盖了：

1. 10万在世、990万死亡冷档案、累计1000万；
2. 5000万全部在世、没有死亡冷档案。

因此“5000万人可能同时活着”不再是未测假设。但正式支持仍不能据此宣布，因为完整游戏
还需要人物属性、组织、关系、事件队列、职业、生产、军事、认知、缓存、Unity和操作系统
共同争用内存与磁盘。正式适配器必须允许全量在世核心存在，同时只把到期对象和玩家关注
对象提升为更昂贵的活动视图。

## 六、未覆盖项

- 5000万在世人物的完整到期队列、一天/月/年推进；
- 5000万人全部拥有完整属性、装备、履历或私人关系；
- 完整生产、消费、征兵、迁徙、疾病和战争守恒；
- 与正式V6/V7存档、Unity运行时和其他系统同时运行；
- 不同硬件档位、最低配置和发布平台复测；
- 累计超过5000万后同时存在大量在世者与死亡冷档案的混合上界。
