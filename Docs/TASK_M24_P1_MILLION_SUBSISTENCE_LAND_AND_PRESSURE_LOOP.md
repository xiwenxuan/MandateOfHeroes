# M24-P1任务书：百万家户粮食、土地承载与人口压力闭环

## 一、阶段目标

在M24-P0“100万永久人物自然演化50年”基础上，加入第一层真实世界约束：

```text
具体在世人物
→ 家户年度口粮需求
→ 县级可耕土地与具体农业劳力形成收获
→ 损耗、地方冲突征夺与家户消费
→ 粮食满足度改变后续生育和具体人物死亡
→ 人口变化反过来改变下一年劳力与消费
```

本阶段仍采用独立压力工具，不修改V28正式世界快照，也不把百万普通人物升级为完整NPC AI。
目标是验证人口、家户、土地、粮食和压力死亡能否在同一永久人物账上连续闭环50年。

## 二、事实与来源等级

1. 郡国人口来源、县级目录和开局人口空间比例继续使用M13审计数据；
2. 每个人和家户沿用M24-P0的永久稳定ID、县、血缘、婚配、生死事实；
3. 土地、基础产量、劳力能力、口粮需求、天气、疾病和地方冲突参数由独立数据档定义，
   来源等级为`gameplay_completion`，只用于技术与玩法压力测试；
4. 不把“标准口粮单位”“每人缩尺土地”或随机压力解释为东汉史实；
5. 同一输入、版本、种子和参数必须形成相同的人口、粮食、压力事件和县级摘要。

## 三、粮食和土地合同

计量使用整数定点：

- `1,000 grain_milli_rations`表示一个标准成年人的一日口粮；
- `1,000 arable_milli_mu`表示一个抽象亩；
- 该标准口粮可以在后续由数据驱动产品批次折算，不固定为某一种作物；
- 增加作物、配方或地方品种不得修改本协议结构。

每县保存固定可耕土地、期初粮食、年度农业劳力、实际耕作面积、收获、田间/留种损耗、
仓储腐败、地方冲突损失、家户需求、实际消费、未满足需求和期末粮食。

每个家户的需求必须由当年具体在世成员年龄计算，不能直接使用人口总数乘固定系数。
县级批量生产和分配可以作为性能缓存，但年度消费必须回填家户满足度；该满足度影响家庭
下一年度生育概率及饥荒死亡风险。

年度粮食必须满足：

```text
期末粮食
= 期初粮食
+ 毛收获
- 田间与留种损耗
- 仓储腐败
- 地方冲突征夺
- 实际家户消费
```

土地总量在本阶段固定，不因界面观察、人口变化或年度结算凭空增加。劳力不足时允许土地
撂荒，人口增长不能自动增加可耕地。

## 四、疾病、饥荒与地方冲突入口

- 饥荒风险由具体家户未满足口粮比例决定；
- 疾病暴发由稳定县级年度坐标决定，并受营养不足放大；
- 地方冲突暴露由稳定县级年度坐标决定，可以征夺真实粮食并造成具体人物死亡；
- 每个额外死亡都写入具体人物、家户、县、日期和原因；
- 已死亡人物退出后续调度，但永久档案和死亡原因不能删除；
- 同一人物同一日最多死亡一次，未来原定自然死亡事件到期时必须无副作用。

这些是可注入压力合同，不是完整瘟疫传播、战役、征粮权限或历史事件系统；技术参数产生的
冲突和疾病不得冒充140—190年的史实事件。

## 五、实现范围

- 扩展`PopulationFiftyYearWorld.cs`，通过可选压力参数保持M24-P0基线模式兼容；
- 新增生计压力数据档和M24-P1独立安全入口；
- 输出最终家户生计侧车、具体压力事件账、逐年县级粮食账和机器可读清单；
- M24-P0没有压力参数时继续使用原有二进制版本、人口规则和摘要；
- 原始长跑证据只写入被Git忽略的`tmp/m24-p1`。

## 六、验收条件

1. 开局严格生成1,000,000名具体人物和1182县；
2. 连续运行50年且不超过300秒硬时限；
3. 每年每县土地不为负，耕作面积不超过可耕地且受具体农业劳力限制；
4. 每年每县和全局粮食等式守恒，没有负库存或凭空粮食；
5. 家户需求来自具体在世成员，实际消费不超过需求与可用粮食；
6. 家户满足度实际改变后续生育概率，未满足量进入可审计累计账；
7. 饥荒、疾病和地方冲突死亡落实到具体人物并与人口死亡总账一致；
8. 压力死亡不能删除人物，未来自然死亡事件不能重复扣减人口；
9. 10,000人小规模双跑的人口、粮食和压力摘要完全一致；
10. 100万人长跑形成耗时、峰值内存、磁盘、年度人口和资源对照报告；
11. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。

## 七、不包含

- 逐块农田、具体作物季节、种子批次、农具与耕牛的百万世界同步结算；
- 家户之间的价格、货币、债务、市场竞价和跨县运输；
- 完整疾病传播网络、军队战役、征粮权限或史实战争时间线；
- 迁徙、职业转移、土地买卖、继承和新土地开垦；
- 正式存档版本升级、Unity界面、提交或推送仓库。
