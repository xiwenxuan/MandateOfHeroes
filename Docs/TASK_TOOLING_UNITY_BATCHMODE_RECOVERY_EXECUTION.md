# Unity批处理恢复执行任务书

## 一、任务目标

执行`TASK_TOOLING_UNITY_BATCHMODE_STARTUP_AND_EDITMODE_RELIABILITY.md`规定的四道闸门，解决当前完整
EditMode批处理进入Test Runner后不能在300秒内稳定生成结果XML的问题，并把验证入口改造成可定位、
可分组、可复查且不会遗留Unity进程的受控工具链。

本任务只修改Unity验证工具、必要的冒烟测试、Skill测试说明和任务记录，不修改游戏玩法、世界状态、
存档版本或正式内容。

## 二、开工证据

- Unity可执行文件与项目版本均为`2022.3.62f3c1 (1623fc0bbb97)`。
- 当前没有Unity Editor进程；项目`Temp/UnityLockfile`存在，但没有对应Unity进程。
- 最近批处理日志显示许可证授权成功、Package Manager完成、脚本编译无错误，并已进入
  `Running tests for EditMode`。
- 2026年8月4日已有完整套件成功XML：274项通过，持续约206—208秒。
- 后续完整套件曾完成284项、持续约224秒；此后新增测试继续增长，最近运行在Test Runner阶段超过
  外部等待窗口，没有XML。
- 多组5—9项精确过滤测试可以在约0.5—1.1秒内完成并生成有效XML。

因此当前首要假设是完整套件单进程运行时间逼近或超过300秒，或新增测试中存在长耗时项；许可证和
引擎启动异常保留为需要通过独立冒烟闸门排除的次要假设。

## 三、实施范围

1. 增强`Tools/Run-UnityTestsSafe.ps1`：
   - 支持`EngineSmoke`、`ProjectLoadSmoke`、`EditModeTests`和`PlayModeTests`模式；
   - 支持精确`TestFilter`；
   - 分别保存Unity日志、测试XML和JSON摘要；标准输出/错误只有在不改变Unity行为时才重定向，
     否则保存说明性证据并以`-logFile`为权威日志；
   - 将无日志、项目锁、总超时、无XML、测试失败区分为稳定退出码；
   - 只终止本次启动的进程树，保留300秒硬上限。
2. 运行闸门A和B各三次，确认引擎与项目加载不是当前阻塞源。
3. 选择一个既有快速EditMode测试作为冒烟过滤器，连续运行三次并解析XML。
4. 从现有测试源生成明确的测试清单，按批次运行；每组独立日志和XML，单组不超过300秒。
5. 若某组超时，继续二分该组直至定位具体测试；修复测试隔离或实现中的真实死循环，但不得删除测试
   或伪造结果。
6. 更新Skill测试说明和统一验证入口，使日常验证先跑冒烟，再跑受控分组。

## 四、验收标准

1. 引擎冒烟连续三次在60秒内成功并生成非空日志。
2. 项目加载冒烟连续三次在120秒内成功，日志无许可证、包解析或编译错误。
3. 最小EditMode测试连续三次生成有效XML且失败数为零。
4. 完整EditMode测试的每个预定分组都生成XML；汇总总数等于发现的测试总数，失败数为零。
5. 任何缺失XML、超时或测试失败都会使汇总返回非零状态。
6. 所有路径结束后均无本任务遗留Unity进程。
7. 全工程编译、核心测试、`git diff --check`分别通过。
8. 完成记录明确写出根因、修复、日志/XML/汇总路径和仍存限制。

## 五、权限边界

- 不擅自关闭用户程序，不自动刷新或修改许可证。
- 不删除`Library`、`Temp`或用户级Unity缓存；若证据证明必须处理，先取得用户确认。
- 不修改防病毒、防火墙、代理、注册表、系统环境变量或Unity安装。
- 所有Unity外部进程硬超时不超过300秒，轮询间隔不超过5秒。
