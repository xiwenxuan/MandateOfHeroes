# M25-P20 任务书：家庭救济照护送餐与逐笔交付审计

## 一、任务定位

承接 M25-P17 的真实进食恢复、M25-P18 的逐人份额以及 M25-P19 的村内救济排序与授权快照。本阶段把儿童、老人和短缺后重度虚弱者的进食从“系统自动消费”改为真实家庭行为：必须有同户、同村、存活、未服役且具备行动能力的成年家庭成员送餐，粮食才会从正式批次扣除并记到受助人名下。

照护只改变交付行为和审计链，不凭空产生粮食、营养或治疗效果。无人可照护时，个人份额继续保留，等待家庭条件变化。

## 二、实现范围

### 2.1 V42 数据合同

- 救济消费单保存照护交付政策稳定命名空间 ID；开放政策不使用固定枚举。
- 每个受损人物保存建单时冻结的 `RequiresCaregiverDelivery`，后续年龄、健康或职务变化不得改写历史需求快照。
- 新增永久 `HouseholdReliefCareDeliveryState`，逐笔保存消费单、受助人、照护者、日期、记入营养、来源类型及来源库存事务。
- 救济进食库存事务同时保存实际受助人 ID；`ActorPersonId` 表示取粮并送餐的人，二者不得混淆。

### 2.2 照护需求与照护者

- 建单时年龄不足 15 岁、超过 60 岁，或短缺伤害结算后健康低于 5,000 基点者需要照护。
- 无需照护者以本人作为库存事务执行人。
- 需要照护时，只从同一家庭成员中选择：不是受助人、仍存活、位于本村、未服役、年龄 15 至 60 岁（含）的永久人物。
- 合格候选按稳定人物 ID 排序，选择首位；不得扫描全世界人口，也不得生成临时照护 NPC。

### 2.3 逐人结算

- V42 新单按受助人稳定 ID 顺序逐人结算准备营养和正式粮食批次。
- 每次正式粮食扣除只记给一个受助人；整数食物单位产生的多余营养继续进入原消费单的准备营养余额，不得重复消费。
- 需要照护的受助人每次实际获得营养都新增照护交付记录；无人照护时不扣粮、不恢复且份额保留。
- `LastConsumerPersonId` 保持“实际进食者”语义；村庄粮食消费账的执行人物记录照护者或自助进食者。
- V41 及更早迁移的旧单继续使用旧家庭共享/自助兼容路径，不倒推照护历史。

### 2.4 V41→V42 迁移

- 新增照护交付集合并置空。
- 既有消费单标记为明确旧自助政策，既有受损人物不推定照护需求。
- 既有库存事务的受助人字段留空，不伪造历史收粮对象。

## 三、验收标准

1. 需要照护的受助人有合格同户成年人时，库存执行人、实际受助人和照护交付记录三者闭合。
2. 同样种子和世界事实选择相同照护者，且照护者选择不依赖集合插入顺序。
3. 无合格照护者时不扣除该人物的保留份额，也不产生恢复或空事务。
4. 独立人物自助进食不生成伪照护记录；照护者本人不会获得受助人的恢复。
5. 篡改照护者、受助人、营养、来源事务、政策或交付日期会被领域校验拒绝。
6. V41 存档迁移不倒推照护需求、照护者或受助人，V42 当前存档可往返保存。
7. 全工程编译、完整核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别通过。

## 四、非目标

- 本阶段不实现护理技能、照护耗时条、病号餐配方、疾病传播、长期营养史或关系好感。
- 不改变 P18 份额计算、P19 跨家庭优先级、公共粮仓授权或人物冷热存储层级。
- 不删除、合并、替代或重新随机任何永久人物。
