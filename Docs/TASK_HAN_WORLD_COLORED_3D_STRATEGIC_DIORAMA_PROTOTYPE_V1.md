# 任务书：天下彩色立体战略沙盘视觉原型 V1

## 1. 任务定位

在正式 `PlayableDemo` 的 `M 天下` 路由中，用原创、可持续扩展的“汉末彩色立体
战略沙盘”替换玩家已否决的水墨舆图方向。视觉目标借鉴经典三国题材战略地图的
信息组织原则，但不得复制任何商业游戏的模型、纹理、字体、界面、地图或代码。

## 2. 玩家决策与本轮结论

- 水墨方案不再作为普通玩家的默认或可见切换项，只保留为开发对照和旧测试兼容。
- 正式天下默认风格为 `STYLE E | Han Strategic Diorama`。
- 继续使用彩色三维地形、斜俯视镜头、清晰山川、道路、水系、行政层级与微缩城邑。
- 全国正式网格仍为 2 km 方格，不改六边形；远景隐藏格线，中近景按上下文显示精确格。
- `M 天下 / C 县域 / F 人物` 与县域 50m 建设空间保持不变。

## 3. 实施范围

### 3.1 彩色分层地形

- 新增独立 Art Profile、稳定 ID 与冻结镜头预设。
- 在现有地形特征掩码上增加彩色分段光照、暖光冷影和地貌轮廓强化。
- 山地、平原、林地、河谷保持互相可辨；禁止重新引入纸纹、灰墨和大面积去饱和。

### 3.2 战略镜头与信息 LOD

- 天下远景使用明显斜俯视构图，不使用垂直棋盘式俯视。
- 远景只显示州级边界和标签；缩放后沿用现有州—郡国—县 LOD。
- 2 km 格网只在约 180—220 的近战略尺度显示 24×24 精确交互窗；更远尺度隐藏。
- 保留中键平移、右键旋转、滚轮连续缩放和行政区选择。

### 3.3 立体城邑标志

- 从正式 `cities.json` 地点数据生成低多边形城墙、城楼和屋顶组合。
- 所有可见城邑合并为单个运行时 Mesh/Renderer，不建立逐城或逐 Cell GameObject。
- 战略沙盘下不再叠加旧二维“邑”方块；自然地形和水墨开发对照保持兼容。

### 3.4 玩家入口

- `M 天下` 自动进入战略沙盘。
- 玩家可在“战略沙盘 / 自然地形”间对照；普通 UI 移除“水墨原型”按钮。
- 风格、镜头、边界和格网变化不得修改 `WorldState`。

## 4. 明确不做

- 不修改全国 3314×2176、7,211,264 个 2 km Cell。
- 不修改洛阳县域 512 km²、320×640、204,800 个 50m PlanningCell 或 2,084 项 Facility。
- 不修改人物、人口、库存、市场、建设结算、道路权威数据或行政归属。
- 不修改 World Schema V79，不做存档迁移。
- 本轮不制作最终军队模型、全国独立城市高模、季节天气或战争特效。

## 5. 参考与素材合规

- 光荣特库摩系列历史页仅用于确认《三国志11》的“统一 3D 地图 + 回合制”产品特征：
  <https://www.koeitecmoamerica.com/rtk40th/us/history/>。
- Steam 商店页仅用于确认其三维战场与城市发展描述：
  <https://store.steampowered.com/app/628070/>。
- 两者只作为高层信息组织参考；本任务没有下载、导入、描摹或复刻其模型、纹理、字体、
  UI、地图截图或代码。运行时画面全部由项目已有正式地理数据、现有 Shader 和本轮原创
  程序几何产生。

## 6. 验收标准

1. 全工程编译通过。
2. 定向 Core / EditMode 验证新 Profile、镜头、M/C/F 路由和世界不变量。
3. 正式 PlayMode 从 `PlayableDemo` 验证：
   - `M 天下` 默认进入 `HanStrategicDiorama`；
   - 远/中景格网关闭，近战略尺度切换为 1×1 精确 2 km 格；
   - 城邑数量大于 0，且合批 Renderer 恰为 1；
   - 行政边界 LOD、道路、水系和地形仍可见；
   - 自然地形对照与战略沙盘可切换；
   - 完整 `WorldSnapshot` 前后一致。
4. 输出远景、中景、近景格网、郡国 LOD、自然对照和玩家默认共 6 张图，以及性能 JSON。
5. 执行 `git diff --check` 和任务范围差异审阅。

自动验收通过后状态只能是
`IMPLEMENTED_AND_AUTOMATED_ACCEPTANCE_PASSED_READY_FOR_USER_REVIEW`；最终视觉是否接受仍由
用户看图决定。
