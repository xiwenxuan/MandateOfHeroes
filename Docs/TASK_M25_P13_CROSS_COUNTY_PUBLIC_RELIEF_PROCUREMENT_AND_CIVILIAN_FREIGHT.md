# M25-P13任务书：跨县公共赈济采购、有限知识寻源与真实民用货运

## 一、任务定位

承接M25-P12本县赈济采购未履约事实：只有本县真实卖单、预算或仓容仍不足时，县政府才提出一次可保存的跨县采购命令。命令不得扫描永久人物、不得暴露承运人未知路线、不得把政府伪装成家庭买方，也不得让外县粮食直接瞬移进县仓。

本阶段把既有M25-P5/P6民用货运合同扩展为“家庭买方或政府组织买方”两种互斥所有权模式。政府跨县采购仍使用真实家庭卖单与批次预留、真实承运人物和移动容器；货物在起运时转为县政府财产，途中按原确定性规则损耗，到达后按县仓容量分批收货，完成后才向承运家庭支付运费。

## 二、实现范围

### 2.1 持久命令与来源

- M25-P12只有在本县采购仍未履约时发布稳定的跨县采购需求事件。
- 事件处理器只为次日建立一张持久命令；重复分发不得制造第二张命令。
- 命令冻结来源事件、目标县、最大数量、商品预算、运费预算和最高单价。
- 事务执行前重新核验来源、县政府、存活领袖、县仓、预算与当前世界日。

### 2.2 有限知识寻源

- 候选只来自外县活动正式家庭卖单，不自动创建卖单。
- 只有活动承运登记的`KnownRouteIds`能够形成从卖方所在地到目标县城的连续路线时，货源才可见、可运。
- 承运人必须存活、位于卖方所在地、没有在途旅程，移动容器也必须同地且容量足够。
- 候选按商品与运费总成本、安全度、路程、卖单及承运登记稳定ID排序；不得依赖集合枚举顺序。

### 2.3 真实履约

- 起运时消耗卖单真实预留批次，更新订单成交量并由县政府金库支付卖方商品款、托管承运费。
- 货物在承运容器中归县政府组织所有；不创建家庭买单或虚构家庭。
- 复用民用货运多段旅行、每日自然损耗、到货分批卸载和完成后运费结算。
- 到货进入目标县正式县仓；容量不足时保持待收货，不删除或瞬移剩余货物。
- 无合格外县货源、无已知路线、无承运容量或预算不足时保存未履约审计，不造粮、不扣款。

### 2.4 存档与兼容

- 世界模式由V34顺序升级为V35。
- V34→V35为旧公共采购成交补齐“本县来源、无货运、零运费”，为旧民用货运补齐家庭买方模式；不得倒推历史跨县采购。
- 公共采购成交增加来源县、民用货运和运费引用；民用货运增加互斥的组织买方、目标库存容器和来源公共采购字段。
- 往返存档必须保留命令、跨县成交、在途组织货物、路线、损耗、到货和资金守恒。

## 三、验收标准

1. 本县采购不足事件只建立一次次日跨县采购命令。
2. 未知路线或未登记承运人不会成为候选，且不扫描永久人物。
3. 有外县卖单和已知路线时，真实批次起运、政府付款、卖方收款、运费托管和旅程同时形成。
4. 在途粮食属于政府组织，按既有民运规则产生确定性自然损耗并最终进入县仓。
5. 无货源、无路线、容量或预算不足留下明确未履约账，不产生虚假商品、资金或家庭买方。
6. V34→V35迁移、V35往返、篡改引用拒绝和相同世界确定性通过。
7. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅按项目规则报告。

## 四、非目标

- 不实现未知市场的主动侦察、驿传信息延迟或组织知识抄录。
- 不实现多承运人换手、动态改道、押运战斗、保险、信用或仓储腐败。
- 不自动生成家庭卖单，不建立州郡审批树，不扫描全部人物寻找临时承运人。
- 不修改玩家关注层级、永久人物身份或冷热存储语义。
