## 1. 定位

本系统借鉴《鬼谷八荒》以性格、关系和定期自主行动塑造NPC生活的优点，但服务于本项目的
历史世界、职业身份和数代家族模拟。

这里的“AI”首先是可离线、可解释、可复现的游戏决策系统，不是让大语言模型直接控制NPC。

## 2. 决策结构

每个完整人物保存：

```text
PersonMind
  personality        // 稳定倾向
  needs              // 当前需要
  goals              // 中长期目标
  memories[]         // 亲历或获知的重要事实
  beliefs[]          // 人物认为真实的信息
  relationships[]    // 多维关系
  commitments[]      // 官职、契约、誓言和债务
```

基础人格维度：

- 野心：追求职位、名望和支配力。
- 顾家：愿意为亲属投入时间与资源。
- 社交：主动交友、拜访和经营关系。
- 冒险：面对旅行、战争和投资风险的接受度。
- 仁厚：救济、宽恕和避免伤害他人的倾向。

基础需要维度：

- 生计
- 家庭
- 身份
- 财富
- 关系
- 战争压力

全部采用`0—10000`整数值，避免浮点差异。

## 3. 月度重点与具体行动

AI分为两步：

1. **月度重点**：决定这个月最在意什么。
2. **具体行动**：根据地点、身份、资源和情报选择可执行行为。

当前月度重点：

| 重点 | 后续具体行动示例 |
|---|---|
| 维持生计 | 务农、做工、求职、借粮、迁徙 |
| 照顾家庭 | 赡养、治病、婚配、教育、分家 |
| 提升身份 | 投仕、应募、考试/察举、拜师、求荐 |
| 积累财富 | 贸易、置地、开工坊、放贷、储粮 |
| 维护关系 | 拜访、赠礼、调解、结义、谢恩 |
| 应对战争 | 参军、避难、囤粮、护送、投靠 |

当前原型已经实现月度重点选择，并接入务工、交易、拜访、求仕、参军、避难六类行为意图。
行为意图先经过`NpcActionValidator`验证，再交给对应领域系统结算。

当前实现进度：

- 务工：已结算确定性收入、口粮与生计需要。
- 交易：已结算基于所在地粮价波动的确定性盈亏。
- 避难：已连接直达道路并创建真实旅程。
- 拜访：已接入有方向的好感、信任与敬重变化。
- 求仕：已接入所在地官署、入门职位和容量验证。
- 参军：已接入所在地军事组织、士卒职位和成员记录。

## 4. 评分

```text
重点分数 =
当前需要
+ 人格倾向
+ 身份与处境
+ 关系与承诺
+ 情报判断
+ 小幅确定性扰动
```

确定性扰动来自命名随机流：

```text
npc_ai / person_id / month_index / monthly_focus / action_id
```

增加其他系统的随机抽签不会改变NPC原有决定。

## 5. 有限认知

AI读取的是`Belief`，不是无条件读取全局事实。

```text
Belief
  subject_id
  claim
  perceived_value
  confidence
  source_id
  learned_day
  expires_day
```

同一场战争可以同时存在事实、官报、商旅传闻和敌方宣传。密探、商人和官吏的价值，
来自他们能够更早获得或验证消息。

人物决策可用信息由个人观察与记忆、合法持有的文档、家族共享档案和当前职位授权的
组织档案共同组成。切换建设、资源、商业或战争专题视图不能成为新的AI信息来源；离任、
权限撤销、信使延误和档案过时都会改变可用信息。

NPC可以抄录、购买、窃取、转交或伪造信息，但必须提交对应行动命令，由领域系统检查
权限、载体、工具、识字与专业能力、文字或图表工作量、地点、时间、校对和风险。产生的
副本拥有自己的来源、完整度和更新时间，不与原档案自动同步。

### 5.1 目标委任与逐级拆解

AI既可以发起自己的行动，也可以接收上级委任。委任至少包含目标、辖区、预算、期限、
权限、红线、上报条件和报告周期。受任者依据自己的认知、能力、性格、忠诚和利益，把目标
拆为下级委任、建设项目、生产工单、运输单或具体人物行动。

受任者可以执行、在权限内调整、请求资源、提出替代方案、延迟或拒绝不可能完成的命令，
也可能因贪腐、野心或私人关系歪曲执行。所有选择必须能够输出依据，不能用直接修改结果的
“托管加成”代替真实工作。

M23-P11已实现第一条受控领域合同：同一军队内，军队主将可把军需根目标拆给分队主将，
分队主将可再拆给具体在役人员；拆分受两层深度、直接子目标数量、军职权限、数量和预算约束，
并由真实叶目标履约后自底向上完成。当前只提供显式命令，还没有让NPC自行选择拆分方案，
也没有伪造尚不存在的君主—都督—太守跨组织法定授权树。

M23-P12进一步提供显式恢复命令：父级受任人可取消尚未发运的失败叶目标，回收其数量和预算，
再在原权限与红线内重派；旧目标、原因、报价关闭和替代关系不会删除。AI以后可以根据自己的
合法认知提出调用这些命令，但当前仍不会自动判断谁“失败”、自动挑选替代人或凭托管加成
补齐已经损失的货物。

### 5.2 自主建设与选址

NPC自主建设只能使用已经掌握的土地、地理、资源、市场和威胁信息：

```text
识别需求
→ 生成已知候选区域
→ 必要时调查、勘察或征询当地人
→ 评估权属、地理、资源、交通、成本、风险和政策
→ 提交建设或审批命令
→ 由建设系统结算人员、材料、时间和结果
```

AI不得因为世界真实存在一条未知矿脉就自动选择该地点，也不得在缺少土地权、许可、资金、
劳力或运输时凭空建成设施。

## 6. 多维关系

```text
Relationship
  affection
  trust
  fear
  respect
  obligation
  shared_interest
  political_alignment
  intimacy
```

亲属、夫妻、师徒、主从、同僚、债权和仇敌是关系类型，不等于单一好感值。

## 7. 家族继承

人物死亡后可以继承：

- 财产与债务；
- 恩义与血仇；
- 门生、故吏和商业关系；
- 家传技能、秘密和政治立场；
- 未完成的家族目标。

继承强度由关系、遗嘱、共同经历与继承人的人格决定，不能机械复制父辈全部关系。

## 8. 更新频率

| 人物层级 | 更新频率 |
|---|---|
| 玩家、同行者、现场对手 | 每时段 |
| 家庭、好友、关键历史人物 | 每日或每旬 |
| 完整远方NPC | 每月 |
| 普通永久人物与家户缓存 | 每季聚合日常结果，异常落实到具体人物 |

所有人物从出生起已经是永久人物。与玩家建立关系、签订契约、取得职位或参与重要事件，
只会提高其决策、关系和表现精度，不会把原本不存在的统计人口临时升级为人物。

## 9. 行为安全边界

- AI只能提交`Command`，不能直接修改世界结果。
- 行动必须经过权限、地点、资源和规则验证。
- 婚姻、死亡、继承、叛乱等重大结果由领域系统解决。
- AI不得读取角色未知的秘密。
- 决策必须能输出评分明细，方便调试玩家质疑的行为。
- 生成式语言模型未来只能表达结果，不能成为唯一规则来源。

## 10. 基础回归验收

使用50名人物模拟10年，检查：

- 同种子结果完全一致；
- 不同性格产生显著不同的月度重点；
- 饥饿或战争压力能压过平时野心；
- 顾家人物在家庭危机时优先照顾家人；
- NPC不会选择无权限、无路径或无资源的行动；
- 每次决定都能显示前三名候选及评分原因。

## 11. 民用承运有限知识执行合同

M25-P6的民用货运规划是本文件“有限认知、真实执行”的首个正式经济切片：

- AI不扫描全部人物寻找虚构承运力，只读取活动承运登记；登记必须绑定真实人物、家庭和移动容器；
- AI不读取世界全路线表寻路，只能使用该登记明确保存的已知路线ID；
- 需求来自真实活动跨县订单，报价保存路线、里程、安全下限、计价和生命周期，不能直接改库存；
- 稳定选择后仍由领域系统建立成交、在途批次、运费托管和人物旅程；
- 关注层级只决定玩家看到多少报价理由，不改变需求、选路、损耗或收货事实。

后续完整经营AI可以决定是否下单、登记承运、调整计价或购买情报，但仍必须提交命令并经过同一
权限、知识、现金、容量和地点校验。

M25-P9把上述既有规划规则接入持久命令管线。正式日界只在活动需求或真实跨县可成交订单存在
时提交系统规划命令，命令处理器不得直接写世界；显式事务预检通过后才允许生成需求、依据活动
登记和已知路线报价并触发真实发运。工作检测不扫描永久人物，未登记人物不会因处于热集而自动
成为承运人；人物冷热变化也不能改变同一订单、登记和路线知识下的规划结果。规划提交后事件可
供后续经营AI、报告和知识系统消费，但这些消费者必须以事件ID幂等，且不能二次修改本次业务账。

M25-P10提供第一个可供经营AI消费的正式家庭食品缺口事件。事件只在按村事务已经完成救济、
实际库存消费、家庭食品安全和具体居民后果后发布；AI不得根据抽象人口比例提前制造缺口，也
不得在事件处理器中再次扣粮。后续委任AI可以把事件与官仓知识、市场订单、路线知识和权限结合，
提交赈济、采购或运输命令，但事件本身不授予库存、财政或跨县信息权限，并须以事件ID幂等。

## 12. 持久命令与事件恢复边界

M25-P7使“AI只能提交命令”从运行时约定变成V33存档合同：AI已提交但尚未到期的命令会随世界
保存，读档后依据稳定命令类型和有序参数重新规划，不会因为更换运行时而消失。失败验证形成稳定
拒绝结果并保留命令待处理，不允许AI绕过失败直接改世界；成功事务产生的事件先进入持久出站箱，
后续AI需求或命令处理器成功接收后才记录处理器确认。

这仍不允许序列化AI委托、思维链或大模型会话。需要长期存在的是命令、结果和可审计事件事实；
候选评分解释、提示词和临时推理缓存可以重建。事件处理器可能在确认前因进程中断而再次收到同一
事件，因此所有会继续提交命令的AI处理器必须以事件ID去重，并为派生命令生成稳定ID。
