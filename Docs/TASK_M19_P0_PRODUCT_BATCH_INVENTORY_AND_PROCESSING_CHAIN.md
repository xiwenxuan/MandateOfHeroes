# M19-P0任务书：产品批次、库存事务与首条加工链

## 一、阶段目标

在M17数据驱动生产内容和M18人物—科研—生产桥接之上，建立可持久、可审计的产品批次与通用库存事务原型，并打通：

```text
家庭旧麦粒余额
→ 明确转换为麦粒批次
→ 手工磨制：麦粒→面粉＋麸皮
→ 制作干粮：面粉→干粮
→ 市场按产品标签聚合可交易库存
```

本阶段同时允许小麦种子从旧`SeedGrain`余额转换为带品种、质量、活力和纯度的种子批次。转换必须扣减旧余额，不能制造第二份库存事实。

## 二、权威边界

- 产品、配方和方法继续使用稳定命名空间ID与数据定义；新增普通内容不升级世界存档结构。
- 批次、事务和加工工单属于可变世界事实，进入世界快照并由V9→V10顺序迁移。
- `Family.Grain/SeedGrain`是尚未转换的旧余额；`ProductBatchState`是已转换或新生产的具体库存。两者不能重复计数。
- `VillageFacilityState.InventoryUnits`是仓库物理占用缓存。等重量转换不改变该缓存，批次导入也不改变物理总量。
- 市场兼容层只聚合带`product.market`标签且未预留的批次数量，不凭空创建或删除批次。
- 加工结算必须先完整验证和预留输入；失败不得产生半笔事务。

## 三、实施范围

### WP1：内容扩展

- 核心内容包新增面粉、麸皮和干粮产品；
- 新增“手工磨麦”和“制作干粮”配方及方法；
- 注册表校验输入输出总重量守恒；种植配方因包含生长周期，不按加工守恒规则处理；
- 核心JSON和内置内容保持解析哈希一致。

### WP2：批次与事务合同

- `ProductBatchState`保存产品、所有者、仓库、数量、预留量、来源、质量、保鲜和可选种子属性；
- `InventoryTransactionState`以多行正负变动记录旧余额转换、预留、释放与配方结算；
- `ProcessingWorkOrderState`保存配方、方法、负责人、仓库、控制方式、时间、批次预留和产出引用；
- 世界校验覆盖稳定ID、引用、范围、事务行、预留守恒和工单状态。

### WP3：库存与加工系统

- 从家庭旧麦粒/种子余额原子转换为批次；
- 按稳定批次顺序预留配方输入；
- 随世界日推进完成到期加工单；
- 原子消耗输入，生成主产品和副产品批次并写一组库存事务；
- 提供仓库物理占用审计和市场可售聚合查询。

### WP4：旧系统兼容

- 农业和村庄缓存刷新不得覆盖已经批次化的仓库占用；
- 当前市场价格系统保持旧`commodity.grain`价格合同，批次聚合只提供数量桥接；
- 暂不让普通家庭自动以干粮替代每日原粮消费，避免在同一阶段暗改生存平衡。

### WP5：存档与验证

- V9→V10初始化批次、事务和加工工单集合并刷新核心内容清单；
- 当前快照往返保存全部新状态；
- 旧V9存档迁移不改变人物、家户、旧粮食余额和人口存储合同；
- 完成全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅。

## 四、不纳入范围

- 全部农业收获自动生成批次；
- 腐败、污染、温湿度和逐日品质衰减；
- 跨仓运输、拆分/合并UI与市场成交撮合；
- 干粮替代家庭消费、军粮装载和商队货物的完整迁移；
- 通用设施定义及磨坊建设系统。

上述内容必须继续沿用本阶段的稳定ID、批次和事务合同，不得退回固定产品枚举。

## 五、验收标准

1. 核心内容注册表包含5种产品、3张配方和3种方法，JSON与内置包哈希一致；
2. 麦粒或种子转换后，旧余额减少、批次数量增加、仓库物理占用不变；
3. 非法数量、错误仓库、容量不一致和不足输入在修改世界前被拒绝；
4. 加工输入按稳定ID预留，同一事实在不同控制方式下得到相同结果；
5. 10麦粒加工为8面粉和2麸皮，8面粉加工为8干粮，质量守恒且有事务证据；
6. 市场聚合只统计带市场标签的未预留批次；
7. 当前版本快照往返保存批次、事务、工单和来源链；
8. V9迁移到V10后人物、家户、人口存储和旧粮食余额不变；
9. 全工程编译、核心测试、受控Unity EditMode与差异检查通过。

## 六、执行记录

### 6.1 实现结果

- 世界模式升级到V10，新增产品批次、库存事务和加工工单持久集合；
- 批次保存产品、仓库、家庭所有权、来源事务/工单、质量、鲜度及可选种子品种、活力和纯度；
- 旧`Grain/SeedGrain`只能通过显式适配器转换，转换扣减旧余额而不改变仓库物理占用；
- 核心内容包升级到3.0.0，新增面粉、麸皮、干粮、两张加工配方和两种加工方法；
- 非种植加工配方加载时校验输入输出重量守恒；
- 加工工单按稳定批次ID预留输入，随世界日推进到期结算，并在单组事务中消耗输入、生成主产品和副产品；
- 家庭粮仓缓存刷新和农业容量计算已经包含批次重量，不会覆盖已经批次化的物资；
- 市场兼容查询按地点、`product.market`标签和未预留数量聚合批次；
- 总纲、生产专项设计和Skill任务路由已经同步M19状态与下一开发顺序。
