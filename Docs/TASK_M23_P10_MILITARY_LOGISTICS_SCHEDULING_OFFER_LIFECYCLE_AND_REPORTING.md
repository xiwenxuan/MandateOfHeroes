# M23-P10 军需委任到期调度、报价生命周期与履约报告任务书

## 1. 阶段目标

在M23-P9的军需目标、真实承运报价和发运委任底座上，补齐委任不依赖玩家逐日手动点击的
时间闭环：

```text
目标进入到期队列
→ 到期日按稳定顺序自动评估
→ 过期或撤回报价退出候选
→ 选中报价生成既有真实货运单
→ 在途按报告周期回写进度
→ 真实到货后关闭目标并保存完成报告
```

调度只决定何时执行既有命令，不得直接增加军粮、跳过权限与预算复核，或根据玩家关注
改变结果。

## 2. 必须完成

1. 为持久委任目标保存下次评估日和完成日；为持久报价保存有效期和关闭日。
2. 报价有效期必须落在提交日到目标期限之间；过期报价自动转为过期状态并形成普通报告。
3. 承运人可以在报价仍有效且目标尚未发运时撤回自己的报价；撤回必须保存关闭日和报告，
   且不得修改库存，因为报价阶段没有预留货物。
4. 每个世界日只处理当日到期目标，使用“下次评估日、目标稳定ID”的确定顺序，不扫描
   全部永久人物，也不依赖界面或玩家关注。
5. 待处理目标到期时复用M23-P9评估入口；失败后按报告周期安排下一次评估，超过期限后
   进入关闭的过期状态，避免每天重复异常。
6. 已发运目标按报告周期读取既有真实货运单，报告剩余、已交付、自然损耗、敌对损失和
   夺回数量；报告不得改变物流账。
7. 真实货运单进入`Delivered`后，目标转为完成状态并保存完成日和完成报告。
8. 将委任到期处理接入`WorldSimulator`日界，安排在运输到达和日界推进之后运行。
9. 存档升级到V24；V23迁移为目标和报价补齐确定性调度默认值，不伪造过期、撤回、进度
   或完成报告。
10. 自动测试覆盖自动发运、报价撤回、报价过期与重试、在途周期报告、到货完成、稳定顺序、
    V24往返和V23迁移。

## 3. 本阶段边界

- 不实现君主—都督—太守—军需官的父子目标递归拆解，该能力留给M23-P11；
- 不自动生成商人报价，不让全天下人物扫描需求；报价仍由明确领域命令提交；
- 不实现保证金、信用、违约赔偿、竞价保密、合同转卖或承运联盟；
- 不改变M23-P5至P8的运输、消耗、损耗、战斗和夺回规则；
- 不增加Unity界面；本阶段交付纯领域状态、模拟调度、存档迁移、报告与测试；
- 不提交、不推送仓库。

## 4. 验收标准

1. 同一世界、同一指令和同一日期得到相同的报价过期、选择、发运和报告顺序；
2. 到期调度不会遍历永久人物，只遍历持久委任目标、相关报价和货运单；
3. 撤回或过期报价永不被选中，且货物数量、预留量和资金保持不变；
4. 自动发运仍由`MilitaryLogisticsSystem.Dispatch`产生真实库存、资金和旅行事务；
5. 在途报告只读取真实物流累计字段，完成状态只由真实货运单到货触发；
6. 过期目标关闭后不会重复产生每日异常；
7. V24快照往返一致，V23迁移保留旧目标、报价和货运链接且不伪造历史报告；
8. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。
