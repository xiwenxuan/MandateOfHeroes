# M26-P1 商旅—家族成熟玩法纵向切片任务书

## 一、任务定位

M26-P1 是 M26-P0 首个可玩 Demo 主循环和 M26-P0A 逻辑纠错完成后的体验重构阶段。
本任务不继续扩张后台医疗、物流或人口合同，而是从普通玩家能够直接感知的目标、选择、演出、
文本、后果和成长入手，把现有世界系统组织成一条可反复游玩的商旅—家族纵向切片。

首批玩家身份采用“家族成员兼商人”。这只是验证成熟玩法结构的首个样本，不缩减商人、家主、
农户、士人、官吏、军人、医者、工匠、侠士、宗教人士和密探等完整身份目标。

参考方向如下：

| 参考作品 | 只吸收的玩法思想 | 本项目原创转化 |
| --- | --- | --- |
| 《九州：商旅》及九州系列 | 城际机会、跑商准备、旅途风险和个人成长 | 由真实县级市场、批次库存、人物行程、有限认知和地方事件结算 |
| 《吾今有世家》 | 家庭责任、产业积累、成员培养和代际目标 | 永久人物、真实家户资产、关系、教育、职业和继承进入同一本世界账 |
| 《了不起的修仙模拟器》 | 人物自主生活、状态反馈和涌现故事 | NPC 在玩家不操作时继续生活，事件只解释已经发生或可被选择的世界事实 |
| 《三国志》系列 | 人物身份、任务、地方局势和逐级战略参与 | 从普通人、家族和地方组织逐步进入官府、军队及势力治理 |

所有程序、数据、公式、文本、地图、界面、美术、动画和音频必须原创或具有兼容许可证并记录
来源。不得反编译、复制、改写或近似复刻商业游戏的源码、专有文本、数据表、UI、美术和音频。

## 二、玩家体验目标

玩家应能在无需开发者说明和开发观察台的情况下完成一条 20—30 分钟路线：

```text
以家族成员兼商人身份进入世界
→ 得知家庭缺口、地方需求或商会委托
→ 比较已知市场机会并确定目标
→ 准备钱、货物、口粮和同行者
→ 沿已知道路旅行并承担时间与风险
→ 处理一项有意义的途中事件
→ 在目标地点交付或交易
→ 看见家庭、人物、市场和关系的真实后果
→ 在偿债、置产、培养族人或扩大经营中作出长期选择
→ 获得下一阶段目标并可继续游玩
```

完成切片后，玩家至少能够回答：

1. 我是谁，与哪些人和家庭有关；
2. 我现在为什么要行动；
3. 每个选择要付出什么并可能得到什么；
4. 世界为什么产生这个结果；
5. 这次行动怎样改变我的人物、家庭和下一步机会。

## 三、核心设计合同

### 3.1 一项行动的六段合同

每项首批玩家行动必须具有以下六段信息，不能只表现为按钮后静默改数值：

1. **动机**：来自家庭需要、人物愿望、任务、市场机会或地方局势；
2. **预期**：展示玩家当前知识允许推断的收益、耗时和主要风险，不泄露未知事实；
3. **代价**：真实消耗时间、钱、物资、体力、关系、权限或机会；
4. **表现**：通过人物动作、移动、时间进度、界面状态或镜头反馈表达行动过程；
5. **结果**：用玩家可理解的语言说明成功、部分成功、受阻或失败及其原因；
6. **记忆**：把有效后果写回人物、家庭、市场、任务、关系、组织或事件事实。

表现层不得在动画回调、按钮脚本或临时场景对象中直接创造核心世界事实。世界命令提交后，
表现层只读取确定结果并演出；动画中断、跳过或重新打开界面不得重复结算。

### 3.2 首批目标链

至少制作一条数据定义的商旅—家庭目标链。推荐主题为“家庭粮食或债务压力”，但最终内容名称、
人物、商品、地点和数值必须根据现有正式内容合同原创确定。

目标链至少包含：

- 一个来自具体家庭或人物的明确问题；
- 两种以上筹措启动资源的合法路径；
- 一个由有限市场知识支持的跨地点机会；
- 一次真实采购或接货；
- 一段消耗时间、口粮并允许事件发生的旅行；
- 一个至少具有两个有意义选择且允许拒绝的途中事件；
- 一次交付或市场交易；
- 至少两个互斥的长期收益选择；
- 一个由结果生成而非预写必然发生的后续目标。

目标链不得锁死唯一正确路线，不得在玩家拒绝或失败时清空进度。失败应产生债务、关系变化、
错失期限、货物损失、伤病或替代机会等可继续游玩的局面。

### 3.3 家庭与长期成长

跑商收益不能只转化为个人货币增长。首批至少接通下列长期用途中的两项：

- 偿还具体家庭债务或补足家庭生活物资；
- 购买、建设或改善一个真实产业单位；
- 资助一名永久家庭成员学习、拜师或履行职业前置；
- 改善家庭与具体人物、商会、乡里或官府的关系；
- 为下一次经营准备库存、工具、运输能力或可信同行者。

家庭成员继续由 AI 生活。玩家只在具有家庭身份、所有权、授权或事件条件时作出相应决定；
不得因玩家打开家族界面就获得无条件控制权。

### 3.4 市场、情报和旅行

- 交易复用正式市场订单、实时价格、具体库存批次、人物金钱与载重，不建立 Demo 专用价格表；
- 玩家只能看到本人通过所在地点、关系、任务、商旅消息或其他合法信息来源获得的行情；
- 行情必须显示获知地点、获知时间和可信程度，过期信息允许产生合理偏差；
- 路线只使用人物已知且世界中存在的道路；预计耗时、口粮需求和已知风险在出发前展示；
- 旅行期间世界、NPC、市场、任务期限和家庭状态继续推进；
- 到达后价格变化、库存不足或委托失效必须按真实世界结果处理，并提供原因摘要。

### 3.5 事件与人物

首批事件必须由具体人物、家庭、地点、组织、货物或地方状态触发，不使用与世界无关的随机
弹窗。事件选择至少改变两类事实，例如：

- 时间或物资；
- 健康或伤情；
- 人物关系、信任或声望；
- 市场库存、任务结果或组织评价；
- 获得的情报、路线知识或后续机会。

随机行为使用稳定 ID、明确日期/行动坐标和项目确定性随机机制。保存读取后，同一已确定事件
不得重新抽取结果。

### 3.6 文本合同

玩家文本分为三层：

| 层级 | 用途 | 必须回答 |
| --- | --- | --- |
| 决策文本 | 目标、对话、事件选择和行动确认 | 发生了什么、我能做什么、主要代价和风险是什么 |
| 结果摘要 | 行动完成、受阻或失败 | 实际发生了什么、为什么、谁受到影响 |
| 展开详情 | 高级信息和开发审计入口 | 价格、库存批次、事务、责任与稳定 ID 等依据 |

普通玩家界面不得直接显示内部类型名、空引用、调试枚举、原始异常或没有解释的稳定 ID。
人物文本至少依据说话者身份、与玩家关系和事件处境选择合适语气。首批文本允许采用原创的数据
模板，但不能把多个身份写成同一种系统播报口吻。

所有可持续扩展的目标、事件、文本模板、商品、设施和任务使用稳定命名空间 ID 与数据定义。
增加普通内容不得要求升级存档结构。缺失内容 ID 必须保留原引用并明确报告或迁移，不能静默
改指到其他内容。

### 3.7 动画与表现状态

首批建立可复用的行动表现序列：

```text
接收玩家命令
→ 锁定本次表现对应的命令/结果 ID
→ 转向或移动到交互对象
→ 播放行动动作与时间进度
→ 读取已经提交的世界结果
→ 播放成功、受阻、受伤或失败反馈
→ 显示结果摘要并恢复可操作状态
```

首批最小动作集合：行走、停留、交谈、搬运/交易、工作、进食/休息、受伤和倒地。若缺少正式
美术资源，可先使用原创占位动作、图标和音效，但状态切换、取消、跳过、场景重载和存档读取
必须正确。动画不能决定交易数量、伤情、关系或任务结果。

### 3.8 信息层级与界面

普通玩家主界面只保留当前决策需要的内容：

- 当前人物、地点、日期与主要状态；
- 一个明确的当前目标及可选跟踪目标；
- 当前情境下真正可执行的行动；
- 已知机会、预计代价和主要风险；
- 最近重要结果及其因果摘要。

开发账、完整世界状态和高级诊断继续保留，但进入独立的展开详情或开发模式。不得要求普通玩家
阅读开发观察台才能理解下一步。

## 四、架构边界

### 4.1 Domain

只在现有状态无法表达必需的永久事实或不变量时增加领域状态。人物、家庭、金钱、库存、关系、
任务、伤情和身份优先复用现有合同。表现步骤、镜头、文字逐字播放和临时 UI 状态不得进入领域层。

### 4.2 Simulation

负责行动可用性、命令提交、时间推进、跨实体结算、确定性事件、市场和家庭后果。一个玩家动作
只能产生一次权威结算，并输出可供表现层消费的稳定结果摘要或事件引用。

### 4.3 Persistence

优先保持当前 V64。只有新增不可由现有事实或数据内容恢复的永久状态时，才提出顺序迁移方案，
并补充旧版本迁移、当前版本往返、无效版本拒绝和不变量校验。不得为了保存动画进度而轻率升级
世界存档；可恢复的表现状态应由持久命令、结果或事件引用重建。

### 4.4 Presentation

负责情境行动界面、目标跟踪、对话/事件卡、行情展示、行动表现、结果摘要和高级详情。
Presentation 不能直接写 Domain，也不能用场景对象、动画机参数或按钮状态充当世界事实。

## 五、实施顺序

### P1-A：人工体验基线

详细执行合同与证据格式见 `TASK_M26_P1A_PLAYABILITY_BASELINE_AUDIT.md`。

1. 在不使用开发观察台的情况下完成一次鼠标点击式 20—30 分钟试玩；
2. 记录每分钟玩家目标、操作、等待、反馈和中断；
3. 按“无目标、无选择、无表现、无解释、无后果、重复操作”分类缺陷；
4. 保存截图、日志、存档和可复现步骤；
5. 冻结首批商旅—家庭验收路线和不在本任务处理的问题。

### P1-B：目标与信息层级

1. 建立当前目标、跟踪目标和结果摘要入口；
2. 把开发字段转换为普通玩家语言；
3. 在行动前展示已知代价、耗时和风险；
4. 为不可用行动提供稳定原因和可执行的解锁提示；
5. 把审计细节移入展开层，不删除底层证据。

### P1-C：商旅目标链

1. 数据定义首批家庭问题、商旅机会、途中事件和长期选择；
2. 接通启动资源、采购、准备、旅行、事件、交付和结算；
3. 让拒绝、延误、亏损、受伤和部分完成均可继续；
4. 确保市场、库存、时间、关系和任务使用正式世界事实；
5. 保存读取后保持任务、行情来源、行程、事件和结果一致。

### P1-D：行动表现和文本

1. 建立命令结果与表现序列的一次性绑定；
2. 接入首批可复用人物动作和状态反馈；
3. 为家庭、商人、商会和地方角色建立原创文本语气模板；
4. 完成行动确认、过程、成功、受阻和失败文本；
5. 验证跳过动画、快速操作、读取存档和切换界面不会重复结算或卡死。

### P1-E：家庭长期后果

1. 接通至少两个互斥的收益去向；
2. 让具体家庭成员、产业、关系或教育状态产生持久变化；
3. 由真实结果生成下一目标或机会；
4. 验证 NPC 与世界在玩家不参与时继续推进；
5. 防止家庭物资、金钱或关系被重复结算或凭空产生。

### P1-F：可玩性验收和整理

1. 邀请不了解实现细节的试玩者按说明完成路线；
2. 记录完成时间、迷失点、重复操作、文本跳过和失败恢复；
3. 修复阻止完成或明显破坏因果理解的问题；
4. 更新唯一 Demo 启动说明、已知限制和下一阶段边界；
5. 不把尚未实施的其他职业、正式历史剧本或战略战争写成已完成。

## 六、验收矩阵

### 6.1 纯 C# 核心测试

至少覆盖：

- 首批目标链的可用、拒绝、失败、部分完成和成功路径；
- 采购、交付、家庭投入和市场交易的金钱/库存守恒；
- 行程时间、口粮、载重、期限和地点约束；
- 确定性事件在相同世界种子、稳定 ID 和行动坐标下结果一致；
- 同一命令或结果重复提交不产生第二次收益、关系或任务结算；
- NPC 不参与玩家目标链时仍按既有世界系统推进；
- 当前版本往返，以及任何实际新增持久状态要求的顺序迁移与不变量校验。

### 6.2 Unity EditMode/PlayMode

至少覆盖：

- 从主菜单进入首批推荐人物或创建合法人物；
- 目标卡、情境行动、行情、事件选择和结果摘要能够正确显示；
- 行动表现严格消费一次权威结果；
- 动画跳过、界面关闭重开和场景重载不会重复结算；
- 不可用行动显示原因且不发送非法命令；
- 一条采购—旅行—事件—交付—家庭投入路径能够完成；
- 保存读取后恢复当前目标、行程、事件和未读结果；
- 没有缺失序列化引用、场景错误或面向普通玩家的内部异常文本。

Unity 测试只能通过 `Tools/Run-UnityTestsSafe.ps1` 执行并保留日志与 NUnit XML；完整回归按当前
分组规则执行，不能用单个冒烟测试代替完整声明。

### 6.3 人工可玩验收

由未阅读本任务书和实现代码的试玩者完成。验收要求：

1. 能在两分钟内理解扮演人物、家庭处境和第一个目标；
2. 不打开开发观察台即可完成采购、旅行、事件和交付；
3. 行动前能理解主要耗时、成本和已知风险；
4. 行动后能说明至少两项世界后果及其原因；
5. 至少面对一次非装饰性的选择，并接受其后续影响；
6. 完成后出现两个以上长期方向，而不是只剩重复跑商；
7. 拒绝或失败后仍能继续游戏；
8. 20—30 分钟内不存在超过 30 秒且无进度、无反馈、无可跳过机制的等待；
9. 关键文本不存在内部类型名、明显占位语、现代网络口吻或与人物身份冲突的表达；
10. 试玩者能用自己的话描述“我为什么做、发生了什么、下一步想做什么”。

## 七、完成定义

只有同时满足以下条件，M26-P1 才能标记完成：

- 商旅—家族路线能够从正式 Demo 入口反复完成；
- 目标、行动、旅行、事件、交易、家庭后果和下一目标使用同一本世界账；
- 至少两个长期收益方向真实改变永久人物、家庭、产业或关系事实；
- 首批行动具备动机、预期、代价、表现、结果和记忆；
- 动画与 UI 不拥有或重复创建核心世界事实；
- 文本、数据和表现资源原创或具有完整兼容许可证记录；
- 全工程编译、适用核心测试、受控 Unity 测试、`git diff --check` 和差异审阅分别取得证据；
- 完成至少一次符合 6.3 的独立人工试玩，并记录问题与修复结果；
- 总纲、任务路由、Demo 启动说明和当前限制与实际状态一致。

## 八、明确不包含

本任务不包含：

- 复制、反编译或改写任何参考游戏的源码、文本、数据、UI、美术、动画或音频；
- 一次完成全部身份职业和全部人生阶段；
- 新建独立于正式世界账的 Demo 经济、家庭、事件或人物；
- 完整商会经营、全国贸易网、自动套利或复杂金融系统；
- 完整婚姻、生育、分家、宗族政治和多代继承 UI；
- 正式 223 年历史剧本、完整外交、官场或大战略战争；
- 为表现方便删除、合并或重新随机永久人物；
- 继续扩展跨组织医疗转运、自动选院或开发审计型医疗细节；
- 未经单独评审的存档版本升级。

## 九、风险与停止条件

- 若现有正式市场、家庭、旅行或任务合同之间存在实质冲突，停止实现并报告冲突，不建立旁路；
- 若实现需要新的永久状态，先提出存档迁移和往返测试方案，再修改结构；
