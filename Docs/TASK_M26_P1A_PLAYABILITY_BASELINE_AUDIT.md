# M26-P1A 可玩性基线审计任务书

## 一、任务定位

M26-P1A 是 M26-P1 商旅—家族成熟玩法纵向切片的开工审计阶段。它只负责取得当前 Demo 的真实
人工试玩证据、建立问题优先级、冻结首条商旅—家庭验收路线，并为 M26-P1B 目标与信息层级改造
提供输入。

本任务是只读诊断与证据整理任务，不实现新 UI、动画、文本、任务、经济、家庭或存档功能。
发现缺陷时只记录事实、影响和复现步骤，不在同一次基线试玩中边玩边修，避免不同代码状态的
证据混入同一结论。

## 二、审计问题

本任务必须回答：

1. 玩家进入 Demo 后，是否在两分钟内知道自己是谁、为什么行动以及下一步能做什么；
2. 当前 20—30 分钟流程中，哪些操作形成了有意义的选择，哪些只是触发后台系统；
3. 交易、旅行、任务、事件和家庭后果之间是否形成连续因果链；
4. 动画、时间推进、文本和结果反馈是否让玩家理解行动过程；
5. 哪些信息缺失，哪些信息过载，哪些内部审计字段错误暴露给普通玩家；
6. 失败、拒绝、资金不足、库存不足、路线未知或受伤后能否继续游戏；
7. 当前底座能够直接复用到首条商旅—家庭路线的内容是什么，真正缺失的最小能力是什么。

## 三、测试对象与冻结条件

### 3.1 测试对象

- 正式入口：项目当前唯一玩家 Demo 启动路径；
- 首选人物：当前世界中合法、在世且具有商人或可执行交易上下文的人物；
- 备选人物：由正式创建流程生成的合法人物；
- 禁止入口：开发观察台、调试按钮、控制台命令、直接编辑存档或场景跳转；
- 目标时长：每次 20—30 分钟，不含启动、编译和填写报告时间。

若当前内容无法提供合法商人，不得临时补造假身份或写死人物；应把“缺少可进入的商旅落点”记录
为阻断级缺陷，并用现有首批身份完成界面和反馈基线。

### 3.2 运行快照

每次正式试玩使用唯一 `run_id`，并记录：

- 日期、操作者和运行时长；
- 当前分支、HEAD 提交号、`git status --short` 和相关源码/内容指纹；
- Unity 版本、启动场景、分辨率和输入方式；
- 新游戏或读取存档，以及世界种子、人物稳定 ID、地点和日期；
- 是否存在用户已经打开的 Unity 编辑器；
- 使用的日志、存档副本、截图和录像路径。

同一 `run_id` 期间不得修改生产代码、场景、预制体、内容数据或存档。发生修改后必须结束该次
运行，并以新 `run_id` 重新开始。现有脏工作区可以作为审计对象，但必须记录完整状态且不得把
未提交状态冒充为稳定基线。

## 四、安全与操作边界

- 开始前检查现有 Unity 进程；编辑器已打开时不得关闭、杀死或另启批处理实例争夺项目锁；
- 自动 Unity 检查只能通过 `Tools/Run-UnityTestsSafe.ps1`，硬超时不超过 300 秒；
- 人工试玩由操作者在可见 Unity 编辑器或正式构建中进行，不以前台无限等待方式启动 Unity；
- 只复制本次需要的日志和存档作为证据，不删除、覆盖或修改用户原存档；
- 截图、录像和报告不得包含访问令牌、私人路径中的敏感信息或与任务无关的个人数据；
- 不读取、导入或对照任何商业游戏源码、反编译结果、专有文本、数据表或素材；
- 参考游戏只用于问题分类和玩法原则，不作为逐像素 UI 或逐句文本复刻目标。

## 五、执行流程

### P1A-0：开工检查

1. 记录 `git status`、HEAD、Unity 版本和当前进程；
2. 确认正式 Demo 启动路径与场景存在；
3. 确认本次使用新游戏还是合法测试存档；
4. 建立唯一 `run_id` 和证据目录；
5. 若编译、项目锁、入口缺失或场景无法加载，记录阻断证据并停止正式计时。

### P1A-1：首次盲玩

操作者只允许阅读游戏内普通玩家可见信息，不阅读任务书、实现代码和开发说明。计时开始后：

1. 从主菜单开始或继续游戏；
2. 创建或选择一个合法人物；
3. 尝试理解当前身份、地点、家庭和目标；
4. 尝试获得商品、行情或任务；
5. 尝试准备并进行一次旅行；
6. 尝试完成一次事件选择；
7. 尝试完成一次交易或交付；
8. 尝试把收益用于家庭或长期成长；
9. 在阻断、死亡或 30 分钟到达时结束。

不得为了“走通流程”接受场外提示。操作者提出“现在该做什么”本身就是迷失证据。

### P1A-2：分钟时间线

按不超过一分钟的颗粒度记录：

| 字段 | 含义 |
| --- | --- |
| 时间段 | 从进入主菜单起的分钟区间 |
| 玩家意图 | 操作者当时想完成什么 |
| 可见线索 | 界面、文本、动画或声音提供了什么信息 |
| 实际操作 | 点击、选择、移动、等待或返回 |
| 系统反馈 | 过程、成功、失败、数值和结果摘要 |
| 世界后果 | 人物、家庭、库存、市场、关系、任务或地点的变化 |
| 困惑/中断 | 不理解、找不到入口、等待、错误或卡死 |
| 证据引用 | 截图、录像时间码、日志或存档编号 |

重要界面切换、第一次使用某类行动、每次失败和每次长等待必须单独记录，不能只写最终印象。

### P1A-3：六类缺陷标注

每个问题至少归入一个主分类：

| 分类 | 判定 |
| --- | --- |
| 无目标 | 玩家不知道当前问题、下一步或完成条件 |
| 无选择 | 只有唯一按钮，或多个选项没有真实差异 |
| 无表现 | 行动静默完成、等待无进度、动画与结果脱节 |
| 无解释 | 不知道为何可用、不可用、成功、失败或得到该数值 |
| 无后果 | 操作未形成可感知的短期或长期变化 |
| 重复操作 | 重复点击、来回切页或逐项处理没有新决策 |

允许附加标签：文本、动画、信息层级、输入、性能、存档、逻辑、内容、无障碍和时代语气。

### P1A-4：严重度与优先级

严重度采用：

- **S0 阻断**：无法启动、无法进入人物、无法继续或存档损坏；
- **S1 主循环断裂**：无法理解或完成目标、旅行、交易、事件或结果；
- **S2 明显损害体验**：能够继续，但因反馈、文本、动画或重复操作显著无聊或困惑；
- **S3 润色问题**：不阻止理解与完成，但降低一致性和品质。

修复优先级不直接等于严重度。每项问题还要估计：

- 首条路线出现频率；
- 影响玩家人数和持续时间；
- 是否已有正式底层事实可复用；
- 是否会改变架构、存档或公开行为；
- 修复是否能够同时解决多个观察点。

P1-B 只接收有证据的 S0/S1 和高收益 S2；S3 默认进入后续清单，不抢占首条闭环。

### P1A-5：引导复跑与事实核对

首次盲玩结束后允许阅读开发说明，并对阻断点进行一次引导复跑，目的只限于：

- 区分“功能不存在”和“功能存在但玩家找不到”；
- 核对按钮操作是否真实改变正式世界账；
- 核对结果是否能在保存读取后保持；
- 收集失败路径和边界条件证据；
- 识别开发观察台与普通玩家入口之间的功能差距。

引导复跑必须使用新的 `run_id`，不得覆盖首次盲玩结果，也不得用开发者能够走通来否定玩家迷失。

## 六、输出物

任务完成时至少产生：

1. `Docs/REPORT_M26_P1A_PLAYABILITY_BASELINE.md`：人类可读的审计报告；
2. `tmp/m26-p1a-playability/<run_id>/timeline.csv`：分钟时间线；
3. 同目录下的 `run-context.txt`：工作区、Unity、人物和存档上下文；
4. 同目录下的截图、录像索引、日志尾部和存档证据清单；
5. 缺陷表：稳定问题 ID、分类、严重度、复现、证据、玩家影响和建议归属阶段；
6. 首条商旅—家庭路线草图；
7. 明确列出的“本轮不处理”范围；
8. 给 M26-P1B 的冻结输入清单。

审计报告中的“已有”“缺失”“阻断”和“推测”必须分开。没有代码、可操作入口或验证证据时，
不得把设计目标写成已有功能。

## 七、首条路线冻结标准

P1A 不负责实现路线，但必须把 P1B—P1E 的首批验收样本冻结到足够具体：

```text
合法玩家人物与家庭落点
→ 第一项家庭问题
→ 两种启动资源路径
→ 一条有限行情来源
→ 一次采购或接货
→ 一条已知道路和旅行准备
→ 一个可拒绝的途中事件
→ 一次交付或交易
→ 两个互斥的长期投入方向
→ 一个由实际结果生成的后续目标
```

冻结项至少包括稳定内容 ID 规划、参与角色/家庭/地点条件、使用的现有系统、缺失入口、成功路径、
拒绝路径、失败路径和必须展示的玩家信息。数值允许在实施时校准，但不得用固定脚本绕开真实市场、
库存、时间、关系和家庭事实。

## 八、验收标准

M26-P1A 只有满足以下条件才能完成：

1. 至少完成一次无场外提示的 20—30 分钟首次盲玩，或以完整证据确认在此之前被 S0 阻断；
2. 首次盲玩和任何引导复跑具有独立 `run_id` 与不可混用的证据；
3. 每分钟时间线能够还原玩家意图、操作、反馈、后果和迷失点；
4. 每个 S0/S1 问题均有可复现步骤和至少一项直接证据；
5. 问题已按六类缺陷、严重度和修复收益排序；
6. 报告明确区分功能缺失、入口不可发现、文本不清、表现缺失和底层逻辑错误；
7. 已冻结一条满足第七节的首批路线，并列出其复用事实和最小缺口；
8. 没有在审计过程中修改生产代码、场景、预制体、内容或存档；
9. `Docs/REPORT_M26_P1A_PLAYABILITY_BASELINE.md` 已完成范围审阅；
10. `git diff --check` 通过，文档模式验证取得明确汇总。

若试玩因 Unity 项目锁、编译失败或入口缺失被阻断，任务可以完成“阻断诊断”，但不能标记
M26-P1A 完成；必须保持进行中并将解除阻断作为下一动作。

## 九、明确不包含

- 修复发现的任何代码、场景、数据、文本或动画问题；
- 为了走通流程临时添加金钱、商品、人物、路线或权限；
- 设计全部身份的完整玩法；
- 建立最终 UI 视觉规范、正式美术或音频资产；
- 校准完整经济、人口、战争或历史剧本数值；
- 修改存档版本或迁移；
- 自动化取代首次人工盲玩；
- 用参考游戏截图、文本或素材直接设计本项目界面和内容。
