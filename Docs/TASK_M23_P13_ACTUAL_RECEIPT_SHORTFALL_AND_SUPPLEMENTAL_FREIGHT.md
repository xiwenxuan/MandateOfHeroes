# M23-P13 按实到货缺口、剩余需求与追加补运任务书

## 1. 阶段目标

修正“货运单结束即等于军需目标完成”的旧语义，把军需目标改为按军队真实收到的数量结算：

```text
目标要求100份军粮
→ 第一次真实发运100份并支付第一笔费用
→ 途中自然损耗或敌对损失3份
→ 军队实际收到97份
→ 目标累计实收97、剩余需求3，保持未完成
→ 新报价只针对剩余3份并再次真实付款、运输和承担风险
→ 累计实收达到100后目标完成
→ 父目标再按实际完成结果自底向上完成
```

追加补运不是补数字，也不是回滚第一次货运。每次尝试都必须拥有独立报价、真实库存出库、
付款、承运人物、路线、损耗和货运账；第一次已经发生的损失与费用永久保留。

## 2. 必须完成

1. 叶目标持久保存履约策略、累计实收、剩余需求和已完成货运单ID；累计实收与剩余需求必须
   按策略满足数量合同。
2. 首批策略使用稳定命名空间ID：新目标采用“足额实收”；V26已经完成的旧目标采用明确的
   “旧版货运结束即关闭”兼容策略，升级不得突然重开玩家已经完成的目标。
3. 报价持久保存其生成的货运单ID；被选择报价在货运结束后转为已完成并保存关闭日，旧报价、
   货运和报告不得覆盖或删除。
4. 新目标、P11拆分目标和P12替代目标都以请求数量作为初始剩余需求，累计实收为0。
5. 报价和候选复核按当前剩余需求检查库存，追加报价不再被要求覆盖最初总数量。
6. 每次发运数量必须精确等于当前剩余需求；目标累计付款等于所有已完成货运与当前在途货运
   的实际付款之和，并且累计付款加下一次候选费用不得超过原目标预算。
7. 货运单结束时，把该单实际交付量加入目标累计实收，并从剩余需求扣除；自然损耗、敌对损失、
   夺回和军队补给增加继续以真实物流账为准。
8. 若剩余需求为0，目标完成；若仍有缺口且期限未过，目标进入`NeedsAttention`并形成持久缺口
   报告；期限已过则保留实际实收但关闭为过期。
9. 一个目标可以依次生成多次货运，但同一时刻只允许一张在途货运单；旧已完成报价不能再次
   被选择。
10. 父目标的累计实收来自活动直接子目标的累计实收，存在未分配数量或任一子目标剩余需求时
    不得完成；取消的历史子目标不重复计入。
11. 日界调度继续只遍历持久目标、相关报价和货运单，按稳定ID处理；不扫描全部永久人物，
    不依赖玩家关注或界面加载。
12. 存档升级到V27。V26未完成目标进入足额实收策略；V26已完成叶目标保留旧完成语义并从
    真实货运读取实际实收，已完成父目标从活动子目标汇总实际实收，不伪造缺失货物。
13. 自动测试覆盖自然损耗缺口、追加补运完成、累计预算拒绝、报价/货运历史保留、父目标不
    提前完成、V27往返和V26完成目标兼容迁移。

## 3. 本阶段边界

- 不自动生成商人报价；缺口出现后仍由明确领域命令或未来AI提交新报价；
- 不返还第一次运输已支付费用，不把自然损耗或敌对损失改写为未曾发生；
- 不支持同时并行多张补运单、跨目标合并补运、跨父目标预算调剂或追加原目标总预算；
- 不处理尚未终结的敌方截获货物重复采购策略，货运单未结束前目标仍保持在途；
- 不实现承运违约赔偿、保险、保证金、自动寻路、跨组织授权或Unity界面；
- 不提交、不推送仓库。

## 4. 验收标准

1. 足额实收目标始终满足“累计实收＋剩余需求＝请求数量”，且二者均不为负；
2. 每张完成货运单只结算一次，重复日界或存档往返不能重复增加实收；
3. 累计付款严格等于目标全部货运单实际付款，下一次补运不能突破原预算；
4. 任何实收缺口都不能被误报为完成，补运只购买缺口数量；
5. 旧报价、旧货运、损耗和费用永久保留，新补运使用新稳定ID；
6. 父目标只在全部活动子目标足额完成且没有未分配数量时完成；
7. V27往返一致，V26已完成目标保持完成但不伪造实收数量；
8. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。
