# M26-P5 商号组织、岗位与经营扩展总任务书

## 一、定位与启动条件

本任务把 `REFERENCE_JIUZHOU_GAMEPLAY_ANALYSIS.md` 提炼出的通用玩法问题，转化为
《MandateOfHeroes》原创、可验收的商号组织经营扩展。参考作品只用于识别体验问题；本任务不复制其代码、数据、文本、数值、地图、界面或素材。

本文件已由用户确定为当前商人身份的成熟玩法建设总任务。它不因编号自动获得优先级；当前
顺序由 `GAME_SYSTEMS_MASTER_AND_STATUS.md` 与用户指令共同确认。M26-P5A 可以先解决城镇、建筑
和商号据点入口；下列未完成验收仍是总任务完成条件，而不是用来阻止首个可玩改进的借口：

1. M26-P1 的独立人工盲玩验收需要在 M26-P5 总体验完成前取得结果并分级。
2. M26-P1 中非食品商品正式市场适配冲突已有明确设计结论。
3. M26-P2 的 Unity 验收不再受项目锁阻塞，或已由用户明确接受受限验证计划。
4. M26-P3/P4 的策略与委任提案保持为权限入口，不被新 UI 绕过。
5. 若需新增持久状态，先确认存档版本、顺序迁移、往返测试和不变量校验范围。

首个实施任务见
`TASK_M26_P5A_ZHONGSHAN_MERCHANT_TOWN_OPERATION_SLICE.md`。它负责“进入中山—看见建筑—进入
商号/仓库—转入经营准备”，不把岗位、招募、载具、完整委托和全国分号提前宣称完成。

## 二、玩家目标与完成后的体验

玩家应能从一个具体商户家庭出发，建立或接管一个商号，在真实成员之间安排有限岗位，准备并执行一次跨县经营活动；抵达后，玩家可以选择亲自结算，或在取得权限后将重复经营委托给成员。所有结果继续写回同一套人物、家庭、组织、库存、市场、行程和事件账。

最小体验闭环：

```text
查看家庭需要与地方商机
→ 选择一次有理由、有期限的经营目标
→ 选择真实成员并安排岗位
→ 从真实库存装入具体商品批次和口粮
→ 沿已知路线启程
→ 处理消耗、损耗或人物事件
→ 到达后交付或出售
→ 查看资金、库存、关系、成员状态和下一目标变化
→ 可选择保留亲自经营或提交有限委任
```

## 三、硬边界

1. 商号、岗位、设施、委托和账本事实属于 Domain/Simulation，不得只存在于 UI 或场景对象。
2. 每个岗位由稳定人物 ID 指向一个永久人物；关注度降低、离开场景或保存读取不得重新随机成员。
3. 商品继续使用稳定命名空间 ID、具体 `ProductBatchState`、库存容器和交易流水；不得生成无来源货物。
4. 人员、货物、资金、口粮和牲畜不能重复计算或凭空产生；所有变化必须可追溯。
5. 路途事件使用稳定 ID、明确的时间/动作坐标和项目确定性随机机制。
6. 自动经营只委托选择权和执行权，仍须经过正式命令、权限、预算、资源预留及相同世界规则。
7. 表现层只读取状态、发出意图并展示结果，不直接改写市场、库存、人物或组织事实。
8. 新增普通商品、配方、岗位类型、设施类型和委托模板优先采用数据定义及稳定 ID，不以枚举锁死开放内容。

## 四、实施切片

### P5-A 商号身份与成员岗位

建立最小商号组织投影，复用现有家庭、人物和组织事实，不复制一套“商会专用人物”。首批岗位为：

- `role.merchant.leader`：对外决策与路线负责人。
- `role.merchant.accountant`：预算、价格和账本报告。
- `role.merchant.guide`：已知路线、预计时间和风险信息。
- `role.merchant.guard`：途中保护和风险应对。
- `role.merchant.cook`：口粮计划与旅途消耗管理。
- `role.merchant.medic`：伤病处置与是否继续行程的建议。

岗位定义必须数据驱动，人物任职必须校验所在位置、组织/家庭关系、有效状态和授权。岗位不直接提供魔法数值加成；效果通过人物能力、装备、健康、知识与具体系统共同计算。

### P5-B 出发准备与可读计划

提供一张原创的“经营准备”页面或面板，至少显示：

- 当前目标、动机、期限、出发地和目的地。
- 路线是否已知、预计时间和可见风险来源。
- 承运容器、载重上限、已装商品批次和来源。
- 旅途口粮、备用资金及其所有者。
- 同行永久人物及岗位缺口。
- 不能出发时的稳定失败码和玩家可理解说明。

确认启程后继续使用正式 `JourneyState`，不得创建专用的 UI 计时器或平行路线。

### P5-C 商业委托生命周期

建立首个正式、有限的商业委托类型：从一个真实发布者接受指定批次或可替代产品定义的跨县交付。状态至少包括：

```text
Offered → Accepted → Reserved → InTransit
→ Completed | PartiallyCompleted | Failed | Cancelled | Expired
```

委托必须记录稳定委托 ID、发布者、受托家庭/组织、负责人、起止地点、目标产品、数量、质量下限、期限、预算/报酬、责任和结算摘要。接受委托时不得立即创造目标货物；资源必须来自真实库存或后续采购。

### P5-D 到达、交付与经营账本

抵达后允许交付委托或在当地正式市场出售。结算必须：

- 按具体批次和实际数量扣减货物。
- 修改真实买卖双方或委托双方的资金。
- 写入库存、交易、委托、旅程和人物结果记录。
- 对短交、损坏、超期、拒收和无仓位给出明确结果。
- 将关系、声望或人生事件变化绑定到具体人物与组织。

经营账本是这些正式流水的只读投影，不拥有第二份资金或库存。它至少能回答：钱从哪里来、货从哪里来、由谁承运、在哪里损耗、交给谁、谁承担后果。

### P5-E 有限委任与例外报告

玩家取得相应权限后，可以把“重复执行已知路线上的指定经营目标”提交为委任提案。复用 M26-P3/P4 的策略、权限、优先级、预算、期限、受任者和报告周期，不直接创建第二套自动经营系统。

首版自动选择必须是有界、确定性的，并允许：

- 玩家随时查看授权范围与剩余预算。
- 受任者因路线未知、人员不足、货源不足、价格越界或风险超限而拒绝执行。
- 异常形成报告，不静默改目标、不借用未授权资金、不凭空补货。
- 撤销时只释放尚未提交的资源；已经发生的交易、消耗和损失不得回滚抹除。

### P5-F 原创交互与人工试玩

交互设计必须从本项目的“目标—行动—结果—记忆”语言出发，不能复刻参考截图的底部标签栏、面板比例、颜色、图标和信息排列。

安排一名未阅读任务书和实现代码的试玩者完成 20–30 分钟盲玩，至少验证：

1. 能找到一个有明确家庭动机的经营目标。
2. 能理解岗位为何需要由具体人物承担。
3. 能独立完成装货、启程、途中选择和到达结算。
4. 能说清钱、货、时间和人物状态发生了什么变化。
5. 能理解“亲自经营”与“有限委任”的权限和风险差异。
6. 失败或短交后仍能继续游戏，并获得明确下一步。

## 五、首个验收场景

首个自动化与人工共同验收场景固定为中山—涿县布帛经营，以复用 M26-P1/P2 已有线路和正式商品映射：

1. 中山的商户家庭拥有真实人物、资金和明确债务/家庭动机。
2. 玩家为至少三名真实同行者安排领队、向导和护卫；缺少成员时允许带风险出发或明确拒绝。
3. 玩家购买六匹 `product.textile.plain_cloth`，中山市场库存和人物资金按实减少，并生成正式批次与购买流水。
4. 六匹布装入家庭所有、人物承运的商队容器；载重和来源可检查。
5. 玩家选择涿县并启动正式行程；途中消耗真实口粮，并由确定性坐标产生一次可复现选择。
6. 选择造成一匹具体批次布损坏或保全，结果写入库存流水和人物记忆。
7. 抵达后交付或出售剩余布匹；涿县库存、人物资金、委托状态和销售流水按实际数量变化。
8. 保存并读取后，人物岗位、容器、批次、行程、事件、委托、市场与账本结果保持一致。
9. 玩家能够为下一次同路线经营创建有限委任提案；提案必须经过正式执行器后才可能改变世界。

## 六、自动化验收

至少覆盖：

1. 同一永久人物不能在同一时间承担互斥岗位或出现在两个商队。
2. 无效、死亡、被拘束、异地或无授权人物不能被静默安排岗位。
3. 装货前后产品批次数量守恒，重复点击不会复制货物。
4. 载重、口粮、资金和路线任一硬条件失败时，启程不产生部分世界写入。
5. 委托从接受到交付按合法状态迁移；重复结算保持幂等。
6. 部分损耗只减少指定批次并留下流水，不能把整个商品定义清零。
7. 出售或交付后，资金、库存、市场与委托数量闭合。
8. 同一存档、时间和动作序列产生相同旅途事件与结果。
9. 存档往返保持全部新增持久事实；旧版本按顺序迁移且不创造人物、货物或资金。
10. UI 关闭、场景切换和关注度改变不修改核心事实。
11. 委任超预算、越权、缺货或路线未知时形成稳定失败码与例外报告。
12. 旧 M26-P1/P2 商旅路线、旧市场、旧行程和旧存档兼容测试保持通过。

## 七、明确不包含

- 复制或近似重制《九州：商旅》的界面、美术、文本、地图、数值、配方和任务。
- 一次性完成全国商号网络、所有商品、所有岗位和所有产业类型。
- 新建与正式市场、产品批次、家庭、组织、行程或策略系统平行的 Demo 数据。
- 无限库存商店、固定套利脚本、自动补货或为玩家专门生成的虚假买家。
- 完整金融、借贷、保险、商号股份、继承、加盟、垄断和 NPC 商战。
- 完整设施建造、土地购买和产业生产；这些只能在后续复用正式建设、土地、工作者和生产订单合同。
- 通过 UI 直接执行组织策略，或让委任提案绕过具体领域命令处理器。
- 未经独立评审的存档升级和未经记录许可的外部素材。

## 八、实施停止条件

- 若 M26-P1/P2 的市场所有权、商品映射或仓储合同与本任务发生冲突，停止实现并报告冲突，不建立旁路。
- 若新增岗位或商号事实需要改变永久人口身份、组织权属或存档结构，先提交迁移与往返测试设计。
- 若 UI 需要的事实在 Domain/Simulation 中不存在，不允许用表现层临时状态冒充完成。
- 若可用素材缺少兼容许可证，使用项目原创占位资源并记录限制，不抓取参考作品素材。
- 若 Unity 编辑器占用项目，报告锁冲突，不关闭用户编辑器。
- 若 M26-P1 的首个可玩目标仍无法通过独立盲玩，不继续扩展全国分会、产业或复杂自动经营。

- `GAME_SYSTEMS_MASTER_AND_STATUS.md`、任务路由、Demo 说明和实际状态同步，且未把候选能力误写成已有完成能力。
