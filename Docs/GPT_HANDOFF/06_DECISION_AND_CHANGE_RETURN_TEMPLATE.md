# GPT 决策与改动回传模板

> 请让GPT在讨论结束后按本模板输出。没有内容的章节可以写“无”，不要假装已经完成实现。

## 1. 基本信息

```text
主题：
资料快照日期：
使用的项目文档：
本次输出性质：讨论 / 候选方案 / 用户已接受决定 / 任务书候选 / 文档修订建议
```

## 2. 用户目标

- 玩家希望获得什么体验；
- 当前问题或不足是什么；
- 本次明确不解决什么。

## 3. 已有项目规则

- 列出与本问题直接相关的现有正式规则；
- 标明来源文档；
- 不把GPT推断写进本节。

## 4. GPT的分析与推断

- 从资料得到但原文未明确冻结的推断；
- 推断依据；
- 不确定性和可能需要补充的资料。

## 5. 候选方案

### 5.1 玩家体验

- 玩家亲自操作什么；
- 可以部分委任什么；
- 可以完全委任什么；
- 玩家看到的反馈、代价和长期后果。

### 5.2 世界事实与数据对象

- 复用的对象；
- 需要新增的对象；
- 稳定ID和数据定义；
- 所有权、控制权、权限、位置、时间与知识来源。

### 5.3 系统交互

```text
人物/家庭
Facility/生产
库存/市场/运输
组织/职位/财政
政治/战争/历史
存档/信息/表现
```

说明输入、输出和后果怎样回到同一本世界账。

### 5.4 NPC与自动化

- NPC可用的信息；
- 候选行为和评分；
- 命令与权限校验；
- 委任、报告、异常和玩家接管；
- 玩家与AI是否共用相同规则。

## 6. 冲突审计

| 冲突或风险 | 涉及现有规则 | 候选处理 | 是否需要用户确认 |
|---|---|---|---|
|  |  |  |  |

至少检查：永久人物、守恒、有限认知、Cell/Facility、稳定ID、确定性、存档、性能、操作复杂度和许可证。

## 7. 用户需要裁决的决定

按以下格式逐条列出：

```text
决定编号：D-001
问题：
方案A：
方案B：
推荐：
推荐理由：
选择影响：
```

没有用户裁决前，不把候选方案写成“项目已确定”。

## 8. 用户已经接受的决定

- 只记录用户在对话中明确接受的内容；
- 未明确回复的建议仍留在第7节；
- 接受设计不等于授权修改代码、提交或推送。

## 9. 实现状态声明

```text
文档是否已修改：否 / 是（列路径）
任务书是否已建立：否 / 是（列路径）
代码是否已实现：否 / 是（列证据）
全工程编译：未运行 / 通过 / 失败
核心测试：未运行 / 通过 / 失败
Unity测试：未运行 / 通过 / 失败 / 环境阻塞
人工试玩：未运行 / 通过 / 发现问题
提交与推送：未执行 / 已执行（列提交与分支）
```

GPT无法访问仓库时，上述实现与验证项目必须写“未知或未运行”。

## 10. 建议修改的项目文档

| 文档 | 修改目的 | 是正式规则还是来源记录 |
|---|---|---|
|  |  |  |


## 12. 一段可直接交给Codex的指令

```text

测试和存档事实。保留无关修改，列出冲突，不把GPT候选误写为已实现。

用户已接受：<填入第8节>
本次授权执行：<填入明确范围>
验收要求：<填入>
是否授权提交/推送：<是/否>
```
