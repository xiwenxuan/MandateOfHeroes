# M25-P6任务书：民用货运需求、承运选择与已知路线多段运输

## 一、任务定位

在M25-P5正式跨县民用货运的直接路线履约底座上，建立第一条可由世界日程自动运行的民用货运规划闭环：从既有真实跨县买卖订单生成货运需求，由已登记的真实承运人物和移动容器提交稳定报价，只使用承运人明确掌握的路线规划多段行程，并由同一套旅行、库存、损耗、收货和运费规则结算。

本阶段不根据抽象人口需求凭空创建买卖订单，也不允许承运AI读取全图。货运需求、承运登记、报价、路线与选择结果均是可保存、可审计的世界事实；关注层级和界面是否打开不得改变结果。

## 二、实现合同

### 2.1 需求与承运登记

- 货运需求只能来自两张真实活动订单：产品相同、不同县、限价相交、数量和卖方批次预留均有效。
- 同一活动买单或卖单同一时刻最多被一张活动货运需求占用，避免在未起运前重复许诺同一订单数量。
- 承运登记必须绑定真实存活人物、其家庭拥有且由其携带的移动库存容器、稳定计价参数、最大里程、路线策略ID和明确的已知路线ID集合。
- 日结只扫描活动市场订单、活动货运需求和活动承运登记，不扫描全部永久人物。

### 2.2 报价、选择与有限知识

- 寻路图严格限制为承运登记中的已知路线；未知路线即使存在于世界总图也不得参与报价。
- 首批支持`shortest_known`与`safest_known`两种稳定策略ID：前者优先总里程，后者优先路径最低安全度；完全相同时按路线序列稳定排序。
- 报价由登记的基础费、里程费和每百单位费确定；报价、总里程、路径最低安全度与完整路线序列持久化。
- 同一需求按运费更低、最低安全度更高、总里程更短、报价ID更小的顺序稳定选择；未中选报价明确关闭。
- 任何时候均复核人物位置、现有旅程、容器位置和容量、订单状态及买方可用现金；失效事实不得被强行履约。

### 2.3 多段运行与守恒

- 一张货运单保存有序路线ID、当前路段索引和当前旅程；相邻路线必须在方向与地点上连续，最终到达买方地点。
- 每段抵达后进入“等待下一段”状态，由到达阶段立即建立下一段真实旅程；最后一段才进入待收货。
- 同一承运人物和同一移动容器贯穿全部路段，本阶段不做中转换手。
- 途中自然损耗、人物口粮、买方在途所有权、目的地容量受限收货和运费托管继续完全复用M25-P5合同。

## 三、工作包

### WP1：V32持久领域合同

- 新增货运需求、承运登记、承运报价及其生命周期状态；
- 扩展民用货运的需求/报价引用、有序路线和当前路段；
- 完成唯一性、引用、有限知识、计价、路径连续性、生命周期和守恒校验；
- 完成V31到V32顺序迁移，既有直接货运迁移为单路段计划，不伪造需求、登记或报价。

### WP2：稳定规划与自动调度

- 实现有界需求生成、登记承运人报价、已知路线寻路和稳定选择；
- 选择成功后原子建立正式货运、成交、在途库存和首段旅程；
- 接入统一日界调度，不进行全人物扫描。

### WP3：多段旅行与回归

- 扩展旅行抵达和货运到达处理，连续启动后续路段并仅在最终地点收货；
- 覆盖未知捷径不泄漏、稳定报价选择、多段实际移动、旧直接接口兼容、V31迁移和非法账簿拒绝；
- 同步系统总纲、世界模拟、NPC AI、确定性存档和Skill任务路由。

## 四、验收标准

1. 没有真实跨县订单时不生成货运需求；重复日结不重复占用同一订单。
2. 未登记人物、未知路线、无容量容器或超预算报价不能起运。
3. 已知路线存在多条路径时按策略与稳定次序得到相同报价和选择结果，未知捷径不参与。
4. 多段货运的人物、容器和货物逐段到达，只有最后一段抵达后收货；数量、资金和口粮继续守恒。
5. 相同世界、种子和命令序列产生字节一致的存档结果。
6. V31安全迁移到V32，既有直接货运保留为单段，不伪造历史需求或报价；V32往返通过。
7. 全工程编译、核心测试、受控Unity EditMode、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 从家庭消费目标自动创建市场买单或从生产预测自动创建卖单；
- 多承运人换手、货栈中转保管、拆单并车、返程配货和动态改道；
- 抢运、盗匪、战斗、保险、信用、关税、路费和赔偿；
- 承运人对未知区域的自动全图探索或即时获得组织情报。
