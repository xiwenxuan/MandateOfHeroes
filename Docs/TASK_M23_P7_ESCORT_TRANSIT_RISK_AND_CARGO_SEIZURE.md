# M23-P7 军需押运、途中风险、截粮与损失审计任务书

## 1. 阶段目标

在M23-P6持久运输分段、中转交接和分批收货之上，建立第一条可审计的军需押运与途中风险闭环：

```text
真实押运人物受命并同行
→ 每个运输日按稳定世界坐标结算路线风险
→ 避开 / 击退 / 被截粮
→ 被截货物进入带威胁组织归属的事件保管记录
→ 货运单、分段和流水共同守恒
```

风险是世界事实，不因玩家是否关注、地图缩放或表现层是否展开而改变。押运人必须是永久人物，不能用一个没有人物来源的“护卫值”代替。

## 2. 必须完成

1. 为每个运输分段保存风险策略、威胁组织，并用稳定ID表示可扩展内容。
2. 押运人必须真实存在、存活、位于起点、属于承运组织、没有其他旅程或现役军职，且不得与承运人重复。
3. 押运人和承运人使用同一路线、目的地和旅行模式；分段交接前，当前押运人员也必须到达中转点。
4. 押运能力在出发时从人物武艺和统率派生并保存快照，途中不重复随机人物属性。
5. 每日风险使用世界种子、货运单稳定ID、绝对日、分段序号和明确用途键进行确定性结算。
6. 风险结果至少包括避开、击退和截粮；截粮数量不得超过当前在途货物。
7. 被截货物同时减少在途量、增加货运单与分段敌对损失，并由事件保存威胁组织及其缴获数量，不能无来源消失。
8. 货物守恒公式扩展为：发运量 = 在途量 + 已交付量 + 自然损失 + 敌对损失 + 应急自用量。
9. 存档升级到V21；V20迁移只初始化空押运/事件集合并为旧分段设置无风险策略，不伪造旧押运或袭击历史。
10. 自动测试覆盖无押运截粮、真实强押运击退、非法押运零变更、确定性往返及V20顺序迁移。

## 3. 不在本阶段

- 将途中袭击展开为完整局部战斗、比武、阵法或战术地图；
- 押运人员受伤、死亡、逃跑、被俘、治疗和战后归队；
- 夺回货物、赎买、转卖、战利品拆分和威胁组织实体库存入库；
- 天气、道路损毁、侦察情报、伏击部署和玩家实时介入；
- 自动寻路、临时改道、并行分拨、民夫车马和递归军需委任；
- 通用民用商旅风险与正式玩家界面。

## 4. 实现结果（2026-08-03）

- 新增分段风险策略、威胁组织、真实押运人物状态和永久途中事件；
- 押运人物随分段旅行，中转时执行到场校验并随下一段重新建立旅程；
- 以稳定命名随机坐标结算每日袭击、威胁强度和结果；
- 避开、击退和截粮均保存事件，截获量明确归属于事件中的威胁组织；
- 货运单、分段、事件和物流流水共同校验敌对损失与货物守恒；
- 存档版本升级至V21，完成V20到V21的无伪造迁移；
- 全工程编译通过；核心测试`225/225`通过；`git diff --check`通过；
- Unity EditMode本轮未运行：沿用同一环境已确认的批处理客户端阻塞结论，按规则使用`-SkipUnity`，未无边界重试。

当前成果是确定性抽象押运风险原型，不得描述为已经实现完整押运战斗、人物伤病、威胁组织通用库存或夺回链。
