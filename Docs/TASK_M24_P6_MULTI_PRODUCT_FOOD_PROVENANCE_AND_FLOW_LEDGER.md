# M24-P6任务书：多产品食物来源与流转账

## 一、阶段目标

在M24-P5正式库存桥接之上，消除百万压力世界“所有食品共用一个标量、检查点再统一解释为
小麦”的限制。建立紧凑产品向量，使以下路径都保留稳定产品ID：

```text
开局库存 / 家庭收获
→ 自用、市场、税粮与地租
→ 官仓、本地赈济、跨县运输
→ 运输损耗与路粮、冲突征夺、腐败
→ 家庭分立、绝户移交、消费
→ M24-P5正式产品批次与库存事务检查点
```

标量粮食余额继续作为既有P2—P5兼容缓存；产品向量是其可审计分解。两者每年必须完全相等，
产品向量不得反向改变人口、生育、死亡、市场价格或粮食总量。

## 二、实施合同

1. 产品集合、开局份额和来源层由数据配置定义，普通增减产品不修改固定枚举或存档结构。
2. 配置只能引用生产内容包中带`product.food`标签的稳定命名空间ID，ID缺失或份额不等于
   10000时拒绝运行。
3. 每个家庭和县级官仓保存紧凑产品数量向量；向量之和必须等于原粮食标量。
4. 收获以农业绑定的实际产出产品入账；税粮和地租进入同产品的县仓账。
5. 市场卖出、赈济和家庭自用在本年度立即消费，但消费产品必须来自真实卖方或官仓库存。
6. 跨县运输先按产品拆分装运，再分别分配自然损耗、路粮和实际到货；不得把运输后的产品
   重新随机或统一改成其他产品。
7. 婚后分家和绝户移交只转移既有产品向量，不产生或删除食物。
8. 每种产品独立满足：

```text
开局 + 收获
= 消费 + 腐败 + 冲突征夺 + 运输损耗 + 路粮 + 期末家庭库存 + 期末官仓库存
```

9. 市场、税粮/地租、赈济、运输和家庭生命周期转移另记内部流量，但不重复计入世界增减。
10. M24-P5检查点按产品向量生成批次；家庭粮食转换继续记录旧粮余额等量负向变动。

## 三、技术验证场景

第一轮使用核心内容中的：

- `product.wheat_grain`：开局80%；
- `product.dry_ration`：开局20%。

该比例是明确标为`gameplay_completion`的技术测试输入，不是东汉食物结构史实。农业收获仍
只产生当前农业内容绑定的小麦；干粮没有凭空再生产，只能被消费、损耗、转移或作为开局
库存保留。后续增加粟、黍、稻等作物时复用同一账，不改变协议结构。

## 四、工作包

### WP1：数据合同

- 生产内容投影暴露所有`product.food`产品及稳定身份；
- 新增多产品来源配置、份额与引用校验；
- 安全入口新增`-FoodProductProvenance`并继承P5全部前置阶段。

### WP2：流转实现

- 家庭/县仓产品向量初始化；
- 接入收获、税粮、地租、消费、市场、赈济、运输、损耗、分家和绝户移交；
- 每年执行标量—向量与逐产品守恒审计。

### WP3：检查点与证据

- 输出`food-product-provenance.json`；
- M24-P5正式批次桥接按产品拆批；
- 双跑比较来源账、正式批次和事务哈希；
- 100万人50年记录耗时、峰值内存和P4/P5回归哈希。

## 五、验收标准

1. 至少两种食品分别拥有独立开局、消费、损耗、内部转移和期末库存记录。
2. 每个家庭与县仓的产品向量每年都等于原标量。
3. 每种产品独立守恒，世界总量继续满足P2—P5原守恒式。
4. 市场、赈济和运输不得改变产品ID或制造第二份库存。
5. 正式桥接源粮总量等于产品来源账期末总量。
6. P4人口、家庭生产、农业工单和年度反馈哈希不变。
7. P0—P6兼容自测、百万50年候选、全工程编译、核心测试、Unity和差异检查分别报告。

## 六、不包含

- 新增粟、黍、稻、豆等正式农业内容及轮作规则；
- 不同食品的营养、体积、保质期和价格换算；
- 逐笔家庭市场成交文件和每餐消费日志；
- 把百万产品向量直接内联进当前V28 JSON快照；
- 1,000万或累计5,000万完整游戏负载。
