# M25-P18 任务书：逐人救济配额、离队保留与备餐余额

## 一、任务定位

承接 M25-P10 的家庭月结缺粮事实、M25-P16 的实物领取和 M25-P17 的实际进食恢复。
本阶段把“家庭应补多少营养”继续拆到同次短缺中每个实际受损人物，防止仍在家的成员
替代离村、服役或死亡成员吃掉其份额，也防止人物回来后因整件食品的整数舍入而永久
无法完成原救济账。

## 二、实现范围

### 2.1 V40 持久合同

- 救济进食账保存开放命名空间分配策略 ID；新账使用
  `mandate.relief_allocation.proportional_individual_need.v1`。
- 每名受损人物保存本月原始营养需求、从家庭缺口分得的精确营养配额和累计已吃营养。
- 家庭缺口按每名受损人物原始需求比例分配；先取整，再按人物稳定 ID 顺序逐单位补齐余数，
  所有逐人配额之和必须精确等于家庭应补营养。
- 整件食品被扣除后、尚未分给任何合格人物的营养保存为备餐余额。备餐不是人物已进食，
  不触发恢复；后续只有原受损且当前合格的人物可以领取。

### 2.2 进食资格与份额保留

- 当前存活、仍在原村且未服征兵役的原受损人物，只能消耗自己的未完成配额。
- 离村、服役或死亡人物的未完成配额保持在原账上，其他家庭成员、迁入者或新成员不得代领。
- 合格人物回来后，先使用同账备餐余额，再扣除同一领取单形成的可追溯食品批次；
  不凭空增加库存，也不重复扣除批次。
- 健康和生活压力恢复仍按本人累计已吃营养占本人配额的比例计算，并受 M25-P17 保存的
  本次实际损失上限约束。

### 2.3 兼容迁移

- V39 到 V40 不从家庭成员、年龄或当前状态伪造历史逐人配额。
- 既有 V39 进食账明确标记为
  `mandate.relief_allocation.legacy_household_shared.v1`，逐人新数值和备餐余额使用 `-1`
  兼容哨兵，继续按 V39 家庭共享语义结算。
- V39 空账、V38 及更早版本继续沿顺序迁移，不倒推历史救济资格或治疗。

## 三、验收标准

1. 新月结账逐人需求为真实年龄口径的 20,000 或 30,000 营养单位，配额精确闭合家庭缺口。
2. 同种子、同世界事实产生完全相同的逐人分配和快照。
3. 一名受损人物服役时，其配额不被家人消费且人物不恢复；返回后可继续吃完自己的份额。
4. 整数食品单位产生的未分配营养有显式备餐余额，满足
   `逐人累计已吃 + 备餐余额 = 批次实际提供营养`。
5. 篡改逐人配额、累计已吃、备餐余额或家庭合计会被领域校验拒绝。
6. V39 有账存档迁移后保留旧家庭共享行为，不伪造逐人历史。
7. 全工程编译、核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别通过。

## 四、非目标

- 本阶段不实现赈济资格政策编辑器、村内跨家庭优先级、排队动画或玩家 UI。
- 不实现照护者送餐、特殊病号餐、长期营养史、疾病恶化或备餐腐败。
- 不改变永久人物冷热存储、关注精度、出生死亡或一般医疗规则。
- 不把设计目标写成上述未实现功能已经完成。
