# Runtime 性能与调度报告

## 调度合同

- HOT：每日决策/结算候选。
- WARM：每7日聚合决策候选。
- COLD：每30日批量决策候选。
- 异常、战争、订单到期、运输到达和重大事件 watcher 可把必要工作提前，但不能改变事实。

LOD 状态只持久化频率与下一次调度时间；从 COLD 切到 HOT 不重生 Person、Facility、Inventory 或关系。Signal 按需从真实对象重算，Arena 只保存实验指标和轨迹。

## 基础档位

代码和测试入口已实际执行100、1,000、1,182县级Agent三档、1,000个条件历史事件Watcher和1,000个订单/运输候选批次。V1 的目标是验证稳定排序、批量入口、无隐藏库存和固定 Seed 可复现；本轮没有建立硬件无关的毫秒阈值，也不将结果外推为全国5,350万人全HOT保证。洛阳400K生活经济回归继续由原V70专项证据和本轮15项Unity回归共同守护。

## 优化门禁

下一阶段应优先建立分区索引和按Location/Container的增量Signal缓存，再进行全量HOT/WARM/COLD压力测试。缓存丢失必须可重算；不得为性能合并、删除或重新随机永久人物。
