# M26-P0 可玩 Demo 主循环整合任务书

## 一、阶段定位

本阶段不再沿 M25-P42 继续扩展医疗账本，而是把项目已经存在的人物、地图、时间、任务、
建设、生产、贸易、战争和医疗底座接成一条普通玩家可以理解、可以操作、可以反复游玩的
Unity Demo 主循环。

M1 已经建立主菜单、自建或选择现有人物、地图旅行、任务、时间推进和开发观察台，是本阶段
的入口壳；M17—M25 已经建立大量共享世界账。本阶段的工作不是重新实现这些系统，也不是
把开发观察台继续堆大，而是补齐玩家命令、情境行动、事件反馈和跨系统回写，让已有系统成为
同一段人生经历。

本任务中的“首批身份”和“Demo 验收切片”只表示首批贯通与验证样本，不缩减完整游戏方案，
不把身份、地图、建设、战斗或内容集合锁死为最终上限。

## 二、玩家可体验目标

玩家在 Unity 中打开正式 Demo 场景并点击播放后，可以完成以下闭环：

```text
开始新游戏或读取存档
→ 自建任意新人物，或从当前世界全部可扮演人物中选择一人
→ 以其真实家庭、地点、身份、组织和资产进入世界
→ 查看自己当前知道的地图、人物、设施、任务和风险
→ 选择旅行、工作、生产、经营、学习、建设、任务或战斗行动
→ 消耗真实时间、劳力、金钱、物资和权限
→ 世界与NPC继续推进
→ 收到事件、结果和后果反馈
→ 保存后继续同一人物与同一世界
```

Demo 必须让玩家感受到“我是世界中的一个人”，而不是“我在操作系统测试按钮”。

## 三、正式范围

### 3.1 Unity 可玩入口

- 新建 `Assets/Scenes/PlayableDemo.unity` 作为普通玩家入口，保留
  `SimulationDashboard.unity` 作为开发观察台与诊断工具；
- Demo 场景必须具备有效相机、EventSystem、可见主界面和可恢复的启动流程，点击 Play 后不得
  出现 `No cameras rendering`；
- 提供开始新游戏、继续游戏、保存、读取、返回主菜单和退出当前局的清晰入口；
- 普通界面默认不显示内部 ID、事务流水、迁移版本、转院责任链等开发信息；开发审计入口仍可
  单独保留。

### 3.2 任意人物创建与世界人物选择

自建人物至少支持：

- 姓名、性别、开局年龄、出生背景和首个主身份；
- 从合法的家庭、村庄、城市、军队或其他组织落点中选择或由规则推荐；
- 生成永久稳定 ID，并建立真实人物、家户、地点、初始资产、身份和组织关系；
- 创建结果必须通过正式模拟服务写入世界，Unity 表现层不得直接拼接不完整人物状态；
- 不得因重新进入界面、缩放地图、切换身份或读档而重新随机人物。

选择现有人物必须：

- 面向当前世界全部合法、在世、可扮演人物，而不是写死少数人物名单；
- 支持按姓名、历史人物标记、地点、家庭、身份和组织筛选；
- 历史人物与普通人物使用同一套世界规则；历史标记只决定资料、内容权重和检索方式，不提供
  凭空资源或规则豁免；
- 选择后接管原人物已有的家庭、资产、关系、伤病、职责和旅程，不复制第二个人物。

### 3.3 身份落点与共同主循环

首批贯通军人/武将、商人、农户、士人四类身份。每类身份进入世界时都必须落到具体家庭、
地点和合法组织关系中，并共享旅行、时间、健康、金钱、物资、任务、关系和事件规则。

| 身份 | 首批可操作循环 | 必须回写的世界事实 |
|---|---|---|
| 农户 | 查看田地与季节，选择劳作、播种/照料/收获或接受农事工单 | 人物时间与体力、家庭库存、种子/产品批次、土地或工单进度 |
| 商人 | 查看已知市场，采购，组织携货旅行，承担口粮与自然损耗，到达后出售 | 现金、具体货物批次、容器、旅程、市场成交、价格与损耗账 |
| 军人/武将 | 进入军队，接受职责或军令，行军、补给并参与一次局部战斗 | 服役、军职权限、军粮装备、士气、伤亡、战果和战后状态 |
| 士人 | 学习、拜访、接受文书/调查/治理类任务，并对事件提出选择 | 时间、能力/知识实践、关系、任务结果和地方状态 |

身份行动必须来自当前人物的能力、地点、职位、知识和资源。没有权限或条件时，应说明原因并
给出可行前置行动，不能只让按钮失效。

### 3.4 地图、旅行、时间与有限认知

- 使用同一张世界地图和现有稳定地点/道路事实，不创建 Demo 专用的第二套地理；
- 玩家只能对已知地点、路线、市场、设施和军情作出相应决策；未知内容显示为未知或传闻，
  不从开发观察台泄露；
- 支持选择地点、查看距离与预计耗时、开始旅程、逐日推进和抵达反馈；
- 旅途中人物仍消耗时间与口粮，世界、NPC、任务和事件继续推进；
- 战略、地区和本地视图可以使用不同聚合与表现，但必须读取同一世界事实；
- Demo 至少提供一天、若干天和“推进到当前行动完成”三种玩家时间控制，长推进必须显示预计
  时长、允许取消，并遵守确定性结算。

### 3.5 统一情境行动与反馈

建立面向玩家的情境行动入口。它只展示当前人物在当前地点、身份、权限、物资和状态下真正可做
的事情，至少覆盖：

- 旅行与休息；
- 身份工作与学习；
- 生产或加工；
- 发起、参与或查看建设；
- 买卖和携货旅行；
- 接受、推进、放弃或提交任务；
- 参加或指挥一次权限匹配的局部战斗；
- 受伤后的治疗或休养选择。

每次行动反馈至少说明：做了什么、消耗多少时间、钱物和劳力、改变了哪些可见状态、产生了
什么新机会或风险。详细审计保留在后台，不把事务流水直接当成玩家叙事。

### 3.6 建设、生产、贸易与任务接通

- 建设复用真实项目、材料、劳力、资金、地点与权限；至少完成“发起或加入项目—推进—完工—
  设施生效”的玩家可见闭环；
- 生产复用数据驱动作物、产品、配方、工单和批次库存；至少完成一个农业生产闭环和一个加工
  或身份生产闭环；
- 贸易复用正式市场订单、货物批次、现金托管、承运、损耗和收货规则；玩家界面提供易懂的
  买入成本、携带量、预计口粮、风险和卖出结果；
- 任务必须由真实地点、家庭、组织或世界需求产生，至少具有成功、部分成功、失败和放弃结果；
- 任务奖励与代价必须写回真实资金、物资、关系、职位、地方或战争状态，不只增加抽象经验值。

### 3.7 事件选择

- 至少接通一条地方动态事件和一条具备历史条件的事件；
- 事件只在人物确实能获知或亲历时展示；
- 每个事件至少提供两个有意义选择，也允许拒绝或不参与；
- 选择通过正式命令改变人物、家庭、组织、地点或历史状态；
- 玩家不参与时，事件和相关组织仍能按世界规则推进，不等待玩家。

### 3.8 局部战斗

局部战斗是完整战争系统的首个玩家表现切片，不是最终战争上限。本阶段至少支持：

- 从军令、任务、旅行遭遇或剿匪需求进入局部战斗；
- 根据人物军职区分个人职责、小队命令和较高层指挥权限；
- 玩家可作出准备、交战方式、坚持/撤退等有限但有后果的选择，也可委任自动结算；
- 复用真实参战人物、装备、兵种派生、士气、补给和确定性战斗结算；
- 战后把伤亡、伤情、战利品、军粮、装备、关系、任务和地方治安写回共享世界账；
- 不在本阶段伪称已经完成军团可视化、攻城、水战或最终战术表现。

### 3.9 面向玩家的医疗闭环

医疗在 Demo 中只表现为：

```text
受伤
→ 选择就近就医、随军治疗或回家休养
→ 显示预计时间、可见费用/药材和主要风险
→ 世界推进并消耗真实资源
→ 康复、继续带伤、永久伤残或死亡
```

- 普通玩家界面不要求理解“住院记录”“转院段序”“床药责任链”等内部名词；
- 底层可以复用 V43—V64 已有病案、药材、军医、设施、伤残和死亡合同，界面将其汇总成
  可理解的选择与结果；
- 只有玩家主动打开开发审计时，才显示详细病案和责任流水；
- 本阶段不继续 M25-P43 跨组织转院、自动选院或更细住院管理扩展。

## 四、架构与数据规则

### 4.1 命令边界

- `Mandate.Presentation` 只负责输入、视图模型和反馈，不直接改写 `WorldState` 集合；
- 人物创建、身份落点、行动可用性、行动执行、事件选择和战斗进入均由
  `Mandate.Simulation` 的明确服务或命令入口完成；
- `Mandate.Domain` 保存永久事实与不变量，不依赖 Unity；
- 所有玩家命令返回结构化结果，至少包含成功状态、玩家摘要、时间成本、可见资源变化和产生的
  世界事件引用。

### 4.2 同一世界账

- Demo 不得建立专用人物、专用钱包、专用背包、专用市场、专用伤亡或专用任务状态；
- 允许建立只读视图模型和缓存，但它们必须可以从世界事实重建；
- 玩家关注只改变加载、信息和表现精度，不改变同一事实的结果；
- 随机行为使用稳定 ID、世界种子和明确日/动作坐标。

### 4.3 存档兼容

- 优先复用当前 V64；只有确认需要新增永久事实时才升级存档版本；
- 如升级版本，必须顺序迁移、验证旧档往返，并保证人物、家户、库存、任务、旅程、伤情和
  玩家控制人物不丢失、不合并、不重随机；
- 普通内容继续使用稳定命名空间 ID 与数据定义，增加身份行动、事件、任务、产品、设施或配方
  不应要求升级存档结构。

## 五、实施顺序

### P0-A：入口和会话边界

1. 建立 `PlayableDemo.unity`、相机、EventSystem 和场景启动器；
2. 抽离开发观察台与玩家会话界面；
3. 建立新游戏、继续、保存、读取和返回主菜单流程；
4. 修复中文显示、分辨率适配和基础交互阻塞。

### P0-B：人物与身份落点

1. 扩展自建人物请求和验证；
2. 建立全部可扮演人物检索、筛选和人物摘要；
3. 将军人、商人、农户、士人落到具体家庭、地点和组织；
4. 验证历史人物与普通人物同规则、同存档。

### P0-C：统一情境行动

1. 建立行动查询、执行命令和结果摘要合同；
2. 接通旅行、时间、休息、任务和事件；
3. 接通四身份首批行动；
4. 为不可用行动提供原因与前置条件。

### P0-D：经营和战争切片

1. 接通建设项目完整玩家反馈；
2. 接通农业/加工生产和批次库存；
3. 接通市场、携货旅行、损耗与成交；
4. 接通局部战斗、战后回写和简化医疗结果。

### P0-E：可玩性验收

1. 制作一条无需开发者操作的 20—30 分钟验收路线；
2. 分别用四个首批身份完成至少一次有效行动；
3. 验证保存读取后继续同一闭环；
4. 完成自动测试、Unity PlayMode/EditMode 与人工冒烟；
5. 更新 README 的唯一 Demo 启动说明和当前限制。

## 六、自动验收矩阵

### 6.1 纯 C# 核心测试

- 自建人物生成永久唯一 ID，并与合法家户、地点和身份绑定；
- 选择任意现有人物不复制、删除、合并或重随机人物；
- 四类身份行动只在地点、资源、状态和权限满足时执行；
- 每次行动的时间、资金、库存、生产、任务与战斗变化守恒且可追溯；
- 同一世界种子与同一命令序列产生相同结果；
- 保存读取保持玩家人物、行动状态、旅程、任务、库存、事件和伤情；
- 医疗结果界面摘要与底层康复、伤残、死亡事实一致。

### 6.2 Unity EditMode/PlayMode

- `PlayableDemo.unity` 能加载且场景引用完整；
- 点击 Play 后首先出现主菜单，不出现黑屏或 `No cameras rendering`；
- 新建人物与现有人物两条入口均能进入游戏；
- 四身份行动面板能显示并执行至少一项合法行动；
- 地图旅行、事件选择、建设/生产/贸易和局部战斗至少各完成一次；
- 受伤后能完成就医、随军治疗或回家休养中的一条路径并显示结果；
- 1280×720、1920×1080 下关键按钮和反馈不被遮挡；
- 开发观察台仍可单独进入且不污染普通玩家界面。

### 6.3 人工可玩验收

必须由测试者从项目打开开始，在不使用 Console、Inspector、测试按钮或代码修改的情况下完成：

1. 新建一名人物或选择任意现有人物；
2. 确认其家庭、地点和身份；
3. 查看地图并旅行到相邻地点；
4. 执行至少一个身份行动和一个任务；
5. 参与生产、建设或贸易中的至少一条经营闭环；
6. 进入并结束一次局部战斗；
7. 处理一次伤情；
8. 保存、返回主菜单、读取并继续；
9. 在行动日志或人生摘要中看见这些行为造成的世界后果。

## 七、完成定义

- Unity 中存在唯一明确的普通玩家 Demo 启动场景；
- 上述 20—30 分钟主循环可以反复完成，不依赖开发观察台；
- 四类首批身份都不是纯标签，至少各有一条真实行动链；
- 建设、生产、贸易、任务、事件、局部战斗和简化医疗都接入共享世界账；
- 没有把底层事务记录直接暴露为普通玩家主要玩法；
- 全工程编译、核心测试、受控 Unity 测试、`git diff --check` 和差异审阅分别完成；
- README 明确说明如何打开并体验 Demo；
- 若本阶段需要提交或推送，必须由用户另行明确授权，并只包含本阶段文件。

## 八、明确不包含

- M25-P43 或更深的转院、住院、医疗责任扩展；
- 最终美术、最终 UI、最终数值和平衡；
- 完整军团可视化、攻城、水战和无双式个人战表现；
- 全部身份的完整内容量；
- 223年正式历史主题剧本的完整内容制作；
- 大模型对话、穿越者框架和大型意难平 MOD；
- 以 Demo 为理由删除、合并或替代任何永久人物和既有世界事实。
