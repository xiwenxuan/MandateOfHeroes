# M24-P4任务书：人口—资源反馈诊断与可解释校准

## 一、阶段目标

在M24-P3具体家庭生产长跑基础上，解释“100万开局、50年后仅19,379人在世”的因果链，
并建立不覆盖原始基线的可重复校准候选：

```text
年度人口、家庭、土地、种子、生产、消费与压力死亡账
→ 统一年度反馈指标
→ 区分土地闲置、劳力不足、种子不足、产量不足和分配不足
→ 结构性规则修复与参数候选分别运行
→ 基线—候选使用同一世界种子和验收口径对照
```

本阶段仍是独立压力工具，不修改V28正式存档，不把校准候选解释为东汉史实，也不通过
删除人物、阻止死亡或重新随机人物制造“稳定人口”。

## 二、已确认的基线诊断

P3主种子`14000024`的年度县账表明：

- 第1年土地耕作率仅34.08%，食物满足率68.03%，饥荒死亡率5.42%；
- 第2年满足率降至38.88%，净人口变化为-9.94%；
- 第10年土地耕作率42.35%，但已有39.15%土地进入未再利用公地；
- 第50年土地耕作率1.47%，未利用公地97.26%，饥荒死亡率仍为6.25%；
- 种植投入的毛收获倍数长期约6.5倍，说明首要异常不是配方产生负收益；
- 绝户土地进入公地后没有重新形成具体家庭工单，加上开局种粮配置与家庭劳力分布不匹配，
  形成“低耕作—缺粮—死亡—更多公地闲置”的正反馈。

因此本阶段不得只提高产量系数掩盖土地利用死锁。

## 三、实施合同

1. 世界证据增加逐年人口—资源反馈记录：人口、出生、死亡、压力死亡、需求、消费、满足率、
   土地耕作率、公地率、劳力理论覆盖率、种子理论覆盖率、毛收获/需求和瓶颈分类。
2. 诊断只读取既有事实，不参与随机公式，不因玩家关注或报告开关改变世界结果。
3. P3基线参数和结果保持可选择、可复跑；校准候选使用独立稳定ID数据档。
4. 县级未分配公地可以按年度临时租给有真实农业劳力的具体家庭；土地所有权不转移，
   工单仍由具体家庭执行，地租进入县级公共库存。
5. 年度临时租地总量不得超过县级公地，家庭总耕作量仍受真实劳力、种子和最小工单限制。
6. 开局种粮储备、死亡压力等参数调整必须分别出现在候选数据档中，禁止写死在模拟代码。
7. 候选目标是无显式历史大战时避免技术性灭绝循环，不是预设人口必然增长；50年期末在世
   人口目标区间、最低平均满足率和最高压力死亡率由校准配置明确声明。
8. 未达到目标的候选必须保留失败证据或在报告中说明，不得把阈值改成结果值后宣称通过。

## 四、验收标准

1. P3基线复跑人口、生产文件和摘要不因开启诊断而变化。
2. 1万人10年双跑的年度反馈记录与诊断摘要完全一致。
3. 人口—资源反馈记录可以自动识别P3的未利用公地死锁和食物不足。
4. 开启季节性公地租用后，每县年度临时租地不超过公地，且总耕作不超过固定可耕地。
5. 候选配置下土地、种子、粮食、现金、人口与逐单分配继续守恒。
6. 100万人50年基线—候选对照均在285秒候选时限内形成机器可读结果。
7. 候选达到配置声明的人口与生计阈值；若未达到则本阶段只记为诊断完成、校准未通过。
8. P0/P1/P2/P3兼容自测继续通过。
9. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。

## 五、不包含

- 把随机技术参数标为135—190年的史实人口曲线；
- 私人地主租约、佃户债务、雇工工资、诉讼和豪族兼并；
- 跨县季节性劳务迁徙、农具、畜力、水利、肥料和多作物轮作；
- 正式V10库存迁移、正式存档升级、Unity校准界面、提交或推送仓库。
