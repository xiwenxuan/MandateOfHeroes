# M25-P15任务书：正式仓储环境、食品腐败与损耗审计

## 一、任务定位

承接M25-P14已经形成的家庭粮仓、村仓、县仓和真实运输库存。本阶段把食品离开运输状态后的仓内时间成本纳入统一世界账：同一批食品按其食品腐败敏感度、当前仓储环境与固定三十日评估周期降低新鲜度，并在仍有未预留实物时形成可追溯的自然损耗。

仓内损耗与民运途中损耗必须严格分离。在途承运容器继续只由民运/军运系统结算；到仓后的静态设施或容器才由本系统结算，不能对同一日、同一批货重复扣减。

## 二、实现范围

### 2.1 V37持久合同

- `VillageFacilityState`与`InventoryContainerState`保存稳定命名空间仓储环境ID和损耗防护基点；仓储环境是开放内容引用，不使用固定枚举。
- `ProductBatchState`保存下一次仓储评估日；新批次和转入新仓的批次从入仓日起重新计算三十日周期。
- 新增仓储损耗审计账，保存批次、食品、仓储目标、环境快照、评估日前后数量和新鲜度、预留保护量及库存事务引用。
- 新增正式库存事务类型`FoodStorageNaturalLoss`。数量损耗必须由负库存行解释；仅新鲜度下降而无数量损耗时也必须保存审计账。
- V36到V37只补齐环境、评估日和空审计账，不倒推旧世界已经发生的腐败。

### 2.2 确定性结算

- 仅处理正式食品定义中的批次，并按批次稳定ID排序。
- 每三十日结算一次；有效损耗率由基础月损耗、食品腐败敏感度和仓储防护共同计算，全程使用整数基点。
- 新鲜度作用于整批实物；数量损耗不得把批次数量降到已预留量以下，不得暗中取消市场、救济、运输或军需预约。
- 移动承运容器及仍在途批次不进入仓内损耗；到达并生成目标仓新批次后重新开始仓储周期。
- 同一评估日重复调度必须幂等，存档恢复后不得重复扣粮或重复建账。

### 2.3 统一世界内核

- 每个新日由持久命令调度器检查到期批次，统一事务先校验再提交。
- 命令、事务、事件和审计ID均由批次ID与评估日稳定生成。
- 执行后保存命令结果、事件发件箱、库存事务和损耗审计，不能只改表现层数字。

## 三、验收标准

1. 家庭粮仓、村仓或县仓内的到期食品按食品敏感度与环境防护确定性降低新鲜度并产生真实损耗。
2. 高防护环境损耗严格不高于低防护环境；零敏感度食品不产生仓储数量损耗。
3. 已预留量不会被仓储数量损耗穿透，库存事务、批次数量、预留量和审计账保持闭合。
4. 民运在途批次不会同时产生仓内损耗；到仓新批次从新的三十日周期开始。
5. 同一日重复调度、存档往返和相同种子世界得到相同结果。
6. V36到V37迁移不倒推历史损耗；篡改审计账、环境或事务引用会被领域校验拒绝。
7. 全工程编译、核心测试、受控Unity测试、`git diff --check`和范围审阅分别报告。

## 四、非目标

- 本阶段不实现具体家庭到村仓排队领取、仓吏贪污、火灾、战争焚仓、熏蒸配方、建筑升级界面或玩家操作面板。
- 本阶段不自动取消已预留市场/军需合同；预留货物仍降低新鲜度，但数量最多损耗到预留边界。
- 本阶段不改变永久人口、关注冷热、历史人口与运输途中损耗口径。
