# 0. 总体设计目标

游戏需要表现一个长期持续运行的东汉—三国世界。玩家、AI人物、家族、官府、商号、产业、军队、商队与历史事件，都发生在同一套世界空间与同一套人口、资产、生产、财政和战争规则中。

核心设计原则：

1. **世界只有一套。** 不拆成战略世界、经营世界、RPG世界三套互不一致的空间。
2. **人口是真实人物。** 农民、工匠、官员、士兵、商人都来自同一套永久 Person。
3. **资产是真实资产。** Cell、Facility、库存、装备、粮食、马匹、车辆都应能追溯真实归属。
4. **兵是人，不是数字。** 军队兵力最终对应具体Person。
5. **职位给权限，不给抽象BUFF。** 官职、军职必须产生真实可玩权力或政治价值。
6. **底层真实不等于界面繁琐。** 高层玩法必须大量使用汇总、筛选、一键委任、异常上报和逐层下钻。
7. **同一个对象只存在一份权威状态。** 台账、汇总、UI只是索引与视图，不复制第二份真实状态。

# 1. 统一世界与 Cell

## 1.1 Cell 的定位

- 天下采用统一 Cell 世界。
- Cell 是抽象的大型标准地块，也是土地所有权、设施建设、部队占格和空间管理的基础单位。
- **不强制规定 1 Cell = 现实多少米。**
- 世界可全部 Cell 化，但 Cell 本身必须保持轻量，不能每天全图高频扫描。

Cell主要保存：

```text
Cell
├─ 地形 / 高程
├─ 水源 / 地表水 / 地下水
├─ 肥力
├─ 林木与采集潜力
├─ 矿产资源[]
├─ 道路 / 大型水体等空间事实
├─ 行政归属
├─ Owner
└─ Facility（若有）
```

## 1.2 行政区域

Cell 可以同时属于：

```text
县
郡 / 国
州
国家 / 势力
```

行政区域是空间和治理关系，不等于产权。

保留项目中现有的县级地理底座（约1182县级目录），但：

> **存在县域 ≠ 一定存在有效县府。**

县域是地理事实；县府是一个真实行政机构 / Facility。

# 2. Cell 产权与建设权

## 2.1 一格一主

- 一个 Cell 同一时间只能有 **一个 Owner**。
- 不做百分比共有、多人共同产权等常态复杂模式。

## 2.2 建设权

> **只有 Cell Owner 可以在该 Cell 上建设。**

不采用常态：

```text
土地属于A
建筑长期属于B
```

若B要建设，需先发生合法产权变化，例如：

- 购买；
- 赠与；
- 继承；
- 征收；
- 没收；
- 战争夺取；
- 其他法定转移。

## 2.3 管理权不等于所有权

县令、太守、州牧拥有行政辖区管理权，但不能因为官职存在就直接把私人/家族 Cell 当作公共资产使用。

例如：

```text
Owner = 张氏家族
```

县令可以：

- 征税；
- 监管；
- 在合法条件下征用 / 征收 / 没收；

但不能直接：

- 盖县营铁坊；
- 拆除私人设施；
- 把库存拿走。

# 3. Facility 统一设施体系

## 3.1 统一 Facility

所有人工设施尽量共用同一套 Facility 框架。

不建议按：

```text
IronWorkshop.cs
Mine.cs
Warehouse.cs
Brewery.cs
```

分别写独立硬编码系统。

建议统一：

```text
FacilityDefinition
+
FacilityState
```

基础结构：

```text
Facility
├─ CellId
├─ OwnerId
├─ 基础能力
├─ WorkerCapacity
├─ StorageCapacity
├─ Equipment / Modules
├─ Capabilities[]
├─ AllowedRecipes[]
├─ 并行生产/服务能力
├─ CurrentWorkers
├─ CurrentProduction / CurrentServiceState
├─ MaxDurability
└─ CurrentDurability
```

## 3.2 一设施一 Cell

> **1个基础 Facility = 1个 Cell。**

大型庄园、县府建筑群、宫城、矿区、产业园等，不做成一个“超级Facility”，而是多个单Cell设施组成的空间集合。

例如：

```text
张氏庄园
=
住宅 × N
农田 × N
仓库 × N
工坊 × N
道路 × N
```

## 3.3 Facility 内部不再细分微型 Cell

不采用“世界Cell → Facility内部再切16×16微格”的方式。

Facility 内部发展通过：

- 工人容量；
- 设备数量；
- 设备质量；
- 仓储；
- 耐久；
- 能力；
- 模块；

来表达。

## 3.4 升级不是 Lv1→Lv2 抽象加成

设施升级主要是：

```text
增加工人容量
增加设备
替换更好设备
增加仓储
改善防火/防潮/排水/支护
提高单位Cell生产能力
增加可用能力或配方条件
```

单个 Facility 达到内部容量上限后，继续扩大生产应通过：

> 购买/取得新 Cell → 再建一个 Facility。

即：

> **升级提高单Cell能力；扩张增加设施Cell数量。**

# 4. 属性、状态、动作、配方必须分开

以后所有设施、人物和系统设计都应严格区分：

## 4.1 属性

回答：

> 这个对象能做什么、上限是多少？

例如铁坊：

```text
人员容量 = 10
并行生产能力 = 4
仓储 = 500
```

## 4.2 状态

回答：

> 现在是什么情况？

例如：

```text
当前工人 = 8
当前耐久 = 83%
当前生产：农具 / 长矛头 / 刀
```

## 4.3 动作

回答：

> 人物 / AI 现在做什么？

例如：

```text
开始生产
停止生产
维修
移动
训练
收割
```

## 4.4 配方

回答：

> 输入什么、耗时多久、输出什么、需要哪些能力？

例如：

```text
铁料 + 木材 + 人工 + 时间
→ 长矛
```

# 5. 生产设施与并行生产

普通生产设施可以同时生产多种产品，也可以多条生产线集中生产同一种产品。

例如铁匠铺：

```text
并行生产能力 = 4

当前：
农具
长矛头
铁刀
建筑铁件
```

也可以：

```text
长矛头
长矛头
长矛头
农具
```

设备、人员、原料与配方共同限制真实执行能力。

---

# 6. 农业特殊约束

农业仍属于统一 Facility 体系，但具有一个天然约束：

> **一个农业 Cell 同一时间只能存在一种主要种植作物。**

例如：

```text
CurrentCrop = 小麦
```

当前周期内不能同时再种粟和菽。

作物具有生长周期；已经确定：

> **作物达到80%成熟即可选择抢收。**

成熟不等于自动进仓，仍需真实收割与运输。

农业辅助事务如灌溉、施肥等属于动作，不是第二种主作物。

---

# 7. 矿业特殊资源结构

矿场与其他设施采用同一 Facility 思路，不建立独立特殊建筑体系。

## 7.1 矿产属于 Cell，自然资源不是 Facility

同一个 Cell 可以有多种矿：

```text
Cell
├─ 铁矿
├─ 铜矿
├─ 铅矿
└─ 石灰石
```

矿场只是利用这些资源的 Facility。

## 7.2 矿场内部能力

矿场通过内部属性表达：

```text
工作面
采矿设备
工人容量
排水
支护
运输
仓储
```

工作面/设备能力决定：

- 同时能开多少条采矿生产线；
- 能开多难的矿；
- 能开多深；
- 真实效率。

例如3个有效工作面可：

```text
铁
铁
铜
```

或：

```text
铁
铜
石灰石
```

矿种属于资源与生产工单，不属于“铁矿场/铜矿场”的固定建筑类型。

# 8. 人口、时间与劳动

## 8.1 一人一事

> **一个 Person 同一时间只能进行一个有效活动。**

生产、农业、建设、旅行、学习、经商、军役、战斗、治疗、休息等全部共享唯一时间占用状态。

例如：

```text
CurrentActivity = 铁坊生产
```

被征兵后：

```text
铁坊生产
↓
MilitaryService
```

铁坊立即失去该人物劳动贡献。

## 8.2 日常通勤不计算

正常本地：

- 家→铁坊；
- 家→农田；
- 城内住宅→县府；

不计算逐Cell上下班时间，也不因为距离产生工作效率惩罚。

位置只决定：

> **能不能在这里工作。**

跨区域移动、迁居、行军、商队、赴任等必须真实花时间。

# 9. 人口生命周期

为了减少计算量，不采用随年龄连续衰减曲线。

| 年龄 | 阶段 | 规则 |
|---|---|---|
| 0–13 | 儿童 | 不进入正式劳动力 |
| 14–19 | 少年 | 可参与生产劳动，但社会资格有限 |
| 20–59 | 成年活动人口 | 可参与生产、经营、行政、军事等 |
| 60–69 | 老年活动人口 | 不再从事农业、采矿、制造、搬运等生产类劳动；可教学、管理、医疗、经商、官府、家族事务等 |
| 70+ | 退休 | 默认不再承担正式工作与任务 |

人物出生/初始化时确定：

```text
NaturalDeathAge
```

自然寿命以约60岁上下为主要分布区域，但实际人物可因：

- 战争；
- 疾病；
- 饥饿；
- 灾害；
- 其他异常事件；

提前死亡。

# 10. 人口与劳动力台账

Person 是唯一真实状态源。

台账只是管理索引：

```text
空闲
生产
农业
经商
学习
从军
旅行
治疗
退休
```

管理界面可以从两种方向操作：

## 10.1 人物派遣

```text
张三
→ 派往铁坊
```

## 10.2 产业派工

```text
铁坊缺10人
→ 从权限范围内筛选10个符合条件Person
```

两种方式最终都修改同一个 Person.CurrentActivity / Assignment。

人口台账应支持：

- 年龄；
- 空闲/占用；
- 职业/技能；
- 所属家族；
- 当前地点；
- 健康；
- 是否可劳动；
- 是否可征役；
- 是否可征兵；

等筛选。

# 11. 管理权限：辖区制

正式确认：

> **不做“职位固定管理人数上限”。**

县令不是“最多管10万人”，而是：

> 管本县。

太守：

> 管本郡国。

州牧：

> 完整管理本州。

中央官：

> 通常在天下范围内管理自身职权领域。

统一权限结构：

```text
AuthorityScope
├─ Scope / Jurisdiction
├─ Domain
├─ ViewRights
├─ ActionRights
├─ SubordinatePosts
└─ DelegationRights
```

管理权、产权、征用权、征兵权应分开。

# 12. 行政官职玩法原则

## 12.1 官职必须有玩法

一个官职若没有以下任何价值，则没有必要单独做：

- 实际权力；
- 分工/委任价值；
- 政治安置价值；
- 组织控制价值；
- 仕途价值；
- 派系/制衡价值。

官职不应只是：

```text
行政效率 +5%
```

而应真正获得可操作领域。

## 12.2 每一级类似

地方主官：

```text
县令 → 本县综合行政
太守 / 国相 → 本郡国综合行政
州牧 → 本州完整综合行政
```

中央官：

```text
Scope = 天下
Domain = 某专业领域
```

例如财政、税粮、工程等。

## 12.3 属官

主官拥有属官任命权，并可把部分事务委任给属官。

例如功曹负责：

- 人才发现；
- 属吏缺员补充；
- 考核；
- 推荐；
- 人事流动。

功曹的意义不是BUFF，而是：

> 有功曹，这类真实事务有人处理；功曹空缺，上级必须自己处理或重新委任。

## 12.4 一键委任

职位系统必须原生支持：

- 全部委任；
- 分领域委任；
- 方针；
- 自动补缺；
- 自动分配；
- 异常上报；
- 重大事项审批；
- 逐层下钻。

职位越高：

> **增加管理视野、任命权和决策尺度，而不是增加点击量。**

# 13. 官职、军职、爵位区别

正式职位只保留两大类：

```text
CivilOffice      行政官职
MilitaryOffice   真实军职
```

爵位独立：

```text
NobleTitle
```

## 13.1 官职

给予：

- 行政辖区；
- 行政职权；
- 公共资源调度；
- 属官任命；
- 委任。

## 13.2 军职

给予：

- 正规军事指挥资格；
- 最大正常统兵上限；
- 军事动作权限；
- 下属军职任命权；
- 军事委任。

## 13.3 爵位

给予：

- 身份；
- 爵禄；
- 封赏/封邑收益；
- 社会地位；
- 继承；
- 政治拉拢价值。

爵位：

> **不自动产生行政权，不自动产生兵权。**

---

# 14. 军职与兵权

## 14.1 军职只设最大统兵上限

取消最低兵额，也取消单独的 AuthorizedStrength。

只保留：

```text
MilitaryOffice.MaxCommandStrength
```

人物当前兵权由实际归入其指挥链的真实部队决定。

例如：

```text
破虏将军
MaxCommandStrength = 10000
当前实际统兵 = 6350
```

则实际兵权就是6350。

## 14.2 有职无兵允许

```text
军司马
Max = 1000
Actual = 0
```

完全合法。

## 14.3 当前军职上限 V1（候选）

| 军职 | 最大正常统兵 |
|---|---:|
| 屯长 | 100 |
| 军候 | 500 |
| 军司马 | 1,000 |
| 别部司马 | 2,000 |
| 校尉 / 骑都尉类 | 3,000 |
| 裨将军 | 5,000 |
| 中郎将 / 偏将军 | 8,000 |
| 杂号将军 | 10,000 |
| 前、后、左、右将军 | 20,000 |
| 卫将军 | 30,000 |
| 车骑将军 | 50,000 |
| 骠骑将军 | 50,000 |
| 大将军 | 100,000 |

说明：以上为当前游戏 V1 候选值，不宣称为固定历史编制。

杂号将军应考虑：

- 破虏将军；
- 讨虏将军；
- 征虏将军；
- 奋武将军；
- 扬武将军；
- 伏波将军；
- 等真实将军号。

具体名称可共享同一个基础统兵上限族，不做简单等级化。

# 15. 君主兵权

君主不是军职。

规则：

> **君主最大直属统兵上限 = 当前势力最高军职的最大统兵上限。**

例如本势力最高军职为大将军：

```text
Max = 100000
```

则君主直属最大正常统兵同样为100000。

君主不能无限直属全国所有军队；超过个人直属上限后，仍需：

> 授军职 → 分兵权 → 建立下级指挥链。

---

# 16. 超编

军职最大兵额不是物理硬限制。

若：

```text
ActualStrength > MaxCommandStrength
```

则进入超编状态。

例如：

```text
校尉
Max = 3000
Actual = 3700
超编 = 700
```

当前建议：

```text
默认整改期限 = 30日
```

战时可由上级批准延长。

超编期间：

- 可以正常移动；
- 可以正常战斗；
- 不直接降低战斗力；
- 常规补员、军需、预算、军政考核受影响；
- 到期未处理则升级为违规超编。

解决方式：

- 晋升军职；
- 分兵；
- 转隶；
- 转地方军；
- 复员；
- 特殊授权（如后续保留）。

---

# 17. 地方军、正规军、私军

## 17.1 地方公共武装

包括：

```text
县兵
郡兵
州兵
```

默认活动范围：

```text
县兵 → 本县
郡兵 → 本郡
州兵 → 本州
```

地方行政官拥有组织、征集、调度这类地方武装的行政权限。

真正亲自带兵者应进入真实军职体系。

例如：

```text
县尉 + 军候
```

可以实际带县兵。

## 17.2 正规军

- 可以跨县、郡、州行动；
- 进入正规军指挥链；
- 使用正式军职；
- 公共军事财政供养。

## 17.3 私军

私军属于个人/家族。

特点：

- 不必先转官军才能参战；
- 可以由私人内部真实指挥者直接带队；
- 不需要建立第三套复杂正式军职体系；
- 军粮、军饷、装备、马匹、训练原则上由私人承担；
- 可以独立参战、协同官军、部分/全部收编。

私军规模主要由：

- 人口；
- 财政；
- 粮食；
- 装备；
- 政治后果；

约束，而不是由国家军职上限约束。

# 18. 私军与官军流转

私军可：

```text
独立参战
协同官军（保持私军归属）
正式收编为官军
```

部分收编允许：

```text
张氏私军 8000
→ 3000 转官军
→ 5000 保持私军
```

也允许：

- 收兵不收原武将；
- 收武将但不收原部；
- 武将进入官军后授真实军职；
- 私军保持原建制协同作战。

正式收编后，人物的：

- 家族关系；
- 原籍；
- 家庭；
- 旧部关系；

仍然保留，只改变军事归属。

不单独设计“运输部队”这种特殊类型。

- 移动；
- 增援；
- 分兵；
- 合并；
- 转隶；
- 驻扎；
- 移交兵员/物资。

> **兵力与军职双边调配界面**

## 19.1 支持部分留下

# 20. 军队装备与库存

每支军队不是“兵数+装备等级”，而是：

```text
MilitaryForce
├─ Persons[]
├─ Officers[]
├─ EquipmentAssignments[]
├─ Inventory
├─ Animals[]
├─ Vehicles[]
├─ CurrentLocation
├─ CurrentOrder
└─ SupplyPolicy
```

## 20.1 每个人有装备状态

真实Person可以保存：

```text
主武器
副武器 / 盾
远程武器
身体防具
头部防具
坐骑
个人携带物
```

重要人物可以详细操作；普通士兵主要通过部队标准自动配装。

## 20.2 睡眠 / 扎营不反复卸装

装备保持Assigned状态。

```text
CurrentActivity = Rest / Camp
```

现实中的脱甲、把武器放身边属于抽象表现，不进行万人级装备入库/再领用。

## 20.3 人与装备可以分别调拨

双边调配界面允许：

- 只调兵；
- 只调装备；
- 人+标准装备一起走；
- 整个建制连同随队物资转移。

已配给个人的装备默认随人；公共库存不自动按比例随人。

# 21. 军粮与供养

军队真实消耗：

- 粮食；
- 军饷/供养；
- 装备维护；
- 马料；
- 运输资源。

谁供养主要由归属决定：

```text
正规军 → 国家/势力军事财政
县兵 → 县财政与县仓
郡兵 → 郡财政
州兵 → 州财政
私军 → 个人/家族
```

驻扎在哪里不等于谁自动负责供养。

每支军队拥有：

```text
SupplySource
随军库存
```

军粮天数由：

```text
真实粮食库存 ÷ 真实每日消耗
```

得到，而不是抽象BUFF。

驻城可周期性从固定仓库结算补给；行军则依赖随军粮、车辆、牲畜和补给线。

# 22. 征兵与新兵

征兵是把真实Person从社会活动中转入MilitaryService。

当前建议常规征兵资格：

```text
20–59岁
```

14–19岁可劳动，但不进入常规兵役池。

60岁以上默认退出普通征兵池。

兵源类型：

```text
行政征兵
官军自愿招募
私人招募
既有地方军/私军转编
```

征兵不会立刻生成精锐军队。

流程：

```text
人口台账
↓
征兵
↓
新兵/集结
↓
分配军官
↓
发装备
↓
训练
↓
进入地方军/正规军
```

征兵与补员分开。

# 25. 兵种形成

Person没有永久固定兵种标签。

兵种由：

```text
Person
+ 当前军事岗位
+ 武器
+ 甲具
+ 马匹
+ 军事技能
=
当前兵种/军事角色
```

例如：

- 有马 + 骑兵装备 → 可形成骑兵；
- 有弓 + 箭 → 可形成弓兵；
- 有弩 + 矢 → 可形成弩兵；
- 有长兵器 → 长兵步卒。

装备决定是否满足条件，技能决定表现好坏。

军队可以设置：

```text
兵种编制目标
```

并一键自动整编。

退伍后人物军事技能和战争经历保留，再次征召时可以优先匹配熟悉兵种。

# 26. 大世界军事单位：Force

## 26.1 一军一格

正式确认：

> **一支独立 Force = 占1个Cell。**

且：

> **一个Cell同一时刻最多存在1支独立Force。**

100人、3000人、10000人，只要仍然是一支Force，都占1 Cell。

多支友军想进入同一Cell：

- 合并；
- 或停在相邻Cell。

分兵后形成多个Force，各占一格。

## 26.2 Force规模自由

Force不是固定“校尉部”“将军部”。

任何合法带队人物 + 一批真实兵员，都可以成为一支独立Force。

例如：

```text
屯长 + 80人
军候 + 400人
校尉 + 2300人
破虏将军 + 9000人
君主 + 50000人
```

均可作为大地图上一支Force。

MilitaryOffice决定：

> 正常最多统多少。

Force决定：

> 当前实际带哪批人、在哪个Cell、执行什么任务。

# 27. 大地图战争参考方向

大地图核心参考：

> **《三国志11》式一军一格。**

表现：

- 一支部队一卡位；
- 不能穿过敌军占格；
- 友军也不能无条件穿过友军占格；
- 山口、桥梁、道路交汇、关隘、城池具有天然卡位价值；
- 分兵占多个Cell可以形成包围；
- 多方向接敌可以形成夹击；
- 行军队列降低大军移动微操。

# 28. 阵型系统

部队内部阵型参考：

> **《三国志9》《三国群英传》式阵型思想。**

但阵型不是简单属性BUFF，也不是硬克制表。

阵型属于Force：

```text
Force
├─ Commander
├─ Officers
├─ Soldiers
├─ Equipment
├─ Formation
└─ Order
```

## 28.1 阵型本质

阵型是：

```text
内部兵力部署模板
+ 武将位置
+ 兵种位置
+ 正面/两翼/中军/预备分配
+ 朝向
+ 机动/展开方式
```

第一批候选：

- 鱼鳞；
- 锋矢；
- 方圆；
- 鹤翼；
- 雁行；
- 长蛇；
- 锥行；
- 行军/无阵。

攻城器械不作为普通阵型处理。

## 28.2 阵型知识

阵型知识可以属于人物。

例如：

```text
张三会：鱼鳞、锋矢
李四会：方圆、鹤翼
```

Force可用阵型受：

- 主将掌握；
- 下属武将掌握；
- 是否有足够组织条件；

影响。

## 28.3 阵型条件

阵型可以有：

### 硬条件

如：

- 至少有掌握该阵的人；
- 足够下属军官；

### 软适配条件

如：

- 弓弩比例；
- 马匹数量；
- 盾牌；
- 长兵；
- 训练度；
- 地形。

允许“能摆但不适合”，而不是大量硬禁止。

# 29. 阵型方向与大地图攻击方向

这是当前军事系统的重要特色。

Force具有：

```text
FormationFacing
```

例如朝北：

```text
北 = 正面
南 = 后方
东/西 = 两翼
```

大地图敌军从不同相邻Cell进攻，直接映射为：

- 正面攻击；
- 左翼攻击；
- 右翼攻击；
- 后方攻击。

因此：

> **《三国志11》的大地图站位直接影响《三国志9/群英传》式阵型内部战斗。**

# 30. 薄弱处与侦察

敌人可以主动选择阵型薄弱方向进攻。

```text
兵种
装备
武将位置
训练
疲劳
地形
阵型朝向
当前受敌方向
```

动态形成。

侦察决定敌人能够知道多少：

```text
敌军总兵力
阵型
某翼兵力
某翼兵种
某处武将
预备队
疲劳情况
```

优秀将领/AI可以利用情报：

> 攻击敌方薄弱翼侧，而不是默认正面对撞。

# 31. 战斗接敌与持续过程

两支敌对Force相邻后可以发生交战。

由于一格一军：

- 战斗发生在双方相邻Cell之间；
- 战斗中双方保持各自原格；
- 战败方撤退后，胜方才可推进占领原敌格。

战斗不是瞬间一次结算，可持续数小时甚至数日。

允许：

- 援军到达；
- 夹击；
- 阵型调整；
- 撤退；
- 追击；
- 夜晚；
- 天气变化；
- 补给变化。

但：

> **不进入第二套微型战斗地图。**

# 32. 包围与夹击

包围来自真实Cell站位。

敌军周边可撤退Cell减少：

```text
出口多 → 普通接战
出口少 → 退路受限
0个合法出口 → 完全包围
```

多支友军从不同相邻Cell同时攻击一支Force，可形成多方向夹击。

夹击优势不做简单：

```text
伤害 +30%
```

而是通过：

- 敌军被迫多方向分兵；
- 阵型侧翼/后方受击；
- 撤退方向减少；
- 预备队压力增加；

自然产生。

# 33. 战斗内部最简结构

Force内部不建立第二套格子地图。

战斗内部可抽象为：

```text

左翼
右翼
中军
预备
```

这些由Formation自动配置。

阵型本质上就是这些内部位置的兵力、兵种和武将部署模板。

玩家普通情况下只需：

> 选择阵型。

高级玩法可展开查看/调整：

- 武将位置；
- 下属部队；
- 兵种；
- 预备队。

# 34. 战斗结算框架（当前方向，尚未冻结公式）

```text

一次全军互扣HP
```

而是先确定：

例如：

```text

```

临时形成局部战斗群进行聚合结算。

核心变量候选：

- 实际参战人数；
- 兵种结构；
- 实际装备；
- 训练/经验；
- 士气；
- 疲劳；
- 阵型位置；
- 地形；
- 武将/军官；
- 当前命令；
- 夹击/包围；
- 补给状态。

不追求大量固定倍率BUFF。

# 36. 士气、疲劳、伤亡

# 38. 与行政、家族、经济的连接

军事不是独立小游戏。

## 38.1 征兵影响生产

被征走的Person不再为原：

- 农田；
- 矿场；
- 工坊；
- 商业；
- 运输；

贡献劳动。

## 38.2 家族私军消耗家族资源

家族养兵会真实消耗：

- 粮食；
- 钱；
- 装备；
- 马匹；
- 产业劳动力。

## 38.3 授军职是政治资源

授军职不是头衔：

> 是正式授予兵权上限与进入国家军事体系的身份。

把军职给大族人物：

- 可以拉拢；
- 可以收编私军；
- 但也会扩大其正式兵权和政治影响。

## 38.4 官职、军职、爵位可以叠加

例如：

```text
某人物
官职：太守
军职：破虏将军
爵位：某侯
家族：某大族家主
```

则同时拥有：

- 郡级行政权；
- 正规军兵权；
- 爵位身份与收益；
- 家族公共/私人势力。

这种人物将成为真正的地方强权。
