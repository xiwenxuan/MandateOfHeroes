# M26-P2 战略世界—商队行旅融合纵向切片任务书

## 一、目标

把现有的三国战略地图底座和 M26-P1 商旅—家庭路线接成同一个可见、可保存、可审计的世界闭环。
本阶段以中山—涿县为首条验收路线：玩家既能从战略舆图判断城市、道路、军队和地方形势，也能
切换到商队行旅模式查看真实车队、口粮、同行者、商品批次与市场机会。

参考作品只提供玩法问题与体验目标：战略层吸收《中华三国志》一类游戏的城市—道路—军队判断，
人物经营层吸收《九州：商旅》的城际跑商、车队岗位、补给和地方市场反馈。代码、文本、数值、地图
和美术必须原创，不复制商业游戏资产或实现。

## 二、共享世界合同

1. 战略舆图和商队行旅不是两个世界，也不拥有两套城市、道路、库存或时间。
2. `commodity` 是玩家可读的地方市场报价入口；可正式追踪的商品通过
   `CommodityState.ProductDefinitionId` 映射到稳定命名空间产品定义。
3. 中山购入布帛必须减少当地市场库存、扣除人物钱财、形成交易记录，并生成家庭所有的正式
   `ProductBatchState`；批次装入由人物承运的商队容器。
4. 旅行继续使用正式 `JourneyState`。人物抵达时，承运容器和其中批次随人物移动。
5. 途中损耗必须减少具体批次数量并生成库存流水；不能只改 UI 文本。
6. 涿县出售必须减少具体批次、增加当地市场库存、改变人物钱财和价格，并生成销售流水。
7. 家庭债务、商行佣金、人物关系、口粮和人生记忆继续使用 M26-P1 已有权威账。
8. 现阶段地方公开市场仍以 `MarketListingState` 表示匿名聚合供给；它与正式批次之间通过可审计的
   购入/损耗/售出流水衔接。家庭对家庭订单、托管、商号仓库和跨县委任承运不得宣称已经完成。

## 三、实施范围

### P2-A 数据与存档合同

- 增加数据驱动的商品—产品映射；首个映射为布帛→`product.textile.plain_cloth`。
- 产品定义包含单位、重量、品质维度和市场标签。
- 追加封闭库存流水类型：市场购入、途中损坏、市场售出；保留既有枚举值顺序。
- 世界存档升级到 V65；V64 迁移刷新生产内容清单并为旧布帛商品补映射，不创造货物或交易。

### P2-B 正式商队货物

- `TradingSystem` 对存在产品映射的商品生成正式批次；未映射旧商品继续走兼容库存栈。
- 商队容器具有家庭所有权、承运人物、当前位置和重量上限。
- 查询数量和载重同时覆盖正式批次与旧兼容栈，避免重复计重。
- 损耗和出售按批次稳定顺序扣减，并保持存档往返。

### P2-C 双地图模式

- 战略舆图：显示地点、道路、军队、地方形势和身份情报。
- 商队行旅：突出人物位置、实际路线、剩余距离、口粮、载重、正式批次、同行者和已知商机。
- 城镇近览基于地图缩放与地点设施事实显示市场、工坊、驿站等标记；没有设施的地点不得凭表现层
  伪造建筑。
- 当地市场面板显示当前价格、库存和常态库存；信息仍受后续知识/战争迷雾系统扩展约束。

## 四、验收标准

自动验收至少覆盖：

1. 购入六匹布后中山库存减少六、人物钱财减少、旧随身布帛栈不存在、正式批次和购入流水存在。
2. 商队启程、途中推进和抵达后，承运容器从中山移动到涿县，商品批次未被复制。
3. 一匹货损只减少具体批次一匹，并留下损耗流水。
4. 出售剩余布帛后涿县库存按实增加、批次数量归零、人物取得实际收入，并留下销售流水。
5. 当前存档往返保持容器、批次、任务和市场结果；V64 可顺序迁移到 V65。
6. Unity 可从 `Assets/Scenes/PlayableDemo.unity` 进入推荐商旅路线并切换两种地图模式。
7. 执行全工程编译、定向核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅。

## 五、停止条件与后续边界

- 不得为了界面效果复制城市、库存、军队或时间账。
- 不得把匿名地方市场聚合库存描述成已经完成全部家庭订单和商号竞争。
- 不得绕开容器容量、人物家庭所有权、行程或库存流水。
- 不得复制《九州：商旅》或其他未取得兼容许可证的游戏代码、地图、文本、数值表和素材。
- 《中华三国志》源码只允许按 `ZHSAN_OPEN_SOURCE_LICENSE_AND_INTEGRATION_AUDIT.md` 的
  Ms-PL 边界进行隔离复用或独立转换，其地图、美术、音乐、剧本、数值表和其他资源仍不得导入。
- 商队岗位工资、饮水、车辆耐久、商号仓库/分号、产业所有权、NPC商号竞争和战争封锁为后续任务，
  但新增内容必须继续复用本阶段的稳定产品、批次、容器、路线和共享市场账。
