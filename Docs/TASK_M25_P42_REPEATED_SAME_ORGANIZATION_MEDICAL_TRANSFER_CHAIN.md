# M25-P42 同组织连续转院与逐段医疗责任链任务书

## 一、阶段目标

承接 M25-P32 的首次转院和 M25-P41 的部分疗程后首次转院，把同一永久伤员、同一伤情、
同一冻结疗程扩展为可审计的同组织连续转院链：

```text
当前设施完成零个或多个剩余阶段
→ 军队级权限签发下一段直接转院
→ 释放上一目标院尚未使用的具体药材预留
→ 在下一目标院重新预留当前全部剩余阶段用药与床位
→ 患者和原救护队沿真实道路旅行
→ 指定医者接收后形成下一段责任
→ 每段治疗、床位、药材、旅程和医者责任分别闭合
```

连续转院不能重做治疗、重新生成伤情或冻结计划，也不能改写前段已经完成的医疗、手术、
永久伤残、死亡和库存事实。

## 二、本阶段范围

1. 存档升级至 V64，为每条转院增加从零开始的段序号、上一段和下一段稳定引用，并增加连续
   转院合同启用日。
2. 第一版只允许同一组织、既有直接路线、同一原救护队和同一住院疗程内最多四段转院；上限是
   当前运行与 AI 安全边界，不是最终设计上限。
3. 只有当前最近一段已经由目标医者正式接收、患者仍在治疗且没有活动旅程时，才能签发下一段；
   同一冻结阶段边界可以继续转院，不虚构中间治疗。
4. 新段来源设施和来源医者必须等于上一段目标设施和实际接收医者；段序、前后引用、创建日和
   已完成阶段快照必须连续且可由世界事实重建。
5. 签发下一段前，上一目标院未使用预留通过正式库存事务全部解锁；已消耗药材不返还。下一目标
   院按当前剩余冻结疗程重新建立具体批次预留。
6. 每一段目标床位只在该段活动或等待接收时预留；签发下一段时释放当前占床，下一段目标床位
   开始预留。
7. 治疗责任按段序和阶段边界归属：首次转院前治疗归原设施；每个相邻边界之间的治疗归该段目标
   设施与接收医者；相同边界的空段不产生治疗或用药。
8. 转运中死亡与住院中死亡始终只结算当前最近一段；已闭合前段不回滚，当前段尚未使用的预留
   继续沿 V57/V58 合同释放。
9. V63→V64 把每条既有单次转院标为第零段、前后引用为空，并把新合同设为迁移日次日；不创造
   第二段，不倒推旧释放、旅程或责任。

## 三、验收条件

- 两次连续转院能够分别闭合路线、接收医者、床位和药材；上一段剩余预留全部释放，下一段仅
  预留当前剩余疗程，最终治疗阶段连续且归属正确。
- 第二段合同未启用、上一段未接收、达到四段上限、跨组织、目标床满、药材不足、路线或人员
  不合法时，在任何旅程、预留、链引用或库存事务写入前原子拒绝。
- 篡改段序、前后链接、阶段边界、来源设施/医者、释放事务、接收责任或最近转院引用时校验失败。
- 当前段转运死亡保留所有既有治疗和前段责任，只释放当前段预留并继续遗体护送闭环。
- V64 往返保持完整链；V63 迁移只包装既有单次转院，不制造历史。
- 全工程编译、聚焦核心、完整核心、受控 Unity、`git diff --check` 和范围审阅分别完成。

## 四、明确不包含

- 跨组织诊金、药材、床位、抚恤、债务或责任结算；
- 转院取消、拒收、动态改道、自动选院、床位排队和多批次药材预留；
- 转运途中急救、车辆、天气、袭击或队员伤亡；
- 玩家医疗界面、护理班次、医疗事故比例和司法追责；
- 提交或推送版本库。
