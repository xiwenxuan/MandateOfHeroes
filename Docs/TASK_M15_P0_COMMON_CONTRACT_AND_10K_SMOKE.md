# M15-P0 任务书：共同存储合同与1万人确定性冒烟

## 一、任务定位

本任务落实 `TASK_M15_PERMANENT_POPULATION_STORAGE_BENCHMARK.md` 的 P0，不宣称完成
M15。目标是在不修改V6世界快照、不引入数据库依赖的前提下，建立一个独立、可重复、
有300秒硬超时的永久人口基准入口，并用1万人样本证明共同合同、稳定身份与守恒审计
可以工作。

## 二、交付范围

1. 建立候选后端共同操作合同，覆盖批量写入、人物与家户读取、地点/职业/状态查询、
   分区加载与卸载、到期事件、检查点与恢复、摘要以及关注视图展开和释放。
2. 实现仅用于合同校验的内存基准后端；它是P0测试替身，不是M15候选结论。
3. 读取并审计M13的六项人口与地理输入，确认105项人口来源、1182项县级目录和稳定
   地理引用仍然成立。
4. 依据M13人口权重生成1万名永久人物、家户、父母引用、稳定地点和到期事件。
5. 对相同种子重复两次，比较核心摘要、事件摘要和守恒结果。
6. 输出机器可读结果文件，记录参数、数据来源层、计数、不变量、摘要、耗时和内存。
7. 提供独立安全启动脚本，记录PID、日志、退出码和结果路径，默认硬超时300秒。

## 三、不可改变的边界

- 每名人物从生成起获得永久、唯一、稳定ID；不得以数组位置作为公开身份。
- 分区卸载、关注释放和检查点恢复不得删除、合并、替代或重新随机人物。
- 压力人物标记为 `pressure_test_v1`，不得冒充史料人口或把郡国人口平均拆成县城人口。
- M13数据只读；本任务不改人口来源、县级目录或地理映射。
- 不修改 `WorldSnapshotSerializer`、存档版本、Unity场景或现有游戏世界状态。
- 不实现SQLite、分区二进制或混合候选；这些属于M15-P1。
- 不运行10万、100万及以上档位；本任务只完成1万人开发冒烟。

## 四、实现合同

共同合同至少提供：

```text
BatchWrite(partition)
GetPerson(personId)
GetHousehold(householdId)
QueryPeople(location, occupation, organization, alive, available)
LoadPartition(partitionId)
UnloadPartition(partitionId)
ReadDueEvents(absoluteDay)
CommitDueChanges(events)
CreateIncrementalSave()
CreateCheckpoint()
RestoreCheckpoint(checkpoint)
ComputeDigest()
ExpandAttention(personIds)
ReleaseAttention(personIds)
```

摘要只包含稳定事实，不包含耗时、机器路径、进程号或内存采样。所有集合在进入摘要前按
稳定ID排序。

## 五、验收条件

1. 启动时六项M13输入均存在，审计状态为通过；人口来源为105项、县级目录为1182项、
   稳定地理与映射引用无缺失。
2. 恰好生成10,000名人物，人物ID唯一，每人具有家户、出生地点、当前位置和下一到期
   事件；父母引用如果存在，必须指向同一家户内更早出生的人物。
3. 共同合同的每项操作至少被冒烟流程调用一次。
4. 分区卸载/重载、关注展开/释放和检查点恢复前后人物数与确定性摘要不变。
5. 到期读取只返回截止指定日期的队列节点，并报告扫描数，不允许全量人物遍历冒充。
6. 相同种子运行两次的核心摘要、事件摘要、家户数、地点计数和职业计数完全一致。
7. 结果JSON明确包含 `pressure_test_v1`、输入计数、生成计数、守恒审计和所有摘要。
8. 安全脚本的外部编译和运行均有300秒硬超时、PID、日志与退出码结果。
9. 独立基准通过后，按项目规则完成全工程编译、核心测试、受控Unity测试、
   `git diff --check`和差异审阅。

## 六、完成定义

上述验收证据齐全后，只能称“M15-P0完成”。不得据此声称M15完成、正式存储方案已选定、
10万或100万人已通过，也不得据此外推5000万人档位已经可用。
