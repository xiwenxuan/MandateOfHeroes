# M21-P2 任务书：村庄生活与人口台账仓储迁移

## 一、阶段目标

承接 M21-P1 的出生增量通路，把村庄生活闭环和人口台账中直接作用于具体人物的操作迁移到统一人物仓储：

```text
村庄月结 / 人口实例化 / 迁徙 / 死亡
→ 按稳定人物ID读取或申请修改
→ 新人物登记、既有人物变更分别进入仓储集合
→ 后续由M21增量检查点统一持久化
```

本阶段覆盖 `PopulationLedgerSystem` 和 `VillageLifeSystem` 自身的人物访问，并让
`WorldSimulator`、旅行和生命系统共享同一人口台账仓储。农业工单、教育、医疗、军事等
独立系统继续分批迁移，不以本阶段接入宣称全部村庄生产或完整外置运行时已经完成。

## 二、权威边界

- 永久身份、家庭批量结算和人口守恒遵循 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 村庄生活事实与账目遵循 `TASK_M14_REAL_VILLAGE_AND_HOUSEHOLD_LOOP.md`。
- 人物仓储、出生新增和增量检查点遵循 M21-P0/P1。
- 本阶段不改变世界存档版本、人口包格式、村庄结算频率、随机坐标或人口交易口径。
- 家庭和村庄可以批量决策，但健康、劳役、征发、婚姻、迁徙、死亡与实例化结果必须落实到永久人物。

## 三、实施范围

### WP1：人口台账仓储接入

- `PopulationLedgerSystem` 支持可选共享 `IPersonRepository`。
- 统计人口实例化通过仓储登记新人物，不再直接追加 `WorldState.People`。
- 出生记录、死亡、单人/多人迁徙在修改人物前通过仓储取得可审计实例。
- 人口审计通过仓储稳定人物视图汇总；未注入时保持现有内联兼容行为。

### WP2：村庄生活人物访问迁移

- 村庄缓存、审计、家庭成员、设施管理者和婚配候选读取通过仓储完成。
- 饥饿健康损失、医疗恢复、劳动力更新、劳役、征发、迁徙、婚姻和下次事件时间修改进入仓储变更集合。
- 村庄账、家庭账、设施账和人口交易继续由现有权威系统维护，不复制到人物仓储。
- 静态缓存刷新保留兼容重载，并允许 `WorldSimulator` 传入共享仓储。

### WP3：统一模拟注入

- `WorldSimulator` 将同一仓储传入旅行、生命、村庄生活和人口台账调用链。
- `TravelSystem` 与 `LifeSimulationSystem` 内部人口台账使用相同仓储，避免人物已修改但台账调用未登记。
- 不改变不相关系统的构造方式和既有调用接口。

### WP4：验证与文档同步

- 验证人口实例化进入新增集合，迁徙与死亡进入修改集合，失败不产生幽灵人物或错误脏记录。
- 验证村庄月结注入前后世界快照完全一致，且实际受影响人物形成稳定变更集合。
- 验证关注报告、村庄审计和人口审计保持只读，不产生仓储变更。
- 验证一年村庄闭环后初始人物仍全部存在，人口与村庄审计继续平衡。
- 更新总纲、M12、M14、M21-P1、确定性说明和 Skill 路由。

## 四、不纳入本阶段

- `AgricultureProductionSystem`、`EducationSystem`、`MedicalSystem`、军队与战争系统的完整迁移。
- 从 `WorldState.People` 移除未驻留人物，或对数千万人执行月度全量人物循环。
- 修改村庄生产配方、粮食批次、家庭结构、婚育概率、税役规则或设施内容。
- 新增存档字段、异步数据库、旧代际清理或千万级完整游戏负载验收。

## 五、验收标准

1. 人口实例化只登记一次永久人物，减少来源人口批次，并进入待新增集合。
2. 人口迁徙、死亡和村庄人物状态变化进入稳定待修改集合，纯审计与报告保持只读。
3. 村庄月结在注入仓储前后产生完全相同的确定性世界结果。
4. 一年村庄闭环保留所有初始人物ID，人口、家庭、粮食与地点审计继续有效。
5. 兼容调用无需提供仓储；共享调用不会重复登记新增人物或把新增人物同时标为修改。
6. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。

## 六、执行记录

### 6.1 实现结果

- `PopulationLedgerSystem` 已支持共享人物仓储；统计人口实例化通过仓储登记永久人物，
  死亡、单人/多人迁徙通过修改访问登记，人口审计通过稳定人物视图汇总。
- `VillageLifeSystem` 已迁移村庄缓存、审计、家庭成员、设施管理者、婚配候选等人物读取；
  饥饿、医疗、劳动力、劳役、征发、迁徙、婚姻与下次事件时间均登记具体人物修改。
- 内联兼容模式会按系统与世界复用运行期人物适配器，避免在家庭成员循环中重复建立索引；
  显式注入时继续使用调用者提供的共享仓储。
- `WorldSimulator` 已把同一仓储传入村庄生活，并在缓存刷新时保留该访问上下文；旅行与
  生命系统内部人口台账也使用同一仓储。
- 新增人口实例化—迁徙—死亡审计测试、一年村庄注入确定性测试，以及村庄审计/关注报告
  只读测试；既有村庄、人口、生产和存档回归保持通过。
- 系统总纲、M12、M14、M21-P1、确定性存档说明和 Skill 路由已同步。

### 6.3 保留限制

- `AgricultureProductionSystem` 仍通过现有内联人物访问执行农业工单；本阶段只迁移
  `VillageLifeSystem` 自身，不把农业生产误写为已完成。
- 教育、独立医疗、军事、军需、建设、科研和交易等系统仍需后续分批迁移。
- `WorldState.People` 继续保留物化人物；尚未验收未驻留人物完全外置运行。
- 当前村庄月结仍面向已载入的活跃村庄和具体成员，不能用于全天下数千万人逐月全量扫描。
- 尚未实现后台检查点编排、异步写入、旧代际引用清理和千万级完整游戏负载。
