## 2. 背景

现有文档已经分别确定多层地图、真实设施、有限认知、生产工单、NPC自主行动、
战争权限和确定性存档，但尚未把以下已接受决策组织为同一套跨系统合同：

- 世界只在创世阶段初始化一次，观察不能创造事实；
- 历史锚点、合理推定和沙盒补充共同形成可配置的资源世界；
- 所有地图比例尺和专题视图读取同一世界实体；
- 玩家和NPC只能依据个人及获授权组织已经掌握的信息行动；
- 知识、文档、地图和账簿可以复制，但复制需要具体人物、材料和时间；
- 玩家与NPC可以自由建设非军事和军事设施；
- 亲自操作、实时派工、工单、目标指令和组织委任使用同一世界账；
- 完整目标不因开发批次被删减，操作压力通过托管、聚合和连续接管解决；
- 每个领域都必须定义具有玩法意义的最小真实单位和向上聚合规则。

## 5. 统一设计合同

### 5.1 世界创世与运行

```text
历史与地理资料
→ 生成一次完整初始世界
→ 生成各人物和组织的有限认知
→ 世界时间开始运行
→ 所有行为改变同一世界账
→ 消息和知识通过实际渠道传播
```

创世完成后，不得因玩家接近、缩放地图、切换视图或进入场景而重新生成已经存在的
人口、资源、设施、库存、所有权或关系。

### 5.2 一图、一物、多尺度、多视图、有限认知

- 一图：全部地点共享稳定世界坐标、地理锚点和路线网络；
- 一物：同一设施、矿脉、军队和人物只有一个世界实体；
- 多尺度：缩放只改变聚合、图标和交互精度；
- 多视图：建设、资源、商业、战争等视图只是认知账本的筛选器；
- 有限认知：任何视图都不能绕过主体知识、组织授权、时效和可信度。

### 5.3 资源创世

史料依据与资源丰度是独立参数。资源来源至少区分：

- 明确史料或考古证据；
- 历史地理合理推定；
- 地质和生态规则生成；
- 玩家选择的沙盒补充。

玩家可以选择档案考据、历史重建、贫瘠、丰富或自定义配置。增加资源仍受地质、
地形、气候和水文约束，且创世选项不能向角色泄露具体资源位置。

### 5.4 信息资产

世界事实、主体记忆、实物文档、家族档案和组织档案相互分离。复制资料需要权限或
秘密行动、具体抄写者、文字或图表工作量、载体、工具、时间、校对、运输和保管。
副本不会自动同步，离任后失去组织更新权限，但合法或秘密取得的副本及个人记忆可以
继续存在并逐渐过时。

### 5.5 自由建设与委任

历史设施是创世锚点，运行期的家庭、工匠、商人、豪族、官府、宗教组织、军队和玩家
都可以基于真实需求建设。上级目标通过建设委任逐级拆为选址、审批、征地、筹资、
运输、施工和运营工单。玩家可以在任意层级接管或交还，既有进度与世界事实不得重置。

### 5.6 实施颗粒度

每个领域设计必须回答：最小永久实体、独立ID条件、计量单位、所有权、行动者、时间、
材料、知识前置、账本变化、聚合方式和存档方式。聚合缓存只降低计算与展示成本，
不得抹除会独立改变所有权、用途、历史、消耗或游戏结果的对象。

## 6. 任务范围

### 纳入

- 设计文档的权威归并、交叉引用、状态校正和旧口径兼容说明；
- 创世配置、资源来源、认知与信息资产的目标数据合同；
- 地图尺度、专题视图、自由建设、NPC选址和全层级委任规则；
- 文档验证和差异审阅。

### 不纳入

- Unity场景、UI和地图渲染实现；
- 新的领域代码、存档版本或迁移；
- 历史资源点数据录入；
- 数值平衡、具体抄写速度和各矿种储量表；
- 提交、推送或创建拉取请求。

这些内容必须在后续实现任务中依据本任务及对应核心设计落地，不能因为本任务完成而
标记为已经支持。

## 8. 验收标准

1. 文档明确区分世界事实、主体认知和专题视图；
2. 文档明确所有视图都不能泄露主体未知事实；
3. 文档明确创世只执行一次，观察与场景加载不能创造世界；
4. 文档定义史料依据与资源丰度两轴配置，并保存资源来源；
5. 文档说明同一山地可以拥有多个独立矿脉及其勘察、开采和枯竭；
6. 文档说明信息复制需要具体人物、材料、时间和权限；
7. 文档说明玩家和NPC自由建设、AI选址及母项目—子设施结构；
8. 文档说明完整系统不靠删减控制复杂度，而靠委任、聚合、报告和连续接管；
9. 文档没有把目标设计误报为代码实现；
10. 纯文档验证、`git diff --check`和任务范围审阅通过。
