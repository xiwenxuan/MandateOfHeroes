# M21-P4 任务书：教育系统人物仓储迁移

## 一、阶段目标

承接 M21-P3，把教育计划、教师选择与月度学习结算中的人物访问接入统一
`IPersonRepository`：

```text
学生、教师稳定ID
→ 仓储只读校验与本地教师查询
→ 到期教育计划结算
→ 仅将实际技能或财富变化的人物登记为待修改
→ 后续增量检查点按受影响人口分区写回
```

本阶段不改变 M9 已有教育公式、教师容量、学习费用、实践岗位、结算频率或存档结构。
失败学习月份可以改变计划和学习记录，但没有人物事实变化时不得制造脏人物。

## 二、权威边界

- 永久身份、冷热存储和增量写回遵守 `TASK_M12_PERMANENT_POPULATION_AND_ATTENTION.md`。
- 属性、专业能力与教育规则遵守 `CHARACTER_ATTRIBUTES_TRAITS_AND_GROWTH.md` 和
  `TASK_M9_EDUCATION_AND_PRACTICE.md`。
- 教育计划和学习记录仍是世界持久事实；人物仓储只负责具体人物的读取与修改登记。
- 本阶段不增加持久字段，不提升 V11 世界存档版本，不改变稳定 ID 或确定性结算顺序。

## 三、工作包

### WP1：人物访问接入

- `EducationSystem` 接受可选共享 `IPersonRepository`。
- 学生、指定教师和结算参与者通过稳定人物 ID 访问仓储。
- 本地最佳教师查询遍历仓储的稳定人物视图，不再遍历 `WorldState.People`。
- 未注入时按世界缓存兼容适配器，保持所有既有构造调用有效。

### WP2：精确人物变更登记

- 创建、取消与只读查询不登记人物修改。
- 成功结算登记技能实际增长的学生。
- 个人付费仍由学生修改承担；家庭付费只修改家庭账，不把学生财富误写为变化。
- 仅在实际收到学费时登记教师财富修改。
- 资金不足、师生异地、教师失效、学生不可用与缺少实践等失败结果不登记人物修改。

### WP3：统一模拟注入

- `WorldSimulator` 把已有共享人物仓储传入教育系统。
- 不增加新的模拟器公开参数，不改变教育计划每日到期检查与 30 日结算规则。

### WP4：验证与状态同步

- 验证注入与兼容模式产生相同教育快照。
- 验证成功结算只登记真实变化的学生和收费教师。
- 验证教师搜索、计划建立和资金不足结算保持人物仓储干净。
- 验证 `WorldSimulator` 注入链保持月度教育事实一致。
- 更新系统总纲、M12、人物设计、M9 后续兼容记录与 Skill 任务路由。

## 四、不纳入本阶段

- 教育公式、技能上限、软潜力、教师容量和费用规则调整。
- 教材、书籍、图纸、学塾、多人课堂、拜师与师门组织。
- 家学形成、代际培养、NPC 长期培养路线和技能子树扩展。
- 医疗、军事、建设、科研、加工与贸易人物访问迁移。
- 未驻留人物完全外置运行和千万级完整教育负载。

## 五、验收标准

1. `EducationSystem` 不再直接遍历 `WorldState.People` 查找或筛选人物。
2. 注入与兼容模式在相同计划、日期和世界事实下生成相同快照。
3. 成功学习准确登记学生与实际收款教师，家庭付费不制造学生财富变更。
4. 只读规划与无人物变化的失败结算不产生新增或修改人物集合。
5. `WorldSimulator` 使用调用者提供的同一人物仓储完成教育结算。
6. M9 既有教育、费用、时间、岗位、确定性与存档回归保持通过。
7. 全工程编译、核心测试、受控 Unity EditMode、`git diff --check` 和范围审阅通过。
