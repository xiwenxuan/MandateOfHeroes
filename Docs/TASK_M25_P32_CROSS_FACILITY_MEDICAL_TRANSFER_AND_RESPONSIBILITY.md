# M25-P32 跨医疗设施转运、床药预留与责任交接任务书

## 一、阶段目标

承接 M25-P31 的冻结伤情、手术、永久伤残和医疗退役闭环，把“转院”落实为同一个永久人物、同一个伤情和同一个住院疗程在两个真实医疗设施之间发生的连续世界事实：

```text
治疗前住院伤员
→ 军队级权限批准并指定目标设施与接收医者
→ 目标床位和完成剩余冻结疗程所需药材被真实预留
→ 源床位释放，患者与原救护队沿真实道路旅行
→ 到达后等待指定医者接收
→ 接收时完成设施、主治责任和当前照护地点迁移
→ 使用目标药库的预留药材继续原冻结疗程
```

转运不能重新生成伤情、重算诊疗计划、恢复健康、复制药材或改变人物身份。玩家关注、冷热分层和读档不改变旅程、床位、药材及责任事实。

## 二、本阶段完成范围

1. 存档升级至 V54，新增跨设施转运记录、目标床位预留、药材预留、真实旅程和责任交接字段。
2. 第一版只允许同一组织所属的两个已运行诊疗设施之间、在首个住院治疗阶段开始前转运一次；该限制是当前实现边界，不是最终设计上限。
3. 转运必须由来源军队具有军队级权限的人批准；患者必须仍处于住院治疗且未完成任何阶段，原救护队全员与患者同地、存活、未旅行。
4. 目标设施必须不同于源设施、正常运行并位于真实路线另一端；指定接收医者必须在目标地存活、未旅行且达到基础军医门槛。
5. 出发前按冻结诊疗计划计算全部剩余草药需求；目标药库一个具体批次必须具有足够未预留数量，并通过正式库存事务增加预留量。
6. 源床位在转运出发时释放；目标床位从出发时起预留，在途和等待接收期间均计入容量，防止超额接收。
7. 患者和原救护队分别建立普通人物旅程，继续消耗个人行粮；军队不得把这些人物随军瞬移。
8. 全员到达后转运进入等待接收；指定医者实际接收时，住院记录、后送记录的当前诊疗点和主治责任才迁移到目标设施。
9. 冻结伤情、疗程序列、已记录的永久身份和军役关系保持不变；目标医者继续执行原计划。
10. 后续治疗优先且只能消耗本次转运预留的具体目标药材批次，库存事务同时扣减数量和预留量；全部冻结阶段完成后预留量应归零。
11. V53→V54 只建立空转运集合、空转运引用和旧后送的当前照护地点，不倒推旧转运、床位预留、药材预留或责任交接。

## 三、领域约束

- 同一住院记录至多对应一次本阶段转运；一个未闭合后送事件至多存在一个活动转运。
- 转运记录必须交叉闭合患者、军役、后送、住院、源/目标设施、源/目标医者、路线、人物旅程、药材批次和库存事务。
- 转运出发后、正式接收前，患者不得接受住院治疗、开始返程或普通旅行。
- 药材预留量必须能够由追加式库存事务重建；不得只在转运记录里写一个展示数字。
- 目标设施的预留床位与实际占床共同受床位容量限制。
- 接收后原救护队仍处于医疗后送勤务，随患者从新的当前照护地点开始后续返程。
- 跨设施转运不得修改原始后送的起点、首次目的地、首次接收医者和首次旅程证据。

## 四、明确不做

- 不支持治疗若干阶段后再转运、多次连续转院或跨组织费用结算。
- 不实现途中死亡、途中急救、车辆/担架耐久、速度差异、袭击或天气风险。
- 不实现多批次药材预留、床位排队、转运取消、改道、拒收、目标设施途中停运后的处置。
- 不实现自动选院 AI、玩家医疗界面、护理班次、院内感染、假肢、抚恤或家庭接回。
- 不提交、不推送；版本操作仍需用户另行授权。

## 五、验收用例

1. 合法转运会释放源床位、预留目标床位和足额目标药材，并为患者及原救护队建立真实旅程。
2. 全员到达后等待接收；指定医者接收后，同一住院记录迁移到目标设施且伤情与冻结计划不变。
3. 目标设施继续治疗时，只消耗预留批次并同步扣减数量和预留量，最终疗程、返程与归队仍可闭合。
4. 目标床满、药材不足、路线错误、接收医者不合格、已完成治疗阶段、重复转运或队员缺失时原子拒绝。
5. 篡改旅程、床位目标、责任医者、药材批次、预留事务、住院/后送引用或当前照护地点时世界校验失败。
6. V53→V54 不制造转运历史；V54 往返保存完整保留转运、旅行、预留和责任事实。
7. 全工程编译、聚焦核心回归、全量核心回归、受控 Unity EditMode、`git diff --check` 和范围审阅分别完成。
