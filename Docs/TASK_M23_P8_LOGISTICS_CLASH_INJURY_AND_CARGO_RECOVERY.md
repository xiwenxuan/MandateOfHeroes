# M23-P8 押运局部交战、人物伤病与截获物资夺回任务书

## 1. 阶段目标

在M23-P7真实押运与截粮事件之上，把抽象风险结果连接到第一条真实人物局部交战和物资夺回闭环：

```text
运输队遭遇袭击
→ 承运人与押运者形成局部防守参与者
→ 确定性结算真实人物伤病
→ 截粮仍由威胁组织保管
→ 有军权人物抽调同路线目标军队的具体在役成员追击
→ 成功夺回或失败
→ 人物、兵员、货物和审计账共同回写
```

本阶段使用统一世界事实和永久人物，不生成只存在于表现层的“临时护卫”或“假士兵”。

## 2. 必须完成

1. 发生真实攻击时建立持久局部交战记录；避开风险不伪造战斗。
2. 初次防守参与者至少包含真实承运人，并加入本分段仍在途的真实押运者。
3. 交战记录保存类型、结果、组织、参与人物、双方力量、伤病和夺回数量，并使用稳定命名空间ID。
4. 伤病必须回写永久人物健康；受伤的在役人物同时进入`Wounded`服役状态并重算军队兵员缓存。
5. 截获物资允许一次同路线追击：货运必须仍在遇袭分段运输中，目标军队也必须仍沿该路线前往同一目的地。
6. 追击命令要求目标军队的军级权限，并记录正式军令。
7. 追击队由一至二十名明确、存活、健康且处于现役或集结状态的真实服役人物组成；不得用人数或战力汇总替代人物身份。
8. 追击力量从人物武艺和统率派生，结果使用世界种子、事件稳定ID、绝对日和明确用途键确定性结算。
9. 成功夺回时减少威胁组织事件保管量和货运敌对净损失，将同量货物恢复到在途清单；失败不得制造货物。
10. 货运单、分段、事件、局部交战和流水分别保存总截获、已夺回和当前敌方保管量，并保持守恒。
11. 存档升级到V22；V21迁移建立空局部交战集合并清零新增夺回字段，不伪造旧战斗、伤病或夺回记录。
12. 自动测试覆盖初次交战和真实伤病、授权夺回、非法队伍零变更、确定性往返及V21迁移。

## 3. 本阶段边界

- 每次截粮事件只允许一次追击，且只支持货运仍在当前分段、目标军队同路线行军的情况；
- 不展开Unity战术场景、逐帧动作、个人招式、阵型、装备损坏或玩家实时操控；
- 不处理死亡、残疾、被俘、逃亡、赎买和完整战后医疗；
- 不支持货运已经中转、入库或结束后的跨地区追缴；
- 不支持多次围剿、援军会合、威胁组织实体仓库、货物转卖和战利品分配；
- 不实现自动军需委任、侦察情报、临时改道和民用商旅通用遭遇。

## 4. 实现结果（2026-08-03）

- 攻击实际发生时建立初次防守局部交战；避开事件不建立交战；
- 承运人与在途押运者作为真实参与者，确定性伤病回写人物健康；
- 在役伤员进入既有军队伤兵状态并同步兵员缓存；
- 新增有军权人物发起的一次性同路线军队追击，参与者均为具体服役人物；
- 成功夺回会从事件敌方保管量转回在途货运，并以负敌对损失和正夺回量进入物流流水；
- V22不变量校验参与者、伤病前后值、军职引用、交战结果、夺回量和订单/分段/事件/流水守恒；
- V21到V22顺序迁移不伪造旧局部交战、伤病和夺回历史；
- 全工程编译通过；核心测试`230/230`通过；`git diff --check`通过；
- Unity EditMode本轮未运行：沿用同一环境已确认的批处理客户端阻塞结论，按规则使用`-SkipUnity`。

当前成果是同路线、单次追击的局部交战底座，不得描述为完整战术遭遇、长期剿匪或通用战利品系统。
