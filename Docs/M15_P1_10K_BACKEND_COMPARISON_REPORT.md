# M15-P1：1万人三后端对比报告

## 一、结论边界

2026-08-01，SQLite、紧凑分区二进制和混合存储三种候选在同一生成器、同一操作顺序、
同一种子和同一批10,000名永久人物上各完成两次运行。三种候选均通过P1共同合同，
两轮内部以及候选之间的核心摘要和事件摘要完全一致。

本报告只关闭M15-P1，不选择正式存储方案，也不把1万人结果外推到10万、100万或更高
人口档位。初次写入时间受文件缓存、JIT和本机环境影响，只作为本轮比较证据。

兼容说明：M15-P2随后为关系、健康和劳动力增加了实验索引，因此当前代码重跑P1时，
SQLite与混合候选的体积和写入时间会高于本报告的P1完成快照；P2完成时已重新执行P1
10K合同并保持摘要一致。本表继续保留为P1当时的历史证据，不冒充P2后的最新性能值。

## 四、当前解释

- 分区二进制在本轮的初始体积、初写和组合查询上占优，但需要项目自行维护格式迁移、
  索引重建和跨分区一致性；
- SQLite文件数最少、即席查询能力最强，但当前逐分区写入实现的初写成本较高；
- 混合方案减少了SQLite人物载荷，保留数据库索引能力，但承担两套格式和偏移索引维护；
- 三者在1万人档均具有可运行证据，尚无证据支持正式淘汰或选定任何候选。

下一步P2应补齐一日、一月和一年到期调度、跨分区引用、血缘/组织/劳动力查询与更细的
扫描计数；P3再执行10万和100万人正式压力并提出选型建议。
